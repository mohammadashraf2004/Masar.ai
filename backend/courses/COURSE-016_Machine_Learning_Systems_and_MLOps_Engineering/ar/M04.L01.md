## 1. Training data جزء من النظام وليست File تُنشأ مرة واحدة

تقضي كثير من دورات ML معظم وقتها على Models. لكن في Production يمكن لـ Data ضعيفة أن تفسد حتى Modeling approach قوية.

يستخدم هذا الفصل مصطلح **Training data** بمعناه الواسع للإشارة إلى Data المستخدمة أثناء Model development، بما يشمل Training و Validation و Test splits.

الصياغة مهمة. فكلمة "Dataset" ثابتة توحي بشيء محدود وثابت، لكن Production data غالبًا ليست كذلك. تصل Examples جديدة، ويتغير Behavior، وتتغير Labels، وتتطور Requirements الخاصة بالـ Model.

لذلك فإن إنشاء Training data هو **Iterative process**:

```text
جمع / أخذ Sample
      ↓
Label
      ↓
Training / Evaluation
      ↓
اكتشاف مشكلات Data
      ↓
إعادة Sampling / Relabeling / Augmentation / جمع المزيد
      ↺
```

ويقدم الفصل تحذيرًا مهمًا أيضًا: قد تحتوي Data على Biases ناتجة عن Collection أو Sampling أو Labeling أو Historical human decisions. ويمكن لـ Model مدرّبة على Data منحازة أن تعيد إنتاج هذه Biases.

## 2. لماذا يهم Sampling؟

يظهر Sampling في أنحاء ML:

- اختيار Subset من Real-world data من أجل Training،
- تقسيم Data إلى Train/Validation/Test sets،
- اختيار Events من أجل Monitoring،
- تشغيل Experiment رخيصة على Subset صغيرة قبل Scaling.

يكون Sampling ضروريًا عندما لا تستطيع الوصول إلى جميع Real-world data الممكنة أوعندما لا تستطيع تحمل Cost معالجة كل ما لديك.

تؤثر Sampling method في ما تراه Model. إذا لم تمثل Sample أجزاء مهمة من الواقع، فقد تفشل Model حتى لو كانت Training procedure نفسها صحيحة.

يقسم الفصل Sampling methods إلى عائلتين عامتين:

1. **Nonprobability sampling** — لا يعتمد الاختيار على Probability.
2. **Random/Probability-based sampling** — يستخدم الاختيار قواعد Probabilistic.

## 3. Nonprobability sampling و Selection bias

تختار Nonprobability sampling الـ Examples دون Mechanism قائمة على Probability.

### Convenience sampling

استخدم أي Data يسهل الحصول عليها.

هذا شائع لأنه سريع ورخيص، لكن سهولة الحصول على Data لا تضمن Representativeness.

### Snowball sampling

ابدأ ببعض Examples واستخدمها لاكتشاف Examples إضافية.

مثال: ابدأ بعدد قليل من Social-media accounts، واجمع Accounts التي يتابعونها، ثم تابع التوسع إلى الخارج.

### Judgment sampling

يقرر Experts أي Examples ينبغي تضمينها.

### Quota sampling

اختر أعدادًا ثابتة من Groups محددة دون Randomization داخل هذه Groups.

مثال: اجمع 100 Response بالضبط من كل Age group حتى لو لم تكن هذه Groups متساوية الانتشار داخل Population الحقيقية.

### لماذا هذا خطر؟

يمكن لهذه Methods إنتاج **Selection bias** لأن Sample غير مضمونة لتمثيل Real-world population.

يقدم الفصل عدة أمثلة:

- Language models مدرّبة على Web sources سهلة الوصول بدل جميع أنواع Language الممكنة،
- Sentiment datasets مبنية من Online reviews، والتي تمثل الأشخاص الراغبين والقادرين على ترك Reviews،
- Early self-driving datasets جُمعت بكثافة في Locations مشمسة، فأصبحت Rain و Snow أقل تمثيلًا.

قد تظل Nonprobability sampling مفيدة لبدء Project مبكرًا، لكن لا ينبغي الخلط بينها وبين Unbiased sample.

## 4. Simple random و Stratified و Weighted sampling

### أخذ العينات العشوائي البسيط

يحصل كل Example على Probability نفسها للاختيار.

مثال: اختر عشوائيًا 10% من Population، بحيث يمتلك كل Member فرصة 10% للدخول في Sample.

ميزتها هي البساطة. وعيبها أن **Rare classes قد تختفي من Sample**.

افترض أن Rare class تمثل 0.01% فقط من Population وأنك أخذت Random subset صغيرة. قد لا تختار أي Example من هذه Class إطلاقًا.

### Stratified sampling

قسّم Population أولًا إلى Groups تسمى **Strata**، ثم خذ Sample من كل Group بصورة منفصلة.

مثال:

```text
Class A → Sample بنسبة 1%
Class B → Sample بنسبة 1%
```

يضمن ذلك إمكانية ظهور كلتا Class حتى عندما تكون إحداهما نادرة.

التحدي هو أن Strata نظيفة قد لا تكون موجودة، خصوصًا في Multilabel tasks حيث يمكن لـ Example واحدة الانتماء إلى عدة Groups.

### Weighted sampling

تحصل كل Example على Weight تتحكم في مدى احتمال اختيارها.

يفيد هذا عندما تخبرنا Domain knowledge بأن بعض Examples أكثر قيمة — مثل Data الأحدث — أوعندما تختلف Distribution الخاصة بـ Collected data عن Real-world distribution.

مثال Python مقتبس من الفصل:

⟦CODE_0⟧

لا تخلط بين **Weighted sampling** و**Sample weights**:

- Weighted sampling تغير أي Examples يتم اختيارها،
- Sample weights تغير مقدار تأثير Examples المختارة في Loss.

## 5. Reservoir sampling و Importance sampling

### Reservoir sampling

تفيد Reservoir sampling مع Stream لا يُعرف حجمها الإجمالي وتكون أكبر من أن تُحفظ كاملة في Memory.

افترض أن Tweets تصل باستمرار وأنك تريد الاحتفاظ بـ Uniform sample حجمها `k` من Tweets.

الـ Algorithm التي يصفها الفصل هي:

1. ضع أول `k` Elements داخل Reservoir.
2. عند وصول Item رقم `n`، اختر Random integer `i` من 1 إلى `n`.
3. إذا كانت `i <= k`، استبدل Element رقم `i` داخل Reservoir بالـ Item الجديدة.
4. وإلا، اترك Reservoir دون تغيير.

الخاصية المهمة هي أن كل Item تمت ملاحظتها تحصل على Chance متساوية لتمثيلها داخل Reservoir، ويمكن إيقاف Algorithm في أي وقت.

[[IMAGE_NEEDED: Reservoir sampling over a stream | A stream of numbered items entering a fixed-size reservoir, with later items sometimes replacing earlier items | Learner should notice that memory stays bounded while all observed items retain equal sampling chance]]

### Importance sampling

تكون Importance sampling مفيدة عندما تكون Distribution التي تريد أخذ Samples منها صعبة أومكلفة، بينما توجد Distribution أخرى أسهل.

إذا كانت Target distribution هي `P(x)` وكانت Proposal distribution الأسهل هي `Q(x)`، فإنك تأخذ Samples من `Q(x)` ثم تعيد Weight للـ Sample لتعويض الفرق بين `P` و`Q`.

يجب أن تمنح Proposal Probability غير صفرية في كل مكان تستطيع Target distribution إنتاج Data فيه.

يقدم الفصل Reinforcement learning مثالًا؛ حيث يمكن إعادة Weight لنتائج Policy أقدم عند تقدير Behavior تحت Policy أحدث ومرتبطة بها بدرجة كافية.

## 6. Labels: لماذا يكون Hand labeling صعبًا؟

معظم Production ML systems التي يناقشها الفصل هي Supervised، ما يعني أنها تحتاج Labels.

ينشئ Hand labeling عدة تحديات رئيسية.

### Cost

يمكن إنشاء بعض Labels بواسطة General annotators. أما Labels أخرى فتحتاج Domain experts نادرين. فمثلًا قد يتطلب Labeling للصور الطبية Qualified specialists بدل Generic crowdsourcing workers.

### Privacy

يعني Human labeling أن أشخاصًا يجب أن يفحصوا Data. وقد لا يُسمح لـ Sensitive records بمغادرة Organization وقد تحتاج Controlled on-premises annotation.

### Speed

يمكن أن يكون High-quality labeling بطيئًا جدًا. و Labeling البطيء يعني Model iteration بطيئة، ما يقلل Adaptability عندما تتغير Requirements أو Data.

تخيل Sentiment system تنتقل من Class ين — POSITIVE و NEGATIVE — إلى ثلاث Classes بإضافة ANGRY. قد تحتاج Old examples إلى Relabeling، وقد تحتاج إلى جمع Examples جديدة لـ ANGRY.

## 7. Label multiplicity و Data lineage

يختلف Annotators كثيرًا فيما بينهم.

ينشئ ذلك **Label multiplicity** أو Label ambiguity: قد تحصل Example واحدة على عدة Labels متعارضة.

تزداد Problem سوءًا عندما تحتاج Tasks إلى Expertise أكبر أوعندما تكون Labeling rules غامضة.

### حسّن تعريف Labeling أولًا

قبل لوم Annotators، عرّف Task بوضوح. يوضح مثال Entity recognition في الفصل أن Rules مثل "اختر أطول Entity span مطابقة" قد تزيل بعض حالات الاختلاف.

ثم يجب دمج هذه Rules في Training الخاصة بالـ Annotators.

### Data lineage

تعني **Data lineage** تتبع مصدر كل Example و Label.

لماذا هذا مهم؟

افترض أن Model مدرّبة على 100,000 Example تعمل بصورة معقولة. ثم تشتري مليون Example جديدة عليها Labels فيتدهور Performance. إذا احتفظت بـ Lineage، يمكنك فحص ما إذا كانت Errors تتركز داخل Data المضافة حديثًا والتحقيق في Labeling process الخاصة بها.

من دون Lineage، قد تختلط Low-quality data بصورة دائمة داخل Training pool، ما يجعل تفسير Failures صعبًا.

## 8. Natural labels و Behavioral labels و Feedback loops

لا تحتاج كل Task إلى Human annotation.

تمتلك Task **Natural labels** عندما يستطيع System لاحقًا ملاحظة Real outcome واستخدامها لتقييم Prediction.

تشمل أمثلة الفصل:

- Predicted travel time مقابل Actual travel time،
- Predicted stock price مقابل Observed future price،
- Recommendations مقابل Clicks لاحقة.

تسمى Labels المستنتجة من User behavior أيضًا **Behavioral labels**.

### Implicit labels مقابل Explicit labels

تأتي **Explicit label** من Direct feedback، مثل Rating أو Downvote.

أما **Implicit label** فتُستنتج. فإذا لم تحصل Recommendation على Click خلال Time window مختارة، فقد يتعامل System معها باعتبارها NEGATIVE.

وقد يكون هذا الـ Inference خاطئًا: فقد ينقر User لاحقًا.

### طول حلقة الـ Feedback

**Feedback loop length** هي الزمن من تقديم Prediction حتى تصبح Natural label الخاصة بها متاحة.

أمثلة Short-loop:

- Clicks على Product recommendations،
- توصيات الأشخاص للمتابعة.

أمثلة Long-loop:

- Clothing recommendations التي تحتاج Delivery وتجربة Item،
- Fraud labels التي قد تعتمد على Disputes تُقدَّم بعد أسابيع أوأشهر.

تساعد Feedback loop الأقصر Teams على اكتشاف Problems بسرعة أكبر. وقد تقدم Loop الأطول Signal أقوى أوأكثر Reliability لكنها تبطئ Adaptation.

### تختلف Feedback signals في القوة

في Ecommerce، قد تشمل Signals:

```text
النقر → الإضافة إلى السلة → الشراء → التقييم/المراجعة → الإرجاع
```

Clicks كثيرة وسريعة لكنها أضعف. أما Purchases فأندر وأبطأ لكنها عادةً تقدم Signal أقوى على Preference و Business value.

لذلك فإن اختيار Feedback target هو Product و ML decision، وليس مجرد Modeling choice.

## 9. أربع استراتيجيات عندما تكون Labels نادرة

يقدم الفصل أربعة Approaches رئيسية:

| الطريقة | الفكرة الرئيسية | هل تحتاج Initial ground truth labels؟ |
|---|---|---|
| Weak supervision | استخدم Noisy heuristics لإنشاء Labels | ليس بالضرورة، مع أن Small labeled set موصى بها |
| Semi-supervision | استخدم Structure و Small labeled seed set لاستنتاج Labels إضافية | نعم |
| Transfer learning | أعد استخدام Model مدرّبة على Task أخرى | ليس دائمًا؛ عادةً تستخدم Fine-tuning بعض Labels |
| Active learning | أنفق Annotation effort على Examples الأكثر فائدة للـ Model | نعم |

يمكن لـ Labeling functions استخدام:

- Regular expressions،
- Database lookups،
- Outputs من Existing models.

لأن Heuristics غير مثالية، قد تتعارض عدة LFs أوتمتلك Accuracies مختلفة. ويجب دمج Outputs الخاصة بها و Denoising لها وإعادة Weight لها لإنشاء Probabilistic labels مفيدة.

### لماذا يكون Programmatic labeling جذابًا؟

- يمكن عمل Version لـ Expert knowledge.
- يمكن مشاركة Rules وإعادة استخدامها.
- يمكن إعادة تطبيق Rules نفسها عندما تتغير Data.
- يمكن تقليل Privacy exposure لأن Experts قد يحتاجون فقط إلى Cleared subset لتطوير Rules.
- قد يكون Scaling للـ Rules عبر Examples كثيرة أسرع من Labeling لكل Example يدويًا.

لا تضمن Weak supervision Labels مفيدة. فإذا كانت Heuristics شديدة الضوضاء، قد يظل Performance ضعيفًا. لكنها قد توفر Starting point منخفضة التكلفة.

## 11. Semi-supervision و Transfer learning و Active learning

### Semi-supervision

يبدأ Semi-supervised learning بـ Small labeled set و Larger unlabeled set.

أحد Approaches التقليدية هو **Self-training**:

1. درّب على Labeled examples.
2. Predict لـ Labels الخاصة بالـ Unlabeled examples.
3. احتفظ بالـ Predicted labels ذات High confidence.
4. أضفها إلى Training data.
5. درّب مرة أخرى.

تفترض فكرة أخرى أن Similar examples ينبغي أن تمتلك Similar labels. وقد تأتي Similarity من Co-occurrence أو Clustering أو Nearest-neighbor relationships.

وتستخدم عائلة ثالثة **Perturbation consistency**: ينبغي ألا يغير Change صغير في Example الـ Label الخاصة بها.

### Transfer learning

تعيد Transfer learning استخدام Model تعلمت Base task كنقطة بداية لـ Downstream task.

فمثلًا يمكن لاحقًا Adapt لـ Pretrained language model من أجل Sentiment analysis أو Intent detection أو Question answering.

قد يكون Adaptation عبر:

- Zero-shot use،
- Prompting باستخدام Input format مناسبة،
- Fine-tuning على Task-specific labeled set أصغر.

تكون Transfer learning مهمة لأنها تقلل الحاجة إلى Training لكل Task من الصفر ويمكن أن تخفض Labeling requirements.

### Active learning

تطرح Active learning سؤالًا:

> إذا كان البشر يستطيعون Labeling لعدد محدود فقط من Examples، فأي Examples ينبغي أن يقوموا بـ Labeling لها؟

إحدى الاستراتيجيات المباشرة هي **Uncertainty sampling**: اختر Examples التي تكون Current model أقل يقينًا بشأنها.

استراتيجية أخرى هي **Query-by-committee**. تقوم عدة Candidate models بالتصويت، وتُرسل Examples ذات أقوى Disagreement إلى Labeling.

الهدف هو الحصول على معلومات أكثر فائدة لكل Annotation بدل إنفاق Labels عشوائيًا.

## 12. لماذا تكون Class imbalance صعبة؟

تعني **Class imbalance** أن بعض Labels تظهر كثيرًا أكثر من غيرها.

مثال:

```text
فحوصات رئة NORMAL: 99.99%
فحوصات CANCER:       0.01%
```

هذا شائع في Real-world ML لأن Events المهمة تكون غالبًا نادرة:

- Fraud،
- Disease،
- Churn،
- Successful job candidates،
- مربعات اكتشاف الكائنات الموجبة.

يسلط الفصل الضوء على ثلاث Problems رئيسية.

### 1. Signal قليلة جدًا من Minority class

قد ترى Model عددًا قليلًا جدًا من Rare examples فلا تستطيع تعلم Pattern مفيدة.

### 2. Shortcuts سهلة للـ Majority class

يمكن لـ Model تحقيق Accuracy مرتفعة جدًا عبر Prediction للـ Majority class دائمًا.

إذا كانت 99.99% من Examples هي NORMAL، فإن Prediction بـ NORMAL دائمًا يعطي Accuracy قدرها 99.99% مع اكتشاف صفر من Cancer cases.

### 3. Costs الخاصة بالأخطاء غير متماثلة

قد تكون Miss لحالة Cancer نادرة أكثر تكلفة بكثير من Incorrectly flag لفحص طبيعي.

قد تكون Imbalance نفسها جزءًا من Reality، لكنها قد تنتج أيضًا من Biased sampling أو Labeling errors. قبل تطبيق Technical fix، افحص لماذا توجد Imbalance أصلًا.

## 13. قيّم Problems غير المتوازنة باستخدام Metrics الصحيحة

يمكن لـ Overall accuracy أن تخفي Failure في Class التي تهتم بها.

يقارن الفصل بين Cancer classifier اثنتين لهما Accuracy نفسها وهي 90%:

- إحداهما تكتشف 10 فقط من 100 حالة Cancer،
- والأخرى تكتشف 90 من 100.

Model الثانية أكثر فائدة بوضوح لاكتشاف Cancer، رغم تطابق Overall accuracy.

### مصطلحات Confusion matrix

| Actual / Prediction | المعنى |
|---|---|
| True Positive (TP) | Example موجبة تم Predict لها بصورة صحيحة على أنها موجبة |
| False Positive (FP) | Example سالبة تم Predict لها بصورة خاطئة على أنها موجبة |
| False Negative (FN) | Example موجبة تم Predict لها بصورة خاطئة على أنها سالبة |
| True Negative (TN) | Example سالبة تم Predict لها بصورة صحيحة على أنها سالبة |

### Precision

```text
الدقة (Precision) = TP / (TP + FP)
```

من كل Examples التي تم Predict لها على أنها موجبة، كم واحدة كانت موجبة فعلًا؟

### Recall

```text
الاستدعاء (Recall) = TP / (TP + FN)
```

من كل Actual positive examples، كم واحدة وجدتها Model؟

### F1

```text
F1 = 2 × الدقة × الاستدعاء / (الدقة + الاستدعاء)
```

توازن F1 بين Precision و Recall باستخدام Harmonic mean.

تعتمد Precision و Recall و F1 على أي Class يتم التعامل معها باعتبارها Positive.

### Thresholds و ROC

تُخرج Classifiers كثيرة Score أو Probability. ويغير تغيير Threshold الـ Trade-off بين True positives و False positives.

ترسم **ROC curve** True-positive rate مقابل False-positive rate عبر Thresholds. وتلخص **AUC** المساحة تحت Curve.

### منحنى Precision-recall

يشير الفصل إلى أنه في Tasks شديدة Imbalance، يمكن لرسم Precision مقابل Recall أن يوفر View أكثر إفادة للـ Performance من ROC وحدها.

## 14. طرق على مستوى البيانات: Resampling

تغير Data-level methods الـ Training distribution.

### Undersampling

أزل Examples من Majority class.

الفائدة: تجعل Training distribution أقل هيمنة من Majority.

المخاطرة: تتخلص من Information قد تكون مفيدة.

### Oversampling

أضف المزيد من Minority examples، غالبًا عبر Duplicating أو Synthesizing لها.

الفائدة: تزيد تعرض Model للـ Minority class.

المخاطرة: قد تسبب Repeated copies Overfitting.

### Tomek links

بالنسبة إلى Low-dimensional data، تحدد Tomek links Close pairs من Opposite classes وتزيل Member الخاص بالـ Majority class. يمكن لذلك جعل Decision boundary أنظف، لكنه قد يزيل أيضًا Boundary detail مفيدة.

### SMOTE

تنشئ SMOTE Synthetic minority examples عبر دمج Nearby minority points داخل Feature space.

يحذر الفصل من أن Techniques مثل SMOTE و Tomek links أظهرت فعاليتها أساسًا في Low-dimensional settings، بينما قد تصبح Distance-based resampling صعبة داخل High-dimensional spaces.

### قاعدة Evaluation حرجة

> **لا تقيّم أبدًا على Resampled training distribution.**

ينبغي أن تعكس Evaluation الـ Intended real-world distribution بدل Artificial distribution المستخدمة لتسهيل Training.

يناقش الفصل أيضًا Two-phase learning و Dynamic sampling كطرق لتحقيق Balance في Learning دون الاعتماد فقط على Resampled set ثابتة واحدة.

## 15. Algorithm-level methods لمعالجة Class imbalance

بدل تغيير Data distribution، تغير Algorithm-level methods الطريقة التي تقيّم بها Learning algorithm الأخطاء.

### التعلّم الحساس للتكلفة

يمكن إعطاء أخطاء مختلفة Costs مختلفة.

إذا كان Predict لـ NEGATIVE في حالة هي في الحقيقة POSITIVE أكثر تكلفة بمرتين من الخطأ المعاكس، يمكن لـ Loss أن تعكس هذا الفرق.

التحدي هو أن Cost matrix يجب تحديدها وفق Problem.

### خسارة موازنة الفئات (Class-balanced loss)

إحدى Approaches تعطي Rare classes Loss weights أكبر، مثلًا بجعل Class weight عكسية مع Class frequency.

يشجع ذلك Model على إيلاء Attention أكبر للـ Underrepresented classes.

### Focal loss

تمنح Focal loss Emphasis أقل للـ Examples التي تصنفها Model بسهولة بالفعل، و Emphasis أكبر للـ Hard examples.

الفكرة هي:

> لا تنفق معظم Learning signal على Examples أتقنتها Model بالفعل؛ ركز أكثر على Examples الصعبة.

## 16. Data augmentation

تزيد Data augmentation كمية Training data أوتنوعها. يقسم الفصل Augmentation إلى ثلاث فئات عامة.

### 1. تحويلات بسيطة تحافظ على الـ label

بالنسبة إلى Images، تشمل الأمثلة:

- Crop،
- Flip،
- Rotate،
- Erase لجزء من Image،
- Invert للاتجاه حيث يكون ذلك مناسبًا.

الافتراض الأساسي هو أن Transformation ينبغي ألا تغير Label.

بالنسبة إلى Text، يقدم الفصل أمثلة مثل استبدال Word بكلمة مشابهة مع محاولة الحفاظ على Meaning و Sentiment.

### 2. Perturbation

يمكن لـ Neural networks أن تكون حساسة لتغيرات صغيرة. تستغل Adversarial attacks هذه Weakness عمدًا عبر تعديل Input بما يكفي لإحداث Wrong prediction مع إبقاء Input متشابهة Perceptually.

يمكن لإضافة Noisy examples مختارة بعناية إلى Training أن تكشف الأجزاء الضعيفة في Decision boundary وتحسن Robustness. يسمي الفصل ذلك **Adversarial augmentation**.

تظهر Perturbation أيضًا في NLP، لكن تغييرات Random في Characters أو Words يمكن أن تدمر Meaning بسهولة أكبر من تغييرات صغيرة في Pixels داخل Images.

### 3. Data synthesis

يمكن لـ Synthetic data أن تبدأ Task عندما يكون جمع Real data مكلفًا أومحدودًا.

بالنسبة إلى Conversational systems، يمكن لـ Templates إنشاء Queries كثيرة:

```text
اعثر لي على مطعم [CUISINE] في نطاق [NUMBER] ميل من [LOCATION].
```

يؤدي ملء Slots بقيم كثيرة إلى إنشاء أعداد كبيرة من Examples.

### Mixup

يقدم الفصل أيضًا **Mixup**، حيث يتم دمج Example ين و Labels الخاصة بهما لإنشاء Intermediate synthetic training example.

الهدف ليس فقط زيادة حجم Dataset. يمكن لـ Augmentation أيضًا تحسين Generalization و Robustness.

## مفاهيم خاطئة مهمة

### المفهوم الخاطئ 1: Random sampling تمثل Rare classes جيدًا دائمًا

قد تختفي Rare classes من Random samples الصغيرة. وقد نحتاج إلى Stratified أو Weighted strategies عندما تكون هذه Slices مهمة.

### المفهوم الخاطئ 2: المزيد من Labels يعني تلقائيًا Model أفضل

يمكن لكمية كبيرة من Low-quality أو Inconsistent labeling أن تقلل Performance. تهم Label quality و Lineage.

### المفهوم الخاطئ 3: Natural labels تكون متاحة فورًا

تصل بعض Natural labels خلال ثوانٍ، بينما تصل أخرى بعد أسابيع أوأشهر. تؤثر Feedback loop length بقوة في سرعة Iteration.

### المفهوم الخاطئ 4: Weak supervision تعني Rules موثوقة تمامًا

تفترض Weak supervision أن Heuristics بها Noise. ويجب أن تجمع Method بين Labeling functions المتعارضة وتستدل عليها.

### المفهوم الخاطئ 5: Accuracy مرتفعة تثبت النجاح في Task غير متوازنة

يمكن لـ Model تحقيق Accuracy ممتازة عبر Prediction للـ Majority class مع فشل كامل في Rare class.

### المفهوم الخاطئ 6: ينبغي استخدام Resampled data أيضًا في Evaluation

قد تعطي Evaluation على Resampled distribution نتائج مضللة. ينبغي أن تعكس Evaluation distribution الـ Intended real setting.

### المفهوم الخاطئ 7: Augmentation مخصصة فقط للـ Datasets الصغيرة جدًا

يشير الفصل إلى أن Augmentation يمكن أن تحسن Robustness و Generalization حتى عندما توجد Training data كثيرة بالفعل.

## المصطلحات الأساسية

| المصطلح | المعنى |
|---|---|
| Sampling | اختيار Subset من Data من أجل Training أو Evaluation أو Monitoring أو Experimentation |
| Convenience sampling | اختيار Examples لأنها سهلة الحصول عليها |
| Stratified sampling | أخذ Samples بصورة منفصلة داخل Groups أو Strata محددة مسبقًا |
| Weighted sampling | تعيين Selection probabilities مختلفة للـ Examples |
| Reservoir sampling | الحفاظ على Uniform sample ثابتة الحجم من Stream طولها الإجمالي غير معروف |
| Importance sampling | أخذ Samples من Proposal distribution أسهل وإعادة Weight باتجاه Target distribution |
| Label multiplicity | وجود عدة Labels متعارضة للـ Example نفسها |
| Data lineage | تتبع Origin و Labeling history الخاصة بـ Data examples |
| Natural label | Ground truth تصبح Observable من System أومن Real-world outcome لاحقة |
| Behavioral label | Label مستنتجة من User behavior مثل Click أو Purchase |
| Implicit label | Label مستنتجة من Behavior أوغياب Behavior بدل تقديمها صراحةً |
| طول حلقة الـ Feedback | الزمن بين تقديم Prediction واستلام Label أو Feedback الخاصة بها |
| Weak supervision | استخدام Noisy heuristics أو Labeling functions لإنشاء Labels |
| Semi-supervision | استخدام Small labeled set مع Unlabeled data و Structural assumptions |
| Transfer learning | إعادة استخدام Model تعلمت Task معينة كنقطة بداية لـ Task أخرى |
| Active learning | اختيار Examples الأكثر فائدة من أجل Annotation |
| Class imbalance | فروق كبيرة في عدد Examples أوأهميتها عبر Classes |
| Precision | نسبة Predicted positives التي تكون Positive فعلًا |
| Recall | نسبة Actual positives التي تحددها Model بصورة صحيحة |
| F1 | Harmonic mean لـ Precision و Recall |
| ROC curve | True-positive rate مقابل False-positive rate عبر Thresholds |
| منحنى Precision-recall | Precision مقابل Recall عبر Thresholds |
| Oversampling | زيادة تمثيل Minority class داخل Training data |
| Undersampling | تقليل تمثيل Majority class داخل Training data |
| SMOTE | إنشاء Synthetic minority examples من Nearby minority points |
| التعلّم الحساس للتكلفة | إعطاء Prediction errors المختلفة Costs مختلفة |
| خسارة موازنة الفئات | Weighting للـ Classes بحيث يكون للـ Rare classes تأثير أكبر |
| Focal loss | تقليل Emphasis على Easy examples وتركيز Learning على Difficult examples |
| Data augmentation | إنشاء Training examples إضافية أومعدلة مع الحفاظ على Useful learning signal |
| Adversarial augmentation | Training باستخدام Examples تم Perturb لها عمدًا لتحسين Robustness |
| Mixup | إنشاء Synthetic examples عبر دمج Existing examples و Labels الخاصة بها |
