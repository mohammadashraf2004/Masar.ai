## 1. ما معنى Multimodal؟

**modality** هي نوع من input أو information.

تشمل الأمثلة:

```text
النص (text)
الصور (images)
الصوت (audio)
الفيديو (video)
بيانات المستشعرات (sensor data)
```

يكون النظام **multimodal** عندما يستطيع العمل مع أكثر من modality واحدة.

على سبيل المثال:

```text
النص + الصورة
```

هو input متعدد الوسائط.

قد يستقبل Model:

```text
صورة + سؤال
```

ويولّد:

```text
إجابة نصية (text answer)
```

لاحظ نقطة مهمة:

> قد يستطيع Model استقبال modality معينة دون أن يستطيع توليد modality نفسها.

فعلى سبيل المثال، قد يستقبل vision-language model:

```text
صورة + نص
```

لكنه لا ينتج إلا:

```text
نص (text)
```

[[IMAGE_NEEDED: Multimodal model overview | Show several modalities—text, image, audio, video, sensors—feeding a multimodal model, with text as one possible output | Learner should notice that input modality support and output modality support are separate capabilities]]

### لماذا تهم Multimodality؟

التواصل البشري ليس نصيًا فقط.

فنحن نستخدم:

- تعبيرات الوجه (facial expressions)،
- الإيماءات (gestures)،
- الصور (images)،
- النبرة (tone)،
- السياق المكاني (spatial context)،
- الأصوات (sounds).

إضافة modalities جديدة يمكن أن تمنح أنظمة AI وصولًا إلى معلومات لا يستطيع النص وحده توفيرها.

وقد يتيح ذلك مهام مثل:

```text
وصف الصور (image captioning)
Visual Question Answering
البحث عن الصور (image search)
تصنيف الصور (image classification)
فهم المستندات (document understanding)
المحادثة متعددة الوسائط (multimodal chat)
```

## 2. Vision Transformer: تطبيق أفكار Transformer على الصور

اشتهرت Transformers في الأصل في مجال اللغة.

لكن architecture نفسها يمكنها العمل مع أنواع أخرى من structured sequences.

يطبّق **Vision Transformer (ViT)** معالجة شبيهة بـ Transformer على الصور.

المشكلة الأساسية هي:

> يمكن تقسيم النص إلى tokens. فكيف ننشئ sequence مشابهة من صورة؟

الإجابة هي:

```text
قسّم الصورة إلى رقع (split the image into patches)
```

وتصبح كل patch شبيهة بـ “token” بصرية.

## 3. تتحول الصور إلى Patches بدلًا من Word Tokens

تخيل صورة بحجم:

```text
512 × 512 pixels   — أبعاد الصورة بالبكسل
```

pixel واحدة لا تخبرنا بالكثير.

لكن patch تحتوي على عدة pixels متجاورة يمكن أن تلتقط local visual structure مفيدة.

يقسم ViT الصورة إلى patches ثابتة الحجم.

من الناحية المفاهيمية:

```text
الصورة (Image)
┌────┬────┬────┐
│ P1 │ P2 │ P3 │
├────┼────┼────┤
│ P4 │ P5 │ P6 │
├────┼────┼────┤
│ P7 │ P8 │ P9 │
└────┴────┴────┘
```

أصبحت الصورة الآن sequence:

```text
P1, P2, P3, ..., P9
```

يستخدم الفصل رسومات مبسطة تحتوي على patches كبيرة وواضحة لأغراض الشرح، ويشير إلى أن ورقة ViT الأصلية اشتهرت باستخدام image patches بحجم `16 × 16`.

[[IMAGE_NEEDED: Image patching | Show a single image divided into a regular grid of patches, then the patches flattened into a sequence P1, P2, P3, ... | Learner should understand image patching as the visual analogue of converting a sentence into a token sequence]]

## 4. لماذا لا تكون Image Patches مجرد Vocabulary Tokens عادية؟

تعمل text tokenization لأن tokenizers تمتلك vocabulary قابلة لإعادة الاستخدام.

على سبيل المثال:

```text
token "cat"   — رمز الكلمة
→ token ID 9246   — المعرّف الرقمي للرمز
```

يمكن أن يظهر هذا token عبر مستندات كثيرة.

أما image patches فمختلفة.

فمن غير المرجح أن تظهر patch صغيرة من pixels في صورة ما بالشكل نفسه تمامًا داخل صورة أخرى.

لذلك لا نبني عادةً vocabulary مثل:

```text
patch #17392 — معرّف Patch افتراضي
```

وبدلًا من ذلك:

```text
قيم Pixels في Patch (patch pixels)
→ إسقاط عددي (numerical projection)
→ تمثيل Patch متجه (patch embedding)
```

تتحول patch مباشرة إلى vector.

ثم يمكن لـ Transformer encoder معالجة هذا vector.

## 5. من Raw Patch Pixels إلى Patch Embeddings

مسار patch هو:

```text
رقعة صورة (image patch)
    ↓
تسطيح قيم Pixels (flatten pixel values)
    ↓
إسقاط خطي (linear projection)
    ↓
متجه Embedding كثيف (dense embedding vector)
```

تحصل كل patch على vector representation.

ثم تصبح الصورة:

```text
embedding(P1)   — تمثيل الرقعة الأولى
embedding(P2)   — تمثيل الرقعة الثانية
embedding(P3)   — تمثيل الرقعة الثالثة
...
```

يمكن تمرير هذه patch embeddings إلى Transformer encoder بصورة مشابهة لـ token embeddings.

[[IMAGE_NEEDED: Patch embedding pipeline | Show image patch → flattened pixel vector → linear projection → dense patch embedding, repeated for several patches before entering a Transformer encoder | Learner should understand how raw visual data is turned into Transformer-compatible numerical representations]]

### التجريد الأساسي

بعد أن تتحول text tokens و image patches إلى vectors:

```text
text token → vector   — رمز نصي يتحول إلى متجه
image patch → vector   — رقعة صورة تتحول إلى متجه
```

يعمل Transformer على numerical representations.

تكون raw modality الأصلية قد تم encode لها بالفعل.

## 6. تنشئ Vision Transformers تمثيلات صور قابلة لإعادة الاستخدام

كما تنتج language encoders تمثيلات مفيدة لمهام مثل:

```text
التصنيف (classification)
البحث (search)
التجميع (clustering)
```

يمكن لـ Vision Transformers إنتاج تمثيلات مفيدة لـ:

```text
تصنيف الصور (image classification)
الاسترجاع البصري (visual retrieval)
المواءمة متعددة الوسائط (multimodal alignment)
أنظمة الرؤية واللغة (vision-language systems)
```

يجعل دور representation learning هذا من ViT مكوّنًا طبيعيًا في multimodal systems.

## 7. Multimodal Embeddings: وضع Modalities مختلفة في Vector Space واحدة

في الدروس السابقة، كانت text embedding models تحوّل:

```text
نص (text)
→ vector
```

أما multimodal embedding model فيمكنها تحويل:

```text
نص (text)
→ vector

صورة (image)
→ vector
```

بحيث تكون vectors من النوعين داخل **embedding space نفسها**.

وهذا يعني أننا نستطيع مقارنتها مباشرة.

على سبيل المثال:

```text
النص (text):
"a picture of a puppy"

الصورة (image):
photo of a puppy
```

يُفترض مثاليًا أن تكون embeddings الخاصة بهما متشابهة.

## 8. CLIP: ربط اللغة والصور عبر Embeddings

يقدم الفصل **CLIP**:

```text
Contrastive Language-Image Pre-training — اسم CLIP الكامل
```

يحتوي CLIP على مسارين رئيسيين للـ encoder:

```text
النص (Text)
  ↓
Text encoder
  ↓
Text embedding
```

و:

```text
الصورة (Image)
  ↓
Image encoder
  ↓
Image embedding
```

يتم training لنوعي embeddings بحيث يصبح من الممكن مقارنتهما.

وهذا يجعل CLIP مفيدًا في:

- تصنيف الصور دون أمثلة (zero-shot image classification)،
- التجميع (clustering)،
- استرجاع الصور والنصوص (image/text retrieval)،
- البحث متعدد الوسائط (multimodal search)،
- توفير representation inputs لأنظمة generation.

## 9. يتعلم CLIP من Image-Caption Pairs

تخيل dataset:

```text
Image A ↔ "a dog running through snow"   — صورة وتعليقها
Image B ↔ "a red sports car"
Image C ↔ "a bowl of fruit"
```

كل training item يحتوي على:

```text
صورة (image)
+
نص يصف تلك الصورة (text describing that image)
```

ينشئ CLIP embeddings لكل من الطرفين.

ثم يحاول training جعل matched pairs متشابهة.

من الناحية المفاهيمية:

```text
image A ↔ caption A
يجب أن يكونا متقاربين (should be close)

image A ↔ caption B
يجب أن يكونا أبعد (should be farther apart)
```

هذا أحد أشكال **contrastive learning**.

---

## 10. Contrastive Learning: تعلم التشابه بمقارنة Positive و Negative Pairs

positive pair هي:

```text
صورة مطابقة + Caption مطابقة
```

negative pair هي:

```text
صورة غير مطابقة + Caption غير مطابقة
```

يشجع training على:

```text
positive pair
→ تشابه أعلى (higher similarity)

negative pair
→ تشابه أقل (lower similarity)
```

وهذا يعلم Model الأمرين معًا:

```text
ما الذي ينتمي معًا (what belongs together)
و
ما الذي لا ينتمي معًا (what does not belong together)
```

[[IMAGE_NEEDED: CLIP contrastive training matrix | Show a batch of images on one axis and captions on the other, forming a similarity matrix where diagonal matching pairs are highlighted as positives and off-diagonal pairs are negatives | Learner should understand why batch-wise contrastive learning provides both positive and negative examples]]

### لماذا تهم Negative Examples؟

إذا كان training يقول فقط:

```text
"اجعل الأزواج المطابقة متشابهة" ("make matched pairs similar")
```

من دون التمييز بين mismatched pairs، فقد لا تصبح embeddings تمييزية بما يكفي.

يحتاج representation learning الجيد إلى structure:

```text
الأشياء المتشابهة متقاربة (similar things close)
الأشياء المختلفة متباعدة (different things separated)
```

ويرتبط ذلك مباشرة بـ retrieval fine-tuning من Chapter 8.

## 11. تقارن Cosine Similarity بين Image و Text Vectors

بعد أن تصبح embeddings في vector space واحدة، يمكننا حساب:

```text
similarity(   — دالة التشابه
    image_embedding,
    text_embedding
)
```

يستخدم الفصل cosine similarity.

إذا كانت embeddings normalized، فإن dot product يعطينا العلاقة الخاصة بـ cosine similarity.

من الناحية المفاهيمية:

```text
المعنى نفسه (same meaning)
→ زاوية أصغر (smaller angle)
→ تشابه أعلى (higher similarity)

معنى مختلف (different meaning)
→ زاوية أكبر (larger angle)
→ تشابه أقل (lower similarity)
```

قد يكون raw score واحدًا صعب التفسير إذا لم نقارنه بأزواج مرشحة أخرى.

ولهذا يوسّع الفصل المثال إلى similarity matrix تحتوي على عدة صور و captions.

## 14. Tokenize لـ CLIP Caption

يستخدم المصدر caption مثل:

```text
a puppy playing in the snow   — وصف الصورة
```

تُرجع tokenization:

```text
input_ids
attention_mask
```

وتحتوي token sequence على special boundary tokens مثل:

```text
<|startoftext|>   — بداية النص
...
<|endoftext|>   — نهاية النص
```

وهذا تذكير آخر بأن multimodal systems لا تزال تعتمد على مبادئ text tokenization المعتادة في جانب اللغة منها.

## 18. مقارنة Image و Caption

يقوم الفصل بعمل normalize لكلتا embeddings ثم يحسب dot product.

من الناحية المفاهيمية:

⟦CODE_6⟧

الناتج similarity score.

لا تتعامل مع score واحد على أنه “جيد” أو “سيئ” بطبيعته من دون سياق.

الأكثر فائدة هو المقارنة بين:

```text
هذه الصورة مقابل عدة Captions (this image versus several captions)
```

أو:

```text
عدة صور مقابل عدة Captions (several images versus several captions)
```

عندها يصبح relative similarity قابلًا للتفسير.

## 20. من Multimodal Embeddings إلى Multimodal Generation

يتيح CLIP:

```text
مقارنة الصورة ↔ النص
```

لكنه لا يحوّل بمفرده text-only LLM إلى conversational visual assistant.

ولتحقيق ذلك نحتاج إلى ربط:

```text
التمثيل البصري (visual representation)
```

بـ:

```text
تمثيل Input الخاص بـ Language Model (language-model input representation)
```

وهذا ينشئ **modality gap**.

يتحدث pretrained vision model بتمثيل embedding معين.

بينما تتوقع pretrained LLM صيغة internal representation مختلفة.

يقدم الفصل BLIP-2 كجسر بينهما.

## 21. BLIP-2: ربط Frozen Vision Encoder بـ Frozen LLM

يتطلب training لـ multimodal LLM ضخمة من الصفر موارد هائلة.

يستخدم BLIP-2 استراتيجية modular:

```text
Pretrained vision encoder
+
جسر صغير قابل للتدريب (small trainable bridge)
+
Pretrained language model
```

يسمى الجسر:

```text
Q-Former — اسم الجسر في BLIP-2
```

أو:

```text
Querying Transformer — الاسم الكامل لـ Q-Former
```

## 22. Q-Former: جسر بين Visual و Language Representations

## 25. ما هي Soft Visual Prompt؟

normal text prompt مرئية:

```text
Describe this image.   — تعليمة المستخدم
```

أما soft visual prompt فمختلفة.

فهي تتكون من learned continuous vectors.

من الناحية المفاهيمية:

```text
صورة (image)
→ Visual vectors
→ Projected vectors
→ LLM input embedding space
```

تستقبل LLM هذه vectors كسياق قبل النص أو بجواره.

وبذلك تكون visual information قد تُرجمت إلى internal representation format الخاصة بـ Language Model.

وهذا هو الجسر الأساسي بين:

```text
الرؤية (vision)
و
توليد اللغة (language generation)
```

## 37. مصادر الفشل الشائعة في Multimodal Systems

يمكن أن يفشل multimodal system في عدة مراحل.

### فشل المعالجة المسبقة البصرية (Visual Preprocessing Failure)

قد تكون input image:

- تم تغيير حجمها بصورة سيئة،
- تم قصها (cropped)،
- تم تشويهها (distorted)،
- منخفضة الدقة أكثر من اللازم.

### فشل المشفر البصري (Visual Encoder Failure)

قد لا تمثل visual features تفاصيل مهمة خاصة بالمجال.

### فشل جسر الوسائط (Modality-Bridge Failure)

قد تفقد projection بين image representations و LLM representations بعض المعلومات.

### فشل نموذج اللغة (Language-Model Failure)

قد تقوم LLM بـ:

- hallucinate لتفاصيل،
- overinterpret للصورة،
- الاعتماد على priors بدلًا من visual evidence الفعلية.

### فشل Prompt

قد يكون السؤال ambiguous.

لذلك يحتاج multimodal system قوي إلى debugging حسب المرحلة.

## 38. يحل CLIP و BLIP-2 مشكلات مختلفة

## مفاهيم خاطئة مهمة

### المفهوم الخاطئ 1

> يجب أن تولّد Multimodal Model كل modality تستطيع استقبالها.

### لماذا هذا خطأ؟

قد تستقبل Model الصور والنصوص بينما تولّد نصًا فقط.

---

### المفهوم الخاطئ 2

> تقوم Vision Transformers بإسناد vocabulary IDs إلى image patches تمامًا مثل word tokens.

### لماذا هذا خطأ؟

عادةً ما يتم عمل linear projection لـ image patches إلى continuous embeddings بدلًا من البحث عنها داخل reusable discrete text vocabulary.

---

### المفهوم الخاطئ 3

> يستخدم CLIP encoder واحدة لكل من raw text و raw pixels.

### لماذا هذا خطأ؟

يستخدم CLIP modality-specific encoders يتم training لمخرجاتها كي تشغل shared embedding space قابلة للمقارنة.

---

### المفهوم الخاطئ 4

> إذا كان لكل من image embeddings و text embeddings عدد 512 بُعدًا، فهما aligned دلاليًا تلقائيًا.

### لماذا هذا خطأ؟

تطابق shape ضروري للمقارنة المباشرة، لكن training هو ما يجعل المفاهيم المتناظرة تشغل مناطق مرتبطة في vector space.

---

### المفهوم الخاطئ 5

> CLIP هو في الأساس text-generation model.

### لماذا هذا خطأ؟

CLIP في الأساس multimodal representation/alignment model. فهو ينشئ image embeddings و text embeddings يمكن مقارنتهما.

---

### المفهوم الخاطئ 6

> يقوم BLIP-2 بتدريب كل من vision encoder و LLM من الصفر.

### لماذا هذا خطأ؟

الفكرة المركزية لـ BLIP-2 في الفصل هي إعادة استخدام frozen pretrained components وتدريب bridge بينها.

---

### المفهوم الخاطئ 7

> Soft visual prompts هي captions نصية عادية.

### لماذا هذا خطأ؟

هي continuous learned vectors تُستخدم داخليًا لجعل LLM conditioned على visual information.

---

### المفهوم الخاطئ 8

> ترى Visual-Language Model الصورة الأصلية نفسها تمامًا.

### لماذا هذا خطأ؟

يتم تغيير حجم الصورة و normalize لها وإجراء preprocessing آخر عليها قبل inference.

---

### المفهوم الخاطئ 9

> يتذكر Multimodal Chat تلقائيًا turns السابقة.

### لماذا هذا خطأ؟

يقوم الفصل بتخزين Q/A pairs السابقة يدويًا ثم يعيد بناء prompt اللاحقة منها.

---

### المفهوم الخاطئ 10

> الإجابة البصرية الواثقة تثبت أن الصورة تحتوي فعلًا على هذه المعلومة.

### لماذا هذا خطأ؟

لا تزال Language Model قادرة على hallucinate أو الاعتماد على learned priors. ويجب تقييم visual grounding.

## المصطلحات الأساسية

| المصطلح | المعنى |
|---|---|
| نوع الوسيط (Modality) | نوع من المعلومات مثل النص أو الصورة أو الصوت أو الفيديو |
| نموذج متعدد الوسائط (Multimodal model) | Model قادرة على معالجة أكثر من modality واحدة |
| محول الرؤية (Vision Transformer) | Transformer architecture تعالج image patches |
| رقعة صورة (Image patch) | منطقة مستطيلة محلية من الصورة تُستخدم كعنصر visual sequence |
| تمثيل رقعة (Patch embedding) | Dense vector يتم إنشاؤها من image patch |
| إسقاط خطي (Linear projection) | Learned transformation تحوّل raw patch features إلى embedding space |
| مشفر بصري (Visual encoder) | Model تحوّل الصور إلى learned feature representations |
| تمثيل متعدد الوسائط (Multimodal embedding) | Vector representation تتم مواءمتها عبر أكثر من modality |
| نموذج CLIP | عائلة Models باسم Contrastive Language-Image Pre-training |
| مساحة تمثيل مشتركة (Shared embedding space) | Vector space يمكن داخلها مقارنة مفاهيم الصور والنصوص المتناظرة مباشرة |
| تعلم تبايني (Contrastive learning) | Training approach تسحب matched examples إلى قرب بعضها وتدفع mismatched examples بعيدًا |
| زوج موجب (Positive pair) | Image-text pair متطابقة |
| زوج سالب (Negative pair) | Image-text pair غير متطابقة |
| تشابه جيبي تمامي (Cosine similarity) | Similarity measure تعتمد على اتجاه vectors |
| تصنيف صور دون أمثلة (Zero-shot image classification) | تصنيف صورة بمقارنة embedding الخاصة بها مع textual class descriptions |
| استرجاع عبر الوسائط (Cross-modal retrieval) | استرجاع modality باستخدام query من modality أخرى |
| نموذج BLIP-2 | Architecture تربط pretrained visual models و language models من خلال trainable bridge |
| جسر Q-Former | Querying Transformer يستخدمه BLIP-2 لربط vision باللغة |
| مطابقة الصورة بالنص (Image-text matching) | مهمة تتنبأ بما إذا كانت image و text تنتميان معًا |
| توليد مستند إلى الصورة (Image-grounded generation) | توليد نص conditioned على image information |
| Prompt بصرية مرنة (Soft visual prompt) | Continuous embedding sequence مشتقة من visual input وتستخدم لتهيئة LLM |
| معالج (Processor) | Model-specific preprocessing interface للصورة و/أو النص |
| وصف الصور (Image captioning) | توليد descriptive text من صورة |
| الإجابة البصرية عن الأسئلة (VQA) | الإجابة عن سؤال نصي باستخدام visual input |
| محادثة متعددة الوسائط (Multimodal chat) | Multi-turn interaction تتضمن visual و textual context |
| تغير المجال (Domain shift) | تدهور الأداء عندما تختلف deployment data عن training data |
