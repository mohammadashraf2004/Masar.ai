## لماذا يُعد Post-training مهمًا؟

ركزت الدروس السابقة على كيفية تجميع VLM وتدريبه.

لكن في العمل العملي، نادرًا ما تبدأ بـ Model غير مدرب تمامًا.

غالبًا ما تبدأ بـ:

```text
Vision encoder مُدرَّب مسبقًا (a pretrained vision encoder)
+
Language model مُدرَّب مسبقًا (a pretrained language model)
+
Multimodal model يفهم بالفعل العديد من علاقات Image-Language (a multimodal model that already understands many image-language relationships)
```

ثم تكيّف ذلك Model ليتصرف بالطريقة التي تحتاج إليها.

مرحلة التكييف هذه هي **Post-training**.

يعرض المصدر ثلاثة مكونات رئيسية:

```text
1. الضبط الدقيق المُراقَب (Supervised fine-tuning — SFT)
2. المواءمة / تحسين التفضيلات
3. Reinforcement learning بمكافآت قابلة للتحقق (Reinforcement learning with verifiable rewards — RLVR)
```

نموذج ذهني مفيد هو:

```text
Model مُدرَّب مسبقًا (PRETRAINED MODEL)
       ↓
SFT
"تعلّم المهمة وصيغة التعليمات" ("learn the task and instruction format")
       ↓
Alignment (ALIGNMENT)
"فضّل Responses الأفضل" ("prefer better responses")
       ↓
Verifiable-RL عند ملاءمته (VERIFIABLE-RL when appropriate)
"حسّن الأداء وفق Rewards يمكن التحقق منها آليًا" ("optimize against automatically checkable rewards")
```

سيغطي هذا الدرس أيضًا تقنيات الكفاءة التي تجعل ذلك عمليًا:

```text
LoRA — أسلوب PEFT منخفض الرتبة
DoRA — أسلوب يفصل Magnitude عن Direction
quantization — تقليل الدقة العددية
QLoRA — Base model مُكمَّم مع LoRA
PEFT — ضبط دقيق بكفاءة في Parameters
TRL — Toolkit لـ Post-training
```

## 1. خريطة Post-training

افترض أن لديك بالفعل VLM عامًا.

يمكنه:

- وصف Images؛
- الإجابة عن أسئلة أساسية؛
- فهم Objects شائعة؛
- اتباع بعض التعليمات.

لكنك تحتاج إلى أن يصبح أفضل في:

```text
Document QA (document QA)
الصور الطبية (medical imagery)
استخدام الكمبيوتر (computer use)
الفحص الصناعي (industrial inspection)
تعليمات الروبوت (robot instructions)
أو مهمة متخصصة أخرى (or another specialized task)
```

يمكنك إعادة تدريب كل Parameter.

لكن ذلك قد يكون:

- مكلفًا؛
- كثيف الاستهلاك لـ Memory؛
- بطيئًا؛
- غير ضروري.

لذلك يطرح Post-training الحديث سؤالين منفصلين.

### السؤال 1 — ما الذي ينبغي أن يتعلم Model فعله؟

غالبًا ما يجيب **SFT** عن هذا السؤال.

```text
Prompt + Image → Response مطلوبة
```

### السؤال 2 — أي Response ينبغي أن يفضلها Model؟

هذا هو مجال **Alignment**.

```text
Response A مقابل Response B (response A vs response B)
→ أيهما أفضل؟
```

### السؤال 3 — هل يمكن التحقق من الصحة آليًا؟

إذا كانت الإجابة نعم، فقد تدعم المهمة **Verifiable reward**.

تشمل الأمثلة في المصدر أشياء مثل:

- الصحة الرياضية؛
- نتائج Code.

## 2. الضبط الدقيق المُراقَب (Supervised fine-tuning)

Supervised fine-tuning هو Supervised learning مطبق على Model مُدرَّب مسبقًا.

أنت توفر:

```text
المدخل (input)
+
المخرج المستهدف (target output)
```

وتحسن Model بحيث يصبح Target أكثر احتمالًا.

بالنسبة إلى VLM:

```text
Image (image)
+
تعليمات المستخدم (user instruction)
→
إجابة Assistant (assistant answer)
```

مثال:

```text
Image: صفحة Document (Image: a document page)

User:
"What date is shown on this letter?"

Assistant:
"1/8/93"
```

يفهم Model بالفعل Language وImages.

ويعلّمه Fine-tuning:

- Target task؛
- نمط Response المطلوب؛
- Domain؛
- صيغة Instruction.

### لا يعني Fine-tuning بالضرورة «تعلّم قدرة جديدة تمامًا»

بل قد يقوم بدلًا من ذلك بـ:

- تحسين قدرة موجودة؛
- تخصيصها؛
- جعل Output أكثر موثوقية؛
- تكييف Model مع Domain الخاص بك.

## 4. Prompt masking: درّب على الإجابة لا على Prompt

إذا درّبنا Autoregressive model على كامل
Formatted sequence، فقد يتلقى Loss على:

```text
تعليمة النظام (system prompt)
تعليمة المستخدم (user prompt)
رموز موضع الصورة (image placeholder tokens)
استجابة المساعد (assistant response)
```

لكن هدفنا الرئيسي عادةً هو:

> بالنظر إلى Context، أنشئ إجابة Assistant الصحيحة.

لذلك نطبق Mask على جزء Prompt.

على المستوى المفاهيمي:

```text
SYSTEM TOKENS      → تجاهل (ignore)
USER TOKENS        → تجاهل (ignore)
IMAGE INPUT        → تجاهل باعتباره Language targets (ignore as language targets)
ASSISTANT ANSWER   → احسب Loss (compute loss)
```

قد يبدو Label sequence كما يلي:

```text
[-100, -100, -100, -100, 512, 912, 44, 2]
```

حيث:

```text
-100 → لا تضمّن هذا Position في Cross-entropy loss (do not include this position in cross-entropy loss)
```

يسمى هذا **Prompt masking**.

### لماذا يهم ذلك؟

من دون Prompt masking، ينفق Model جزءًا من Training signal
على إعادة إنتاج Question وSystem instructions.

وهذا ليس عادةً السلوك الذي نريد تحسينه.

يشير المصدر إلى أن TRL يتعامل مع هذا النوع من
Training behavior في Workflow الذي يوضحه.

## 5. الضبط الدقيق الفعال من حيث المعاملات (Parameter-efficient fine-tuning)

قد يحتوي VLM كبير على مليارات Parameters.

يعني Full fine-tuning حساب Updates
وتخزينها لجزء كبير منها.

ويتطلب ذلك قدرًا كبيرًا من:

- GPU memory؛
- Optimizer memory؛
- Gradient storage؛
- Compute.

يقلل **PEFT** هذا العبء.

الفكرة الأساسية هي:

> أبقِ معظم Parameters المُدرَّبة مسبقًا Frozen، ودرّب
> فقط مجموعة صغيرة من Parameters الجديدة أو المحددة.

يركز الفصل على:

- LoRA؛
- DoRA.

## 6. Matrix rank: الحدس الذي تحتاج إليه لفهم LoRA

افترض أن Weight matrix هي:

```text
W ∈ R^(d × k)
```

يكون Full update:

```text
ΔW
```

وله أيضًا:

```text
d × k
```

من Entries.

تفترض LoRA أن Update المفيدة يمكن غالبًا
تمثيلها ببنية ذات Rank أقل بكثير.

بدلًا من تدريب:

```text
ΔW ∈ R^(d × k)
```

بشكل مباشر، ندرب Matrix أصغر:

```text
B ∈ R^(d × r)
A ∈ R^(r × k)
```

ثم:

```text
ΔW = BA
```

مع:

```text
r << min(d, k) — Rank أصغر كثيرًا من أصغر بُعد
```

### ماذا يعني Rank بصورة حدسية؟

Rank هو عدد Directions/Components المستقلة
اللازمة لتمثيل Matrix transformation.

يمكنك التفكير في الأمر هكذا:

```text
Rank صغير (small rank)
→ ضغط أقوى (stronger compression)
→ Trainable parameters أقل (fewer trainable parameters)

Rank كبير (large rank)
→ Update أكثر تعبيرًا (more expressive update)
→ Trainable parameters أكثر (more trainable parameters)
```

## 7. LoRA: تعلّم Low-rank update

تظل Matrix الأصلية المُدرَّبة مسبقًا Frozen:

```text
W
```

تضيف LoRA:

```text
ΔW = BA
```

بحيث يصبح Effective weight:

```text
W' = W + scale × BA — Effective weight بعد إضافة Adapter update
```

يصف المصدر Scale على أنه:

```text
alpha / r — نسبة Scaling
```

حيث:

- يتحكم `alpha` في مساهمة Adapter؛
- يمثل `r` الـ Rank.

### حدس عدد Parameters

افترض:

```text
W shape = 4096 × 4096 — شكل Weight matrix
```

الـ Full matrix:

```text
16,777,216 parameters — عدد Parameters في Full matrix
```

إذا استخدمت LoRA:

```text
r = 8
```

فإن:

```text
B: 4096 × 8 = 32,768
A: 8 × 4096 = 32,768
```

إجمالي Adapter parameters:

```text
65,536
```

بدلًا من أكثر من 16 مليونًا لتلك Matrix.

لهذا تستطيع LoRA تقليل عدد Trainable parameters بصورة كبيرة.

### اختيار Rank

Rank أعلى يعني:

- Expressivity أكبر؛
- Memory أكثر؛
- Trainable parameters أكثر.

Rank أقل يعني:

- تكلفة أقل؛
- قيودًا أكبر.

يعرض المصدر قيمًا صغيرة مثل:

```text
2
4
8
```

كأمثلة شائعة للتجريب.

وليست هذه قيمًا مثلى عالمية.

## 8. DoRA: افصل Magnitude عن Direction

يعرض المصدر **DoRA** كتوسعة لـ LoRA.

بدلًا من التعامل مع Weight باعتبارها Matrix واحدة فقط، يفككها DoRA إلى:

```text
المقدار (magnitude)
+
الاتجاه (direction)
```

ثم:

- تظل Magnitude قابلة للتدريب؛
- تتلقى Direction تحديثًا منخفض Rank بأسلوب LoRA.

على المستوى المفاهيمي:

```text
Weight الأصلية (original weight)
   ↓
magnitude × direction   — المقدار في الاتجاه
                 ↓
          تحديث منخفض الرتبة (low-rank update)
```

يمنح هذا التكييف تحكمًا أكبر في كيفية تغير Weight المُدرَّبة مسبقًا.

### المقايضة في PEFT

يؤكد المصدر على ملاحظة مهمة:

```text
PEFT يحدّث Parameters أقل (PEFT updates fewer parameters)
```

لذلك قد يتعلم أقل من Full fine-tuning في بعض الإعدادات.

لكنه يميل أيضًا إلى إبقاء Model المتكيف أقرب إلى نقطة البداية.

وقد يعني ذلك:

```text
Adaptation أقل (less adaptation)
+
Forgetting أقل (less forgetting)
```

هذه مقايضة، وليست مجرد قاعدة تقول إن «PEFT أفضل دائمًا».

## 10. Quantization: تقليل الدقة العددية

طريقة أخرى لتقليل Memory هي تخزين Weights باستخدام Bits أقل.

تشمل التمثيلات الشائعة التي يناقشها الفصل:

```text
FP32 — تمثيل Floating-point بدقة 32-bit
FP16 — تمثيل Floating-point بدقة 16-bit
BF16 — تمثيل Brain floating-point بدقة 16-bit
INT8 — تمثيل Integer بدقة 8-bit
صيغ أقل Bits مثل 4-bit NF4 (lower-bit formats such as 4-bit NF4)
```

### المقايضة الأساسية

```text
Precision أعلى (higher precision)
→ Memory أكثر (more memory)
→ تمثيل عددي أوسع (wider numeric representation)

Precision أقل (lower precision)
→ Memory أقل (less memory)
→ احتمال Approximation error (possible approximation error)
```

يمكن لـ Quantization جعل Model ملائمًا لـ
Hardware لم يكن يستطيع تخزينه بخلاف ذلك.

### حدس 8-bit

يصف المصدر نهجًا مختلطًا حيث:

- يمكن لمعظم Computation استخدام قيم أقل Precision؛
- تحصل Outlier values على معالجة بدقة أعلى؛
- يتم Dequantize للنتائج مرة أخرى داخل Computation path أعلى Precision.

يُعد التنفيذ الدقيق للمكتبة أكثر تعقيدًا من هذا الملخص التعليمي.

المفهوم الثابت هو:

> يضغط Quantization التمثيل العددي لتوفير Memory
> مع محاولة الحفاظ على جودة Model.

### تنبيه بشأن صياغة المصدر

يستشهد الفصل المقدم برقم Performance لدراسة Quantization بـ 8-bit،
لكن الجملة غير مكتملة في النص المقدم ("results in 0.36% performance").
هذا الدرس **لا** يستنتج الصياغة المفقودة.

## 11. QLoRA: Base model مُكمَّم + LoRA adapters قابلة للتدريب

تجمع QLoRA بين:

```text
Model مُكمَّم وFrozen (quantized frozen model)
+
Low-rank adapters قابلة للتدريب (trainable low-rank adapters)
```

يصف المصدر Base model باستخدام **NF4** بدقة 4-bit.

### لماذا يساعد ذلك؟

إذا كانت Weight matrices الكبيرة المُدرَّبة مسبقًا:

- Quantized؛
- Frozen؛

فإنها تحتاج Memory أقل كثيرًا من نسخة Full-precision قابلة للتدريب.

ويتم Optimization للـ Adapters فقط.

### NF4

يقدم المصدر **NF4** كطريقة Quantization بدقة 4-bit مصممة
لتوزيعات Weights المرتبطة بـ Neural-network parameters.

يؤجل المصدر رياضيات Quantization الدقيقة إلى فصل لاحق.

بالنسبة إلى هذا الدرس، احتفظ بالفكرة التالية:

```text
NF4 — تمثيل 4-bit
→ تمثيل Low-bit لـ Frozen model weights (low-bit representation for frozen model weights)
```

### Double quantization

يشرح المصدر:

1. Quantize لـ Model weights؛
2. Quantize لـ Scaling constants المستخدمة بواسطة ذلك Quantization.

ويحقق ذلك توفيرًا إضافيًا في Memory.

## 15. RLHF: تعلّم Reward من تفضيلات البشر

## 17. لماذا نستخدم KL regularization؟

افترض أن Reward optimization تقول:

```text
"maximize reward"   — تعظيم المكافأة
```

قد يكتشف Model طرقًا غريبة لاستغلال Reward function.

ويُسمى ذلك Reward hacking بالمعنى العام.

لذلك يقدم المصدر Penalty يعتمد على الفرق بين:

```text
توزيع Policy (policy distribution)
و (and)
توزيع Reference (reference distribution)
```

باستخدام KL divergence.

صيغة مبسطة متوافقة مع المصدر للـ Reward هي:

```text
r = r_reward - lambda × KL(policy || reference) — Reward بعد طرح KL penalty
```

التفسير:

```text
Reward term (reward term)
→ تحرك نحو السلوك المفضل (move toward preferred behavior)

KL penalty
→ لا تبتعد كثيرًا عن Reference model (do not move too far from the reference model)
```

### لماذا يهم ذلك؟

الهدف ليس:

```text
تعظيم Reward بأي تكلفة (maximize reward at any cost)
```

بل الهدف هو:

```text
تحسين Preference (improve preference)
مع الحفاظ على سلوك Language/Model المفيد
```

## 18. PPO-style RLHF

استُخدمت PPO تاريخيًا على نطاق واسع في Policy optimization بأسلوب RLHF.

يشرحها المصدر باستخدام مفهوم **Advantage**.

### الحدس

إذا كان أداء Response:

```text
أفضل من المتوقع (better than expected)
```

فزد احتمال السلوك المشابه.

وإذا كان أداؤها:

```text
أسوأ من المتوقع (worse than expected)
```

فقلل ذلك الاحتمال.

يمثل Advantage:

```text
Reward فعلية - Reward متوقعة (actual reward - expected reward)
```

على مستوى مفاهيمي عالٍ.

ثم تستخدم PPO Update محكومًا حتى لا تتغير Policy بصورة مفاجئة جدًا.

### التعقيد

قد يتضمن PPO-style RLHF:

- Policy model؛
- Reference model؛
- Reward model؛
- Value estimation؛
- Online generation؛
- Policy updates.

وقد ساعد هذا التعقيد على تحفيز Preference methods أبسط.

## 20. فهم `beta` في DPO


نسبةً إلى Reference model.


## 21. التحسين المختلط للتفضيلات (Mixed Preference Optimization)

يعرض المصدر **MPO** بوصفه يضيف عدة Objectives.

على المستوى المفاهيمي:

```text
MPO loss
=
DPO-style preference loss — Loss للتفضيل النسبي
+
BCO loss — Loss للجودة المطلقة
+
SFT generation loss — Loss لتوليد الإجابة المطلوبة
```

### مكوّن DPO

يعلّم Preference نسبيًا:

```text
chosen > rejected   — المختارة أفضل من المرفوضة
```

### مكوّن BCO

يساعد Model على تمثيل الجودة المطلقة لأمثلة Chosen وRejected بصورة منفصلة.

### مكوّن SFT

يستمر في تعليم Preferred generation نفسها.

يعرض المصدر مثالًا للأوزان:

```text
sigmoid/DPO: 0.8 — وزن DPO
BCO:         0.2 — وزن BCO
SFT:         1.0 — وزن SFT
```

هذه إعدادات خاصة بالمصدر، وليست Defaults عامة.

### لماذا نجمع Objectives؟

إحدى Signals تقول:

```text
أي Response هي المفضلة (which response is preferred)
```

وأخرى تقول:

```text
مدى جودة/سوء كل Response
```

ويعزز Generation loss:

```text
كيفية إنتاج الإجابة المطلوبة (how to produce the desired answer)
```

## 25. Reinforcement learning بمكافآت قابلة للتحقق

Human preference ليست مصدر Reward الوحيد الممكن.

في بعض المهام، يمكن التحقق من Correctness آليًا.

تشمل الأمثلة التي يقدمها المصدر:

```text
الرياضيات (mathematics)
Code (code)
```

بدلًا من:

```text
يقول Human إن Response A أفضل من Response B (human says response A is better than response B)
```

يمكنك استخدام:

```text
reward = passed verifier? — هل اجتازت Response أداة التحقق؟
```

هذا هو **RLVR**.

### لماذا يمكن أن يتوسع؟

قد يكون Automatic verification أرخص كثيرًا من Human preference labeling.

لكنه يعمل فقط عندما تكون Target property قابلة فعلًا للتحقق.

ليست كل السلوكيات المرغوبة لها Objective checker بسيط.

على سبيل المثال:

```text
"Is this explanation empathetic and clear?"   — هل هذا الشرح متعاطف وواضح؟
```

أصعب كثيرًا في Automatic verification من:

```text
"Does this code pass all unit tests?"   — هل تجتاز هذه الشيفرة كل اختبارات الوحدة؟
```

## 26. تحسين السياسة النسبي للمجموعة (Group Relative Policy Optimization)

يقدم المصدر **GRPO** من خلال مجموعة من الإجابات المولدة.

الحلقة عالية المستوى هي:

```text
Question (question)
   ↓
أنشئ عدة إجابات (generate multiple answers)
   ↓
امنح كل إجابة Score (score every answer)
   ↓
قارن كل إجابة بالمجموعة (compare each answer to the group)
   ↓
احسب Relative advantage (compute relative advantage)
   ↓
حدّث Policy (update policy)
```

### Group normalization

افترض أن Rewards هي:

```text
[0.2, 0.9, 0.5, 0.1]
```

تقارن GRPO كل Response بإحصاءات المجموعة.

على المستوى المفاهيمي:

```text
الأفضلية (advantage)
=
مكافأة الاستجابة ناقص متوسط المجموعة (response reward - group mean)
/
الانحراف المعياري للمجموعة (group standard deviation)
```

تحصل Response أعلى من Group mean على Relative advantage موجب.

وتحصل Response أدنى من المتوسط على Relative advantage سالب.

### لماذا يُعد ذلك مفيدًا؟

يتجنب بعض Machinery المرتبطة بـ Value estimation في PPO.

ومع ذلك، يشير المصدر إلى KL regularization مقابل Reference model.

## 27. Online generation هي أيضًا مشكلة Systems

تحتاج Methods مثل Online DPO وGRPO إلى Generations جديدة أثناء Training.

وهذا يعني أن Training يتضمن الآن Inference workload.

### التشغيل المشترك (Colocated)

```text
نفس GPU (same GPU)
→ training + generation   — التدريب والتوليد
```

### Serving منفصل

```text
GPU(s) للتدريب (training GPU(s))
      ↕ Requests (requests)
GPU لـ vLLM inference (vLLM inference GPU)
```

ينشئ هذا قرارًا في Systems design:

```text
ترتيب Hardware أبسط (simpler hardware arrangement)
مقابل (vs)
فصل أفضل بين Training workloads وGeneration workloads (better separation of training and generation workloads)
```

لذلك لا تُعد Alignment مجرد Optimization algorithm.

بل تؤثر أيضًا في:

- Serving infrastructure؛
- GPU allocation؛
- Throughput؛
- Synchronization.

```text
            ↓

5. اختر Efficiency method (CHOOSE EFFICIENCY METHOD)
ضبط دقيق كامل (full fine-tune)
أو LoRA / DoRA
أو QLoRA (or QLoRA)
            ↓

6. درّب (TRAIN)
TRL / trainer abstraction   — طبقة تجريد المدرِّب
            ↓

7. قيّم (EVALUATE)
المهمة المستهدفة (target task)
القدرات العامة (general capabilities)
مخرجات للفحص النوعي (qualitative generations)
            ↓

8. نفّذ Alignment إذا لزم (ALIGN IF NEEDED)
تفضيلات المختارة والمرفوضة (chosen/rejected preferences)
أو Reward signal (or reward signal)
            ↓

9. أعد التقييم (RE-EVALUATE)
الفائدة (helpfulness)
نجاح المهمة (task success)
التراجعات (regressions)
```

الرسالة الأعمق للفصل هي:

> Post-training ليست تقنية واحدة. إنها
> Toolbox لتشكيل Model قادر بالفعل.

## مفاهيم خاطئة مهمة

### المفهوم الخاطئ 1: «Post-training تعني تدريب VLM من الصفر.»

لا.

تبدأ Post-training من Model قادر بالفعل وتقوم بتكييفه.

### المفهوم الخاطئ 2: «SFT وAlignment متطابقتان.»

يعلّم SFT Responses المطلوبة من Target examples.

وتستخدم Alignment إشارات Preference/Reward
لدفع Model نحو سلوك أكثر رغبة.

### المفهوم الخاطئ 3: «أثناء Multimodal SFT، ينبغي أن يتعلم Model إعادة إنتاج User prompt.»

عادةً لا.

يسمح Prompt masking بتركيز Loss على Assistant response.

### المفهوم الخاطئ 4: «LoRA تدرب Weight matrix الأصلية مباشرة.»

تجمّد LoRA الـ Base weight وتدرب Low-rank
adapter matrices التي تنشئ Update.

### المفهوم الخاطئ 5: «LoRA rank الأعلى أفضل دائمًا.»

يزيد Rank الأعلى Expressivity، لكنه يزيد أيضًا Parameters وMemory.

يعتمد Rank الصحيح على Adaptation problem والقيود.

### المفهوم الخاطئ 6: «يجب أن تتفوق PEFT على Full fine-tuning.»

ليس بالضرورة.

إنها مقايضة في Efficiency.

يشير المصدر صراحة إلى أن Adapter-based methods
قد تتعلم أقل بينما تنسى أقل أيضًا.

### المفهوم الخاطئ 7: «Quantization هو Lossless compression.»

لا.

إنه يقلل Numerical precision وقد يضيف Approximation error.

### المفهوم الخاطئ 8: «QLoRA تعني أن Adapters نفسها يجب تخزينها بدقة 4-bit.»

المفهوم الأساسي في المصدر هو Low-bit frozen base
model مع Trainable adapter weights فوقه.

### المفهوم الخاطئ 9: «DPO تحتاج إلى Reward model مُدرَّب.»

هذا تحديدًا ما صُممت DPO لتجنبه.

فهي تنفذ Optimization مباشرةً من Preference pairs.

### المفهوم الخاطئ 10: «بيانات Chosen/Rejected هي نفسها بيانات SFT.»

يوفر SFT Target مرغوبة.

أما Preference data فتقارن بين Response candidates اثنتين على الأقل.

### المفهوم الخاطئ 11: «KL regularization هي Reward.»

إنها Regularizing penalty تُبقي Policy من
الابتعاد كثيرًا عن Reference behavior.

### المفهوم الخاطئ 12: «GRPO تولّد إجابة واحدة فقط لكل Question.»

المجموعة أساسية: تُولد عدة Candidate
answers وتُقارن نسبيًا ببعضها.

### المفهوم الخاطئ 13: «كل مهمة Alignment يمكنها استخدام Verifiable rewards.»

لا.

تتطلب RLVR خاصية Output يمكن التحقق منها فعلًا وبشكل موثوق.

## المصطلحات الأساسية

| المصطلح | المعنى |
|---|---|
| Post-training | مرحلة Adaptation تطبق بعد وجود قدرة عامة مُدرَّبة مسبقًا |
| SFT | Fine-tuning مُراقَب باستخدام أمثلة Prompt-Target |
| Chat template | Formatting خاصة بـ Model للأدوار وImages وSpecial tokens |
| Generation prompt | Marker يحدد موضع بدء Assistant generation |
| Prompt masking | إزالة Positions الخاصة بـ Input/Prompt من Language-generation loss |
| PEFT | Fine-tuning بكفاءة في Parameters |
| Rank | عدد الأبعاد/المكونات المستقلة في Matrix transformation |
| LoRA | Low-rank adaptation باستخدام Matrix A وB قابلة للتدريب |
| LoRA alpha | Scaling hyperparameter يتحكم في مساهمة Adapter |
| DoRA | Weight-decomposed low-rank adaptation يفصل Magnitude عن Direction |
| Quantization | تمثيل قيم Model باستخدام Numerical precision أقل |
| QLoRA | Low-bit frozen model مع LoRA-style adapters قابلة للتدريب |
| NF4 | تمثيل NormalFloat بدقة 4-bit يناقشه QLoRA |
| Double quantization | Quantization لـ Scaling constants بالإضافة إلى Weights |
| PEFT library | مكتبة Hugging Face التي تنفذ Adapter-based fine-tuning methods |
| TRL | مكتبة توفر Trainers/Objectives لـ SFT وAlignment workflows |
| Alignment | Training يوجّه Outputs نحو السلوك المفضل |
| RLHF | Reinforcement learning من Human feedback |
| Reward model | Model يمنح Responses Scores وفق Preferences متعلمة |
| Policy model | Model الذي يجري Optimization له |
| Reference model | Model مرجعي يستخدم لتنظيم سلوك Policy |
| KL divergence | مقياس لاختلاف Distribution يُستخدم كـ Regularization term |
| PPO | Policy optimization method استُخدمت تاريخيًا في RLHF |
| Preference pair | Chosen وRejected responses لنفس Prompt |
| DPO | التحسين المباشر للتفضيلات (Direct Preference Optimization) |
| Beta | DPO hyperparameter يتحكم في مقايضة Policy/Reference وفق صياغة المصدر |
| MPO | Mixed preference objective تجمع Preference وBCO وGeneration losses |
| Online DPO | Preference optimization باستخدام Responses مولدة حديثًا أثناء Training |
| RLVR | Reinforcement learning باستخدام Rewards قابلة للتحقق آليًا |
| GRPO | تحسين السياسة النسبي للمجموعة (Group Relative Policy Optimization) |
| Advantage | Signal تشير إلى الأداء بالنسبة إلى Baseline أو Group |
| Online generation | توليد Candidate outputs جديدة أثناء Alignment training |

## احتفظ بهذه الفكرة

**Post-training هي عملية تشكيل Multimodal model قادر بالفعل ليصبح
Model الذي تحتاج إليه فعليًا. يعلّم SFT السلوك المستهدف، وتجعل
PEFT وQuantization عملية Adaptation ميسورة، وتوجّه Preference
أو Verifiable-reward methods أي Outputs ينبغي لـ Model تفضيلها.
يتمثل التحدي الهندسي في اختيار Objective وData format وEfficiency
method وEvaluation المناسبة معًا.**
