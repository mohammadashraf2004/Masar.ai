## مخرجات التعلّم

بنهاية هذا الدرس يجب أن تكون قادرًا على:

- شرح كيف يحوّل المصدر معماريته على AWS إلى Google Cloud.
- إنشاء مشروع GCP ومنح دور Compute Admin الوارد في المصدر.
- شرح إعداد الـ VM في المصدر: المنطقة ونوع الجهاز وحجم القرص ووسم الشبكة.
- شرح لماذا يحسّن سكربت بدء التشغيل قابلية التكرار.
- تحديد ما يثبّته سكربت بدء التشغيل وما يفعّله.
- ضبط مفتاح SSH من نوع RSA وعنوان IP خارجي ثابت.
- شرح قواعد جدار الحماية في GCP باستخدام وسوم الشبكة ونطاقات CIDR المصدرية.
- نشر تطبيق Streamlit مباشرةً على المنفذ 8501.
- إعادة استخدام حزمة GitHub/Docker/Nginx/SSL على GCP.
- توسيع جدار الحماية من منفذ تطبيق واحد إلى ثلاثة منافذ خدمات.
- نقل الـ deployment على GCP إلى النطاقات الفرعية على المنفذين القياسيين 80 و443.
- شرح كيف يعيد المصدر استخدام تصميم Docker Compose وNginx نفسه عبر مزوّدي السحابة.

## 2. أنشئ VM على Compute Engine مع سكربت بدء التشغيل

ينشئ المصدر VM على Compute Engine باستخدام:

```text
الاسم (Name): webserver
المنطقة (Region): europe-west10 أو أقرب منطقة
نوع الجهاز (Machine type): e2-standard-8
القرص (Disk): 100 GB
وسم الشبكة (Network tag): vm-network-tag
```

ويصف `e2-standard-8` بأنه:

```text
8 vCPUs
32 GB RAM
```

### لماذا يهمّ وسم الشبكة؟

تستهدف قواعد جدار الحماية في GCP لاحقًا:

```text
vm-network-tag    # وسم الشبكة
```

إذن يصبح الوسم رابطًا بين:

```text
VM/القالب
و
سياسة جدار الحماية
```

### سكربت بدء التشغيل

يؤتمت المصدر تجهيز الـ VM عبر سكربت إقلاع/بدء تشغيل.

وينفّذ ما يلي:

```text
تحديث/ترقية النظام
تثبيت Python
تثبيت Docker
تشغيل خدمة Docker
تفعيل خدمة Docker
إضافة المستخدم الحالي إلى مجموعة Docker
تثبيت Docker Compose
تثبيت Git
التحقق من الإصدارات
```

### لماذا نؤتمت أعمال التهيئة الأولية (bootstrap)؟

تطلّب إعداد AWS السابق أوامر يدوية كثيرة.

أما فصل GCP فيجعل الإعداد قابلًا للتكرار:

```text
إنشاء VM
      ↓
تنفيذ سكربت بدء التشغيل
      ↓
تثبيت الأدوات المطلوبة بشكل متسق
```

ويصوغ المصدر ذلك صراحةً على أنه تقليل للأخطاء اليدوية وعدم اتساق الاعتماديات.

## 3. اضبط SSH واحجز عنوان IP خارجيًا ثابتًا

يولّد المصدر زوج مفاتيح SSH محليًا:

⟦CODE_0⟧

وينتج عنه:

```text
~/.ssh/id_rsa    # المفتاح الخاص
~/.ssh/id_rsa.pub    # المفتاح العام
```

### أضف المفتاح العام إلى GCP

يُضاف المفتاح العام إلى إعداد مفاتيح SSH الخاص بالـ VM.

ويبقى المفتاح الخاص على الجهاز المحلي.

### احجز عنوان IP خارجيًا ثابتًا

يحجز المصدر عنوان IP خارجيًا إقليميًا ويربطه بالـ VM.

وهذا يمنح الـ deployment عنوانًا مستقرًا من أجل:

- إعداد SSH،
- الوصول المباشر إلى Streamlit،
- DNS لاحقًا.

### الاسم المستعار لـ SSH في VS Code

يضيف المصدر:

```text
Host vm-book-project    # الاسم المستعار
HostName <STATIC_IP>
IdentityFile ~/.ssh/id_rsa
User <gcp-username>
```

إلى إعداد SSH المحلي.

### SSH عبر وحدة تحكم GCP

ويعرض الفصل أيضًا SSH عبر المتصفح من خلال وحدة تحكم GCP (console) بديلًا.

### ملاحظة حول قاعدة SSH الافتراضية

يشير المصدر إلى أن GCP كثيرًا ما تتضمن قاعدة SSH افتراضية، لكن أولوية قاعدة جدار حماية مخصصة قد تتجاوزها أو تتعارض معها.

## 4. المستوى 1 — انشر تطبيق Streamlit بسيطًا مباشرةً

يتدرج المصدر عن قصد عبر مستويات.

المستوى 1 هو deployment مباشر بسيط.

### أنشئ بيئة افتراضية

على الـ VM:

```text
إنشاء مجلد المشروع
إنشاء بيئة Python افتراضية
تثبيت Streamlit
```

### شغّل Streamlit

يشغّل المصدر التطبيق على:

```text
8501
```

### قاعدة جدار الحماية في GCP

وينشئ:

```text
الاسم (Name): allow-rule-webserver
الاتجاه (Direction): Ingress
الإجراء (Action): Allow
وسم الهدف (Target tag): vm-network-tag
المصدر (Source): IP موثوق/32
منفذ TCP (TCP port): 8501
```

وهذا هو ما يقابل تفكير الـ security group السابق في GCP.

### ربط وسم الشبكة

تنطبق قاعدة جدار الحماية لأن:

```text
للجهاز الافتراضي (VM) الوسم vm-network-tag
```

ولأن:

```text
جدار الحماية يستهدف الوسم vm-network-tag
```

### العنوان المباشر

يصبح التطبيق متاحًا على:

```text
http://STATIC_IP:8501    # عنوان مثالي
```

وهذا ليس التصميم الآمن النهائي عن قصد.

إنه مستوى للتحقق.

## 7. ماذا تغيّر عن AWS، وماذا بقي كما هو؟

### المكوّنات السحابية التي تغيّرت

مفاهيم المصدر في AWS:

```text
EC2
Security Groups (مجموعات الأمان)
Elastic IP
Network Load Balancer (موازن الحمل الشبكي)
```

ومفاهيم المصدر في GCP:

```text
Compute Engine VM
VPC Firewall Rules (قواعد جدار حماية VPC)
Static External IP (عنوان IP خارجي ثابت)
لاحقًا: global load balancer
```

### تصميم التطبيق المعاد استخدامه

يُبقي المصدر عبر المزوّدين كليهما على:

```text
Docker
Docker Compose
Nginx
Streamlit
Flask
Jenkins
ملفات شهادة TLS
مزوّد DNS
```

وهذا يوضح قابلية نقل السحابة على مستوى طبقة التطبيق.

يتغير توفير الـ VM والشبكة.

أما حاويات التطبيق وتصميم الوكيل العكسي فيبقيان إلى حد كبير كما هما.

## مفاهيم خاطئة شائعة

### المفهوم الخاطئ 1
> "الترحيل إلى GCP يتطلب إعادة كتابة حزمة التطبيق."

يعيد المصدر استخدام المستودع نفسه وملفات Docker Compose وإعداد Nginx وخدمات التطبيق إلى حد كبير.

> "سكربت بدء التشغيل هو شيفرة تطبيق."

إنه أتمتة لتهيئة الـ VM.

### المفهوم الخاطئ 3
> "جدار الحماية في GCP ينطبق تلقائيًا على كل VM."

يستهدف المصدر صراحةً وسم شبكة.

### المفهوم الخاطئ 4
> "عنوان IP الثابت وهوية الـ VM الداخلية مفهوم واحد."

عنوان IP الخارجي الثابت هو العنوان المستقر المواجه للعملاء المستخدم في هذا الفصل.

### المفهوم الخاطئ 5
> "المستوى 1 هو المعمارية الآمنة النهائية."

إنه خطوة تحقق تدريجية قبل TLS والنطاقات الفرعية.

## المصطلحات الأساسية

| المصطلح | المعنى |
|---|---|
| مشروع GCP (GCP Project) | حدّ للموارد والإدارة في Google Cloud |
| Compute Engine | خدمة الأجهزة الافتراضية في GCP |
| Compute Admin | دور IAM يستخدمه المصدر |

| قاعدة جدار حماية VPC (VPC firewall rule) | قاعدة لحركة الشبكة في GCP |
| وسم الهدف (Target tag) | وسم شبكة يحدّد الأجهزة الافتراضية المتأثرة بقاعدة جدار حماية |
