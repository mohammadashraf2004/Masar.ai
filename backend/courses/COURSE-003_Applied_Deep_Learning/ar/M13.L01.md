## 2. كل تنبؤ ثنائي ينتمي إلى واحدة من أربع نتائج

في التصنيف الثنائي، يمكن أن يكون ground truth موجبًا أو سالبًا، ويمكن أن يكون تنبؤ الـ model موجبًا أو سالبًا أيضًا.

وهذا ينتج أربع حالات:

| ground truth | التنبؤ | الاسم |
|---|---|---|
| موجب | موجب | موجب حقيقي (True positive، أي TP) |
| سالب | سالب | سالب حقيقي (True negative، أي TN) |
| سالب | موجب | موجب كاذب (False positive، أي FP) |
| موجب | سالب | سالب كاذب (False negative، أي FN) |

[[IMAGE_NEEDED: Four binary-classification quadrants | A clean 2×2 confusion-grid showing true positive, true negative, false positive, and false negative with nodule/non-nodule examples | Learner should immediately see that false positives and false negatives are different mistakes with different consequences]]

وفي مشروع CT:

- **TP:** عقيدة حقيقية جرى تعليمها صحيحًا على أنها عقيدة.
- **TN:** غير عقيدة جرى رفضها صحيحًا.
- **FP:** غير عقيدة جرى تعليمها خطأً على أنها عقيدة.
- **FN:** عقيدة حقيقية جرى تجاهلها خطأً.

## 3. استعارة كلبي الحراسة: طريقتان مختلفتان للإخفاق

يستخدم الفصل كلبي حراسة لجعل المفاضلة حدسية.

## 4. عتبة التصنيف تخلق المفاضلة

ينتج الـ model درجة أو احتمالًا متصلًا للفئة الموجبة.

وتحوّل العتبة ذلك المخرَج المتصل إلى قرار منفصل:

```text
الدرجة > العتبة   -> تنبّأ بموجب
الدرجة <= العتبة  -> تنبّأ بسالب
```

وتحريك العتبة إلى اليسار يجعل تسمية شيء بأنه موجب أسهل:

- سالبات كاذبة أقل،
- موجبات كاذبة أكثر.

وتحريكها إلى اليمين يجعل التنبؤات الموجبة أكثر صرامة:

- موجبات كاذبة أقل،
- سالبات كاذبة أكثر.

[[IMAGE_NEEDED: Threshold tradeoff between positives and negatives | Overlapping distributions of negative and positive model scores with a movable vertical threshold; arrows show that moving left raises recall while moving right raises precision | Learner should notice that threshold changes trade one error type for another]]

ولا تستطيع العتبة إصلاح كل مشكلة لأن توزيعي الدرجات الموجبة والسالبة قد يتداخلان تداخلًا كبيرًا.

## 5. Recall: كم موجبًا حقيقيًا وجدنا؟

يسأل recall:

> **من بين كل العيّنات الموجبة فعلًا، كم منها اكتشفها الـ model؟**

الصيغة:

```text
recall = TP / (TP + FN)   # الصيغة
```

ولزيادة recall، قلّل السالبات الكاذبة.

ويستطيع model أن يحصل على recall ممتاز بتسمية كل شيء تقريبًا موجبًا — لكن ذلك قد يخلق موجبات كاذبة كثيرة.

ويشير الفصل إلى أن recall يُسمّى أيضًا **sensitivity** في بعض السياقات.

---

## 6. Precision: إلى أي مدى تُوثَق تنبؤاتنا الموجبة؟

يسأل precision:

> **من بين كل ما تنبأ الـ model بأنه موجب، كم كان موجبًا فعلًا؟**

الصيغة:

```text
precision = TP / (TP + FP)   # الصيغة
```

ولزيادة precision، قلّل الموجبات الكاذبة.

ويستطيع model أن يحصل على precision مرتفع جدًا بالتنبؤ بالموجب فقط في الحالات الأوضح — لكن ذلك قد يفوّت كثيرًا من الموجبات الحقيقية.

[[IMAGE_NEEDED: Precision versus recall denominators | Two small diagrams highlight TP/(TP+FN) for recall and TP/(TP+FP) for precision using the same TP/FP/FN/TN grid | Learner should notice that both metrics use TP but answer different questions]]

## 8. F1: ادمج precision وrecall في درجة واحدة

لا يلتقط precision ولا recall وحده الهدف الكامل.

ولذلك يقدّم الفصل درجة F1:

```text
F1 = 2 × (precision × recall) / (precision + recall)   # الصيغة
```

وتتراوح F1 بين 0 و1.

وهي **المتوسط التوافقي (harmonic mean)** لـ precision وrecall.

ويعاقب المتوسط التوافقي model بشدة حين تكون إحدى القيمتين أقل بكثير من الأخرى.

[[IMAGE_NEEDED: F1 surface over precision and recall | A conceptual contour/surface plot where the best values occur when both precision and recall are high and balanced, while regions with one value near zero remain poor | Learner should see why F1 discourages extreme one-sided behavior]]

## 9. لماذا لا نأخذ متوسط precision وrecall ببساطة؟

افترض:

```text
precision = 1.0   # دقة تامة
recall    = 0.0   # لا اكتشاف
```

المتوسط الحسابي هو `0.5`.

لكن مصنِّفًا بـ recall صفري ليس مفيدًا عادةً لغرض الفصل.

وفي المقابل:

```text
precision = 0.5   # متوازن
recall    = 0.5   # متوازن
```

يساوي متوسطه `0.5` أيضًا، رغم أنه مصنِّف أكثر توازنًا بكثير.

وينظر الفصل أيضًا في أخذ الحد الأدنى أو ضرب precision في recall، ثم يشرح لماذا تفقد هذه البدائل فروقًا مفيدة.

وتُختار F1 لأنها تستجيب استجابة ذات معنى للمفاضلات بين النسبتين.

## 10. المقاييس غير المعرَّفة معلومات، لا مجرد تحذيرات مزعجة

حين لا يتنبأ الـ model بأي موجب إطلاقًا:

```text
TP = 0
FP = 0
```

يحاول precision أن يقسم على صفر:

```text
0 / (0 + 0)
```

ولذلك تنتج التشغيلات المبكرة في المصدر `nan` لـ precision وF1.

وهذا التحذير تشخيصي بذاته: فالـ model في حالة متردية يرفض فيها التنبؤ بالفئة الموجبة.

وفي تنفيذ إنتاجي، عالج المقامات الصفرية صراحةً كي تبقى لوحات المتابعة مستقرة مع حفظ معنى حالة الإخفاق.

## 14. لماذا لا نعتمد على sampler في DataLoader وحده؟

يدعم PyTorch الوسيط `sampler=...` في `DataLoader`، بما في ذلك أدوات مثل أخذ العيّنات العشوائي الموزون.

ويشرح المصدر قيدًا عمليًا: فواجهة `Dataset` القياسية لا تعرض إلا الوصول المفهرس والطول. ولا تضمن وجود طريقة عامة تقول أي الفهارس تنتمي إلى أي الفئات.

وإذا كنت تتحكم في تنفيذ dataset، فقد يكون إعادة تشكيل البيانات مباشرةً داخل dataset أوضح من كسر التغليف لبناء أوزان sampler.

ولذلك يختار المصدر الموازنة على مستوى dataset لهذا المشروع.

## 19. المزيد من التدريب يكشف overfitting

مع استمرار التدريب الموازَن، تصبح مقاييس التدريب شبه مثالية.

لكن أداء الفئة الموجبة في التحقق يبدأ بالتدهور.

ويبرز المصدر نمطًا مثل:

```text
خسارة التدريب الموجبة   -> قرب الصفر
خسارة التحقق الموجبة    -> ترتفع
```

وهذا التباعد إشارة classic على overfitting.

[[IMAGE_NEEDED: Training versus validation positive loss divergence | Two curves over epochs: training positive loss falls toward zero while validation positive loss turns upward | Learner should identify the point where more training begins to harm generalization]]

ويمكن لخسارة التحقق الكلية أن تخفي هذا لأن مجموعة التحقق المختلة التوازن طبيعيًا تهيمن عليها العيّنات السالبة.

ومرة أخرى، **يهم مقياس المجموعة الفرعية الصحيح**.

## 20. يعني overfitting حفظ الخصوصيات بدلًا من تعلّم الخصائص العامة

يعيد الفصل زيارة overfitting بتشبيه الوجه والعمر.

فالـ model الذي يعمّم جيدًا يتعلم أنماطًا متعلقة بالعمر تنتقل إلى أشخاص لم يرَهم.

أما الـ model المفرط التلاؤم فيتعلم بدلًا من ذلك غرائب مميِّزة لأشخاص التدريب ويتذكر إجاباتهم فعليًا.

وفي مصنِّف CT، لا يوجد إلا عدد صغير من العقيدات الموجبة في التدريب. وتكرارها يوازن إشارة التدريب، لكن التكرار **لا** ينشئ تنوعًا بيولوجيًا جديدًا.

وقد يستطيع model ذو سعة كافية في النهاية حفظ تلك العيّنات الموجبة.

## 32. ما الذي تُظهره تجارب التعزيز في الفصل

يذكر المصدر عدة ملاحظات مهمة من التشغيلات المثالية:

### التعزيز المجمَّع

يجد الـ model المعزَّز كاملًا مرشَّحين موجبين أكثر بكثير ويقاوم overfitting أفضل من التشغيل غير المعزَّز.

### الضجيج وحده

يؤدي تعزيز الضجيج أسوأ من الـ model غير المعزَّز في تحديد الموجبات في التجربة المعروضة.

### التدوير

يؤدي التدوير تقريبًا بقدر التعزيز الكامل في recall وله precision أفضل في التشغيلات المعروضة، مما قد يقود إلى F1 أفضل.

### الاتجاه المختار

يُبقي المصدر الـ model المعزَّز كاملًا للعمل اللاحق لأن حالة الاستخدام تعطي الأولوية لـ recall مرتفع، بينما تبقى F1 مفيدة لتحديد أي epoch هي الأفضل.

[[IMAGE_NEEDED: TensorBoard comparison of augmentation runs | Multiple validation curves for balanced baseline, rotation, noise, and fully augmented models across recall, precision, F1, and positive loss | Learner should notice that different augmentations affect precision and recall differently and that full augmentation reduces overfitting]]

والدرس المهم ليس أن تحويلًا واحدًا هو الأفضل عالميًا. بل إن خيارات التعزيز **فرضيات تعتمد على المهمة والبيانات ويجب قياسها**.

## 34. مخطط evaluation والتحسين الكامل

```text
MODEL OUTPUTS
    ↓
حوّل بالعتبة إلى تنبؤات موجبة/سالبة
    ↓
TP / TN / FP / FN
    ↓
precision / recall / F1
    ↓
شخّص انهيار الفئة الأغلبية
    ↓
وازِن تدفق TRAINING
أبقِ VALIDATION طبيعية
    ↓
راقب منحنيات التدريب/التحقق الخاصة بكل فئة
    ↓
اكشف overfitting
    ↓
طبّق تعزيزًا عشوائيًا صالحًا للمجال
    ↓
قارن جولات TensorBoard
    ↓
اختر التحسينات بحسب الأولويات الحقيقية للمهمة
```

### نقطة تحقق تعلّمية 3 — شخّص قبل أن تعدّل

بالنظر إلى model له:

```text
الدقة (accuracy) = 99.3%
precision        = 0.21
recall           = 0.82
```

لا ينبغي أن تلخّصه ببساطة بأنه '99.3% دقيق.'

اشرح ما تعنيه تلك الأرقام بشأن الموجبات الكاذبة والسالبات الكاذبة في dataset مختلة التوازن، وأي رسوم إضافية خاصة بكل فئة ستفحصها قبل تغيير التدريب.

## مفاهيم خاطئة شائعة

### المفهوم الخاطئ 1: الدقة كافية إذا كانت مجموعة التحقق كبيرة

قد تبقى مجموعة تحقق كبيرة شديدة الاختلال في التوازن. ويمكن لأداء الفئة الأغلبية أن يهيمن على الرقم المجمَّع.

### المفهوم الخاطئ 2: recall المرتفع يعني أن المصنِّف جيد

يستطيع model الحصول على recall مثالي بالتنبؤ بكل شيء موجبًا، على حساب precision سيئ جدًا.

### المفهوم الخاطئ 3: precision المرتفع يعني أن المصنِّف جيد

يستطيع model الحصول على precision مرتفع جدًا بالتنبؤ بالموجب فقط في مجموعة صغيرة من الحالات الواضحة، بينما يفوّت معظم الموجبات.

### المفهوم الخاطئ 4: F1 مجرد متوسط عادي

F1 هي المتوسط التوافقي لـ precision وrecall، اختيرت تحديدًا لمعاقبة الأداء أحادي الجانب بقوة أكبر.

### المفهوم الخاطئ 5: ينبغي أن يكون للتدريب والتحقق دائمًا توازن فئات متطابق

يوازن المصدر التدريب عمدًا لتحسين التعلّم مع الحفاظ على توزيع التحقق المختل طبيعيًا.

### المفهوم الخاطئ 6: تكرار الأمثلة الموجبة النادرة يحلّ اختلال توازن الفئات حلًا كاملًا

تصلح الموجبات المكررة اختلال التدرّج المبكر، لكن يمكن بعد ذلك حفظ المجموعة الصغيرة، مما يقود إلى overfitting.

### المفهوم الخاطئ 7: أي تحويل صور عشوائي تعزيز مفيد

يجب أن يبقى التعزيز ممثِّلًا للفئة وأن يحترم الهندسة الخاصة بالمجال.

### المفهوم الخاطئ 8: ينبغي تخزين العيّنات المعزَّزة مؤقتًا لتوفير الوقت

قد يجمّد caching التعزيز العشوائي العشوائية. وينبغي تخزين الاقتطاع الحتمي مؤقتًا قبل التعزيز.

### المفهوم الخاطئ 9: مزيد من الإفساد ينتج دائمًا تنظيمًا أقوى

قد يؤدي تشغيل الضجيج وحده في الفصل أسوأ لأن التعزيز قد يجعل المهمة صعبة جدًا أو يدمّر إشارة مفيدة.

## المصطلحات الأساسية

| المصطلح | المعنى |
|---|---|
| True positive (TP) | عيّنة موجبة جرى التنبؤ بها موجبة تنبؤًا صحيحًا. |
| True negative (TN) | عيّنة سالبة جرى التنبؤ بها سالبة تنبؤًا صحيحًا. |
| False positive (FP) | عيّنة سالبة جرى التنبؤ بها موجبة خطأً. |
| False negative (FN) | عيّنة موجبة جرى التنبؤ بها سالبة خطأً. |
| Classification threshold | حدّ درجة يُستخدم لتحويل مخرَج متصل إلى قرار ثنائي. |
| Recall | `TP / (TP + FN)`؛ نسبة الموجبات الحقيقية التي وُجدت بنجاح. |
| Sensitivity | اسم بديل لـ recall في بعض السياقات. |
| Precision | `TP / (TP + FP)`؛ نسبة الموجبات المتنبَّأ بها التي هي موجبة فعلًا. |
| F1 score | المتوسط التوافقي لـ precision وrecall. |
| Class imbalance | تفاوت شديد في عدد الأمثلة من الفئات المختلفة. |
| Balanced training | إعادة تشكيل تدفق التدريب كي تسهم الفئات في التعلّم بقدر أكثر تقاربًا. |
| Oversampling | إعادة استخدام أمثلة الفئة الأقلية بصورة أكثر تكرارًا أثناء التدريب. |
| Sampler | مكوّن في DataLoader يتحكم في أي فهارس dataset تُسحب وبأي ترتيب. |
| Overfitting | تعلّم تفاصيل خاصة بالتدريب لا تعمّم على بيانات لم تُرَ. |
| Data augmentation | إنشاء تحويلات عشوائية تحافظ على الفئة لعيّنات التدريب. |
| Affine transform | تحويل خطي/إزاحة يُستخدم لإعادة أخذ العيّنات مكانيًا. |
| `affine_grid` | دالة PyTorch تبني شبكة أخذ عيّنات من تحويل أفيني. |
| `grid_sample` | دالة PyTorch تعيد أخذ عيّنات tensor باستخدام شبكة مقدَّمة. |
| Mirroring | قلب عيّنة عبر محور واحد أو أكثر. |
| Translation / shift | تحريك محتوى العيّنة داخل الاقتطاع. |
| Scaling | تكبير المحتوى المأخوذ أو تصغيره. |
| Rotation | تدوير العيّنة حول محور صالح فيزيائيًا مختار. |
| Noise augmentation | إضافة ضجيج عشوائي مباشرةً إلى قيم voxel. |

36. لماذا يمكن أن تكون لتشغيل التدوير وحده F1 أقوى من تشغيل ذي recall أعلى؟

## احتفظ بهذه الفكرة

**لا يمكن تحسين model تحسينًا ذكيًا إلا حين تكشف مقاييسه الإخفاق المهم. ففي التصنيف المختل التوازن، يمكن للدقة أن تخفي استراتيجية أغلبية عديمة الفائدة. ويكشف precision وrecall وF1 والخسائر الخاصة بكل فئة السلوك الحقيقي؛ ويصلح التدريب الموازَن إشارة التعلّم المبكرة؛ ويمنع التعزيز الصالح للمجال حفظ فئة أقلية صغيرة ببساطة.**
