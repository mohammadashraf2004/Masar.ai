## 1. ماذا يولّد Language Model فعليًا؟

لا يكتب Language Model فقرة كاملة في عملية واحدة.

في كل Generation Step، يستقبل النص الذي تم إنتاجه حتى الآن، ثم يتنبأ بـ Probability Distribution على جميع Next Tokens الممكنة.

لنفترض أن الـ Prompt هو:

```text
Transformers هي الـ
```

قد يمنح الـ Model احتمالات مثل:

```text
most       0.085   — أعلى كلمة تالية احتمالًا
only       0.050
best       0.047
ultimate   0.022
...
```

تحدد Decoding Strategy أي Candidate Token سيتم اختيارها.

بعد اختيار Token، تتم إضافتها إلى الـ Prompt:

```text
Transformers هي الـ most
```

بعد ذلك تُرسل الـ Sequence المحدّثة إلى الـ Model مرة أخرى، فينتج Distribution جديدة للـ Next Token، ثم يتم اختيار Token أخرى، وتتكرر العملية.

يتوقف Generation عندما ينتج الـ Model End-of-sequence Token أو يصل إلى Length Limit محدد.

{{image:autoregressive-generation-loop}}

### أول فرق أساسي يجب فهمه

ينتج Language Model Scores/Probabilities، بينما تحدد Decoding Algorithm كيف تتحول هذه الاحتمالات إلى Text Sequence فعلية.

ولهذا يمكن للـ Model والـ Prompt نفسيهما إنتاج نصوص مختلفة جدًا عندما نغير Decoding Settings.

## 2. نمذجة اللغة السببية (Causal Language Modeling)

Models من عائلة GPT هي Autoregressive، ويُطلق عليها أيضًا Causal Language Models.

يمكن تلخيص Training Objective الخاصة بها ببساطة:

> بالنظر إلى جميع Tokens السابقة، توقّع الـ Next Token.

بالنسبة إلى Sequence:

```text
x1, x2, x3, ..., xn
```

يمكن تحليل احتمال الـ Sequence الكاملة إلى Conditional Next-token Probabilities:

```text
P(sequence)   — احتمال التسلسل كاملًا
=
P(x1) × P(x2 | x1) × P(x3 | x1,x2) × ... × P(xn | x1,...,x(n-1))   — حاصل ضرب احتمال كل Token بشرط ما سبقها
```

لا تحتاج إلى حفظ المعادلة. احتفظ بالفكرة:

**يتم بناء Sequence طويلة من عدد كبير من قرارات Next-token Prediction.**

يختلف ذلك عن Masked-language Modeling مثل Training Objective الخاصة بـ BERT. فالـ Causal Model يتنبأ اعتمادًا على Past Context، بينما يستطيع Masked Encoder استخدام Context الموجود على جانبي الموضع المحجوب.

### توليد النص الشرطي (Conditional Text Generation)

يعتمد النص المولّد بدرجة كبيرة على الـ Prompt الأولي. لذلك نسمّي هذا غالبًا Conditional Generation: الـ Continuation تكون مشروطة بالنص الذي تم تقديمه بالفعل.

## 3. Greedy Search: اختر الفائز الحالي دائمًا

أبسط Decoder هو Greedy Search.

في كل خطوة:

1. احسب Next-token Probabilities،
2. اختر Token ذات أعلى Probability،
3. أضفها إلى الـ Sequence،
4. كرر العملية.

### تنفيذ مبسط

⟦CODE_0⟧

تنفّذ Generation API المدمجة النوع نفسه من Deterministic Decoding عندما يكون Sampling معطلًا:

⟦CODE_1⟧

### لماذا يعد Greedy Search جذابًا؟

- بسيط،
- Deterministic،
- منخفض التكلفة نسبيًا،
- يختار دائمًا Next Token ذات أعلى احتمال محليًا.

### لماذا قد يفشل Greedy Search؟

أفضل Token محليًا لا تضمن الوصول إلى أفضل Sequence كاملة.

تخيّل مسارين:

```text
الخطوة 1
A = 0.60
B = 0.40

الخطوة 2
بعد A: أفضل Continuation = 0.20
بعد B: أفضل Continuation = 0.90
```

يختار Greedy Search المسار A فورًا لأن `0.60 > 0.40`. لكن أقوى مسار من خطوتين عبر B احتماله:

```text
0.40 × 0.90 = 0.36
```

بينما يعطي المسار A:

```text
0.60 × 0.20 = 0.12
```

لا يستطيع Greedy Search العودة إلى القرار السابق وإعادة النظر فيه.

وفي النصوص الحرة الطويلة، تظهر مشكلة شائعة أخرى هي Repetition.

## 4. Beam Search: احتفظ بعدة مسارات واعدة

يحاول Beam Search تجنب الالتزام بمسار Token واحد مبكرًا جدًا.

إذا كان عدد الـ Beams هو b، يحتفظ الـ Decoder بأفضل b Partial Sequences في كل خطوة.

مثلًا، مع Beamين:

```text
Prompt
 ├── Candidate A
 └── Candidate B

الخطوة التالية:
 A ── A1, A2, ...
 B ── B1, B2, ...

احتفظ بأفضل Extended Sequences اثنتين.
ثم كرر.
```

## 5. لماذا يستخدم Beam Search الـ Log Probabilities؟

لتقييم Sequence مولّدة كاملة، يمكننا ضرب Conditional Token Probabilities لكل Tokens.

لكن ضرب عدد كبير من الاحتمالات يسبب مشكلة عددية: كل Probability تقع بين 0 و1، ولذلك قد يصبح حاصل الضرب صغيرًا للغاية.

مثلًا:

⟦CODE_3⟧

ينتج قيمة قريبة جدًا من الصفر.

بدلًا من ذلك نستخدم Log Probabilities.

العلاقة المفيدة هي:

```text
log(a × b × c) = log(a) + log(b) + log(c)   — لوغاريتم حاصل الضرب يساوي مجموع اللوغاريتمات
```

وهكذا، بدلًا من ضرب مئات القيم الصغيرة، نجمع Logarithms الخاصة بها.

دالة مبسطة:

⟦CODE_4⟧

### Log Probability الأعلى تعني احتمالًا أكبر

تكون Log Probabilities سالبة عادة. لذلك تكون القيمة `-55` أعلى من `-87`، وتمثل Sequence أكثر احتمالًا وفقًا للـ Model.

لكن هناك تحذير مهم:

**الـ Sequence ذات Model Probability الأفضل ليست بالضرورة الـ Sequence التي سيفضّلها البشر.**

قد تحصل نتيجة Beam Search في مثال الفصل على Log Probability أفضل من Greedy Output، ومع ذلك قد تحتوي على Repetition غير مرغوب فيها.

## 6. التحكم في Repetition باستخدام N-gram Constraint

قد يقع Greedy وBeam Decoding في Patterns متكررة.

أحد أساليب التحكم البسيطة هو `no_repeat_ngram_size`.

الـ N-gram عبارة عن Sequence من n Tokens. إذا كان `n=2`، فنحن نراقب أزواج Tokens. يستطيع الـ Decoder حجب Candidate Tokens التي ستؤدي إلى إعادة تكوين 2-gram سبق توليدها.

⟦CODE_5⟧

قد يقلل ذلك Repetition حتى إذا أصبحت الـ Sequence الناتجة ذات Model Log Probability أقل.

وهذا يعلّمنا مبدأ مهمًا في Generation:

> **تحسين Model Probability وحدها لا يساوي تحسين جودة النص المفيد.**

في مهام مثل Translation أو Summarization، قد يكون Deterministic Search مع Repetition Controls مفيدًا عندما تكون Stable Output أهم من Creativity.

## 7. Sampling: اسمح بأكثر من مستقبل محتمل

يكون Greedy Search وBeam Search العادي Deterministic. إذا استخدمت الـ Model والـ Prompt والـ Settings نفسها، فإنهما يميلان إلى اختيار النتيجة نفسها.

يغيّر Sampling القاعدة. بدلًا من اختيار Token ذات أعلى Probability دائمًا، نقوم بأخذ عينة من Probability Distribution.

تبقى Token ذات الاحتمال الأعلى أكثر ترجيحًا للاختيار، لكن قد يتم أحيانًا اختيار Token أخرى معقولة.

وهذا يضيف Diversity.

### Temperature

تعيد Temperature تحجيم الـ Logits قبل Softmax:

```text
probabilities = softmax(logits / temperature)   — الاحتمالات الناتجة بعد قسمة logits على temperature
```

فكّر في Temperature باعتبارها عاملًا يتحكم في مدى تفضيل الـ Model للمرشحين المتصدرين حاليًا.

| سلوك Temperature | التأثير |
|---|---|
| أقل | يصبح Distribution أكثر حدّة، وتسيطر High-probability Tokens |
| أعلى | يصبح Distribution أكثر تسطحًا، وتصبح Lower-probability Tokens أكثر قدرة على المنافسة |

إذن:

```text
Temperature أقل  → غالبًا أكثر تحفظًا/اتساقًا
Temperature أعلى → غالبًا أكثر تنوعًا/مخاطرة
```

## 8. Top-k Sampling: استبعد الذيل الطويل

لأخذ عينات من Vocabulary كاملة نقطة ضعف: حتى Token ذات احتمال منخفض جدًا تظل لديها فرصة صغيرة لأن تُختار.

ومع توليد عدد كبير من Tokens، تتراكم هذه المخاطر الصغيرة. قد تدفع Token غريبة واحدة الـ Continuation إلى اتجاه سيئ.

يحد Top-k Sampling عملية Sampling إلى أعلى k Tokens من حيث Probability في كل Generation Step.

إذا كان:

```text
k = 50
```

يتخلص الـ Decoder من جميع Candidates باستثناء أعلى 50 Token حاليًا، ثم يعيد تطبيع الاحتمالات المتبقية ويأخذ Sample من هذه المجموعة الأصغر.

⟦CODE_7⟧

### القيد

تكون `k` ثابتة، رغم أن درجة عدم يقين الـ Model تتغير من Token Position إلى آخر.

أحيانًا لا يوجد سوى عدد قليل من Continuations المعقولة. وفي موضع آخر قد يكون هناك عدد كبير من Continuations المنطقية. لا يستطيع Fixed Cutoff التكيّف مع هذا الاختلاف.

## 9. Nucleus Sampling: اختر Probability Mass بدل عدد ثابت

ينشئ Nucleus Sampling، ويُسمّى أيضًا Top-p Sampling، Candidate Set ديناميكية.

لنفترض:

```text
top_p = 0.90
```

تعمل Algorithm كالتالي:

1. ترتب Candidate Tokens من أعلى Probability إلى أقلها،
2. تبدأ بإضافتها إلى Candidate Set،
3. تتوقف عندما يصل مجموع الاحتمالات التراكمي إلى نحو 90%،
4. تأخذ Sample من الـ Nucleus المختارة.

إذا كانت Token واحدة شديدة الاحتمال، فقد تكون Candidate Set صغيرة جدًا. وإذا كان الـ Model غير واثق، فقد تحتوي المجموعة على Tokens كثيرة.

## 10. أي Decoding Method ينبغي أن تستخدم؟

لا يوجد Decoder واحد هو الأفضل دائمًا. الاختيار الصحيح يعتمد على نوع Output الذي تحتاجه.

| الحاجة | اتجاه مناسب |
|---|---|
| Output قصيرة، مستقرة وDeterministic | Greedy أو Deterministic Strategy أخرى |
| البحث بين عدة Sequences محتملة بقوة | Beam Search |
| تقليل العبارات المتكررة في Deterministic Generation | Repetition Constraints مثل N-gram Blocking |
| Continuation أكثر تنوعًا | Sampling |
| Sampling أكثر تحفظًا | Temperature أقل |
| Sampling أكثر تنوعًا | Temperature أعلى، لكن بحذر |
| تجنب Sampling من Tail Tokens ضعيفة جدًا | Top-k أو Top-p |
| Candidate-set Size متكيفة | Top-p |

يقارن الفصل بين المهام الدقيقة وبين Generation الأكثر إبداعًا. المهمة التي تحتاج فيها إلى Stable High-probability Answer تتطلب Decoding Strategy مختلفة عن Story Generation أو Open-ended Conversation.

### لا تخلط بين Decoding وFactuality

تتحكم Decoding Strategy في أي Continuation يتم اختيارها من Distribution الخاصة بالـ Model. لكنها لا تجعل الـ Model الأساسي يعرف ما إذا كان Claim مولّد صحيحًا أم لا.

قد تكون Continuation سلسة وعالية الاحتمال، ومع ذلك تحتوي على معلومات مختلقة.

## 11. لماذا يكون Text Generation مكلفًا حسابيًا؟

في Sequence Classification العادية، يمكننا غالبًا الحصول على Prediction باستخدام Forward Pass واحدة.

أما Autoregressive Generation فهو Iterative:

```text
ولّد Token 1
      ↓
ولّد Token 2
      ↓
ولّد Token 3
      ↓
...
```

نحتاج إلى Model Computation لكل Token يتم توليدها. ويزيد Beam Search العمل أكثر لأنه يتتبع عدة Candidate Sequences.

هذا مهم عند Deploying Generation Systems على نطاق واسع. جودة Generation ليست سوى جزء من المشكلة الهندسية؛ إذ تهم أيضًا Latency وMemory وThroughput وCost.

## 12. تجميع عملية Generation كاملة

استخدم هذا Mental Model كلما تعاملت مع Generative Transformer:

```text
Prompt
  ↓
Tokenizer
  ↓
Token IDs الحالية
  ↓
Causal Language Model
  ↓
Next-token Logits
  ↓
Softmax / Probability Distribution بعد التعديل
  ↓
Decoding Rule
  ├── Greedy
  ├── Beam Search
  └── Sampling
       ├── Temperature
       ├── Top-k
       └── Top-p
  ↓
اختر Next Token
  ↓
أضف Token وكرر العملية
```

## مفاهيم خاطئة مهمة

### المفهوم الخاطئ 1: الـ Model يولّد الإجابة كاملة دفعة واحدة

> تتنبأ Network بالفقرة المكتملة في Forward Pass واحدة.

### لماذا هذا خطأ

تولد Autoregressive Models بصورة Iterative. تصبح كل Token يتم اختيارها جزءًا من الـ Context المستخدم في Prediction التالية.

### المفهوم الخاطئ 2: Greedy Search يجد دائمًا أكثر Sequence كاملة احتمالًا

> اختيار أفضل Token في كل خطوة يضمن أفضل نص نهائي.

### لماذا هذا خطأ

قد تقود Token مثالية محليًا إلى مسار سيئ لاحقًا. يستكشف Beam Search عدة Partial Sequences لتقليل هذا القيد.

### المفهوم الخاطئ 3: Temperature الأعلى تجعل الـ Model أذكى

> زيادة Temperature تحسن معرفة الـ Model أو Reasoning الخاصة بها.

### لماذا هذا خطأ

تقوم Temperature فقط بإعادة تشكيل Probability Distribution المستخدمة في Sampling. القيم الأعلى تزيد Randomness وقد تقلل Coherence في النهاية.

### المفهوم الخاطئ 4: Model Probability الأعلى تعني دائمًا نصًا أفضل

> الـ Sequence ذات أفضل Log Probability يجب أن تكون أكثر Output فائدة للإنسان.

### لماذا هذا خطأ

Probability تعبّر عن تفضيل الـ Model، وليست Human-quality Metric كاملة. تظل Repetition وUsefulness وFactuality ومتطلبات المهمة عوامل مهمة أيضًا.

## المصطلحات الرئيسية

| المصطلح | المعنى |
|---|---|
| Autoregressive Model | Model تتنبأ بالـ Next Token باستخدام Previous Context |
| نموذج اللغة السببي (Causal Language Model) | Autoregressive Language Model لا يسمح Prediction فيها باستخدام Future Tokens |
| Conditional Generation | Generation مشروطة بـ Prompt أو Context أولي |
| Logit | Raw Model Score قبل Probability Normalization |
| Softmax | Function تحوّل Logits إلى Probability Distribution مُطبّعة |
| Decoding | عملية اختيار Output Tokens من Model Scores/Probabilities |
| Greedy Search | اختيار أعلى Next Token احتمالًا في كل خطوة |
| Beam Search | الاحتفاظ بعدة Partial Sequences ذات Scores مرتفعة أثناء Decoding |
| Beam | Candidate Sequence جزئية واحدة داخل Beam Search |
| Log Probability | Logarithm للاحتمال، وتسمح بجمع Sequence Scores بصورة مستقرة |
| N-gram | Sequence مكوّنة من n Tokens متتالية |
| Sampling | اختيار Tokens عشوائيًا وفق Probability Distribution معدّلة |
| Temperature | Parameter تتحكم في مدى حدّة أوتسطح Sampling Distribution |
| Top-k | Sampling فقط من أعلى k Tokens احتمالًا |
| Top-p / Nucleus | Sampling من أصغر High-probability Set يصل مجموع احتمالها إلى p |
| EOS | End-of-sequence Token المستخدمة للإشارة إلى اكتمال Generation |

## احتفظ بهذه الفكرة

**يوفّر Causal Language Model احتمالات الـ Next Token، بينما تحدد Decoding Strategy كيف تتحول هذه الاحتمالات إلى نص. ولذلك فإن Greedy Search وBeam Search وTemperature وTop-k وTop-p ليست Models مختلفة، بل طرق مختلفة للتنقل داخل Distribution الخاصة بالـ Model، مع Trade-offs مختلفة بين Stability وCompute وRepetition وDiversity.**
