# موازن الحمل الشبكي في AWS ومجموعات الأهداف

> **المقرر:** أسس الـ Deployment الآمن على AWS  
> **الدرس:** M08.L03  
> **مواءمة المصدر:** BOOK-XXX، الفصل 3. يتبع هذا الدرس تصميم Network Load Balancer ومنافذه في المصدر بالضبط بوصفه معمارية تعليمية.

---

## مخرجات التعلّم

بنهاية هذا الدرس يجب أن تكون قادرًا على:

- شرح موازن الحمل (load balancer) بوصفه البوابة العامة في معمارية المصدر.
- شرح أدوار الـ listeners ومجموعات الأهداف (target groups).
- شرح لماذا يستخدم تسجيل الهدف عنوان IP الخاص بنسخة EC2.
- ضبط ربط الـ TCP listener بمجموعة الأهداف في المصدر للمنافذ 8501 و8502 و8504 و22.
- شرح أهمية استخدام الـ VPC نفسه ووضع شبكي متوافق.
- وصف إعادة تنظيم الـ security groups في المصدر.
- شرح مسار الحركة من العميل إلى NLB ثم إلى مجموعة الأهداف ثم إلى تطبيق EC2.
- التحقق من تطبيق Streamlit عبر نقطة DNS الخاصة بموازن الحمل.

## 1. لماذا نضع موازن حمل أمام النسخة؟

في الدرس السابق، كان المتصفح يصل إلى:

```text
Elastic IP لنسخة EC2:8501
```

مباشرةً.

ويقدّم الفصل 3 طبقة أخرى:

```text
الإنترنت (Internet)
   ↓
موازن الحمل (Load Balancer)
   ↓
مجموعة الأهداف (Target Group)
   ↓
عنوان IP الخاص بـ EC2
   ↓
التطبيق (Application)
```

يصف المصدر موازن الحمل بأنه بوابة:

- تستقبل الطلبات العامة،
- وتوجّهها إلى مجموعات الأهداف،
- وتوفّر طبقة تحكم إضافية أمام الخادم،
- وتساعد على توزيع الطلبات الواردة.

### التغيير المعماري

قبل:

```text
العميل → عنوان IP العام لـ EC2
```

بعد:

```text
العميل → load balancer → EC2
```

وهذا يفصل نقطة الاتصال التي يراها العميل عن خادم التطبيق نفسه.

[[IMAGE_NEEDED: Network Load Balancer fronting EC2 | A diagram showing a trusted external client reaching an internet-facing AWS Network Load Balancer, which forwards through TCP target groups to the EC2 instance's private IP | Learner should notice that the load balancer becomes the public gateway while EC2 is reached as a backend target]]

## 2. أنشئ Network Load Balancer

يختار المصدر:

```text
Network Load Balancer (موازن الحمل الشبكي)
```

مع:

```text
Scheme (النمط): internet-facing
IP address type (نوع العنوان): IPv4
```

ويؤكد أيضًا اختيار الـ VPC نفسه المستخدم لنسخة EC2.

### مواءمة الـ VPC

يحتاج الهدف وموازن الحمل إلى شبكات متوافقة.

ويوجّه المصدر المتعلّم مرارًا إلى التحقق من:

- الـ VPC،
- سياق منطقة التوافر/الشبكة الفرعية (availability zone/subnet)،
- عنوان IPv4 الخاص بنسخة EC2.

### أول listener

أول listener للتطبيق في المصدر هو:

```text
Protocol (البروتوكول): TCP
Port (المنفذ): 8501
```

وهذا يطابق تطبيق Streamlit.

والإجراء الافتراضي للـ listener هو التوجيه إلى:

```text
target group (مجموعة الأهداف) tg-8501
```

## 3. مجموعات الأهداف تربط الـ listeners بالخدمات الخلفية

تحدّد مجموعة الأهداف (target group) الوجهة التي يجب أن يوجّه إليها موازن الحمل الحركة.

وينشئ المصدر:

```text
Target type (نوع الهدف): IP addresses
Protocol (البروتوكول): TCP
Port (المنفذ): 8501
```

ويسجّل:

```text
EC2 private IP (عنوان IP الخاص بـ EC2)
```

### لماذا عنوان IP الخاص؟

مسار الطلب داخل الـ VPC هو:

```text
NLB
 ↓
مجموعة الأهداف (target group)
 ↓
عنوان IP الخاص بـ EC2
```

ينقل المصدر عن قصد التوجيه إلى الـ backend بعيدًا عن الاستخدام المباشر للعنوان العام للنسخة.

### فحوصات الصحة (Health checks)

تستخدم أول مجموعة أهداف الإعداد الافتراضي:

```text
TCP health check (فحص صحة عبر TCP)
```

يستخدم موازن الحمل معلومات الصحة ليحدد هل ينبغي أن يتلقى الهدف حركة.

### الـ listener مقابل مجموعة الأهداف

فكّر هكذا:

```text
Listener
= أي منفذ بوابة يستقبل الحركة؟

Target group
= أي هدف (أو أهداف) في الـ backend ينبغي أن يستقبل تلك الحركة؟
```

## 4. أضف مجموعات أهداف لعدة خدمات

يوسّع المصدر المعمارية لتتجاوز Streamlit.

ومجموعة المنافذ النهائية فيه هي:

| الخدمة | منفذ TCP | اسم مجموعة الأهداف المثالي |
|---|---:|---|
| SSH | 22 | `tg-ssh-22` |
| Streamlit | 8501 | `tg-8501` |
| Flask API | 8502 | `tg-flask-8502` |
| Jenkins | 8504 | `tg-jenkins-8504` |

تسجّل كل مجموعة أهداف عنوان IP الخاص بنسخة EC2.

ثم يوجّه كل listener في موازن الحمل إلى المجموعة المقابلة له.

### النموذج الذهني

```text
NLB    # موازن الحمل الشبكي
├── TCP 22   → tg-ssh-22     → EC2 private IP:22
├── TCP 8501 → tg-8501       → EC2 private IP:8501
├── TCP 8502 → tg-flask-8502 → EC2 private IP:8502
└── TCP 8504 → tg-jenkins    → EC2 private IP:8504
```

هذا توجيه قائم على المنفذ على مستوى TCP listener في معمارية المصدر.

[[IMAGE_NEEDED: Multi-port NLB target-group map | A central Network Load Balancer with four TCP listeners—22, 8501, 8502, 8504—each pointing to a correspondingly named target group that registers the same EC2 private IP on the matching port | Learner should notice that one EC2 host can expose multiple backend services through separate listener/target-group pairs]]

## 5. أعد تنظيم الـ security groups حول موازن الحمل

ثم يغيّر المصدر قواعد الوصول الشبكي.

نموذج الأمان المطلوب فيه هو:

```text
عنوان IP/VPN خارجي موثوق
        ↓
security group الخاص بالـ load balancer
        ↓
load balancer
        ↓
security group الخاص بـ EC2 يسمح بحركة المرور القادمة من load balancer
        ↓
خدمات EC2
```

### الـ security group الخاص بموازن الحمل

يعرض المصدر قواعد واردة للمنافذ:

```text
22
8501
8502
8504
```

مقيّدة بعنوان عام موثوق بصيغة `/32`.

### الـ security group الخاص بـ EC2

ثم يعرض مخطط المصدر نسخة EC2 وهي تسمح بمنافذ التطبيقات من جهة موازن الحمل بدلًا من السماح بها على نطاق واسع من العميل العام.

ويوضّح المصدر تحديدًا عنوان موازن الحمل الخاص مصدرًا لقواعد EC2 الواردة.

هذه هي المعمارية التي يعلّمها المصدر.

### هدف الأمان

القصد من التصميم:

> يتعامل المستخدمون الخارجيون مع طبقة موازن الحمل، بينما لم تعد نسخة EC2 نقطة التطبيق الرئيسية المواجهة للعامة.

## 6. تحقق من Streamlit عبر موازن الحمل

ما زالت عملية Streamlit تعمل على نسخة EC2:

⟦CODE_0⟧

لكن المتصفح الآن يستخدم اسم DNS الخاص بموازن الحمل:

```text
LOAD_BALANCER_DNS:8501
```

بدلًا من:

```text
EC2_ELASTIC_IP:8501
```

### مسار الحركة

```text
المتصفح (Browser)
   ↓
NLB DNS :8501
   ↓
TCP listener على المنفذ 8501
   ↓
tg-8501
   ↓
عنوان IP الخاص بـ EC2 :8501
   ↓
Streamlit
```

إذا تم تحميل الصفحة، فقد تحققت من:

- إنشاء الـ NLB،
- إعداد الـ listener،
- تسجيل الهدف،
- الصحة (health)،
- توجيه الـ VPC،
- الـ security groups،
- عملية Streamlit.

## مفاهيم خاطئة شائعة

### المفهوم الخاطئ 1
> "الـ listener ومجموعة الأهداف هما الكائن نفسه."

يستقبل الـ listener الحركة، بينما تحدّد مجموعة الأهداف وجهات الـ backend.

### المفهوم الخاطئ 2
> "تسجّل مجموعة الأهداف عنوان IP العام للمتصفح."

يسجّل المصدر عنوان IP الخاص بنسخة EC2.

### المفهوم الخاطئ 3
> "كل خدمة تحتاج إلى نسخة EC2 منفصلة."

يوجّه المصدر عدة منافذ إلى عنوان IP الخاص نفسه لنسخة EC2 واحدة.

### المفهوم الخاطئ 4
> "إضافة موازن حمل تعني أننا لم نعد بحاجة إلى security groups."

يستخدم المصدر الـ security groups على طبقتي موازن الحمل وEC2 معًا.

## المصطلحات الأساسية

| المصطلح | المعنى |
|---|---|
| موازن الحمل الشبكي (Network Load Balancer) | موازن حمل في AWS يستخدمه المصدر لحركة TCP |
| Listener | بروتوكول/منفذ في الواجهة يستقبل حركة موازن الحمل |
| مجموعة الأهداف (Target group) | مجموعة وجهات خلفية لأحد الـ listeners |
| الهدف (Target) | وجهة خلفية مسجّلة، مثل عنوان IP الخاص بـ EC2 مع المنفذ |
| فحص الصحة (Health check) | اختبار يُستخدم لتحديد توفّر الهدف |
| VPC | شبكة AWS خاصة تحتوي الموارد |
| Internet-facing | نمط لموازن الحمل يمكن الوصول إليه من الشبكات الخارجية |
| اسم DNS (DNS name) | اسم المضيف الذي تعيّنه AWS لموازن الحمل |
