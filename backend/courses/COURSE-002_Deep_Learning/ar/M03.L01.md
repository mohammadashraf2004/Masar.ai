## 1. مشهد الـ frameworks الحديثة لـ Deep Learning

عمليًا، لا ينفّذ مهندسو Deep Learning تقريبًا كل عملية tensor وكل قاعدة تدرّج وكل خاصية لإدارة الأجهزة من الصفر. بل يستخدمون الـ frameworks.

يعرّف الفصل بأربع أدوات رئيسية:

```text
TensorFlow  (منظومة إنتاج)
PyTorch     (تنفيذ فوري)
JAX         (دوال بلا حالة)
Keras       (واجهة عالية المستوى)
```

وهي مترابطة، لكنها لا تؤدي كلها الدور نفسه.

ونموذج ذهني مفيد هو:

```text
واجهة API لبناء الـ model عالية المستوى
          Keras
            │
            ▼
الواجهات الخلفية العددية / الاشتقاق التلقائي منخفضة المستوى
 ┌────────────┬────────────┬────────────┐
 │ TensorFlow │  PyTorch   │    JAX     │
 └────────────┴────────────┴────────────┘
            │
            ▼
       CPU / GPU / TPU
```

توفّر TensorFlow وPyTorch وJAX الآليات العددية منخفضة المستوى اللازمة لـ Deep Learning. أما Keras فيوفّر واجهة أعلى مستوى لتعريف الشبكات العصبية وتدريبها.

### نظرة تاريخية موجزة

يعرض الفصل الـ frameworks الحديثة على أنها نتاج عدة تطورات التقت معًا:

- أصبح Python العلمي واسع الاستخدام،
- صارت وحدات GPU متاحة للحوسبة العامة الغرض،
- أصبح الاشتقاق التلقائي عمليًا،
- صار التدريب الموزَّع (distributed training) مهمًا،
- جمعت الـ frameworks هذه القدرات في أدوات قابلة لإعادة الاستخدام.

وقد ساعدت أنظمة أقدم مثل Theano وTorch 7 وCaffe على ترسيخ أفكار ظهرت لاحقًا في الـ frameworks الحديثة.

لا تحتاج إلى حفظ التاريخ كاملًا. والدرس الهندسي المهم أن الـ frameworks الحالية موجودة لحل مشكلات البنية التحتية المتكررة التي لا ينبغي لمطوري Deep Learning أن يعيدوا تنفيذها في كل مشروع.

### ثلاث قدرات تفتح الباب أمام Deep Learning الحديث

يبرز الفصل ثلاث قدرات تشترك فيها frameworks الـ Deep Learning الحديثة:

1. **الاشتقاق التلقائي (Automatic differentiation)** — حساب تدرّجات الحسابات القابلة للاشتقاق.
2. **الحوسبة المتسارعة للـ tensors (Accelerated tensor computation)** — تشغيل العمليات العددية على CPU وGPU والعتاد المتخصص.
3. **الحوسبة الموزَّعة (Distributed computation)** — توسيع العمل عبر عدة أجهزة أو آلات.

وترتبط هذه القدرات مباشرةً بحلقة التدريب التي تعلّمتها سابقًا:

```text
الحساب الأمامي (forward computation)
       ↓
الخسارة (loss)
       ↓
التدرّجات (gradients)
       ↓
تحديث المعاملات (parameter update)
```

وتختلف الـ frameworks أساسًا في **كيفية عرض هذه الأفكار للمبرمج**.

## 2. المفاهيم الأساسية المشتركة عبر الـ frameworks

مع أن الـ API تبدو مختلفة، فإن المفاهيم نفسها تتكرر مرارًا.

### الـ Tensors

الـ tensor هو بنية البيانات العددية المحورية.

ويمكنك أن تعدّ الـ tensors مصفوفات معمَّمة:

```text
قيمة مفردة (scalar)    -> الرتبة 0
vector                 -> الرتبة 1
مصفوفة (matrix)        -> الرتبة 2
دفعة صور (image batch) -> غالبًا الرتبة 4
```

وتحوّل models الـ Deep Learning الـ tensors إلى tensors أخرى.

### الحالة القابلة للتدريب (Trainable state)

يحتوي الـ model على قيم تتغير أثناء التدريب، مثل الأوزان والانحيازات.

ولكل framework طريقته الخاصة في تمثيل هذه الحالة القابلة للتدريب:

| Framework | الحالة القابلة للتدريب النموذجية |
|---|---|
| TensorFlow | `tf.Variable` |
| PyTorch | `torch.nn.Parameter` أو tensors مفعَّلة لها التدرّجات |
| JAX | arrays عادية تُمرَّر صراحةً بوصفها حالة |
| Keras | أوزان تملكها كائنات `Layer` |

والفرق ليس مجرد تسمية. فهو يعكس فلسفة البرمجة في كل framework.

### عمليات الـ Tensors

تظهر العمليات الرياضية نفسها في كل مكان:

```text
الجمع (addition)
الضرب (multiplication)
ضرب المصفوفات (matrix multiplication)
التربيع / الجذر التربيعي
الدمج (concatenation)
دوال التنشيط (activation functions)
عمليات الاختزال مثل المتوسط (mean)
```

ويمكن التعبير مفاهيميًا عن التحويل الكثيف (dense) هكذا:

```text
المخرَج (output) = activation(inputs @ W + b)
```

حيث:

- `inputs` هو tensor المُدخَل،
- `W` مصفوفة أوزان،
- `b` vector انحياز،
- `@` يمثّل ضرب المصفوفات.

### الاشتقاق التلقائي (Automatic differentiation)

يتطلب التدريب تدرّجات.

وتعرض الـ frameworks حساب التدرّج بطرق مختلفة:

| Framework | أسلوب التدرّج |
|---|---|
| TensorFlow | سجّل العمليات باستخدام `GradientTape` |
| PyTorch | ابنِ computation graph ضمنيًا واستدعِ `.backward()` |
| JAX | حوّل دالة باستخدام `jax.grad()` أو `jax.value_and_grad()` |

والهدف الرياضي واحد:

> احسب كيف تتغير الخسارة بالنسبة إلى المعاملات القابلة للتدريب.

### التجميع (Compilation)

Python مريح، لكن التنفيذ على مستوى Python قد يصبح عنق زجاجة في الأداء.

ولكل framework طريقة لنقل الحسابات المهمة إلى شكل مجمَّع:

```text
TensorFlow -> tf.function / XLA
PyTorch    -> torch.compile()
JAX        -> jax.jit
```

يمكن للتجميع أن يحسّن الأداء، لكنه قد يجعل التنقيح (debugging) أصعب لأن البرنامج المنفَّذ لم يعد مجرد تفسير لـ Python سطرًا بسطر.

### مفاهيم التدريب عالية المستوى

على مستوى أعلى، ما يزال تدريب الشبكات العصبية يحتاج إلى:

```text
الـ model
الخسارة (loss)
المُحسِّن (optimizer)
المقاييس (metrics)
حلقة التدريب (training loop)
التحقق (validation)
inference
```

## 6. Keras: من الطبقات إلى التدريب وinference

يقع Keras عند مستوى أعلى من التجريد.

فبدلًا من التركيز أولًا على آليات الـ tensors منخفضة المستوى، يركّز Keras على الكائنات ومسارات العمل المستخدمة لبناء الشبكات العصبية.

### الواجهات الخلفية لـ Keras (Backends)

يستطيع Keras استخدام:

```text
TensorFlow
PyTorch
JAX
```

بوصفها محرّكات خلفية (backend engines).

وهذا يعني أن كود Keras يمكنه وصف الـ model بينما يتولى الـ backend عمليات الـ tensors منخفضة المستوى وحساب التدرّجات والتنفيذ على العتاد.

وتشبيه مفيد:

```text
Keras        -> نظام البناء / الواجهة عالية المستوى
Backend      -> المحرّك العددي والآليات منخفضة المستوى
العتاد       -> CPU / GPU / TPU
```

ويجب ضبط الـ backend قبل استيراد Keras إذا أردت تجاوز إعداد البيئة الافتراضي.

### الطبقات هي اللبنات الرئيسية

تجمع `Layer` في Keras بين:

```text
الحالة (state) + الحساب (computation)
```

وتعني الحالة عادةً الأوزان القابلة للتدريب.

والحساب هو التمرير الأمامي (forward pass).

وتستخدم أنواع البيانات المختلفة عائلات طبقات مختلفة بصورة طبيعية:

```text
بيانات vector/الجدولية         -> Dense
بيانات التسلسلات                -> طبقات recurrent أو طبقات 1D convolution
بيانات الصور                    -> طبقات 2D convolution
```

ونموذج ذهني مفيد أن تعامل الطبقات كلبنات متوافقة تحوّل الـ tensors.

### build() وcall()

تفصل الطبقة المخصصة عادةً بين:

- `build()` — إنشاء الحالة بعد معرفة شكل المُدخَل،
- `call()` — تعريف الحساب الأمامي.

مثال:

⟦CODE_33⟧

وفكرة التصميم المفيدة هي **البناء الكسول (lazy building)**.

يمكن للطبقة أن تنتظر حتى ترى أول مُدخَل قبل إنشاء الأوزان بالبعد الصحيح للمُدخَل.

وهذا يعني أن Keras كثيرًا ما يستنتج الأشكال تلقائيًا.

### من الطبقات إلى الـ Models

الـ model رسم بياني (graph) من الطبقات.

وأبسط صورة هي حزمة متسلسلة (sequential stack):

ويحدد معمار الـ model **فضاء الفرضيات (hypothesis space)**.

ولذلك فاختيار المعمار يشفّر افتراضات عن أنواع العلاقات التي يستطيع الـ model تعلّمها.

### compile(): ضبط التعلّم

بعد اختيار المعمار، ما يزال التدريب يحتاج إلى ثلاثة خيارات رئيسية:

```text
الخسارة (loss)
المُحسِّن (optimizer)
المقاييس (metrics)
```

مثال:

⟦CODE_35⟧

#### الخسارة (Loss)

الخسارة هي الكمية التي يحاول التدريب تقليلها.

ويشدد الفصل على أن اختيار الخسارة الصحيحة مهم، لأن الـ model سيحسّن الهدف الذي تعرّفه أنت، لا النية التي نسيت ترميزها.

وتشمل الأمثلة المعتادة:

```text
التصنيف الثنائي (binary classification)      -> BinaryCrossentropy
التصنيف متعدد الفئات (multiclass)            -> CategoricalCrossentropy
الانحدار (regression)                        -> MeanSquaredError
```

ويعتمد الاختيار الصحيح بدقة على المهمة وعلى تمثيل الأهداف.

#### المُحسِّن (Optimizer)

يتحكم المُحسِّن في كيفية إجراء تحديثات المعاملات.

وتشمل الأمثلة الشائعة:

```text
SGD      (انحدار تدرّجي عشوائي)
RMSprop  (مُحسِّن تكيّفي)
Adam     (مُحسِّن تكيّفي)
```

#### المقاييس (Metrics)

المقاييس قيم تريد مراقبتها، مثل:

```text
الدقة (accuracy)
precision
recall
AUC
```

ولا يحسّن المُحسِّن المقاييس مباشرةً بالضرورة.

وهذا التمييز مهم:

```text
الخسارة (loss)    -> تقود تحديثات المعاملات
المقاييس (metrics) -> تساعد البشر على مراقبة الأداء
```

### fit(): تشغيل حلقة التدريب

عدد أمثلة التدريب المستخدمة لحساب تحديث واحد للمعاملات.

فإذا كان هناك 10,000 عيّنة تدريب وحجم الدفعة 100، فتُعالَج نحو 100 دفعة في كل epoch.

وتُرجع `fit()` سجلًّا (history) لقيم الخسارة والمقاييس، مما يتيح لك فحص كيف تغيّر التدريب عبر الـ epochs.

### بيانات التحقق (Validation data)

فالهدف هو الأداء الجيد على أمثلة جديدة.

ولهذا يُحتجَز عادةً جزء من البيانات المتاحة بوصفه **بيانات تحقق (validation data)**.

بيانات التحقق:

## المصطلحات الرئيسية

| المصطلح | المعنى |
|---|---|
| Tensor | مصفوفة عددية متعددة الأبعاد تُستخدم بنية بيانات أساسية في Deep Learning |
| Automatic differentiation | الحساب التلقائي للتدرّجات عبر العمليات القابلة للاشتقاق |
| Trainable state | قيم الـ model، مثل الأوزان، التي تتغير أثناء التدريب |
| `tf.Variable` | كائن TensorFlow لحالة الـ model القابلة للتعديل |
| `torch.nn.Parameter` | نوع tensor في PyTorch يُستخدم لوسم حالة الـ model القابلة للتدريب |
| Stateless function | دالة تعتمد نتيجتها على المُدخَلات الصريحة فقط ولا تخفي حالة قابلة للتغيير |
| `GradientTape` | آلية TensorFlow لتسجيل العمليات وحساب التدرّجات |
| `.backward()` | عملية PyTorch تشغّل الانتشار العكسي عبر الحساب المسجَّل |
| `jax.grad()` | تحويل JAX الذي ينشئ دالة تحسب التدرّج |
| JIT compilation | تجميع دالة قبل تنفيذها مباشرةً لتحسين الأداء |
| Layer | تحويل tensor قابل لإعادة الاستخدام قد يملك أوزانًا قابلة للتدريب |
| Model | رسم بياني أو تركيب من الطبقات |
| Loss | هدف التدريب الذي يقلّله المُحسِّن |
| Optimizer | القاعدة التي تحدّث المعاملات باستخدام التدرّجات |
| Metric | قياس مراقَب للأداء |
| Epoch | مرور كامل واحد على dataset التدريب |
| Batch | مجموعة جزئية من الأمثلة تُستخدم لتحديث تدريب واحد |
| Validation data | بيانات محتجَزة تُستخدم لمراقبة الأداء دون تحديث الأوزان |
| Inference | استخدام model مدرَّب لتوليد تنبؤات على مُدخَلات جديدة |
| Backend | الـ framework منخفض المستوى الذي يستخدمه Keras للحساب العددي والاشتقاق |

## مقارنة الـ frameworks

| المفهوم | TensorFlow | PyTorch | JAX | Keras |
|---|---|---|---|---|
| الدور الرئيسي | framework/منصة ML منخفضة المستوى | framework لـ ML منخفض المستوى مع بعض المستوى العالي | مكتبة حوسبة عددية قابلة للاشتقاق | واجهة Deep Learning عالية المستوى |
| المصفوفة الأساسية | `tf.Tensor` | `torch.Tensor` | JAX array | tensor الـ backend عبر `keras.ops` |
| الحالة القابلة للتدريب | `tf.Variable` | `Parameter` / tensor مفعَّل له التدرّج | arrays صريحة في الحالة | أوزان الطبقات |
| التدرّجات | `GradientTape` | `.backward()` | `grad()` / `value_and_grad()` | يتولاها `fit()` عادةً |
| أسلوب الحالة المعتاد | متغيّرات قابلة للتغيير | معاملات module قابلة للتغيير | حالة صريحة ووظيفية | مغلَّفة في الطبقات والـ models |
| التجميع | `tf.function` وXLA | `torch.compile()` | `jax.jit` | يعتمد على الـ backend |
| واجهة الـ model عالية المستوى | متوفرة | متوفرة | مكتبات خارجية عادةً | هي الغرض المحوري |
| نقطة القوة الشائعة | منظومة الإنتاج | مسار العمل الفوري ومنظومة الـ models | السرعة وأسلوب NumPy والتوسّع | الإنتاجية وقابلية نقل الـ backend |
