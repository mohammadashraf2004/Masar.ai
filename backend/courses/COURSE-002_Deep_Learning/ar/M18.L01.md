## 1. الحصول على أداء أفضل من الـ models

حين تعرف كيف تدرّب model يعمل، يكون السؤال التالي:

> كيف تجعله أفضل بصورة منهجية؟

وهندسة تعلّم الآلة الحقيقية تنطوي على أكثر بكثير من كتابة معمار واحد وتدريبه مرة واحدة.

فأنت تتخذ مرارًا خيارات مثل:

```text
كم طبقة؟
كم وحدة؟
أي مُحسِّن؟
ما معدّل التعلّم؟
كم dropout؟
هل ينبغي استخدام BatchNormalization؟
أي عائلة معمار؟
```

وهذه الخيارات هي **hyperparameters**.

### المعاملات مقابل الـ hyperparameters

**المعامل (parameter)** يتعلّمه الانحدار التدرّجي.

أمثلة:

```text
أوزان طبقة Dense
نوى الالتفاف
vectors الانحياز
vectors الـ embedding
```

أما الـ **hyperparameter** فيُختار خارج عملية الانتشار العكسي العادية.

أمثلة:

```text
عدد الوحدات
عدد الطبقات
اختيار المُحسِّن
معدّل dropout
معدّل التعلّم
```

فكّر فيها هكذا:

```text
BACKPROPAGATION (الانتشار العكسي)
→ يتعلّم الأوزان

HYPERPARAMETER SEARCH (بحث الـ hyperparameters)
→ يختار كيف ينبغي ضبط الـ model نفسه
```

### لماذا لا يستطيع الانحدار التدرّجي تحسين كل شيء؟

كثير من خيارات الـ hyperparameters منفصلة (discrete).

مثلًا:

```text
optimizer = Adam OR RMSprop   # اختيار المُحسِّن

units = 32 OR 64 OR 128   # عدد الوحدات

use BatchNorm = True OR False   # استخدام BatchNorm
```

ولا تشكّل هذه الخيارات فضاءً ناعمًا قابلًا للاشتقاق بالطريقة نفسها التي تشكّلها أوزان الشبكة العصبية.

ولذلك تعتمد عادةً عملية تحسين الـ hyperparameters على استراتيجيات بحث بلا تدرّجات مثل:

```text
البحث العشوائي (random search)
التحسين البايزي (Bayesian optimization)
الخوارزميات الجينية (genetic algorithms)
```

### حلقة ضبط الـ hyperparameters

العملية هي:

```text
اختر إعدادًا
       ↓
ابنِ الـ model
       ↓
درّب الـ model
       ↓
قيّم على بيانات التحقق
       ↓
استخدم النتيجة لاختيار الإعداد التالي
       ↓
كرّر
```

ولا ينبغي استخدام مجموعة الاختبار التي لم تُمَس للـ evaluation النهائي إلا بعد البحث واختيار الـ model النهائي.

### لماذا الضبط مكلف

حين يحدّث التدريب العادي أوزان الـ model، يحتاج كل تحديث فقط إلى تمرير أمامي وخلفي على دفعة صغيرة.

أما تحسين الـ hyperparameters فأكثر كلفة بكثير لأن تقييمًا واحدًا قد يتطلب تدريب model جديد بالكامل.

```text
تجربة hyperparameter واحدة
=
ابنِ الـ model
+
درّب من الصفر
+
قيّم
```

وإذا اختبرت 100 إعداد، فقد يعني ذلك 100 جولة تدريب كبيرة.

### Overfitting على مجموعة التحقق (Validation-set overfitting)

هناك خطر خفي.

لنفترض أنك نفّذت:

```text

100 تجربة
1,000 تجربة
10,000 تجربة
```

وكل قرار مبني على مجموعة التحقق نفسها.

فمع الوقت يبدأ بحث الـ hyperparameters في التكيّف مع نزوات عشوائية في مجموعة التحقق تلك.

وهذا هو **overfitting على مجموعة التحقق (validation-set overfitting)**.

```text

مجموعة التحقق
→ اختر المعمار + hyperparameters

مجموعة الاختبار
→ evaluation نهائي مستقل
```

## 2. توسيع التدريب عبر عدة أجهزة

تعتمد جودة الـ model اعتمادًا كبيرًا على التجريب.

وحلقة هندسية مفيدة هي:

```text
فكرة
 ↓
تجربة
 ↓
نتائج
 ↓
تحليل
 ↓
فكرة أفضل
 ↓
كرّر
```

وإذا استغرق تدريب تجربة واحدة يومين، فالتكرار بطيء.

وإذا استغرق خمس عشرة دقيقة، فيمكن اختبار أفكار أكثر بكثير.

ولذلك يسهم التدريب الأسرع بصورة غير مباشرة في models أفضل.

### شكلان من التوازي

هناك طريقتان رئيسيتان لتوزيع حسابات Deep Learning:

```text
DATA PARALLELISM (توازي البيانات)
→ قسّم البيانات

MODEL PARALLELISM (توازي الـ model)
→ قسّم الـ model
```

### توازي البيانات (Data parallelism)

مع توازي البيانات، يخزّن كل جهاز نسخة كاملة من الـ model.

وتُقسَّم الدفعة بين الأجهزة.

لنفترض أن:

```text
حجم الدفعة العام = 128
عدد GPUs         = 2
```

عندئذٍ:

```text
GPU 0
→ نسخة model (replica)
→ 64 عيّنة

GPU 1
→ نسخة model (replica)
→ 64 عيّنة
```

وتحسب كل نسخة التدرّجات من دفعتها الفرعية المحلية.

ثم تُدمج التدرّجات — عادةً بأخذ المتوسط — وتتلقى كل نسخ الـ model التحديث نفسه.

مفاهيميًا:

```text
الدفعة
 ├── GPU 0 → التدرّجات ──┐
 └── GPU 1 → التدرّجات ──┤
                          ↓
                    متوسط التدرّجات
                          ↓
                    حدّث كل النسخ
```

وهذا يُبقي أوزان الـ model متزامنة.

### قيد توازي البيانات

يجب أن يحتوي كل جهاز نسخة كاملة من الـ model.

ولذلك:

```text
يجب أن يتسع الـ model على GPU واحد
```

وإذا كان الـ model نفسه أكبر من memory جهاز واحد، فلا يكفي توازي البيانات وحده.

### توازي الـ model (Model parallelism)

مع توازي الـ model، يُقسَّم model واحد عبر عدة أجهزة.

```text
GPU 0 → جزء من الـ model
GPU 1 → جزء من الـ model
GPU 2 → جزء من الـ model
GPU 3 → جزء من الـ model
```

وهذا يتيح تدريب models لا تتسع على مسرِّع واحد.

### التقسيم الأفقي للـ model

يضع أحد النهج طبقات مختلفة على أجهزة مختلفة.

مثلًا:

```text
GPU 0
→ الطبقة 1

GPU 1
→ الطبقة 2
```

والعيب هو كلفة الاتصال.

فيجب أن ينتقل مخرَج GPU 0 إلى GPU 1 قبل أن يستمر الحساب.

وإذا كانت tensors الوسيطة كبيرة، فقد يصبح اتصال الأجهزة عنق زجاجة.

### التقسيم الرأسي

نهج آخر يقسّم معاملات الطبقة الفردية عبر الأجهزة.

لنفترض أن لنواة Dense الشكل:

```text
(16000, 64000)
```

ومع GPUين، يمكن تقسيمها إلى:

```text
GPU 0 → (16000, 32000)
GPU 1 → (16000, 32000)
```

ويحسب كل GPU جزءًا من المخرَج، ثم تُدمج الأجزاء.

ويُسمّى هذا غالبًا **sharding** أو التقسيم (partitioning).

### الجمع بين توازي البيانات وتوازي الـ model

قد تستخدم أنظمة التدريب الكبيرة كليهما.

مثلًا، مع ثمانية GPUs:

```text
4 GPUs
→ نسخة model مجزَّأة واحدة

4 GPUs أخرى
→ نسخة model مجزَّأة ثانية
```

والآن لديك:

```text
توازي model داخل كل مجموعة
+
توازي بيانات بين المجموعات
```

## 3. تدريب TPU وإبقاء المسرِّعات مشغولة

ليست GPUs العتاد الوحيد المستخدم في Deep Learning.

و**وحدة معالجة tensors (Tensor Processing Unit)**، أو TPU، عتاد متخصص مصمَّم لحسابات tensors الخاصة بتعلّم الآلة.

والمبدأ العام هو نفسه:

> العتاد المتخصص مفيد فقط حين تغذّيه بعمل كافٍ.

### توزيع TPU

يشرح الفصل أن واجهات توزيع Keras (APIs) يمكن استخدامها أيضًا مع أجهزة TPU.

وكما في توزيع GPU، ينبغي ضبط إعداد التوزيع قبل إنشاء الـ model.

### قد يصبح تحميل البيانات عنق الزجاجة

لنفترض أن TPU يستطيع استهلاك الدفعات بسرعة هائلة.

فإذا كان تخزينك يسلّم البيانات ببطء، فقد يبقى TPU خاملًا.

```text
تخزين بطيء
      ↓
انتظار
      ↓
مسرِّع مستغَل بأقل من طاقته
```

وفي الـ datasets الصغيرة بما يكفي، قد يساعد caching:

⟦CODE_14⟧

### حجم الدفعة واستغلال المسرِّع

تحتاج المسرِّعات الكبيرة عمومًا إلى أحجام دفعات كافية لبلوغ استغلال عالٍ.

وقد لا توفّر دفعة صغيرة جدًا عمليات مصفوفات كافية لإشغال كل وحدات الحوسبة المتاحة.

### الدفعات الكبيرة ومعدّل التعلّم

إذا نما حجم الدفعة نموًا كبيرًا، يجري الـ model تحديثات معاملات أقل لكل epoch.

لكن كل تحديث يستند إلى أمثلة أكثر وقد يوفّر لذلك تقدير تدرّج أكثر استقرارًا.

ويلاحظ المصدر أن الدفعات الأكبر تستدعي غالبًا معدّل تعلّم أكبر.

مفاهيميًا:

```text
دفعة أكبر
→ تحديثات أقل
→ كل تدرّج يستخدم عيّنات أكثر
→ خطوة تحديث مفيدة أكبر محتملًا
```

وهذا قرار ضبط لا صيغة ثابتة عالمية.

### دمج الخطوات (Step fusing)

نهج آخر هو تنفيذ عدة خطوات تدريب داخل دورة تنفيذ واحدة للمسرِّع.


## 4. الدقة المختلطة وQuantization

طريقة كبرى أخرى لتسريع Deep Learning هي جعل العمليات العددية الفردية أرخص.

وهذا يقودنا إلى الدقة العددية.

### ما الدقة العددية؟

تمثّل الحواسيب الأعداد بعدد محدود من البتات.

وتشمل أنواع الفاصلة العائمة الشائعة:

```text
float16 → 16 بت
float32 → 32 بت
float64 → 64 بت
```

وتوفّر البتات الأكثر دقة عددية أدق لكنها تتطلب memory وحوسبة أكثر.

فكّر في الدقة العددية كدقة الصورة:

```text
بتات أكثر
→ تفاصيل أدق
→ كلفة أكبر

بتات أقل
→ تفاصيل أقل
→ كلفة أقل
```

### لماذا قد تكون الدقة المنخفضة أسرع

تحتوي GPUs وTPUs الحديثة عتادًا محسَّنًا لعمليات المصفوفات منخفضة الدقة.

وقد تشمل الفوائد:

```text
استخدام أقل لـ memory
throughput أعلى
ضرب مصفوفات أسرع
أحجام دفعات ممكنة أكبر
```

### inference بـ float16

في inference، غالبًا ما تكون الدقة المنخفضة مباشرة.

ويعرض المصدر:

⟦CODE_16⟧

وينبغي ضبط هذا قبل إنشاء الـ model.

ويلاحظ الفصل أن عتاد GPU أو TPU المناسب قد يقترب من تسريع inference بنحو 2×.

### bfloat16

يستخدم `bfloat16` أيضًا 16 بتًا لكنه يوزّع تلك البتات توزيعًا مختلفًا.

بالمقارنة مع float16:

```text
float16
→ دقة mantissa أكبر
→ نطاق أس (exponent) أصغر

bfloat16
→ دقة mantissa أقل
→ نطاق أس (exponent) أكبر
```

وبعض العتاد محسَّن أكثر لـ bfloat16.

### لماذا لا ندرّب كل شيء مباشرةً بـ float16؟

يُدخل التدريب مشكلة لا توجد في inference:

```text
قد تصبح التدرّجات صغيرة للغاية
```

مثلًا:

```text
1e-5
1e-6
```

وقد لا تمثّل الدقة المنخفضة هذه التحديثات بدقة كافية.

وقد يُقرَّب تدرّج ضئيل حتى إلى الصفر.

وحينئذٍ يتوقف التعلّم لذلك المعامل.

### تدريب الدقة المختلطة (Mixed-precision training)

الحل هو استخدام دقات مختلفة لأجزاء مختلفة من التدريب.

والفكرة الأساسية:

```text
الحساب الأمامي
→ float16 في الغالب

متغيّرات الـ model
→ float32

التحديثات الحساسة
→ float32
```

ويهدف هذا إلى الحفاظ على معظم ميزة السرعة في حساب نصف الدقة مع الحفاظ على تحسين مستقر.

### dtype الحساب مقابل dtype المتغيّر

يمكن أن تملك طبقة Keras مفاهيميًا:

```text
compute_dtype
→ الدقة المستخدمة للعمليات

variable_dtype
→ الدقة المستخدمة لتخزين الأوزان
```

وفي ظل الدقة المختلطة:

```text
compute_dtype  ≈ float16   # دقة الحساب
variable_dtype = float32   # دقة التخزين
```

وهذا يتيح للـ model استخدام عمليات مصفوفات سريعة منخفضة الدقة مع إبقاء تحديثات المعاملات دقيقة.

### بعض العمليات تحتاج float32

قد تكون بعض العمليات غير مستقرة عدديًا في float16.

ويذكر المصدر تحديدًا عمليات مثل:

```text
softmax
crossentropy   # الإنتروبيا المتقاطعة
```

ويمكن لطبقة أن تنسحب من الدقة المختلطة:

### Underflow التدرّج (Gradient underflow)

تخيّل تدرّجًا:

```text
0.000001
```

فإذا لم يستطع float16 تمثيله بدقة، فقد يصبح فعليًا:

```text
0
```

ويُسمّى هذا **underflow**.

### تحجيم الخسارة (Loss scaling)

التدرّجات متناسبة مع الخسارة.

فإذا كبّرنا الخسارة مؤقتًا، تكبر التدرّجات أيضًا.

لنفترض أن:

```text
التدرّج الأصلي = 0.000001
```

فإذا حُجِّمت الخسارة بمقدار 1,000:

```text
التدرّج بعد التحجيم ≈ 0.001
```

وهذا العدد الأكبر أسهل تمثيلًا في float16.

وبعد ذلك يمكن احتساب التحجيم احتسابًا صحيحًا أثناء تحديث المُحسِّن.

ويعرض المصدر تحجيم الخسارة التلقائي:

⟦CODE_19⟧

ويفيد التحجيم التلقائي لأن المقياس المناسب قد يتغير أثناء التدريب.

### ماذا عن float8؟

الانتقال من float32 إلى float16 يعمل غالبًا بقدر قليل نسبيًا من المعالجة الخاصة.

أما الانتقال إلى float8 فأصعب بكثير لأن قدرًا أكبر بكثير من المعلومات العددية يُفقَد.

ويشرح المصدر أن منطق إعادة تحجيم خاصًا مطلوب وأن كلفته الإضافية لا تستحق العناء عمومًا إلا مع models كبيرة جدًا وعتاد حديث مناسب.

ولذلك:

```text
دقة مختلطة بـ float16
→ عملية على نطاق واسع

تدريب float8
→ تحسين متخصص واسع النطاق
```

### Quantization

تركّز الدقة المختلطة أساسًا على الحساب أثناء التدريب وinference.

أما **quantization** فتأخذ model مدرَّبًا بالفعل وتمثّل قيمًا معينة بصيغة عددية أصغر.

ومثال شائع:

```text
أوزان float32
→ أوزان int8
```

### لماذا int8؟

يستخدم `int8` ثمانية بتات فقط.

ونطاقه المُشار تقريبًا:

```text
-127 to 127
```

ويمكن أن يوفّر استخدام int8:

```text
حجم model أصغر
عرض نطاق memory أقل
عمليات مصفوفات مدعومة أسرع
inference أسرع
```

### لماذا لا نحوّل الأعداد العشرية ببساطة إلى أعداد صحيحة؟

لنفترض:

```text
0.1
0.9
-0.8
```

قد يدمّر تحويل ساذج إلى أعداد صحيحة معظم المعلومات:

```text
0.1 → 0
0.9 → 0
-0.8 → 0
```

وبدلًا من ذلك، **تُحجَّم** القيم لاستخدام نطاق int8 المتاح.

### حدس التحجيم بأقصى قيمة مطلقة (Abs-max scaling)

لنفترض أن أكبر قيمة مطلقة في tensor هي:

```text
1.2
```

ونريد أن تُربط تلك القيمة بما يقارب:

```text
127
```

ولذلك:

```text
scale ≈ 127 / 1.2   # عامل التحجيم
```

ثم:

```text
القيم العشرية
   ↓ حجّم (scale)
قيم عددية أكبر
   ↓ قرّب (round)
أعداد صحيحة
   ↓ حوّل (cast)
int8
```

وبعد ضرب مصفوفات int8، تُحوَّل النتيجة عائدةً وتُزال عنها عملية التحجيم.

ولا تكون النتيجة مطابقة تمامًا لـ float32 لأن التقريب يفقد بعض المعلومات، لكنها قد تبقى قريبة جدًا.

### الدقة المختلطة مقابل quantization

أبقِ هذين المفهومين منفصلين:

| التقنية | الهدف الرئيسي | الاستخدام المعتاد |
|---|---|---|
| inference بـ float16 | تمرير أمامي أسرع | Inference |
| الدقة المختلطة (mixed precision) | حساب سريع + تحديثات أوزان مستقرة | التدريب |
| تحجيم الخسارة (loss scaling) | منع اختفاء التدرّجات الصغيرة منخفضة الدقة | تدريب الدقة المختلطة |
| quantization إلى int8 | تمثيل عددي أصغر/أسرع | Inference |

### حزمة التحسين في العالم الحقيقي

يمكنك الآن رؤية عدة طرق مستقلة لتحسين نظام:

```text
BETTER MODEL QUALITY (جودة model أفضل)
→ ضبط hyperparameters
→ تجميع الـ models

FASTER TRAINING (تدريب أسرع)
→ multi-GPU (عدة وحدات GPU)
→ TPU
→ توازي البيانات
→ توازي الـ model
→ الدقة المختلطة

FASTER / SMALLER INFERENCE (inference أسرع وأصغر)
→ float16
→ quantization إلى int8
```

> **شكل يدوي موصى به:** أضف شكل مقارنة واحدًا هنا يوضّح `float32 → mixed float16 → int8`، مع المفاضلة بين الدقة واستخدام memory وكلفة الحوسبة.

## مغالطات مهمة

### المغالطة 1

> تُتعلَّم الـ hyperparameters وأوزان الـ model بالطريقة نفسها.

### لماذا هذا خطأ

تُحسَّن أوزان الـ model بالانحدار التدرّجي. أما الـ hyperparameters مثل عمق الـ model أو اختيار المُحسِّن فتُختار عادةً باستخدام إجراء بحث منفصل.

### المغالطة 2

> ينبغي استخدام مجموعة الاختبار هدفًا أثناء ضبط الـ hyperparameters.

### لماذا هذا خطأ

إن اختيار الـ models مرارًا بناءً على نتائج الاختبار يدرّب عملية التطوير فعليًا على مجموعة الاختبار. وينبغي أن تقود بيانات التحقق عملية الضبط، بينما تبقى مجموعة الاختبار محجوزة للـ evaluation النهائي.

### المغالطة 3

> يتحسن التجميع لمجرد أنه يحتوي models كثيرة.

### لماذا هذا خطأ

التنوع حاسم. فالـ models المتطابقة تقريبًا الكثيرة تميل إلى ارتكاب أخطاء متشابهة وتوفّر فائدة تجميع أقل.

### المغالطة 4

> يتيح توازي البيانات model أكبر من memory GPU واحد.

### لماذا هذا خطأ

يخزّن كل عامل في توازي البيانات نسخة كاملة من الـ model. وإذا لم يتسع الـ model على جهاز واحد، فيلزم توازي الـ model أو التجزئة (sharding).

### المغالطة 5

> ثمانية GPUs تضمن تدريبًا أسرع بثماني مرات بالضبط.

### لماذا هذا خطأ

يُدخل الاتصال والمزامنة وتحميل البيانات وعدم كفاية استغلال الأجهزة كلفة توسيع إضافية.

### المغالطة 6

> تشغيل كل أجزاء التدريب بـ float16 آمن دائمًا.

### لماذا هذا خطأ

تتطلب التدرّجات الصغيرة وبعض العمليات الحساسة عدديًا دقة أكبر. وتُبقي الدقة المختلطة الحالة والتحديثات الحساسة بـ float32.

### المغالطة 7

> يعني quantization ببساطة تحويل قيم الفاصلة العائمة مباشرةً إلى int8.

### لماذا هذا خطأ

يجب أن تُحجَّم القيم أولًا إلى النطاق الصحيح القابل للتمثيل. أما تحويل القيم العشرية الصغيرة تحويلًا ساذجًا فسيدمّر المعلومات.

### المغالطة 8

> الدقة العددية الأقل تجعل الـ model أسرع دائمًا.

### لماذا هذا خطأ

تعتمد السرعة الفعلية على دعم العتاد وحجم الـ model وكلفة التنفيذ الإضافية وما إذا كان حمل العمل كبيرًا بما يكفي للاستفادة من الحساب المتخصص منخفض الدقة.

## المصطلحات الرئيسية

| المصطلح | المعنى |
|---|---|
| Parameter | قيمة تُتعلَّم أثناء تدريب الـ model مثل الوزن |
| Hyperparameter | إعداد للـ model أو التدريب يُختار خارج الانتشار العكسي العادي |
| Search space | مجموعة إعدادات hyperparameters المتاحة لمُحسِّن |
| Trial | تدريب وتقييم إعداد hyperparameter واحد |
| Bayesian optimization | استراتيجية بحث تستخدم نتائج التجارب السابقة لاختيار تجارب مستقبلية واعدة |
| Validation-set overfitting (overfitting على مجموعة التحقق) | تكيّف الـ hyperparameters تكيّفًا مفرطًا مع مجموعة تحقق واحدة |
| Ensemble | جمع تنبؤات عدة models |
| Weighted ensemble | مجموعة تسهم فيها models مختلفة بأوزان مختلفة |
| Model diversity | درجة استخدام أعضاء المجموعة تمثيلات مختلفة أو ارتكابهم أخطاء مختلفة |
| Data parallelism | تكرار model وتقسيم الدفعات عبر الأجهزة |
| Model parallelism | تقسيم حساب model واحد أو معاملاته عبر الأجهزة |
| Replica | نسخة model كاملة تُستخدم في التدريب المتوازي للبيانات |
| Sharding | تقسيم tensor أو متغيّر model عبر الأجهزة |
| Device mesh | ترتيب منطقي متعدد الأبعاد لأجهزة المسرِّعات |
| Layout map | مواصفة لكيفية تكرار متغيّرات الـ model أو تجزئتها عبر شبكة أجهزة |
| TPU | Tensor Processing Unit؛ مسرِّع متخصص في حسابات تعلّم الآلة |
| Step fusing | تنفيذ عدة خطوات تدريب في دورة تنفيذ واحدة للمسرِّع |
| float16 | صيغة عددية بفاصلة عائمة بـ 16 بت |
| float32 | صيغة عددية بفاصلة عائمة بـ 32 بت |
| bfloat16 | صيغة بـ 16 بت بنطاق أس أكبر من float16 القياسي |
| Mixed precision | الجمع بين حساب منخفض الدقة وحالة وتحديثات model أعلى دقة |
| Underflow | قيمة عددية صغيرة جدًا تصبح غير قابلة للتمثيل وتُقرَّب فعليًا نحو الصفر |
| Loss scaling | ضرب الخسارة لجعل تدرّجات الدقة المنخفضة أكبر عدديًا أثناء التدريب |
| Quantization | تمثيل قيم model مدرَّب بصيغ عددية أقل دقة |
| int8 | تمثيل عدد صحيح مُشار بـ 8 بت يُستخدم عادةً لـ inference كفء |

## احتفظ بهذه الفكرة

**هندسة Deep Learning في العالم الحقيقي لا تقتصر على بناء شبكة عصبية صحيحة. فالأنظمة القوية تأتي من البحث المنهجي في إعدادات الـ models، والجمع بين models متنوعة حين يفيد ذلك، وتوسيع الحوسبة عبر العتاد، واختيار تمثيلات عددية توازن بين الدقة والسرعة وmemory.**

احتفظ بهذا التدرّج في ذهنك:

```text
IMPROVE QUALITY (تحسين الجودة)

baseline جيد
   ↓
بحث hyperparameters
   ↓
أفضل الإعدادات
   ↓
مجموعات متنوعة


SCALE TRAINING (توسيع التدريب)

1 جهاز
   ↓
توازي البيانات
   ↓
توازي الـ model / sharding
   ↓
عناقيد GPU / TPU


REDUCE COMPUTE COST (تقليل كلفة الحوسبة)

float32
   ↓
تدريب float16 مختلط
   ↓
inference بـ float16
   ↓
inference بـ int8 مكمَّم
```
