## 3. Confusion matrix: افهم بالضبط أين يخطئ Classifier

بدلًا من أن تسأل فقط:

> «كم Prediction كان صحيحًا؟»

اسأل:

> **«ما أنواع Predictions التي كانت صحيحة أو خاطئة؟»**

هذا بالضبط ما تعرضه **Confusion matrix**.

لتقييم Training examples دون أن يتدرب Model ويتنبأ على Instance نفسها، استخدم تنبؤات Cross-validation:

⟦CODE_9⟧

الآن كل Prediction هو **Out-of-sample** داخل Training set: فقد تم التنبؤ بالـ Instance بواسطة Model لم يتدرب على Fold الذي تنتمي إليه.

احسب Confusion matrix:

⟦CODE_10⟧

يحصل المصدر على:

```text
[[53892,   687],
 [ 1891,  3530]]
```

فسّرها بالشكل التالي:

| الفعلي / المتوقع (Actual / Predicted) | ليس 5 (Not 5) | 5 |
|---|---:|---:|
| ليس 5 (Not 5) | 53,892 | 687 |
| 5 | 1,891 | 3,530 |

والآن سمِّ الخلايا الأربع.

### True negative — سالب صحيح

```text
Actual: not 5 — الفعلي: ليس 5
Predicted: not 5 — المتوقع: ليس 5
```

Prediction سلبي صحيح.

### False positive — موجب كاذب

```text
Actual: not 5 — الفعلي: ليس 5
Predicted: 5 — المتوقع: 5
```

يرفع Classifier Prediction إيجابيًا بالخطأ.

ويُسمى أيضًا **Type I error**.

### False negative — سالب كاذب

```text
Actual: 5 — الفعلي: 5
Predicted: not 5 — المتوقع: ليس 5
```

يفوّت Classifier حالة إيجابية حقيقية.

ويُسمى أيضًا **Type II error**.

### True positive — موجب صحيح

```text
Actual: 5 — الفعلي: 5
Predicted: 5 — المتوقع: 5
```

Prediction إيجابي صحيح.

{{image:binary-confusion-matrix}}

Classifier مثالي سيحتوي فقط على:

```text
true negatives — حالات سالبة صحيحة
true positives — حالات موجبة صحيحة
```

مع أصفار في خليتي الخطأ.

### لماذا Confusion matrix مهمة؟

قد يحقق Modelان Accuracy متقاربة بينما يرتكبان أنواعًا مختلفة جدًا من الأخطاء.

وقد يحدد هذا الفرق أي Model مقبول للمشروع.

على سبيل المثال:

```text
medical screening: — الفحص الطبي
false negatives may be especially costly — قد تكون False negatives مكلفة جدًا

automatic content moderation: — الإشراف الآلي على المحتوى
false positives may be especially costly — قد تكون False positives مكلفة جدًا

fraud alerts: — تنبيهات الاحتيال
both may matter, but in different ways — كلا النوعين مهم ولكن بطرق مختلفة
```

يجب أن تتوافق Metric مع عاقبة الخطأ.

## 4. Precision وRecall وF1 score

تحتوي Confusion matrix على معلومات غنية، لكننا نحتاج أحيانًا إلى Metrics تلخيصية أصغر.

### الدقة الإيجابية (Precision)

يسأل **Precision**:

> من بين الأمثلة التي تنبأ Model بأنها Positive، كم منها كان Positive بالفعل؟

```text
precision = TP / (TP + FP) — معادلة Precision
```

بالنسبة إلى Classifier الموجود في المصدر:

⟦CODE_11⟧

يحصل المصدر تقريبًا على:

```text
0.837
```

إذًا عندما يتنبأ Classifier بأن الرقم هو “5”، يكون صحيحًا في نحو:

```text
83.7%
```

من الحالات.

### الاستدعاء (Recall)

يسأل **Recall**:

> من بين كل الأمثلة Positive الحقيقية، كم منها اكتشفه Classifier؟

```text
recall = TP / (TP + FN) — معادلة Recall
```

ويُسمى أيضًا:

- مقياس Sensitivity،
- معدل True positive rate،
- الاختصار TPR.

⟦CODE_12⟧

يحصل المصدر تقريبًا على:

```text
0.651
```

أي أن Classifier يكتشف نحو:

```text
65.1%
```

فقط من حالات الرقم 5 الحقيقية.

### Precision وRecall يصفان مخاطر مختلفة

ارتفاع Precision يعني:

```text
when I say positive, — عندما أقول إن الحالة Positive
I am usually right — أكون صحيحًا غالبًا
```

ارتفاع Recall يعني:

```text
when a real positive exists, — عندما توجد حالة Positive حقيقية
I usually catch it — أكتشفها غالبًا
```

فكّر في تطبيقين.

**فلترة فيديو آمنة للأطفال (Child-safe video filtering)**

قد تكون False positives مقبولة إذا كان معناها رفض بعض الفيديوهات الآمنة.

لكن السماح بمرور فيديوهات غير آمنة قد يكون غير مقبول.

لذلك قد يكون Precision المرتفع لتنبؤ “safe” مهمًا بشكل خاص.

**الفحص الطبي (Medical screening)**

قد يكون تفويت حالة حقيقية خطرًا.

وقد يتحمل النظام مزيدًا من False alarms إذا حقق Recall مرتفعًا جدًا.

المفاضلة الصحيحة تعتمد على المشروع.

### مقياس F1 (F1 score)

يجمع **F1 score** بين Precision وRecall باستخدام Harmonic mean.

```text
F1 = 2 × (precision × recall) / (precision + recall) — معادلة F1
```

في Scikit-Learn:

⟦CODE_13⟧

يحصل المصدر تقريبًا على:

```text
0.733
```

تكون F1 مرتفعة فقط عندما يكون كل من Precision وRecall مرتفعين بدرجة معقولة.

لكن F1 ليست دائمًا Metric التي ينبغي تحسينها إلى أقصى حد.

إذا كان أحد نوعي الخطأ أعلى تكلفة بكثير من الآخر، فقد لا يكون من المناسب إخفاء Precision وRecall داخل رقم واحد.

### اختيار Metric قرار تجاري

لا تسأل:

> «أي Metric هي الأفضل رياضيًا؟»

بل اسأل:

> **«أي الأخطاء أكثر أهمية في هذا التطبيق؟»**

### ماذا يحدث عندما يرتفع Threshold؟

```text
higher threshold — Threshold أعلى
    ->
fewer positive predictions — Predictions إيجابية أقل
    ->
precision tends to increase — يميل Precision إلى الارتفاع
recall tends to decrease — يميل Recall إلى الانخفاض
```

```text
"We need at least 90% precision." — نحتاج إلى Precision لا تقل عن 90%.
```

أو:

```text
"We need at least 95% recall." — نحتاج إلى Recall لا تقل عن 95%.
```

## 6. ROC curves وAUC ومقارنة Classifiers

طريقة أخرى لتقييم Binary classifier عبر Thresholds المختلفة هي **ROC curve**.

ترسم ROC:

```text
y-axis -> true positive rate (TPR) — المحور الرأسي
x-axis -> false positive rate (FPR) — المحور الأفقي
```

تذكّر أن:

```text
TPR = recall — TPR يساوي Recall
```

أما False positive rate فهو:

```text
FPR = FP / (FP + TN)
```

ويُسمى True negative rate أيضًا **Specificity**.

```text
FPR = 1 - specificity — العلاقة بين FPR وSpecificity
```

{{image:binary-roc-curve}}

### المساحة تحت منحنى ROC (ROC AUC)

تلخص **Area under the ROC curve** أو ROC AUC منحنى ROC بالكامل.

```text
perfect classifier -> AUC = 1.0 — Classifier مثالي
random classifier  -> AUC = 0.5 — Classifier عشوائي
```

### ROC أم Precision-recall curve؟

يقدم الفصل قاعدة عملية:

فضّل **Precision-recall curve** عندما:

- تكون Positive class نادرة،
- أو تكون False positives مهمة بشكل خاص.

Dataset الخاصة بـ 5-versus-not-5 غير متوازنة.

ولأن Negatives أكثر بكثير، فقد تجعل ROC curve الأداء يبدو أقوى مما تشير إليه PR curve.


## 7. التصنيف متعدد الفئات (Multiclass classification)

يميز **Binary classifier** بين فئتين.

أما **Multiclass classifier** فيميز بين أكثر من فئتين.

بالنسبة إلى MNIST:

```text
10 classes — عشر Classes
0 through 9 — من 0 إلى 9
```

تدعم بعض Algorithms مسائل Multiclass مباشرة.

بينما تكون Algorithms أخرى Binary بطبيعتها ويمكن توسيعها باستخدام Strategies.

### واحد مقابل البقية (One-versus-the-rest)

تدرب **One-versus-the-rest (OvR)** Binary classifier واحدًا لكل Class.

بالنسبة إلى MNIST:

```text
0 vs rest — 0 مقابل البقية
1 vs rest — 1 مقابل البقية
2 vs rest — 2 مقابل البقية
...
9 vs rest — 9 مقابل البقية
```

وهذا ينتج:

```text
10 classifiers — عشرة Classifiers
```

عند Prediction، يقيّم النظام المثال باستخدام جميع Class detectors ويختار Class ذات أقوى Score.

### واحد مقابل واحد (One-versus-one)

تدرب **One-versus-one (OvO)** Classifier واحدًا لكل زوج من Classes.

لعدد `N` من Classes:

```text
N × (N - 1) / 2
```

بالنسبة إلى MNIST:

```text
10 × 9 / 2 = 45 classifiers — أي 45 مصنِّفًا (Classifier)
```

أمثلة:

```text
0 vs 1
0 vs 2
0 vs 3
...
8 vs 9
```

يُحدد Class النهائي وفق Class التي تفوز بأكبر عدد من المقارنات الثنائية.

### أي Strategy ينبغي أن تستخدم؟

تدرب OvO عددًا أكبر من Models، لكن كل Model يرى أمثلة من Classين فقط.

قد يكون ذلك مفيدًا مع Algorithms التي تزداد تكلفة Training فيها بشكل كبير مع حجم Dataset، مثل بعض Support vector machines.

بالنسبة إلى كثير من Binary algorithms الأخرى، تكون OvR أكثر عملية عادةً.

### زيادة البيانات (Data augmentation)

أحد الحلول هو إضافة نسخ محوّلة من Training images:

```text
slightly left — إزاحة بسيطة إلى اليسار
slightly right — إزاحة بسيطة إلى اليمين
slightly up — إزاحة بسيطة إلى أعلى
slightly down — إزاحة بسيطة إلى أسفل
slightly rotated — دوران بسيط
```

وهذا يسمى **Data augmentation**.

بدلًا من إخبار Model رياضيًا بأن الإزاحات الصغيرة يجب ألا تغيّر هوية الرقم، تعرض عليه أمثلة كثيرة تحتوي تلك التحويلات.

```text

   |
inspect examples — افحص الأمثلة
   |
form a hypothesis — كوّن Hypothesis
   |
change data / features / model — غيّر البيانات والميزات والـ Model
   |
evaluate again — قيّم من جديد
```

## مفاهيم خاطئة مهمة (Important misconceptions)

### المفهوم الخاطئ 1

> Accuracy بنسبة 95% في Classification تعني دائمًا أن Model ممتاز.

### لماذا هذا خطأ؟

إذا كانت Class واحدة تهيمن على Dataset، فقد يحقق حتى Classifier يتجاهل Minority class قيمة Accuracy مرتفعة. قارن مع Baseline وافحص Metrics الخاصة بـ Confusion matrix.

### المفهوم الخاطئ 2

> Precision وRecall اسمان للفكرة نفسها.

### لماذا هذا خطأ؟

يسأل Precision عن مدى موثوقية Predictions الإيجابية، بينما يسأل Recall عن عدد الحالات Positive الحقيقية التي تم اكتشافها.

### المفهوم الخاطئ 3

> يجب دائمًا تعظيم F1.

### لماذا هذا خطأ؟

توازن F1 بين Precision وRecall. لكن بعض التطبيقات تعطي أحدهما أهمية أكبر بكثير من الآخر عمدًا.

### المفهوم الخاطئ 4

> Threshold بقيمة 0.5 أو 0 إلزامي رياضيًا.

### لماذا هذا خطأ؟

Threshold هو Decision policy، ويمكن تعديله لتلبية متطلبات Business الخاصة بـ Precision أوRecall أوCost أو Metric أخرى.

### المفهوم الخاطئ 5

> ROC AUC هي دائمًا أفضل Metric لـ Imbalanced classification.

### لماذا هذا خطأ؟

عندما تكون Positive class نادرة أو تكون False positives مهمة جدًا، غالبًا ما تكشف Precision-recall curve نقاط الضعف بصورة أوضح.

### المفهوم الخاطئ 6

> Multiclass وMultilabel classification هما الشيء نفسه.

### لماذا هذا خطأ؟

عادةً تختار Multiclass Class واحدة من عدة بدائل، بينما يمكن لـ Multilabel classification إسناد عدة Labels إلى Instance نفسها.

## المصطلحات الأساسية (Key terminology)

| المصطلح (Term) | المعنى (Meaning) |
|---|---|
| التصنيف (Classification) | التنبؤ بـ Classes أوLabels منفصلة |
| التصنيف الثنائي (Binary classification) | Classification بفئتين |
| التصنيف متعدد الفئات (Multiclass classification) | Classification بأكثر من فئتين متنافيتين |
| التصنيف متعدد التسميات (Multilabel classification) | التنبؤ بعدة Binary labels لـ Instance واحدة |
| التصنيف متعدد المخرجات (Multioutput classification) | التنبؤ بعدة Outputs بحيث يمكن أن يمتلك كل Output عدة قيم محتملة |
| الدقة الكلية (Accuracy) | نسبة جميع Predictions الصحيحة |
| عدم توازن الفئات (Class imbalance) | حالة تكون فيها بعض Classes أكثر تكرارًا بكثير من غيرها |
| مصفوفة الالتباس (Confusion matrix) | جدول يعدّ نتائج Actual مقابل Predicted لكل Class |
| موجب صحيح (True positive) | مثال Positive تم التنبؤ به بشكل صحيح على أنه Positive |
| سالب صحيح (True negative) | مثال Negative تم التنبؤ به بشكل صحيح على أنه Negative |
| موجب كاذب (False positive) | مثال Negative تم التنبؤ به خطأً على أنه Positive |
| سالب كاذب (False negative) | مثال Positive تم التنبؤ به خطأً على أنه Negative |
| الدقة الإيجابية (Precision) | نسبة Predictions الإيجابية التي كانت صحيحة |
| الاستدعاء (Recall) | نسبة الحالات Positive الفعلية التي تم اكتشافها |
| الحساسية (Sensitivity) | اسم آخر لـ Recall / True positive rate |
| النوعية (Specificity) | معدل True negative rate |
| مقياس F1 (F1 score) | Harmonic mean لـ Precision وRecall |
| حد القرار (Decision threshold) | حد Score المستخدم لتحويل Scores الخاصة بالـ Classifier إلى قرارات Class |
| منحنى PR (PR curve) | Precision-recall curve عبر Decision thresholds |
| منحنى ROC (ROC curve) | True positive rate مقابل False positive rate عبر Thresholds |
| المساحة تحت منحنى ROC (ROC AUC) | المساحة تحت ROC curve |
| معايرة الاحتمالات (Probability calibration) | جعل Probabilities المقدرة تتوافق بصورة أفضل مع التكرارات المرصودة |
| واحد مقابل البقية (One-versus-the-rest) | Multiclass strategy تستخدم Detector واحدًا لكل Class |
| واحد مقابل واحد (One-versus-one) | Multiclass strategy تستخدم Classifier واحدًا لكل زوج من Classes |
| تحليل الأخطاء (Error analysis) | دراسة منهجية لأخطاء Model لتوجيه التحسين |
| زيادة البيانات (Data augmentation) | إنشاء Training examples محولة لزيادة Robustness |
| سلسلة المصنفات (Classifier chain) | Multilabel strategy تستخدم فيها Classifiers اللاحقة Predictions الخاصة بالـ Labels السابقة |
