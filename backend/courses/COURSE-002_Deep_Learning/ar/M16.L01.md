## مخرجات التعلّم

بنهاية هذا الدرس يجب أن تكون قادرًا على:

- شرح كيف يجمع GPT بين التنبؤ بالـ token التالي وTransformer بمُفكِّك فقط (decoder-only).
- وصف كيف تُجزَّأ المدونات النصية الكبيرة إلى tokens وتُحوَّل إلى نوافذ تدريب للـ token التالي.
- شرح self-attention السببي والـ embeddings الموضعية والـ embeddings المرتبطة بين المُدخَل والمخرَج (tied embeddings) والـ logits وإحماء معدّل التعلّم (learning-rate warmup).
- وصف فك الترميز ذاتي الانحدار ولماذا قد يكون التوليد الساذج غير كفء.
- شرح لماذا يهم caching المفاتيح والقيم (key-value caching) في توليد Transformer السريع.
- المقارنة بين الاختيار الجشع والعشوائي والمتحكَّم فيه بـ temperature وأخذ العيّنات بـ top-K.
- شرح لماذا يتصرف model لغة سببي مدرَّب مسبقًا كـ model استكمال قبل ضبط التعليمات (instruction tuning).
- وصف instruction fine-tuning باستخدام أزواج prompt-استجابة.
- شرح Low-Rank Adaptation ولماذا يقلّل بصورة كبيرة المعاملات القابلة للتدريب وmemory المُحسِّن.
- شرح مسار عمل RLHF عالي المستوى.
- وصف كيف يمكن إدراج تمثيلات الصور في تسلسل model لغة بوصفها tokens ناعمة (soft tokens).
- شرح الـ foundation models وRAG وتناول الفصل للتدريب الموجَّه نحو التفكير المنطقي.
- مناقشة المفاضلات العملية لتوسيع الحجم بين حجم الـ LLM وبيانات التدريب وكلفة inference وتوفّر البيانات.

## 1. من توليد التسلسلات إلى GPT

أصبحت النمذجة التوليدية تطبيقًا مركزيًا لـ Deep Learning تدريجيًا.

واستخدم توليد التسلسلات المبكر شبكات عصبية تكرارية مثل LSTMs في:

```text
الموسيقى
الكتابة اليدوية
النص
```

وجاء التحول المهم حين اجتمعت ثلاث أفكار:

```text
نمذجة اللغة للـ token التالي
+
معمار Transformer
+
نص غير موسوم واسع النطاق
```

وأنتج هذا الجمع عائلة GPT:

```text
GPT = Generative Pretrained Transformer   # المحوِّل التوليدي المدرَّب مسبقًا
```

### ماذا تعني «generative pretrained Transformer»

**توليدي (Generative)**

يتنبأ الـ model بالنص token واحدًا في كل مرة ولذلك يستطيع توليد تسلسلات.

**مدرَّب مسبقًا (Pretrained)**

قبل تكييفه مع مسألة لاحقة محددة، يُدرَّب الـ model تدريبًا واسعًا على مدونة نصية كبيرة.

**Transformer**

يستخدم العمود الفقري للشبكة العصبية كتل Transformer القائمة على attention بدلًا من الطبقات التكرارية.

### توسيع الوصفة

يستخدم الفصل GPT-1 وGPT-2 وGPT-3 لتوضيح نمط تاريخي بسيط:

```text
معاملات أكثر
+
بيانات تدريب أكثر
+
حوسبة أكثر
        ↓
سلوك توليدي أقوى بكثير
```

وكانت التغييرات المعمارية متواضعة نسبيًا مقارنةً بتغييرات الحجم.

والدرس المهم ليس حفظ كل عدد من المعاملات.

بل فهم أن هدف التدريب نفسه للـ token التالي أصبح أقدر بكثير حين دُرّب على نطاق أكبر بكثير.

### few-shot prompting والـ prompting الشبيه بالتعليمات

حين أصبحت models اللغة أكبر، صارت قادرة بصورة متزايدة على أداء مهام مباشرةً من prompts نصية.

ويمكن أن يتضمن الـ prompt عدة أمثلة:

```text
English -> French   # من الإنجليزية إلى الفرنسية

sea otter -> ...   # قضاعة البحر
peppermint -> ...   # النعناع
cheese -> ?   # جبن
```

وهذا مثال على **few-shot prompting**.

وعلى نطاق أكبر بعدُ، قد يكفي أحيانًا وصف المهمة بلغة طبيعية.

ولم يزل هذا هدف الـ token التالي الأساسي.

بل غيّر الـ prompt ببساطة السياق الذي تُنتَج منه احتمالات الـ token التالي.

### قيد مهم

يشدد الفصل على أن models اللغة الكبيرة قد تولّد محتوى سلسًا لكنه خاطئ.

فالـ model لديه دائمًا توزيع للـ token التالي.

وهذا **لا** يعني أن استمراره المولَّد مستند إلى وقائع.

ويصبح هذا التمييز محوريًا لاحقًا حين نناقش:

```text
instruction tuning (ضبط التعليمات)
RLHF
RAG
تدريب بأسلوب التفكير المنطقي (reasoning-style)
```

## 2. تجهيز البيانات لـ pretraining الـ mini-GPT

يمكن تدريب model بأسلوب GPT من نص عادي دون فئات موسومة يدويًا.

فالنص نفسه يوفّر التسميات.

### مدونة نصية كبيرة

يستخدم الفصل مجموعة جزئية صغيرة من مدونة C4 لمثال mini-GPT التعليمي.

ومسار العمل الأساسي هو:

```text
مستندات نصية خام
      ↓
tokenizer للكلمات الجزئية
      ↓
معرّفات token
      ↓
نوافذ ثابتة الطول
      ↓
tokens المُدخَل + تسميات token التالي
```

### tokenization الكلمات الجزئية

يعطي tokenizer الكلمات الجزئية حلًّا وسطًا مفيدًا بين tokenization الحروف والكلمات.

فبدلًا من أن تكون:

```text
"unbelievable"   # لا يُصدَّق
```

دائمًا token كلمة كاملة واحدًا أو حروفًا مفردة كثيرة، قد تُمثَّل بعدة أجزاء قابلة لإعادة الاستخدام.

ويدعم tokenizer:

```text
النص -> معرّفات token
معرّفات token -> النص
```

### token حدود المستندات

حين تُضم مستندات كثيرة في تدفق token واحد، يمكن لعلامة خاصة أن تشير إلى مكان انتهاء مستند.

مفاهيميًا:

```text
المستند A
<end-of-text>
المستند B
<end-of-text>
المستند C
```

وهذا يتيح لهدف token تالٍ عام واحد أن يتدرّب عبر مستندات كثيرة غير مترابطة.

### نوافذ token ثابتة الطول

لنفترض أن:

```text
sequence_length = 256
```

فقد يحتوي المُدخَل:

```text
tokens[0:256]   # المُدخَل
```

والتسميات:

```text
tokens[1:257]   # التسميات
```

ولذلك تكون كل تسمية هي الـ token التالي.

ويتوسّع النمط نفسه من الفصل السابق الآن إلى مدونة pretraining كبيرة.

### streaming pipeline

لا ينبغي تحميل المدونات النصية الكبيرة وتجزئتها بالكامل إلى tokens في memory المسرِّع دفعة واحدة.

ويستطيع streaming pipeline:

- قراءة الأجزاء (shards)،
- التجزئة إلى tokens بالتوازي،
- تداخل المستندات،
- تكوين نوافذ ثابتة،
- تجميع الأمثلة في دفعات،
- جلب الدفعات القادمة مسبقًا (prefetch).

وهذا يجعل التدريب واسع النطاق ممكنًا دون الاحتفاظ بالـ dataset الكامل في memory.

## 3. معمار Transformer بمُفكِّك فقط

استخدم Transformer الأصلي ذو المُرمِّز والمُفكِّك:

```text
المُرمِّز (encoder)
+
المُفكِّك (decoder)
```

ويبسّط GPT ذلك.

فهو يزيل المُرمِّز ويحتفظ فقط بحزمة Transformer سببية.

```text
معرّفات token
   ↓
embeddings token + الموضع
   ↓
كتلة مُفكِّك
   ↓
كتلة مُفكِّك
   ↓
كتلة مُفكِّك
   ↓
...
   ↓
logits المفردات
```

### لماذا مُفكِّك فقط؟

يطابق model بمُفكِّك فقط مهمة الـ token التالي بطبيعته.

فيستطيع كل موضع أن ينتبه فقط إلى:

```text
نفسه
+
المواضع السابقة
```

ولا ينتبه أبدًا إلى المواضع المستقبلية.

وهذا يتيح تحويل أي نص إلى بيانات pretraining دون الحاجة إلى أزواج مصدر-هدف.

### تسلسل واحد لمهام كثيرة

في الإجابة عن الأسئلة، يمكن أن يتلقى الـ model:

```text
Question: ...   # السؤال
Answer:   # الإجابة
```

بوصفهما تسلسلًا واحدًا.

ولا يوجد مُرمِّز مصدر منفصل.

فالسؤال والإجابة موجودان في فضاء token نفسه.

وهذا أبسط من تدريب بنى مُدخَل/مخرَج مختلفة لكل مهمة لاحقة.

### self-attention السببي

داخل كل كتلة مُفكِّك:

```text
token t
يستطيع أن يُجري attention على:
0 ... t

token t
لا يستطيع أن يُجري attention على:
t+1 ... end
```

ويُفرَض هذا بقناع سببي.

### شبكة feedforward والمسار المتبقي

تحتوي كتلة المُفكِّك على:

```text
self-attention سببي متعدد الرؤوس
        ↓
dropout
        ↓
وصلة متبقية (residual connection)
        ↓
تطبيع الطبقة (layer normalization)
        ↓
شبكة feedforward
        ↓
dropout
        ↓
وصلة متبقية (residual connection)
        ↓
تطبيع الطبقة (layer normalization)
```

يمزج attention المعلومات عبر المواضع.

وتحوّل كتلة feedforward كل موضع تحويلًا لاخطيًا.

## 4. الـ embeddings الموضعية وأوزان المفردات المرتبطة

يجب أن يُمثَّل كل token بكلٍّ من:

```text
هوية token
+
الموضع
```

ولذلك يستطيع الـ model استخدام:

```text
token embedding   # تمثيل الـ token
+
position embedding   # تمثيل الموضع
```

### مصفوفات المفردات الكبيرة

تظهر عادةً مصفوفتان كبيرتان بصفة خاصة في model لغة.

جانب المُدخَل:

```text
vocab_size × hidden_dim
```

تربط معرّفات token بـ vectors مخفية.

وجانب المخرَج:

```text
hidden_dim × vocab_size
```

تربط الـ vectors المخفية بدرجات على tokens المفردات.

### ربط الأوزان (Weight tying)

يمكن للمصفوفتين مشاركة الأوزان.

مفاهيميًا:

```text
embedding أمامي:
فضاء token -> الفضاء المخفي

embedding عكسي:
الفضاء المخفي -> فضاء token
```

ويمكن لإسقاط المخرَج أن يستخدم مدوَّر (transpose) مصفوفة token embedding.

وهذا يقلّل كلفة المعاملات والـ memory.

### الـ Logits

لا يحتاج إسقاط المخرَج إلى تضمين طبقة softmax.

ويمكنه إنتاج قيم خام تُسمّى **logits**.

مفاهيميًا:

```text
logits
  ↓ softmax
احتمالات token
```

وحين يُخرج model الـ logits مباشرةً، يجب أن تعرف دالة الخسارة أن softmax ما تزال بحاجة إلى التطبيق داخليًا.

ولهذا قد تُضبط خسارة تصنيف بـ:

```text
from_logits=True   # الـ logits خام
```

## 5. الـ pretraining لـ Transformer سببي كبير

قد يكون تدريب Transformer الكبير غير مستقر.

ومشكلة عملية واحدة أن تحديثات المعاملات المبكرة الكبيرة قد تجعل التحسين يتباعد.

### إحماء معدّل التعلّم (Learning-rate warmup)

بدلًا من استخدام معدّل التعلّم الكامل فورًا:

```text
الخطوة 0 -> معدّل التعلّم الكامل
```

استخدم:

```text
معدّل تعلّم صغير
        ↓
زِده تدريجيًا
        ↓
حتى تبلغ معدّل التعلّم المستهدف
```

مفاهيميًا:

```text
معدّل التعلّم
^
|       ─────────────
|      /
|     /
|    /
|___/________________> الخطوات
```

وهذا هو **إحماء معدّل التعلّم (learning-rate warmup)**.

وهو يجعل تحديثات المعاملات الأولية ألطف.

### الدقة المختلطة (Mixed precision)

تستهلك الـ models الكبيرة memory هائلة.

ويمكن لاستخدام أنواع عددية أقل دقة في الحسابات المناسبة أن:

- يقلّل استخدام memory،
- يزيد throughput.

ويستخدم الفصل الدقة المختلطة وسيلةً عملية لجعل تدريب mini-GPT أكثر جدوى.

### هدف الـ pretraining

ما يزال الـ model يحسّن:

```text
cross-entropy للـ token التالي
```

ولم يُضَف شيء جديد مفاهيميًا.

وتأتي الصعوبة من التوسيع:

```text
طبقات أكثر
معاملات أكثر
مفردات أكبر
تسلسلات طويلة
مدونة نصية ضخمة
خطوات تدريب كثيرة
```

### حجم التدريب مهم

الـ mini-GPT التعليمي مدرَّب بأقل من اللازم عمدًا مقارنةً بـ models عائلة GPT الحقيقية.

وهذا مفيد تعليميًا:

> الوصفة الأساسية مفهومة على عتاد متواضع، لكن جودة LLM الحديث تعتمد اعتمادًا هائلًا على الحجم.

## 6. التوليد ذاتي الانحدار وفك الترميز الكفء

يولّد LLM سببي النص مرارًا:

```text
prompt
   ↓
تنبأ بـ logits الـ token التالي
   ↓
اختر token
   ↓
أضف token
   ↓
كرّر
```

### التوليد الساذج

يشغّل التنفيذ المباشر الـ model على التسلسل كله بعد كل token جديد.

وإذا بلغ التوليد:

```text
1000 tokens   # طول المخرَج
```

فإن جزءًا كبيرًا من التسلسل السابق نفسه يُعاد حسابه مرارًا.

### التجميع والأشكال الثابتة

يمكن للتنفيذ المجمَّع أن يحسّن سرعة inference تحسينًا كبيرًا.

لكن تغيير شكل المُدخَل بعد كل token مولَّد قد يسبب إعادة تجميع متكررة.

وحل بديل واحد هو حشو مخزن التوليد إلى طول أقصى ثابت.

عندئذٍ يرى الـ model المجمَّع شكلًا متسقًا.

### عدم الكفاءة الأعمق

حتى مع التجميع، فإن إعادة حساب كل حالات attention السابقة إهدار.

فالـ tokens السابقة لم تتغير.

وداخل attention السببي، لا تتغير أيضًا تمثيلات المفاتيح والقيم الأسبق.

### caching المفاتيح والقيم (Key-value caching)

لكل طبقة Transformer، خزّن:

```text
المفاتيح السابقة (keys)
القيم السابقة (values)
```

ثم حين يصل token جديد:

```text
token جديد
   ↓
احسب query/key/value الخاصة به
   ↓
أعد استخدام keys/values السابقة المخزَّنة
   ↓
أنتج الحالة المخفية التالية
```

وهذا مماثل لحمل حالة RNN إلى الأمام.

ولذلك يستطيع محرك inference عملي تقليل العمل المتكرر تقليلًا كبيرًا.

### لماذا يهم caching الـ KV

بدون caching:

```text
أعد حساب التسلسل القديم في كل خطوة
```

ومع caching:

```text
احسب حالات token القديمة مرة واحدة
أعد استخدامها
```

وكلما كان التسلسل المولَّد أطول، زادت الفائدة.

## 7. استراتيجيات أخذ العيّنات

ينتج الـ model توزيعًا على المفردات.

ولذلك يتطلب التوليد قاعدة قرار لاختيار الـ token التالي.

### فك الترميز الجشع (Greedy decoding)

اختر:

```text
argmax(logits)   # أعلى logit
```

في كل خطوة.

المزايا:

```text
بسيط
حتمي (deterministic)
استمرار عالي الاحتمال
```

المشكلة:

```text
قد يصبح متكررًا
```

فقد يختار الـ model نمطًا محتملًا محليًا مرارًا.

### أخذ العيّنات العشوائي (Random sampling)

بدلًا من اختيار القيمة القصوى فقط، خذ عيّنة مباشرةً من التوزيع المتنبَّأ به.

وهذا يزيد التنوع.

لكن أخذ العيّنات العشوائي غير المقيَّد قد ينتج مخرَجات غير متماسكة لأن tokens ذات الاحتمال المنخفض تبقى ممكنة.

### Temperature

تعيد temperature تشكيل توزيع المخرَج قبل أخذ العيّنات.

مفاهيميًا:

```text
adjusted_logits = logits / temperature   # الـ logits مقسومة على temperature
```

temperature منخفضة:

```text
توزيع أحدّ
مخرَج أكثر تحفظًا
أقرب إلى فك الترميز الجشع
```

temperature مرتفعة:

```text
توزيع أكثر تسطحًا
استكشاف أكثر
مخرَج أقل قابلية للتنبؤ
```

### Top-K sampling

احتفظ فقط بأعلى `K` من المرشَّحين درجةً.

مثال:

```text
المفردات = 32,000 tokens
K = 20

خذ عيّنة من أعلى 20 فقط
```

ويُستبعد كل ما هو خارج تلك المجموعة.

وهذا يجمع بين:

```text
التنوع
+
الحماية من tokens بالغة الندرة
```

### الجمع بين عناصر التحكم

temperature وtop-K مختلفان.

فتغيّر temperature الاحتمالات النسبية.

ويزيل top-K المرشَّحين خارج مجموعة مختارة.

ويمكن الجمع بينهما.

### بحث الحزمة (Beam search)

استراتيجية أخرى تُبقي عدة تسلسلات مرشَّحة حيّة في آن واحد.

وكل مسار مرشَّح هو **حزمة (beam)**.

ويستكشف بحث الحزمة عدة استمرارات ممكنة بدلًا من الالتزام فورًا بواحد فقط.

ويذكر الفصل هذا بوصفه استراتيجية فك ترميز أخرى، مع أن الأمثلة العملية الرئيسية تركّز على الجشع والعشوائي وtop-K.

---

## 8. استخدام model لغة مدرَّب مسبقًا

تدريب LLM كبير من الصفر مكلف.

ولذلك تبدأ مسارات عمل عملية كثيرة بـ model مدرَّب مسبقًا.

ويستخدم الفصل Gemma مثالًا.

ويمكن لحزمة model لغة سببي عالية المستوى أن تجمع:

```text
tokenizer مطابق
+
معمار صحيح
+
أوزان مدرَّبة مسبقًا
+
API للتوليد
```

وهذا يتجنب إعادة إنشاء كل تفصيل من المعالجة المسبقة وinference يدويًا.

### ما يتعلّمه model أساسي مدرَّب مسبقًا فعلًا

قبل ضبط التعليمات، تعلّم الـ model في الغالب:

```text
استمر في النص بصورة معقولة
```

والأفضل أن نفكر فيه على أنه:

```text
إكمال تلقائي (autocomplete) واسع النطاق
```

لا على أنه مساعد محادثة.

فإذا طُلب منه:

```text
How can I make brownies?   # كيف أصنع البراونيز؟
```

فقد يستمر model أساسي بنص يشبه:

- منشور منتدى،
- وصفة،
- نقاشًا،
- استمرارًا آخر شبيهًا بالويب.

ويحدد سياق الـ prompt أي منطقة من التوزيع المتعلَّم تُدخَل.

### الـ prompting بوصفه بناء سياق

إذا قدّمت:

```text
The following brownie recipe is easy to make.   # وصفة البراونيز التالية سهلة التحضير
You can start by...   # يمكنك أن تبدأ بـ
```

فإن استمرارًا شبيهًا بالوصفات يصبح أرجح بكثير.

وهذا يفسّر لماذا يمكن لتصميم الـ prompt أن يغيّر السلوك دون تعديل أوزان الـ model.

### الـ prompting صعب التحكم فيه

يحذّر الفصل من أن سلوك الـ prompt يصعب التنبؤ به.

فقد تؤدي تغييرات صغيرة في الصياغة إلى فروق كبيرة في السلوك.

وهذا يعكس أن الـ prompting يغيّر السياق ولا يبرمج صراحةً قاعدة حتمية.

### Hallucinations

لدى model اللغة دائمًا استمرار ما للـ token التالي.

فإذا طلب الـ prompt حقيقة غير موجودة، فقد يولّد الـ model مع ذلك إكمالًا يبدو معقولًا.

وهذه هي مشكلة hallucination المحورية:

```text
مخرَج سلس
≠
حقيقة موثَّقة
```

## 9. Instruction fine-tuning (ضبط التعليمات)

يتعلّم model أساسي التنبؤ العام بالـ token التالي.

أما المساعد فيحتاج سلوكًا أكثر تحديدًا:

```text
تعليمات
   ↓
استجابة مفيدة
```

ويعلّم instruction fine-tuning هذا النمط بأمثلة خاضعة للإشراف.

### صيغة التدريب

يحتوي dataset أزواجًا:

```text
التعليمات (instruction)
الاستجابة (response)
```

ويمكن دمجها في تسلسل واحد بعلامات متسقة:

```text
[instruction]
How do I ...?   # كيف أقوم بكذا؟
[end]

[response]
You can ...   # يمكنك أن تقوم بكذا
[end]
```

وما يزال هدف model اللغة السببي يتنبأ بالـ token التالي.

والفرق هو توزيع أمثلة التدريب.

فالآن يرى الـ model مرارًا:

```text
prompt شبيه بالتعليمات
يتبعه
الاستجابة المرغوبة
```

### تقنيع الخسارة

عند تدريب مساعد، قد نهتم أساسًا بـ tokens الاستجابة.

فـ tokens الـ prompt يوفّرها المستخدم.

و tokens الحشو لا تحتوي أي محتوى.

ولذلك يمكن لأوزان العيّنات أن تخبر الخسارة:

```text
tokens الـ prompt  -> تجاهل أو قلّل
tokens الاستجابة -> درّب
tokens الحشو -> تجاهل
```

وهذا يركّز التحديثات على سلوك الاستجابة المرغوب.

### لا ينشئ ضبط التعليمات معرفة لغوية من الصفر

تعلّم الـ model الكبير المدرَّب مسبقًا بالفعل تمثيلات لغوية عامة.

والـ fine-tuning أقرب إلى:

```text
وجِّه القدرة الموجودة
نحو نمط تفاعل مرغوب
```

ولهذا يمكن لـ datasets تعليمات صغيرة نسبيًا أن تغيّر سلوك الـ model تغييرًا ذا معنى.

## 10. LoRA: fine-tuning للـ models الكبيرة بمعاملات قابلة للتدريب أقل بكثير

قد يكون الـ fine-tuning الكامل كثيف الاستهلاك لـ memory.

فيتطلب model من مليار معامل memory لـ:

```text
معاملات الـ model
التدرّجات (gradients)
حالة المُحسِّن (optimizer state)
التنشيطات الوسيطة
```

وقد يتطلب المُحسِّن عدة قيم إضافية لكل معامل قابل للتدريب.

### جمّد الـ model الأساسي

إذا جُمِّد معامل:

```text
لا تحديث للتدرّج
لا حاجة إلى حالة مُحسِّن
```

وهذا يوفّر memory.

لكن تجميد كل شيء ببساطة سيمنع التكيّف.

### Low-Rank Adaptation في LoRA

يُبقي LoRA مصفوفة الأوزان الأصلية مجمَّدة ويضيف تحديثًا صغيرًا قابلًا للتدريب.

لنفترض أن الإسقاط الأصلي هو:

```text
y = xW
```

ويستخدم LoRA:

```text
y = xW + xAB
```

حيث:

```text
W = مصفوفة كبيرة مجمَّدة
A = مصفوفة صغيرة قابلة للتدريب
B = مصفوفة صغيرة قابلة للتدريب
```

فإذا كان:

```text
شكل W = 2048 × 2048
```

فهي تحتوي ملايين المعاملات.

ومع الرتبة:

```text
r = 8
```

تحتوي مصفوفتا LoRA قيمًا قابلة للتدريب أقل بكثير.

### لماذا «منخفض الرتبة»؟

يمر التكييف عبر بُعد داخلي ضيق:

```text
المُدخَل
 ↓
تمثيل برتبة 8 (rank-8)
 ↓
تحديث المخرَج
```

وهذا يحدّ من القوة التعبيرية للتحديث.

لكن الـ fine-tuning اللاحق يحتاج عادةً إلى مرونة أقل بكثير من الـ pretraining الأصلي.

### أين يُطبَّق LoRA

يركّز الفصل على إسقاطات attention مثل:

```text
إسقاط الاستعلام (query)
إسقاط المفتاح (key)
```

مع تجميد الـ model الأساسي الأكبر بكثير.

ويمكن أن تقلّل النتيجة المعاملات القابلة للتدريب بمراتب من الحجم.

### تمييز مهم

لا يجعل LoRA بالضرورة أوزان الـ model المجمَّدة تختفي من memory.

فما تزال تحتاج إلى الـ model الأساسي لـ inference.

ويأتي التوفير الرئيسي من تجنّب:

```text
التدرّجات
حالة المُحسِّن
```

لما يقارب كل المعاملات الأساسية.

وهذا يجعل الـ fine-tuning أيسر كثيرًا على memory مسرِّع محدودة.

## 11. التعلّم المعزَّز بالتغذية الراجعة البشرية (RLHF)

يتطلب ضبط التعليمات الخاضع للإشراف أن يكتب الناس الاستجابات المرغوبة.

وهذا مكلف.

ويحاول RLHF التعلّم من نوع مختلف من الإشراف البشري:

```text
التفضيلات (preferences)
```

فبدلًا من أن نسأل:

> اكتب الإجابة المثالية.

نسأل:

> أي هاتين الإجابتين أفضل؟

### الخطوة 1 — ضبط التعليمات الخاضع للإشراف

ابدأ بتدريب prompt-استجابة العادي الموصوف سابقًا.

وهذا ينشئ خط أساس معقولًا لمساعد.

### الخطوة 2 — اجمع ترتيبات التفضيل

لكل prompt، اجمع عدة استجابات.

ويرتّبها البشر:

```text
الأفضل
ثاني أفضل
...
الأسوأ
```

### الخطوة 3 — درّب model مكافأة

درّب model آخر على الربط:

```text
prompt + استجابة
      ↓
درجة المكافأة
```

وتعني الدرجة الأعلى أن الاستجابة يُتوقَّع أن تتوافق أكثر مع التفضيلات البشرية.

### الخطوة 4 — حسّن model اللغة باستخدام المكافآت

يولّد model اللغة استجابات.

ويقيّمها model المكافأة.

وتُستخدم تلك المكافآت لتحديث model اللغة.

وحلقة مفاهيمية مبسَّطة هي:

```text
prompt
  ↓
يولّد LLM استجابة
  ↓
يعطي model المكافأة درجة للاستجابة
  ↓
تحديث التدريب
  ↓
يصبح LLM أرجح لإنتاج الاستجابات المفضَّلة
```

### التحسين التكراري

يمكن أن تتكرر العملية:

```text
model سياسة (policy) أفضل
   ↓
مرشَّحات مولَّدة أفضل
   ↓
ترتيبات بشرية جديدة
   ↓
model مكافأة أفضل
   ↓
مزيد من تدريب السياسة
```

### قيد مهم

يمكن لضبط التفضيلات أن يحسّن السلوك دون تغيير الطبيعة الجوهرية لـ model الـ token التالي.

وهو لا يضمن الصدق.

ويبيّن الفصل أن حتى model أنفع مضبوطًا بالتعليمات يمكن أن يرتكب أخطاء واقعية مع ذلك.

## 12. models اللغة متعددة الوسائط (Multimodal)

الـ Transformer في جوهره model تسلسل، لا معمار للنص فقط.

وإذا أمكن تمثيل نوع بيانات آخر بوصفه تسلسلًا من vectors، فيمكن من حيث المبدأ إدراجه في حساب Transformer نفسه.

### الصور بوصفها عناصر تسلسل

يستطيع مُرمِّز صور تقسيم صورة إلى رقع (patches).

وتصبح كل رقعة vector.

مفاهيميًا:

```text
الصورة
  ↓
مُرمِّز الرؤية (vision encoder)
  ↓
vector الرقعة 1
vector الرقعة 2
...
vector الرقعة N
```

ويمكن تشكيل هذه الـ vectors لتطابق البُعد المخفي لـ model اللغة.

ثم يمكن إدراجها في تسلسل token.

### الـ tokens الصلبة والناعمة

token نصي:

```text
معرّف (ID) عدد صحيح
   ↓
بحث في جدول embedding
   ↓
vector embedding ثابت
```

رقعة صورة:

```text
مُرمِّز الصورة
   ↓
vector متصل
```

ويصف الفصل هذه الـ vectors المتصلة للصور بأنها **tokens ناعمة (soft tokens)**.

وعلى خلاف معرّفات token العادية، لا تُختار من جدول embedding لمفردات محدودة.

### التسلسل المدمج

مفاهيميًا:

```text
tokens نصية
+
tokens ناعمة للصور
+
مزيد من tokens النص
       ↓
Transformer
```

والآن يستطيع الـ model توليد نص مشروط بالمعلومات البصرية.

### تدريب models متعددة الوسائط

تبقى الوصفة العامة متشابهة:

```text
مُرمِّز صور مدرَّب مسبقًا
+
Transformer لـ model اللغة
+
تدريب مختلط صور/نص
```

ويظل الـ model يتنبأ بـ tokens النص.

ولا يلزم تطبيق الخسارة على مواضع عناصر الصور البديلة (placeholders).

### الـ Foundation models

حين تتعامل Models مع عدة وسائط ومهام لاحقة كثيرة، يصبح مصطلح **Large Language Model (النموذج اللغوي الكبير)** غير كامل.

ومصطلح أوسع هو:

```text
foundation model   # model الأساس
```

ويعرّف الفصل الـ foundation models بأنها أنظمة مدرَّبة مسبقًا تدريبًا واسعًا — عادةً باستخدام أهداف ذاتية الإشراف واسعة النطاق — ويمكن تكييفها مع مهام لاحقة كثيرة.

## 13. Retrieval-Augmented Generation في الممارسة

لـ LLM مدرَّب مسبقًا نقطتا ضعف خطيرتان حين يُستخدم نظام معلومات.

### المشكلة 1 — Hallucination

قد يولّد الـ model وقائع غير صحيحة.

### المشكلة 2 — حدّ المعرفة (Knowledge cutoff)

لا يستطيع الـ model معرفة معلومات أُنشئت بعد انتهاء بيانات تدريبه ما لم يُزوَّد بسياق جديد.

ويعالج RAG الاثنتين بإضافة معلومات خارجية إلى الـ prompt.

### الـ pipeline الأساسي

```text
سؤال المستخدم
     ↓
نظام retrieval
     ↓
مستندات ذات صلة
     ↓
السؤال + السياق المجلوب
     ↓
LLM
     ↓
الإجابة
```

ولم يعد يُطلب من الـ model الاعتماد على معاملاته الداخلية المدرَّبة مسبقًا وحدها.

بل يتلقى الأدلة ذات الصلة مباشرةً.

### مصادر الـ retrieval

قد يستعلم نظام الـ retrieval من:

```text
قاعدة بيانات
محرك بحث
مخزن مستندات
قاعدة معرفة خاصة بالشركة
```

### Vector database لحفظ الـ vectors

يُضمّن تصميم RAG شائع المستندات بوصفها vectors.

```text
المستند
   ↓
model embedding
   ↓
vector
```

ويُضمَّن الاستعلام في الفضاء نفسه.

ثم تُجلب المستندات التي تقترب vectors الخاصة بها من vector الاستعلام.

مفاهيميًا:

```text
vector الاستعلام
    ↓
أقرب vectors مخزَّنة
    ↓
نص المستند المقابل
```

### الفوائد التي يصفها الفصل

يستطيع RAG أن:

- يوفّر معلومات أحدث،
- يوفّر معلومات خاصة،
- يقلّل التوليد الواقعي غير المدعوم بتوفير سياق ذي صلة.

وهو لا يضمن اختفاء الـ hallucinations.

لكنه يعطي الـ LLM مصدرًا أقوى بكثير لـ grounding الواقعي.

## 14. التوليد بأسلوب التفكير المنطقي والتدريب القابل للتحقق

يناقش الفصل فئة من الـ models دُرّبت لتؤدي أداءً أفضل في مسائل مثل:

```text
الرياضيات
البرمجة
المنطق
```

ومن الملاحظات المفيدة أن الـ models تؤدي غالبًا أداءً أفضل حين تولّد خطوات وسيطة قبل الإجابة النهائية.

### الـ prompting بأسلوب chain-of-thought

قد يشجّع الـ prompt الـ model على:

```text
العمل عبر الخطوات الوسيطة
   ↓
ثم إعطاء الإجابة النهائية
```

ويصبح النص الوسيط المولَّد سياقًا إضافيًا يستطيع الـ model أن ينتبه إليه أثناء توليد tokens لاحقة.

### التدريب بنتائج قابلة للتحقق

في بعض المجالات، يمكن فحص الإجابة النهائية تلقائيًا.

أمثلة:

```text
مسألة رياضيات -> قارن العدد النهائي
مسألة برمجة -> شغّل الاختبارات
```

وهذا يتيح حلقة تدريب مثل:

```text
المسألة
  ↓
ولّد عدة حلول مرشَّحة
  ↓
افحص الإجابات النهائية
  ↓
احتفظ بالحلول الناجحة أو كافئها
  ↓
درّب على المسارات الناجحة
  ↓
كرّر
```

ويعرض الفصل هذا على أنه وثيق الصلة بالتعلّم المعزَّز.

وتوفّر البيئة إشارة نجاح قابلة للقياس.

### الفكرة الأساسية

لا يتعلّم الـ model مجرد:

```text
"قل الإجابة"
```

بل يُدرَّب على إنتاج تسلسلات وسيطة تجعل المخرَجات النهائية الصحيحة أرجح.

ويصف الفصل هذا بأنه ضرب من البحث في مسارات الحلول التي يولّدها الـ model نفسه.

## 15. مفاضلات التوسيع وإلى أين قد تتجه LLMs لاحقًا

ينتهي الفصل بفحص ما إذا كان المستقبل ببساطة:

```text
model أكبر = model أفضل
```

والإجابة أدق من ذلك.

### ميزانية حوسبة ثابتة

مع كمية ثابتة من الحوسبة، يمكنك إنفاقها على:

```text
model أكبر
أو
بيانات تدريب أكثر
```

وقد يكون model أكبر أكثر من اللازم نسبةً إلى كمية البيانات والحوسبة المستخدمة لتدريبه.

ولذلك قد تأتي نتائج أفضل من:

```text
model أصغر
+
تدريب أكثر
```

بدلًا من زيادة عدد المعاملات فقط.

### كلفة inference مهمة

يجب في النهاية نشر الـ model.

وقد يكون model أضعف قليلًا أنفع إذا كان:

```text
أسرع
أرخص
أصغر
أسهل في الـ deploy
```

وقد يكون model باهظ الكلفة في التشغيل غير عملي رغم نتائج benchmark أقوى.

### البيانات عالية الجودة محدودة

تحدٍّ آخر هو نفاد:

```text
بيانات التدريب
عالية الجودة
العامة
التي كتبها البشر
```

ومع توليد models لمحتوى إنترنت أكثر، قد تحتوي مدونات التدريب المستقبلية كميات متزايدة من البيانات الاصطناعية.

وهذا يغيّر مشكلة التوسيع.

### التعلّم المعزَّز مصدرًا آخر لإشارة التدريب

إذا استطاعت بيئة مهمة إنتاج مسائل جديدة وفحص الحلول تلقائيًا، فيستطيع الـ model مواصلة التعلّم من محاولاته هو.

وهذا أحد أسباب أن الأساليب الشبيهة بالتعلّم المعزَّز مهمة لـ:

```text
الرياضيات
البرمجة
مجالات أخرى قابلة للتحقق
```

### عدم الكفاءة المتبقية

يؤكد الفصل أن LLMs الحالية ما تزال تتعلّم بكفاءة أقل بكثير من البشر.

فتستهلك الأنظمة الحديثة نصوصًا أكثر بكثير مما يستطيع شخص قراءته.

ولذلك فحتى مع استمرار التوسيع، يبقى تحسين:

```text
كفاءة البيانات
كفاءة التعلّم
أهداف التدريب
المعمار
```

ميدانًا بحثيًا مهمًا.

## مغالطات مهمة

### المغالطة 1

> «يحتاج GPT إلى أزواج سؤال-إجابة موسومة بعناية لـ pretraining.»

لا. فمهمة الـ pretraining الأساسية تستخدم نصًا عاديًا والتنبؤ بالـ token التالي.

### المغالطة 2

> «الـ model الأساسي المدرَّب مسبقًا هو بالفعل chatbot يتبع التعليمات.»

ليس بالضرورة. فـ model سببي أساسي يتعلّم في الأساس استمرار النص المعقول. ويغيّر ضبط التعليمات التوزيع نحو سلوك prompt-استجابة مفيد.

### المغالطة 3

> «فك الترميز الجشع هو دائمًا أفضل استراتيجية توليد.»

قد يصبح فك الترميز الجشع متكررًا. وتفاضل استراتيجيات أخذ العيّنات بين الحتمية والتنوع.

### المغالطة 4

> «يضغط LoRA الـ model بالكامل في model صغير.»

يُبقي LoRA الـ model الأساسي الكبير مجمَّدًا ويُدخل تحديثات صغيرة منخفضة الرتبة قابلة للتدريب. وتأتي فائدته الرئيسية في memory التدريب من التقليل الكبير في المعاملات القابلة للتدريب وحالة المُحسِّن.

### المغالطة 5

> «يضمن RLHF إجابات واقعية.»

يمكن لضبط التفضيلات أن يجعل المخرَجات أنفع وأكثر توافقًا مع السلوك المرغوب، لكنه لا يزيل hallucination بوصفه احتمالًا جوهريًا.

### المغالطة 6

> «تتطلب LLMs متعددة الوسائط معمار لغة مختلفًا تمامًا.»

يبيّن الفصل أن معلومات الصور يمكن ترميزها بوصفها تسلسلًا من vectors متصلة وإدراجها في تمثيل تسلسل Transformer.

### المغالطة 7

> «يكتب RAG وقائع جديدة بصورة دائمة في أوزان الـ model.»

يوفّر RAG المعلومات المجلوبة سياقًا وقت inference. ولا حاجة إلى أن تتغير معاملات الـ model الأساسي.

## المصطلحات الرئيسية

| المصطلح | المعنى |
|---|---|
| GPT | Generative Pretrained Transformer (المحوِّل التوليدي المدرَّب مسبقًا) |
| Causal language model (model لغة سببي) | model يتنبأ بالـ token التالي باستخدام السياق السابق فقط |
| Pretraining | تدريب أولي واسع النطاق قبل التكييف الخاص بالمهمة |
| Subword tokenizer | tokenizer يمثّل النص بأجزاء قابلة لإعادة الاستخدام أصغر من كثير من الكلمات |
| Decoder-only Transformer (Transformer بمُفكِّك فقط) | حزمة Transformer تستخدم self-attention سببيًا دون مُرمِّز منفصل |
| Causal mask | قناع يمنع الوصول إلى مواضع التسلسل المستقبلية |
| Logit | درجة مخرَج غير مطبَّعة قبل softmax |
| Weight tying | مشاركة أوزان embedding المُدخَل مع إسقاط مفردات المخرَج |
| Warmup | زيادة معدّل التعلّم تدريجيًا في بداية التدريب |
| Mixed precision | استخدام صيغ عددية أقل دقة لحسابات مختارة |
| KV cache | حالات attention المخزَّنة للمفاتيح والقيم التي يُعاد استخدامها أثناء التوليد ذاتي الانحدار |
| Greedy search | اختيار الـ token التالي ذي أعلى درجة |
| Temperature | تحجيم الـ logits للتحكم في مدى تركّز توزيع أخذ العيّنات |
| Top-K sampling | حصر أخذ العيّنات في tokens المرشَّحة الـ K الأعلى درجةً |
| Instruction fine-tuning (ضبط التعليمات) | تدريب خاضع للإشراف على أمثلة تعليمات-استجابة |
| LoRA | Low-Rank Adaptation؛ fine-tuning كفء في المعاملات بتحديثات صغيرة منخفضة الرتبة قابلة للتدريب |
| RLHF | التعلّم المعزَّز بالتغذية الراجعة البشرية (Reinforcement Learning with Human Feedback) |
| Reward model | model يُدرَّب على تقييم المخرَجات بدرجات بحسب التفضيلات البشرية |
| Soft token | vector متصل يُدرَج في تسلسل Transformer بدلًا من بحث مفردات منفصل |
| Multimodal model | model يعمل على أكثر من وسيط بيانات واحد |
| Foundation model | model مدرَّب مسبقًا تدريبًا واسعًا يمكن تكييفه مع مهام لاحقة كثيرة |
| RAG | التوليد المعزَّز بالـ retrieval (Retrieval-Augmented Generation) |
| Vector database | قاعدة بيانات تدعم البحث بالتشابه على vectors الـ embedding |
| Reasoning-style generation (توليد بأسلوب التفكير المنطقي) | توليد يتضمن خطوات حل وسيطة قبل المخرَج النهائي |

## اختبر نفسك

قبل المتابعة، تأكّد أنك تستطيع الإجابة عن:

1. ما المكونات الثلاثة التي تعرّف وصفة GPT الأساسية؟
2. لماذا يمكن للنص العادي غير الموسوم أن يوفّر تسميات الـ token التالي؟
3. ما الفرق المعماري بين Transformer الأصلي ذي المُرمِّز والمُفكِّك وGPT؟
4. لماذا يجب أن يستخدم GPT self-attention سببيًا؟
5. ما غرض token نهاية المستند؟
6. لماذا يمكن لـ embeddings المُدخَل وإسقاطات مفردات المخرَج مشاركة الأوزان؟
7. ما الـ logit؟
8. لماذا يفيد إحماء معدّل التعلّم؟
9. لماذا يكون التوليد ذاتي الانحدار الساذج مهدرًا للحوسبة؟
10. ماذا يخزّن KV cache؟
11. كيف يختلف فك الترميز الجشع عن أخذ العيّنات العشوائي؟
12. ماذا تغيّر temperature؟
13. ماذا يزيل أخذ العيّنات بأعلى K من توزيع المرشَّحين؟
14. لماذا يتصرف model أساسي مدرَّب مسبقًا غالبًا كإكمال تلقائي لا كـ chatbot؟
15. ماذا يتغير أثناء instruction fine-tuning؟
16. لماذا يتطلب fine-tuning كامل لـ LLM هذا القدر الكبير من memory المسرِّع؟
17. كيف يقلّل LoRA عدد المعاملات القابلة للتدريب؟
18. ما دور model المكافأة في RLHF؟
19. ما tokens الصور الناعمة؟
20. ما الذي يجعل model foundation model؟
21. كيف يضيف RAG معلومات دون تغيير أوزان الـ model؟
22. لماذا يمكن لـ RAG أن يساعد في حدّ المعرفة وgrounding الواقعي؟
23. كيف يمكن لإجابات الرياضيات أو البرمجة القابلة للتحقق أن توفّر إشارة تعلّم معزَّز؟
24. لماذا قد يتفوق model أصغر لكنه مدرَّب بصورة أفضل على model أكبر مدرَّب بأقل من اللازم؟
25. لماذا تهم كلفة الـ deployment عند اختيار حجم الـ model؟

## احتفظ بهذه الفكرة

**تجمع LLMs الحديثة بين Transformer سببي والتنبؤ بالـ token التالي ومدونات نصية غير موسومة ضخمة. وتُضبط عملية التوليد باستراتيجيات فك الترميز؛ ويعتمد inference العملي على التجميع وcaching الـ KV؛ ويتشكل سلوك المساعد المفيد بضبط التعليمات وLoRA والتدريب القائم على التفضيلات؛ ويمكن تحويل المُدخَلات متعددة الوسائط إلى تمثيلات تسلسل؛ ويوفّر RAG معرفة خارجية وقت inference؛ ويوازن البحث الحالي بصورة متزايدة بين حجم الـ model وبيانات التدريب وكلفة الحوسبة والتغذية الراجعة القابلة للتحقق.**
