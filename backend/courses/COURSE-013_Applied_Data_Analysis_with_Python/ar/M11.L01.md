## لماذا يهم هذا الدرس؟

يمكن أن يكون نموذج Machine Learning واحدًا مفيدًا، لكن أي نموذج منفرد قد يمتلك نقاط ضعف.

قد يقوم نموذج بسيط بما يلي:

```text
يفوّت بنية مهمة
→ Underfit
→ High bias
```

وقد يقوم نموذج شديد المرونة بما يلي:

```text
يتتبع Noise الخاصة ببيانات Training بصورة مفرطة
→ Overfit
→ High variance
```

تطرح Ensemble learning سؤالًا قويًا:

> **ماذا لو جمعنا عدة Models بحيث تلغي نقاط ضعفها الفردية جزءًا من بعضها؟**

يقدم الفصل عائلتين رئيسيتين من Ensemble:

```text
Bagging
→ تدريب Models كثيرة بصورة مستقلة
→ عادةً على Data أُعيد Sampling لها
→ تجميع Predictions الخاصة بها

Boosting
→ تدريب Models بصورة Sequential
→ كل Learner جديدة تركز على الأخطاء المتبقية
→ دمج جميع Learners في Predictor قوي واحد
```

ثم يوسع الفكرة عبر:

- Random Forest،
- Extra Trees،
- AdaBoost،
- Gradient Boosting،
- Voting ensembles،
- One-vs-Rest،
- One-vs-One،
- Stacking،
- XGBoost.

الهدف الأساسي ليس حفظ أسماء Algorithms.

بل فهم:

```text
ما نوع Model error التي نحاول تقليلها؟
كيف نصنع Diversity بين Base learners؟
هل يتم تدريب Learners بصورة مستقلة أم Sequential؟
كيف يتم دمج Predictions؟
ما Preprocessing التي يحتاجها كل Base model؟
كيف نمنع Ensemble أقوى من التحول ببساطة إلى آلة Overfitting أكثر تعقيدًا؟
```

خريطة مفيدة للفصل هي:

```text
حدود النموذج الواحد
        ↓
حدس الانحياز والتباين (Bias–variance)
        ↓
Bagging
├── Bootstrap sampling
├── Random Forest
└── Extra Trees
        ↓
Boosting
├── AdaBoost
└── Gradient Boosting
        ↓
أطر ensemble البسيطة
├── Voting
├── OvR
└── OvO
        ↓
ensembles متقدمة
├── Stacking
└── XGBoost
```

## 1. ما Ensemble method؟

تجمع Ensemble عدة Models داخل Predictive system واحدة.

مفاهيميًا:

```text
النموذج 1 ─┐
النموذج 2 ─┼─→ التجميع → التنبؤ النهائي
النموذج 3 ─┘
```

Intuition الخاصة بالفصل هي أن Models المختلفة غالبًا ما ترتكب أخطاء مختلفة.

إذا لم تكن Errors متطابقة تمامًا، فإن Aggregation يمكن أن تقلل أثر خطأ أي Model واحدة.

وقد يحسن ذلك:

- Stability،
- Generalization،
- Predictive performance.

---

### 1.1 Ensemble لا تعني تلقائيًا «أفضل»

قد يضيف دمج Models ضعيفة أوشديدة الارتباط Complexity دون فائدة كبيرة.

ينبغي أن تنشئ Ensemble:

```text
تنوّع مفيد
```

بين Base learners.

يمكن أن تأتي Diversity من:

- Training samples مختلفة،
- Feature subsets مختلفة،
- Model families مختلفة،
- Sequential error focus مختلف.

تربط هذه الفكرة كل Methods في هذا الفصل.

## 2. Bias وVariance

يحفز الفصل استخدام Ensembles عبر Bias–variance trade-off.

---

### 2.1 Bias

Bias هي Systematic error يسببها Model شديدة التقييد أوغير مناسبة للـ True pattern.

مثال:

```text
العلاقة الحقيقية
→ منحنية

النموذج
→ خط مستقيم
```

يفوّت Straight line الـ Curvature بصورة متكررة.

هذا هو:

```text
انحياز مرتفع (high bias)
```

وغالبًا يرتبط بـ:

```text
underfitting    # ملاءمة ناقصة
```

---

### 2.2 Variance

تصف Variance مقدار تغير Fitted model إذا تغيرت Training data.

قد تلائم Model شديدة المرونة Training sample واحدة بصورة شديدة الدقة لكنها تتغير بصورة كبيرة عند تدريبها على Sample مختلفة قليلًا.

هذا هو:

```text
تباين مرتفع (high variance)
```

وغالبًا يرتبط بـ:

```text
overfitting    # فرط الملاءمة
```

---

### 2.3 ملاحظة حول صياغة المصدر

يصف المصدر في البداية High variance بأنها تحدث لأن Model «عممت بصورة جيدة جدًا».

تتعارض هذه الصياغة مع الشرح اللاحق في الفصل.

الفكرة المقصودة هي:

```text
Overfitting
→ Model تلائم Training data بصورة مفرطة في الخصوصية
→ ضعف Stability/Generalization على Samples جديدة
→ High variance
```

---

## 3. المفاضلة Bias–variance trade-off

غالبًا تؤدي زيادة Model flexibility إلى:

```text
الانحياز ↓
التباين ↑
```

وغالبًا تؤدي زيادة Regularization إلى:

```text
التباين ↓
الانحياز ↑
```

الهدف ليس:

```text
Minimum bias بأي تكلفة
```

ولا:

```text
Minimum variance بأي تكلفة
```

بل إيجاد Balance مفيدة.

يستخدم المصدر:

```text
الانحدار الخطي
مقابل
الانحدار كثير الحدود عالي الدرجة
```

لشرح Intuition.

---

### 3.1 Underfitting

```text
بسيط أكثر من اللازم
→ يفوّت True pattern
→ High bias
```

### 3.2 Overfitting

```text
مرن أكثر من اللازم
→ يتبع Noise
→ High variance
```

### 3.3 دافع استخدام Ensemble

يمكن لـ Ensembles تقليل إحدى المشكلتين أوكلتيهما عبر دمج عدة Learners.

ترتبط Bagging بصورة خاصة بتقليل Variance.

ويرتبط Boosting بصورة خاصة بتصحيح Errors المتبقية Sequentially وتقليل Bias، بينما تتحكم Regularization في Variance.

## 4. Bagging

تعني Bagging:

```text
Bootstrap Aggregating: التجميع بإعادة العيّنات
```

يصفها المصدر هكذا:

```text
تدريب نسخ كثيرة من Base learner
على إصدارات مختلفة أُعيد Sampling لها من Training data
ثم تجميع Predictions
```

يتم تدريب Models بصورة مستقلة.

تعني هذه الاستقلالية أن Training يمكن أن تتم غالبًا بالتوازي.

---

### 4.1 لماذا تعمل Bagging؟

إذا رأت كل Model Training sample مختلفة قليلًا:

```text
Model errors تختلف
```

فإن Aggregation تقوم بعد ذلك بتنعيم Variation الفردية.

لهذا ترتبط Bagging بقوة بـ:

```text
تقليل التباين
```

## 5. Bootstrap sampling

ينشئ Bootstrapping Datasets جديدة عبر Sampling:

```text
مع الإرجاع (with replacement)
```

افترض أن Original data هي:

```text
[A, B, C, D, E]
```

قد تكون إحدى Bootstrap samples:

```text
[A, C, C, E, B]
```

وأخرى:

```text
[D, D, A, E, C]
```

يمكن لكل Sample أن:

- تكرر Rows،
- تحذف Rows أخرى،
- تبقى بالحجم نفسه مثل Original training set.

## 6. تجميع Bagged predictions

بعد تدريب Independent learners:

### Regression

Aggregation شائعة:

```text
Average للـ Numeric predictions
```

مثال:

```text
الشجرة 1 → 80
الشجرة 2 → 90
الشجرة 3 → 85

Ensemble
→ 85
```

---

### Classification

Aggregation شائعة:

```text
تصويت الأغلبية (majority vote)
```

أو:

```text
Average للـ Predicted probabilities
```

مثال:

```text
النموذج 1 → churn
النموذج 2 → stay
النموذج 3 → churn

الأغلبية
→ churn
```

## 7. Random Forest

Random Forest هي Algorithm الـ Bagging الأساسية في الفصل.

تجمع:

```text
bootstrap sampling
+
مجموعات خصائص عشوائية فرعية
+
أشجار قرار كثيرة
+
تجميع التنبؤات
```

المكوّن الجديد المهم مقارنة بـ Ordinary bagging هو:

```text
feature subspacing    # الفضاءات الفرعية للخصائص
```

عند كل Tree split، يتم النظر فقط إلى Random subset من Features.

---

### 7.1 لماذا تهم Random feature subsets؟

افترض أن Predictor واحدة قوية جدًا.

من دون Feature subsetting:

```text
Many trees
→ تختار Predictor نفسها بصورة متكررة
→ تصبح Trees أكثر تشابهًا
```

إذا اتخذت Trees قرارات متشابهة جدًا:

```text
تنوّع ensemble ↓
```

تجبر Random feature selection الـ Trees على استكشاف Alternative splits.

وهذا يقلل Correlation بين Trees ويقوي Variance reduction.

## 12. الأشجار شديدة العشوائية Extremely Randomized Trees (Extra Trees)

تزيد Extra Trees الـ Randomness مقارنة بـ Random Forest.

يسلط المصدر الضوء على اختلافين رئيسيين.

---

### 12.1 Bootstrap behavior

تستخدم Random Forest عادةً:

```text
يستخدم عيّنات bootstrap
```

أما Extra Trees فتستخدم عادةً:

```text
يستخدم مجموعة البيانات كاملة
بدون bootstrap
```

ما لم يتم تفعيل Bootstrapping صراحة.

---

### 12.2 Split thresholds

Random Forest:

```text
تبحث Candidate split thresholds
وتختار Split قوية
```

Extra Trees:

```text
تأخذ Thresholds بصورة Random
ثم تختار من بين هذه Random proposals
```

وهذا يزيد Tree diversity.

---

### 12.3 المفاضلة المتوقعة (Expected trade-off)

قد تؤدي Randomness الأكبر إلى:

```text
Variance ↓
Bias ↑ قليلًا
```

ومع ذلك قد تظل Overall ensemble قادرة على Generalize بصورة ممتازة.

يذكر المصدر أن Extra Trees يمكن أن تتدرب بسرعة وتعمل جيدًا مع Noisy أوHigh-dimensional tabular data.

---

## 13. Random Forest مقابل Extra Trees

| الخاصية | Random Forest | Extra Trees |
|---|---|---|
| Base learner | Decision tree | Decision tree |
| أخذ عيّنات الصفوف المعتاد | Bootstrap | غالبًا Full data |
| Feature randomness | نعم | نعم |
| Threshold search | بحث أقوى بين Candidate thresholds | Thresholds أكثر Random |
| Diversity | مرتفعة | غالبًا أعلى |
| الأثر الرئيسي في ensemble | تقليل Variance | Variance reduction عبر Randomization أقوى |

لا توجد ضمانة أن واحدة منهما ستفوز دائمًا.

يشجع المصدر على فهم كيف تغيّر Randomness الإضافية Bias وVariance.

## 14. Boosting

Boosting مختلفة جذريًا عن Bagging.

Bagging:

```text
Models يتم تدريبها بصورة مستقلة
```

Boosting:

```text
Models يتم تدريبها بصورة Sequential
```

تركز كل Learner جديدة على ما لا تزال Ensemble الحالية تخطئ فيه.

---

### 14.1 النموذج الإضافي المرحلي (Stage-wise additive model)

مفاهيميًا:

```text
Model 1
    ↓
العثور على Errors
    ↓
Model 2 تصحح بعض Errors
    ↓
Model 3 تصحح Errors المتبقية
    ↓
...
    ↓
Weighted/Additive final model
```

لهذا يصف المصدر Boosting بأنها:

```text
تكراري
تصحيحي
```

---

## 15. لماذا تعمل Boosting — ولماذا يمكن أن Overfit؟

يسلط المصدر الضوء على أربع أفكار.

### Error focus

تركز Learners اللاحقة أكثر على:

- Misclassified points،
- Residual-like errors،
- Loss gradients.

### Learning rate

تساهم كل Learner بتصحيح مضبوط فقط.

يمكن لـ Small steps أن تجعل Ensemble أقل حساسية للـ Noise.

### Regularization

تشمل الأمثلة:

- Shallow trees،
- Row subsampling،
- Feature subsampling،
- Early stopping.

### Loss optimization

يمكن لـ Boosting تحسين Loss مختارة مثل:

- Squared error،
- Logistic loss.

---

### 15.1 Bias وVariance

غالبًا تقلل Boosting الـ Bias عبر إضافة Corrective learners.

لكن من دون Regularization:

```text
عدد كبير جدًا من Learners
أو
تصحيحات Aggressive أكثر من اللازم
→ Overfitting risk
```

إذن تأتي قوة Boosting من:

```text
تصحيح تسلسلي
+
تعقيد مضبوط
```

## 16. AdaBoost

AdaBoost تعني:

```text
Adaptive Boosting: التعزيز التكيفي
```

وهي تدمج Weak learners كثيرة.

يستخدم المصدر Shallow decision trees كـ Weak learners.

الفكرة الأساسية:

```text
Hard examples
تتلقى Attention أكبر
في Rounds اللاحقة
```

---

### 16.1 Initial weights

في البداية:

```text
كل Training observation
لها Importance متساوية
```

---

### 16.2 Fit للـ Weak learner

درّب Learner الأولى باستخدام Current sample weights.

---

### 16.3 قياس Weighted error

تساهم Observations التي تم Misclassify لها في Error الخاصة بالـ Learner.

تحصل Learner الأفضل على Influence أكبر داخل Ensemble.

---

### 16.4 Reweight للـ Observations

Misclassified examples:

```text
الوزن ↑
```

أمثلة مصنَّفة بشكل صحيح:

```text
الوزن النسبي ↓
```

لذلك تركز Learner التالية بصورة أقوى على Difficult observations.

---

### 16.5 Aggregation للـ Learners

تستخدم Final output Weighted combination من Learners.

في Classification تُستخدم عادةً:

```text
تصويت / درجات موزونة
```

## 18. Gradient Boosting

Gradient Boosting أيضًا Stage-wise، لكنها لا تعتمد أساسًا على Reweighting للـ Examples مثل AdaBoost.

بدلًا من ذلك، تلائم كل Learner جديدة:

```text
Error signal
مشتقة من Loss gradient
```

يصف المصدر ذلك بأنه اتباع Negative gradient للـ Loss المختارة.

---

### 18.1 Core workflow

ابدأ بـ:

```text
تنبؤ ثابت أساسي (baseline)
```

ثم كرر:

```text
1. حساب Current loss error signal
2. حساب Negative gradient
3. Fit لـ Weak learner على ذلك Signal
4. Scale لمساهمة Learner باستخدام Learning rate
5. إضافة Correction إلى Current model
```

---

### 18.2 Intuition

في Squared-error regression، تتصرف Negative gradient مثل Residual correction.

وفي Classification، يعكس Loss gradient الاتجاه الذي يقلل Classification loss.

إذن تعمم Gradient Boosting الفكرة:

```text
"Fit للـ Remaining mistakes"
```

عبر Explicit loss optimization.

## 27. OvR مقابل OvO

| OvR | OvO |
|---|---|
| Classifier واحدة لكل Class | Classifier واحدة لكل Class pair |
| تتوسع تقريبًا Linear مع عدد Classes | تنمو Quadratic مع عدد Classes |
| Strong default عندما تكون Classes كثيرة | مفيدة عندما يكون عدد Classes متوسطًا |
| كل Classifier ترى Class واحدة مقابل جميع الآخرين | كل Classifier تركز على Classين |

Rule of thumb في المصدر:

```text
Classes كثيرة / Compute محدود
→ OvR

عدد Classes متوسط / Pairwise discrimination قوية
→ OvO
```

### ملاحظة اتساق المصدر

يقول المصدر إن «كلتا الطريقتين تحتاجان Model واحدة فقط»، لكنه يشرح بعد ذلك بصورة صحيحة أن OvR تدرب Classifier لكل Class وأن OvO تدرب Classifier لكل Pair من Classes.

المعنى المقصود هو:

```text
Base model family/Type واحدة
يُعاد استخدامها عبر Binary subproblems متعددة
```

وليس Fitted classifier واحدة فقط.

## 29. Out-of-fold predictions للـ Stacking

هذه واحدة من أهم أفكار الفصل.

```text

```

كرر حتى تصبح لكل Training observation:

```text
تنبؤ out-of-fold
```

تصبح OOF predictions هذه Features للـ Meta-model.

## 33. Intuition الخاصة بـ Gradient وHessian

لكل Training point، يمكن لـ XGBoost استخدام:

### Gradient

المشتقة الأولى للـ Loss.

مفاهيميًا:

```text
الميل (slope)
→ اتجاه التحسن
```

---

### Hessian

المشتقة الثانية.

مفاهيميًا:

```text
Curvature
→ مدى سرعة تغير Slope
```

يشرح المصدر أن استخدام الاثنين يسمح بإجراء Updates أدق للـ Splits/Leaves مقارنة بالاعتماد على First-order gradient فقط.

لا تحتاج إلى اشتقاق Optimization equations كاملة هنا.

الفكرة الأساسية هي:

> تستخدم XGBoost كلًا من Direction وCurvature information الخاصة بالـ Loss أثناء بناء Corrective trees.

## 35. Parameters خاصة بـ Regularization في XGBoost

### `reg_lambda`

L2 penalty على Leaf weights.

مفاهيميًا:

```text
أوزان الأوراق الكبيرة
→ تقليص (shrink)
```

---

### `reg_alpha`

L1 penalty على Leaf weights.

يذكر المصدر أنها قد تدفع بعض Weights نحو Zero.

---

### `min_child_weight`

Minimum Hessian sum مطلوبة داخل Child قبل السماح بالـ Split.

يقارن المصدر دورها مفاهيميًا بـ Minimum leaf-size restriction.

---

### `gamma`

Minimum required loss reduction المطلوبة للـ Split.

إذا لم يحسن Proposed split الـ Objective بما يكفي:

```text
لا تنشئ Split
```

---

### `tree_method`

تتحكم في Tree-building strategy.

يستخدم المصدر:

```text
"hist"    # خوارزمية بناء الأشجار
```

ويسرد Alternatives في نصه التوضيحي.

---

### 35.1 لماذا تهم هذه Parameters؟

لا يأتي أداء XGBoost فقط من إضافة Trees كثيرة.

بل تتحكم أيضًا في Complexity بصورة صريحة.

وهذا يساعد على إدارة:

```text

compute    # الحوسبة
sparsity    # التناثر
```

## مفاهيم خاطئة مهمة

### المفهوم الخاطئ 1

> «Ensemble هي مجرد Model واحدة كبيرة جدًا.»

تجمع Ensemble عدة Learners، وغالبًا تختلف هذه Learners في Data أوFeatures أوErrors أوModel families.

---

### المفهوم الخاطئ 2

> «High variance تعني أن Model تعمم بصورة جيدة جدًا.»

الصياغة الافتتاحية في المصدر غير متسقة مع شرحه اللاحق.

ترتبط High variance بعدم الاستقرار وOverfitting، وليس Strong generalization.

---

### المفهوم الخاطئ 3

> «Bagging تدرب Models الخاصة بها بصورة Sequential.»

يتم تدريب Bagging models بصورة مستقلة.

أما Boosting فهي Sequential.

---

### المفهوم الخاطئ 4

> «Bootstrap sampling تعني Sampling without replacement.»

تستخدم Bootstrap sampling الـ Replacement.

ومن المتوقع وجود Observations مكررة.

---

### المفهوم الخاطئ 5

> «Random Forest هي فقط Ordinary bagging للـ Trees.»

تستخدم Random Forest أيضًا Random subsets من Candidate features عند Splits.

تساعد هذه Randomness الإضافية على تقليل Correlation بين Trees.

---

### المفهوم الخاطئ 6

> «Out-of-bag تعني أن Row حُذفت من Forest كلها.»

قد تكون Row مستبعدة من Bootstrap sample الخاصة بـ Tree واحدة لكنها موجودة داخل Sample الخاصة بـ Tree أخرى.

---

### المفهوم الخاطئ 7

> «Feature importance تثبت أن Feature تسبب Outcome.»

يتعامل المصدر معها بوصفها Predictive split contribution ويحذر من Bias المرتبط بالـ Correlated variables.

---

### المفهوم الخاطئ 8

> «Extra Trees تستخدم دائمًا Bootstrap samples.»

يذكر المصدر أن Extra Trees تستخدم Full data غالبًا ما لم يتم Enable للـ Bootstrap.

---

### المفهوم الخاطئ 9

> «Boosting تدرب كل Learners بصورة مستقلة.»

تتأثر كل Learner بما لم تنجح Learners السابقة في Modeling له جيدًا.

---

### المفهوم الخاطئ 10

> «Learning rate تتحكم فقط في Training speed.»

هي تغير أيضًا قوة Correction في كل Stage وبالتالي تؤثر في Regularization.

---

### المفهوم الخاطئ 11

> «AdaBoost وGradient Boosting تصلحان Errors بالطريقة نفسها تمامًا.»

تزيد AdaBoost الاهتمام بـ Difficult weighted examples.

أما Gradient Boosting فتلائم Negative gradient الخاصة بـ Loss مختارة.

---

### المفهوم الخاطئ 12

> «Hard voting تقوم بعمل Average للـ Probabilities.»

تجمع Hard voting الـ Predicted labels.

أما Soft voting فتجمع Probabilities.

---

### المفهوم الخاطئ 13

> «ينبغي أن تحصل كل Model داخل Voting ensemble على Preprocessing نفسها.»

يستخدم المصدر Model-specific pipelines لأن KNN/Linear models وTree models لها احتياجات Preprocessing مختلفة.

## ملاحظات اتساق المصدر والتفسير

### صياغة High variance

يقول المصدر:

```text
تباين مرتفع
لأن النموذج عمّم أكثر من اللازم
```

لكنه يشرح لاحقًا بصورة صحيحة أن High-degree polynomial حساسة لتغييرات Training data وعرضة للـ Overfitting.

يتبع هذا الدرس التفسير اللاحق المتسق داخليًا.

### Random Forest والبيانات Mixed

يقول النص إن Random Forest تعمل جيدًا مع Mixed-type tabular data.

لكن Implementation الفعلية في المصدر ما تزال تعمل Encoding للـ Categorical features باستخدام `OneHotEncoder`.

لذلك لا ينبغي تفسير «Mixed-type» على أنها تعني أن Raw strings مقبولة مباشرة في Scikit-learn pipeline المعروضة.

### Feature importance

Random Forest feature importance في المصدر Impurity-based.

كما يحذر من أن Correlated predictors قد تجعل Interpretation منحازة.

### صياغة Extra Trees للـ Threshold

يصف المصدر Extra Trees بأنها تستخدم Randomized split thresholds بدل Exhaustive evaluation لكل Thresholds الممكنة.

التمييز المفاهيمي المهم هو Increased split randomness، وليس ضمانًا لتفصيل Implementation محدد في كل Library/Version.

### تفسير Diagram الخاصة بـ Boosting

يوحي المصدر بأن Later learners ينبغي نظريًا أن تملك Error أقل من Earlier learners.

تهدف Sequential boosting إلى تقليل Ensemble loss، لكن جودة Individual learner لا يلزم أن تتحسن Monotonically بصورة مستقلة وبسيطة.

### معادلات AdaBoost

بعض Formulas في النص المقدم تالفة جزئيًا بسبب Image extraction.

يحافظ الدرس على الخطوات المفاهيمية التي يدعمها المصدر:

```text
أوزان متساوية
→ ملاءمة learner ضعيف
→ قياس الخطأ الموزون
→ وزن الـ learner
→ زيادة أوزان الأمثلة الصعبة
→ تكرار
```

من دون اختراع Symbols مفقودة.

### صياغة «Model واحدة» في OvR/OvO

يقول المصدر إن الطريقتين «تحتاجان Model واحدة فقط»، ثم يوضح بصورة صحيحة أن OvR تدرب Classifier لكل Class وأن OvO تدرب Classifier لكل Pair من Classes.

التفسير المتسق هو:

```text
Base classifier family واحدة
يُعاد استخدامها عبر Fitted binary submodels كثيرة
```

### قائمة Parameters الخاصة بـ XGBoost

يحافظ الدرس على معاني Parameters الواردة في المصدر ولا يوسعها بوثائق خارجية خاصة بإصدارات بعينها.
