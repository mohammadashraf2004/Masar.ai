## 1. الصورة الرقمية هي بيانات (Digital image)



أهم فكرة في هذا الدرس بسيطة:



> **الصورة الرقمية ليست مجرد صورة مرئية؛ بل هي بنية بيانات رقمية.**



عندما تنظر إلى صورة فوتوغرافية، ترى أجسامًا وألوانًا وملامس وأشكالًا. لا يبدأ الكمبيوتر بهذه المعاني، بل يبدأ بأرقام مرتبة على Grid منفصلة.



يُسمّى موضع واحد في الصورة **Pixel** (picture element). ويخزن كل Pixel قيمة رقمية واحدة أو أكثر.



### صورة Grayscale



تخزن صورة Grayscale قيمة Intensity واحدة في كل موضع.



من الناحية المفاهيمية:



```text
[
  [  0,  40, 120, 255],
  [ 10,  80, 160, 240],
  [ 20, 100, 180, 220]
]
```



إذا كان ارتفاع الصورة هو `H` وعرضها هو `W`، فعادةً ما تُمثّل صورة Grayscale بالشكل:



```text
(H, W)
```



على سبيل المثال:



```text
(340, 453)
```



وهذا يعني 340 صفًا و453 عمودًا.



### صورة ملونة (Color image)



تخزن صورة RGB ثلاث قيم لكل Pixel:



```text
(R, G, B)
```



لذلك يكون Shape الخاص بـ Array عادةً:



```text
(H, W, 3)
```



تمثّل Channels الثلاث مكونات Red و Green و Blue.



وتضيف صورة RGBA قناة Alpha للشفافية:



```text
(H, W, 4)
```

### Sampling و Quantization



يتطلب تحويل مشهد بصري مستمر إلى صورة رقمية فكرتين أساسيتين:



1. **Spatial sampling** يقسم المساحة المستمرة إلى Grid من مواضع Pixels.

2. **Amplitude quantization** يحوّل قياسات Intensity أو اللون المستمرة إلى مجموعة محدودة من القيم الرقمية.



وهذا يمنحنا Array رقمية محدودة يمكن للبرمجيات معالجتها.



في صورة شائعة بدقة 8-bit، تستخدم Channel واحدة غالبًا قيمًا من:



```text
0 to 255
```



أما في المعالجة باستخدام Floating-point بعد Normalization، فغالبًا ما تُمثّل القيم تقريبًا بالشكل:



```text
0.0 to 1.0
```



### الملف مقابل الصورة داخل الذاكرة (File versus in-memory image)



ملف PNG أو JPEG ليس الشيء نفسه الذي تمثله Array التي تتعامل معها في Python.



قد يحتوي الملف على:



- بيانات Pixels مضغوطة،

- Metadata،

- معلومات الألوان،

- بنية خاصة بالتنسيق.



عندما تحمّل مكتبة لمعالجة الصور الملف، فإنها **تفك ترميز** التمثيل المخزن إلى Object داخل الذاكرة مثل:



- كائن `PIL.Image.Image`، أو

- كائن NumPy `ndarray`.



وهذه Array هي ما تعمل عليه فعليًا معظم خوارزميات Image processing.



### لماذا يهم هذا النموذج الذهني؟



عندما تفهم الصورة على أنها Array، تصبح كثير من العمليات مجرد عمليات رقمية عادية:



- يصبح Cropping عبارة عن Array slicing،

- يصبح Thresholding عبارة عن Comparison،

- يصبح Masking عبارة عن Boolean indexing،

- تصبح تغييرات Brightness عمليات حسابية،

- يصبح Color conversion تحويلًا بين تمثيلات Channels،

- يصبح Filtering حسابًا محليًا على Neighborhoods.



وهذا هو الجسر بين «الصور» و«الخوارزميات».

## 2. Image Processing و Computer Vision و Processing Pipeline



### ما هي Digital Image Processing؟



Digital Image Processing هي المعالجة والتحويل والتحليل والتفسير الحسابي للصور الممثلة في صورة رقمية.



تشمل الأهداف الشائعة:



- تحسين الجودة البصرية،

- إزالة Noise،

- تصحيح العيوب،

- تغيير اللون أو Contrast،

- تنفيذ Segmentation للمناطق،

- استخراج Features،

- تجهيز البيانات البصرية لتحليل لاحق.



### Image Processing مقابل Computer Vision



يتداخل المجالان، لكن من المفيد التمييز بين أهدافهما.



يركز **Image Processing** غالبًا على تحويل بيانات الصورة أو تحليلها.



أمثلة:



- Denoising لإزالة Noise،

- Sharpening لزيادة الحدة،

- تحسين Contrast،

- Color conversion،

- Segmentation،

- تنفيذ Edge detection.



ويركز **Computer Vision** بدرجة أكبر على تمكين الآلة من تفسير المحتوى البصري.



أمثلة:



- Image classification،

- Object recognition،

- Object detection،

- Tracking،

- مهام Scene understanding.



نموذج ذهني مفيد هو:



```text
Image processing: "كيف ينبغي أن أحوّل Pixels أو أحللها؟"

Computer vision:  "ماذا تخبر البيانات البصرية الآلة عن العالم؟"
```



ويربط الفصل هذه الأفكار أيضًا بمجالات ذات صلة:



- **Machine vision:** الفحص الصناعي والقياس واكتشاف العيوب و Automation.

- **Computational photography:** تقنيات HDR و Image stitching و Deblurring و Computational enhancement.

- **Remote sensing:** تحليل الصور الملتقطة بواسطة الأقمار الصناعية والطائرات وغيرها من Sensors.



### تطبيقات شائعة



تظهر Digital Image Processing في:



- التصوير الطبي والبيولوجي،

- صور الأقمار الصناعية والفضاء،

- التصوير الفوتوغرافي،

- OCR،

- التعرف على بصمات الأصابع والوجوه،

- Robotics،

- Barcode scanning،

- مراقبة الجودة الصناعية،

- معالجة الصور في Social media،

- أنظمة الفيديو والبث.



### Processing Pipeline القياسي للصور



غالبًا ما يتبع نظام عملي لـ Image processing تسلسلًا مثل الآتي:



```text
الاكتساب (Acquire)
   ↓
التحميل والتمثيل (Load / Represent)
   ↓
المعالجة المسبقة والتحسين والاستعادة (Preprocess / Enhance / Restore)
   ↓
تنفيذ Segmentation أو عزل المناطق المهمة (Segment or isolate relevant regions)
   ↓
استخراج Features أو تعلّمها (Extract or learn features)
   ↓
التعرّف والاكتشاف والتصنيف والقياس (Recognize / Detect / Classify / Measure)
   ↓
عرض النتائج وحفظها ونقلها (Visualize / Save / Transmit results)
```



لا يستخدم كل مشروع جميع المراحل، وقد يختلف الترتيب، لكن هذا Pipeline وسيلة قوية لتنظيم طريقة تفكيرك.

### Features المصممة يدويًا مقابل المتعلّمة



قبل أن يصبح Deep learning مهيمنًا، اعتمدت أنظمة Vision كثيرة بدرجة كبيرة على Features مصممة مثل Edges و Corners أو Descriptors مثل HOG.



أما الأنظمة الحديثة فقد تتعلم Feature representations تلقائيًا باستخدام Neural networks.



ومع ذلك، يعتمد كلا النهجين على الأساس نفسه:



> يجب أولًا تمثيل الصور وتحميلها وتحويلها وتفسيرها بصورة صحيحة.

## 5. File formats و Image modes و Data types



هذه الأفكار الثلاثة مترابطة لكنها مختلفة.



### تنسيق الملف (File format)



يصف **File format** كيفية Encoding الصورة وتخزينها.



من الأمثلة الشائعة الواردة في الفصل:



| التنسيق (Format) | الخصائص الرئيسية |
|---|---|
| تنسيق BMP | تمثيل Raster بسيط، وغالبًا ما يكون حجمه كبيرًا |
| تنسيق PNG | ضغط Lossless ويدعم الشفافية |
| تنسيق JPEG | ضغط Lossy ومناسب جدًا للصور الفوتوغرافية |
| تنسيق GIF | يعتمد على Palette وألوانه محدودة ويدعم Animation |
| تنسيق PPM/PNM | تنسيقات بسيطة، غالبًا كبيرة الحجم ومفيدة أساسًا للتبادل البسيط والتعليم |
| تنسيق TIFF | تنسيق مرن وعالي الجودة مع دعم قوي لـ Metadata والاستخدام الاحترافي |



### نمط الصورة (Image mode)



يصف **Image mode** كيفية تفسير قيم Pixels.



تشمل Pillow modes الشائعة:



| النمط (Mode) | المعنى |
|---|---|
| النمط `1` | Binary / أبيض وأسود |
| النمط `L` | Grayscale بدقة 8-bit |
| النمط `P` | لون قائم على Palette / Indexed color |
| النمط `RGB` | Red و Green و Blue |
| النمط `RGBA` | RGB مع Alpha / Transparency |
| النمط `CMYK` | Cyan و Magenta و Yellow و Black |
| النمط `F` | Pixels من نوع Floating-point |



### عمق البت (Bit depth)



يحدد Bit depth عدد القيم التي يمكن لـ Pixel أو Channel تمثيلها.



بالنسبة إلى 8 bits:



```text
2^8 = 256 levels — عدد المستويات الممكنة في 8 bits
```



وعادةً:



```text
0 ... 255
```

## 6. Color spaces: اختيار التمثيل المناسب



Color space هو نظام إحداثيات لتمثيل اللون.



تكون التمثيلات المختلفة مفيدة لأن المهام المختلفة تهتم بجوانب مختلفة من اللون.



### نموذج الألوان RGB



يمثل RGB اللون باستخدام مكونات Red و Green و Blue.



وهو تمثيل طبيعي لـ:



- الشاشات،

- الكاميرات،

- التمثيل الرقمي العام للصور.



فكّر فيه على أنه ثلاث Channels للـ Intensity:



```text
R
G
B
```



### نموذج الألوان HSV



يفصل HSV اللون إلى:



- **Hue:** نوع اللون،

- **Saturation:** مدى تشبّع اللون،

- **Value:** مستوى Brightness.



وغالبًا ما يكون مفيدًا في:



- Color filtering،

- Color segmentation،

- تغيير Saturation،

- اختيار لون مع تغيير Brightness بصورة مستقلة.





### نموذج الألوان CMYK



يستخدم CMYK:



- اللون Cyan،

- اللون Magenta،

- اللون Yellow،

- اللون Black.



وهو Subtractive color model مرتبط بقوة بالطباعة.



يعتمد RGB على الضوء المنبعث، بينما يعتمد CMYK على الأحبار التي تطرح أجزاءً من الضوء المنعكس.



### نموذج الألوان Lab



يفصل Lab بين:



- `L*`: Lightness،

- `a*`: بُعد لوني متقابل (opponent color dimension)،

- `b*`: بُعد لوني متقابل (opponent color dimension).



يستخدم الفصل Lab في العمليات التي يكون فيها تغيير Brightness بصورة مستقلة عن اللون مفيدًا.



### تمثيلات YUV / YCbCr



تفصل هذه التمثيلات معلومات Luminance/Luma عن معلومات Chrominance.



وهي مهمة في:



- التلفزيون،

- Workflows المرتبطة بـ JPEG،

- Video compression،

- البث.

- استهلاك Memory،

- Computational cost،

- التعقيد.



لكنه قد يتخلص أيضًا من معلومات مهمة للمهمة.



على سبيل المثال، إذا كان تمييز Object يعتمد أساسًا على اللون، فقد يجعل التحويل إلى Grayscale فصله أكثر صعوبة بكثير.

## المصطلحات الأساسية



| المصطلح (Term) | المعنى |
|---|---|
| البكسل (Pixel) | أصغر عنصر قابل للعنونة في الصورة ويخزن قيمة واحدة أو أكثر |
| القناة (Channel) | مكوّن واحد من تمثيل صورة متعدد المكونات |
| عملية Sampling | تحويل الإحداثيات المكانية المستمرة إلى مواضع Pixels منفصلة |
| عملية Quantization | تحويل القياسات المستمرة إلى مجموعة محدودة من قيم Intensity/Color |
| تمثيل Grayscale | تمثيل Intensity أحادي Channel |
| نموذج RGB | تمثيل لوني Additive يعتمد على Red و Green و Blue |
| نموذج HSV | تمثيل يعتمد على Hue و Saturation و Value |
| نموذج Lab | تمثيل لوني يفصل Lightness عن أبعاد اللون المتقابلة |
| تمثيلات YUV / YCbCr | تمثيلات تفصل Luminance/Luma عن Chrominance |
| قناة Alpha (Alpha channel) | معلومات الشفافية لكل Pixel |
| نطاق الألوان (Color gamut) | نطاق الألوان الذي يستطيع جهاز أو نظام تمثيله |
| مصفوفة NumPy ndarray | Array رقمية متعددة الأبعاد تُستخدم عادةً لتخزين بيانات الصور |
| نمط الصورة (Image mode) | تفسير مكونات Pixel، مثل `L` أو `RGB` أو `RGBA` |
| تنسيق الملف (File format) | تمثيل تخزين مُرمّز مثل PNG أو JPEG |
| عمق البت (Bit depth) | عدد Bits المستخدمة لتمثيل قيم Pixel/Channel |
| عملية Normalization | تحويل القيم إلى نطاق رقمي مختار |
| القناع (Mask) | Array تحدد Pixels/المناطق المطلوب اختيارها أو تعديلها |
| خريطة الألوان (Colormap) | Mapping من Scalar values إلى ألوان معروضة |
| ترتيب BGR | ترتيب Channels من Blue ثم Green ثم Red والمستخدم عادةً في OpenCV |
| عملية Cropping | استخراج منطقة فرعية مستطيلة |
| عملية Alpha blending | دمج موزون لصورتين متوافقتين |
| أسلوب Vectorization | تطبيق عمليات على مستوى Array بدلًا من Python loops الصريحة |
