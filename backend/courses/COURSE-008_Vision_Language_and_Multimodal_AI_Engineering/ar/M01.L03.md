## 2. "كيف": أهم Training paradigms

### 2.1 التعلم الخاضع للإشراف (Supervised learning)

يستخدم Supervised learning هدفًا صريحًا.

بالنسبة إلى VLM:

```text
المدخل (input):
صورة (image) + تعليمات (instruction)

الهدف (target):
إجابة كتبها إنسان أو إجابة synthetic
```

مثال:

```text
الصورة (Image): cat sitting on a chair
المطالبة (Prompt): "Describe the image."
الهدف (Target): "A cat is sitting on a chair."
```

يتعلم Model أن يجعل مخرجاته المُولَّدة أقرب إلى target المقدم.

يربط الفصل المقدم Supervised learning بمهام مثل:

- OCR؛
- إنشاء التعليقات التوضيحية (captioning)؛
- التصنيف (classification)؛
- ضبط التعليمات (instruction tuning).

المفاضلة الأساسية هي جودة data مقابل التكلفة.

يمكن أن تكون أمثلة supervised عالية الجودة مفيدة جدًا، لكن إنتاجها قد
يتطلب:

- human annotation؛
- synthetic generation بعناية؛
- filtering؛
- فحص الجودة (quality control).

### 2.2 التعلم غير الخاضع للإشراف (Unsupervised learning)

يستخدم Unsupervised learning بيانات من دون target labels صريحة.

يقدم الفصل الفكرة على هيئة تجميع الصور المتشابهة من دون الحاجة إلى
أسماء لتلك المجموعات.

على سبيل المثال:

```text
صور الجبال (mountain images) → المجموعة A (cluster A)
صور latte-art (latte-art images) → المجموعة B (cluster B)
```

يكتشف النظام البنية من دون أن يُخبر بها:

```text
المجموعة A (cluster A) = جبال (mountains)
المجموعة B (cluster B) = latte art
```

### 2.3 التعلم الذاتي الإشراف (Self-supervised learning)

ينشئ Self-supervision هدف التعلم من data نفسها.

تشمل الأمثلة:

- إخفاء image patch والتنبؤ به؛
- إخفاء text token والتنبؤ به؛
- التنبؤ بالـ next token؛
- استخدام بيانات image-caption المقترنة طبيعيًا.

تكمن قوة Self-supervision في قابلية التوسع.

إذا اشتُقت labels تلقائيًا من data، تصبح datasets ضخمة
قابلة للاستخدام من دون الحاجة إلى human annotation لكل مثال.

### 2.4 التعلم شبه الخاضع للإشراف (Semi-supervised learning)

يجمع Semi-supervised learning بين:

```text
كمية صغيرة من بيانات labeled مرتفعة التكلفة
+
كمية كبيرة من بيانات unlabeled
```

تساعد الأمثلة labeled في تنظيم أو تحسين التعلم من مجموعة
unlabeled الأكبر بكثير.

### 2.5 التعلم التبايني (Contrastive learning)

يعلّم Contrastive learning الـ Model باستخدام العلاقات.

بالنسبة إلى multimodal learning:

```text
صورة (image) + نص (text) متطابقان
        ↓
اجعل embeddings أكثر تشابهًا

صورة (image) + نص (text) غير متطابقين
        ↓
اجعل embeddings أقل تشابهًا
```

هذه هي الفكرة الأساسية التي رأيتها بالفعل في CLIP.

غالبًا ما يُعد Contrastive learning شكلًا من Self-supervised learning، لكنه
يستحق اهتمامًا منفصلًا لأنه كان مهمًا جدًا في ربط فضاءات تمثيل image
و text على نطاق واسع.

### مقارنة مفيدة

| أسلوب التدريب (Training paradigm) | من أين يأتي supervision؟ | مثال |
|---|---|---|
| التعلم الخاضع للإشراف (Supervised learning) | target labels/answers صريحة | صورة + instruction → target answer |
| التعلم غير الخاضع للإشراف (Unsupervised learning) | لا توجد target labels | تجميع الصور المتشابهة |
| التعلم الذاتي الإشراف (Self-supervised learning) | تولّد data هدفها بنفسها | إخفاء patch ثم التنبؤ به |
| التعلم شبه الخاضع للإشراف (Semi-supervised learning) | مجموعة labeled صغيرة + مجموعة unlabeled كبيرة | تعلم موجّه بالـ labels عبر قدر أكبر بكثير من raw data |
| التعلم التبايني (Contrastive learning) | علاقات المطابقة/عدم المطابقة | تقريب أزواج image-text المتطابقة من بعضها |

## 3. "متى": مراحل دورة حياة VLM

### 3.1 مرحلة ما قبل التدريب (Pretraining)

ينشئ Pretraining قدرة أساسية واسعة.

يصف الفصل هذه المرحلة بأنها المكان الذي يتعلم فيه Model فهمًا أوليًا
للعالم من datasets ضخمة جدًا.

بالنسبة إلى VLM مُجمّع من مكونات pretrained، قد يبدأ Pretraining بـ:

```text
vision encoder مُدرَّب مسبقًا (pretrained vision encoder)
+
multimodal connector جديد
+
LLM مُدرَّب مسبقًا (pretrained LLM)
```

استراتيجية عملية هي:

1. تجميد المكونات الكبيرة pretrained؛
2. تدريب connector؛
3. السماح لاحقًا بتحديث أجزاء أكبر من vision/language backbones.

يحمي ذلك المعرفة المفيدة المكتسبة في Pretraining بينما يكون الاتصال الجديد cross-modal
غير مستقر في البداية.

### 3.2 مرحلة التدريب الوسيط (Midtraining)

يستخدم الفصل **midtraining** لمرحلة أحدث تقع بين rough pretraining واسع النطاق
و post-training المنسّق بعناية.

الفكرة هي:

```text
بيانات noisy بحجم الويب (web-scale noisy data)
        ↓
    pretraining — مرحلة ما قبل التدريب
        ↓
بيانات synthetic / وسيطة أعلى جودة
        ↓
    midtraining — مرحلة التدريب الوسيط
        ↓
بيانات instruction/preference أصغر وأعلى جودة
        ↓
    post-training — مرحلة ما بعد التدريب
```

هذه الحدود ليست موحدة في كل مكان. المصطلحات ما تزال تتطور.

وهذه نقطة مهمة:

> أسماء Training stages مفاهيم تنظيمية مفيدة، وليست قوانين ثابتة لا تتغير.

### 3.3 مرحلة ما بعد التدريب (Post-training)

يهدف Post-training إلى تحويل Model ذي قدرة واسعة إلى Model يتبع مهامًا
وتعليمات مفيدة.

تشمل الأهداف المعتادة:

- الإجابة عن الأسئلة؛
- اتباع التعليمات؛
- التصرف باتساق في chat؛
- حل downstream tasks المستهدفة.

يظهر Supervised fine-tuning كثيرًا هنا.

### 3.4 المواءمة السلوكية (Alignment)

يناقش الفصل المقدم Alignment بعد instruction tuning، مستخدمًا
أساليب preference optimization مثل DPO أو PPO كأمثلة.

الهدف هو توجيه behavior نحو preferences مرغوبة.

على مستوى عالٍ:

```text
Model قادر (capable model)
     ↓
instruction tuning — ضبط التعليمات
     ↓
preference/alignment optimization — تحسين التفضيلات والمواءمة
     ↓
سلوك مستهدف أكثر فائدة (more useful target behavior)
```

لا تخلط بين **alignment** وطبقة visual-language projection.

هنا:

- قد تعني **multimodal alignment** جعل تمثيلات vision و language متوافقة؛
- تشير **behavioral alignment** إلى توجيه behavior/preferences الخاصة بالـ Model.

السياق هو الذي يحدد المعنى.

## 5. بناء VLM autoregressive بسيط

يختار الفصل الأبسط بين أسلوبين عامين لبناء VLM:

- دمج autoregressive عبر projected visual embeddings؛
- تفاعل أغنى قائم على cross-attention.

في المثال التعليمي، يستخدم التصميم autoregressive.

البنية المبسطة هي:

```text
مسار الصورة (IMAGE PATH)
الصورة الخام (raw image)
   ↓
معالج الرؤية (vision processor)
   ↓
مشفّر الرؤية (vision encoder)
   ↓
visual embeddings — تمثيلات الصورة
   ↓
linear projector — طبقة الإسقاط الخطي
   ↓
visual embeddings متوافقة مع LLM


مسار النص (TEXT PATH)
النص الخام (raw text)
   ↓
tokenizer — مُقسِّم النص إلى tokens
   ↓
معرّفات tokens (token IDs)
   ↓
طبقة LLM token embedding
   ↓
text embeddings — تمثيلات النص


الدمج (COMBINE)
projected visual embeddings — تمثيلات بصرية مُسقطة
+
text embeddings — تمثيلات النص
   ↓
دمجها بـ concatenation في sequence واحد
   ↓
causal language model — نموذج لغوي سببي
   ↓
next-token logits — درجات token التالية
```

### 5.1 لماذا نحتاج إلى Projector؟

لنفترض أن vision encoder يخرج vectors ذات بُعد:

```text
768
```

بينما يتوقع language model embeddings ذات بُعد:

```text

```

لا يمكن concatenation بينهما مباشرة.

يتعلم linear projector التحويل:

```text
R^768 → R^576
```

حتى تدخل image features إلى LLM بعرض embedding نفسه المستخدم مع text tokens.

### 5.3 ما هي Logits؟

مخرجات LLM هي tensor من raw vocabulary scores.

عند كل موضع في التسلسل:

```text
logits[position] = score for every possible next token — درجة لكل next token ممكنة عند هذا الموضع
```

يحوّل Softmax هذه scores إلى probabilities.

لكن أثناء التدريب نمرر عادةً raw logits مباشرة إلى cross-entropy
loss، والذي ينفذ normalization المناسب داخليًا.

## 6. جعل VLM يتعلم: التنبؤ بالـ Next token

لا يقوم forward pass وحده بتدريب أي شيء.

يتطلب التدريب:

```text
التنبؤ (prediction)
+
الهدف (target)
+
الخسارة (loss)
+
التدرج (gradient)
+
تحديث optimizer (optimizer update)
```

يستخدم الفصل causal language modeling القياسي:

> بالاعتماد على السياق السابق، تنبأ بـ next text token.

### 6.1 لماذا لا نتنبأ بـ Image tokens؟

في architecture البسيط، تكون visual embeddings vectors مستمرة تُنتَج
بواسطة vision encoder.

وليست vocabulary tokens عادية ينبغي أن يتعلم language model
إصدارها.

لذلك يستبعد المصدر المواضع المقابلة لـ image embeddings
من language-model loss.

### 6.2 محاذاة Predictions و Labels

لنفترض أن text tokens هي:

```text
[BOS, The, animal, is, a, giraffe, EOS] — تسلسل tokens مثال
```

يتعلم Model:

```text
عند BOS            → تنبأ بـ The
عند BOS The        → تنبأ بـ animal
عند ... animal     → تنبأ بـ is
... — ويستمر التسلسل
```

يتطلب ذلك إزاحة بمقدار موضع واحد.

مفاهيميًا:

```text
logits: [prediction at t0, prediction at t1, ..., prediction at t(n-1)] — predictions لكل موضع
labels: [token at t1,      token at t2,      ..., token at tn] — target tokens بعد الإزاحة
```

### 6.4 Cross entropy بوصفه "المفاجأة"

عند كل text position، ينتج Model distribution على عناصر vocabulary.

إذا حصل next token الصحيح على probability:

```text
p(correct) = 0.90 — probability مرتفعة للـ token الصحيحة
```

فإن loss تكون صغيرة.

أما إذا:

```text
p(correct) = 0.01 — probability منخفضة للـ token الصحيحة
```

فتكون loss أكبر بكثير.

بالنسبة إلى target token واحد:

```text
loss = -log p(correct token) — خسارة target token الصحيحة
```

لذلك يشجع تقليل cross entropy الـ Model على زيادة probability الخاصة بـ
continuation الصحيح.

- generation عالي الجودة؛
- grounding صحيح؛
- عدم وجود hallucination؛
- generalization جيد.

ما زلنا بحاجة إلى evaluation أثناء inference.

## 9. Naive padding و Constrained padding

### 9.1 الحشو المباشر (Naive padding)

لنفترض أن أطول sequence يحتوي على 2800 tokens.

يجعل Naive padding طول كل sample يساوي 2800.

```text
sample 1: 150 real + 2650 padding — العينة 1
sample 2: 2800 real — العينة 2
sample 3: 310 real + 2490 padding — العينة 3
sample 4: 940 real + 1860 padding — العينة 4
```

هذا سهل التنفيذ، لكنه مكلف.

يظل Model ينفذ attention وحسابات أخرى على عدد كبير من padded
positions رغم أنها لا تحمل learning signal.

يذكر الفصل المقدم أن implementation حقيقيًا بسيطًا قد يهدر
نسبة كبيرة من compute بهذه الطريقة.

### 9.2 تجاهل Padding في Loss

يجب ألا يصبح Padding prediction target.

من الأعراف الشائعة:

```text
ignore_index = -100
```

لأن PyTorch cross entropy يدعم هذه القيمة طبيعيًا.

يناقش المصدر أيضًا خيارًا آخر:

```text
استخدم padding token ID حقيقية
+
اطلب من loss تجاهل هذا الـ ID
```

القاعدة الأساسية هي:

> يجب ألا تساهم مواضع Padding في training objective.

### 9.3 الحشو المقيّد (Constrained padding)

يحدد أسلوب مختلف حدًا أقصى لطول sample:

```text
max_length = 512
```

ثم:

- يتم padding للعينات الأقصر حتى 512؛
- تُستبعد العينات الأطول.

يقلل ذلك هدر Padding.

لكنه يتخلص من الأمثلة الطويلة.

### 9.4 لماذا قد يكون Truncation خطيرًا؟

في تدريب بأسلوب chat، قد يؤدي truncating النهاية إلى إزالة جزء من assistant
response.

وقد يؤدي ذلك إلى إزالة target content نفسه الذي نريد من Model تعلمه.

لذلك يركز الفصل المقدم على استبعاد العينات الأطول من الحد بدلًا
من truncating إياها بصورة عمياء.

## 10. Packing: فكّر في Token budgets لا في Samples منفردة

يغيّر Packing وحدة التفكير.

بدلًا من:

```text
صف تدريب واحد (one training row) = عينة واحدة (one sample)
```

نستخدم:

```text
صف تدريب واحد (one training row) = token budget تحتوي عدة samples
```

على سبيل المثال:

```text
max_length = 2048
```

قد يحتوي packed row على:

```text
sample A: 300 tokens — العينة A
sample B: 700 tokens — العينة B
sample C: 500 tokens — العينة C
sample D: 430 tokens — العينة D
padding: 118 tokens — مقدار الحشو
```

الإجمالي:

```text
2048 tokens — إجمالي طول row
```

كثافة أعلى بكثير.

### 10.1 التعبئة المباشرة (Naive packing)

خوارزمية بسيطة:

1. اقرأ sample؛
2. نفّذ tokenization لها؛
3. إذا كانت تتسع داخل row الحالي، فألحقها به؛
4. وإلا فابدأ row جديدًا.

نسخة متوافقة مع المصدر:

⟦CODE_4⟧

يقلل ذلك Padding بدرجة كبيرة مقارنةً بـ naive sample-by-sample padding.

لكنه ليس optimal لأن ترتيب samples يؤثر في مدى امتلاء rows.

### 10.2 الفكرة الحدسية لـ Bin packing

يشبه Packing هذه المسألة:

```text
الصناديق سعتها 2048 (boxes have capacity 2048)
العناصر لها أحجام مختلفة (items have different sizes)
ضع العناصر داخل الصناديق (place items into boxes)
قلّل المساحة الفارغة (minimize empty space)
```

ولهذا تظهر أفكار knapsack/bin-packing.

## 11. Greedy packing و Balanced packing

### 11.1 التعبئة الجشعة (Greedy packing)

يقترح الفصل:

1. اجمع pool من samples؛
2. رتّبها من الأطول إلى الأقصر؛
3. ضع كل sample في row موجود إذا كانت تتسع؛
4. وإلا فأنشئ row جديدًا.

مفاهيميًا:

```text
مجموعة العينات (pool):
[900, 800, 700, 650, 500, 400, 300, 200] — أطوال samples

السعة (capacity):
2048 — السعة القصوى

Rows ممكنة (possible rows):
[900 + 700 + 400] — row محتمل
[800 + 650 + 500] — row محتمل
[300 + 200 + ...] — row محتمل
```

يمكن أن يقلل ذلك المساحة غير المستخدمة بدرجة كبيرة.

### 11.2 لماذا يساعد Sorting؟

يصعب وضع samples الطويلة لاحقًا.

وبوضعها أولًا، تستطيع الخوارزمية استخدام samples الأقصر لملء
الفجوات المتبقية.

### 11.3 التعبئة المتوازنة (Balanced packing)

قد ينتج Pure greedy packing:

- عدة rows كثيفة؛
- row أخيرًا يحتوي Padding كبيرًا؛
- أعدادًا غير متوازنة من samples/images لكل row.

يصف الفصل استراتيجية balanced تحاول وضع sample التالية
داخل أقصر row حالي يمكنه استيعابها.

والهدف هو الحصول على أطوال rows أكثر توازنًا.

### 11.4 التوازن Multimodal لا يتعلق بـ Text tokens فقط

في VLMs، للصور تكلفة compute أيضًا.

تخيّل distributed training:

```text
GPU 1 row: 8 images — row على GPU 1
GPU 2 row: 2 images — row على GPU 2
GPU 3 row: 1 image — row على GPU 3
GPU 4 row: 1 image — row على GPU 4
```

حتى إذا كانت أطوال text متشابهة، فقد ينتهي GPU 1 من vision encoding بعد الآخرين بكثير.

لذلك يمكن لـ packing المتقدم تتبع:

- عدد tokens؛
- عدد الصور.

## 15. التدريب باستخدام Real packed batches

بعد نقل preprocessing إلى خارج Model، يصبح data pipeline كالتالي:

```text

  ↓
تنسيق المحادثة (chat formatting)
  ↓
إدراج image placeholders
  ↓
تنفيذ tokenization
  ↓
تنفيذ packing لعدة samples
  ↓
تنفيذ padding للـ packed rows
  ↓
stack للـ rows داخل tensor batch
  ↓
جمع الصور المقابلة
  ↓
```

## 17. لماذا تهم اختبارات Qualitative generation؟

يدرّب الفصل VLM صغيرًا جدًا لعدد محدود من الخطوات.

وعند اختباره qualitatively، تظهر مشكلتان شائعتان:

### Hallucination

يصف Model أشياء غير موجودة.

نمط مثال:

```text
الصورة (image): mountain landscape
Model: mentions trees that are not actually there — يذكر أشجارًا غير موجودة فعليًا
```

### التكرار (Repetition)

قد يكرر Model:

```text
"It is a mountain. — جملة مكررة
 It is a mountain. — جملة مكررة
 It is a mountain..." — جملة مكررة
```

كشف هذا التكرار عن training bug أعمق.

### 17.1 خطأ PAD/EOS

يوضح الفصل أنه، بالنسبة إلى إعداد language model المختار:

```text
رمز الحشو (padding token)
=
end-of-sentence token — token نهاية الجملة
```

تجاهلت training loss رمز pad.

وبالتالي تجاهلت EOS أيضًا.

وهذا يعني أن Model لم يتلقَّ reward أبدًا لتعلم:

```text
"this is where the answer should stop" — هذا هو موضع توقف الإجابة
```

لذلك كان يمكنه الاستمرار بلا نهاية.

### الإصلاح

استخدم semantics مختلفة:

```text
PAD → ignored by loss — يتجاهله loss
EOS → valid prediction target — target صحيحة للتنبؤ
```

implementation آمن هو:

```text
padding label = -100 — label خاصة بالـ padding
EOS label = eos_token_id — label الخاصة بـ EOS
```

⟦CODE_11⟧

الدرس الأساسي أكبر من EOS.

يمكن أن تتناقص training loss مع وجود defect سلوكي خطير.

يمكن للفحص qualitative أن يكشف:

- نصًا متكررًا؛
- failures في grounding؛
- hallucinations؛
- output مشوهًا؛
- stopping behavior سيئًا؛
- bugs في prompt template.

## 19. KV cache: نفّذ Prefill مرة واحدة و Decode بكفاءة

تخزّن **key-value cache** الـ keys و values السابقة لكل Transformer
layer.

### المرحلة 1 — Prefill

شغّل prompt كاملًا مرة واحدة:

```text
صورة (image) + prompt tokens
       ↓
Transformer — نموذج المحوّل
       ↓
logits + cached K/V tensors — درجات مع tensors مخزنة
```

### المرحلة 2 — Decode

لكل new token:

1. احسب query/key/value الخاصة بها؛
2. ألحق K/V الجديدة بالـ cache؛
3. نفّذ attention على history المخزنة في cache؛
4. تنبأ بـ next token.

## 21. Tiling: Pixels أكثر دون إعادة تصميم Encoder

إحدى الاستراتيجيات البسيطة هي **tiling**.

لنفترض أن صورة عالية الدقة قُسمت إلى:

```text
5 أعمدة × 3 صفوف = 15 tiles
```

إذا كانت كل tile بحجم:

```text
256 × 256
```

فيمكن لـ vision encoder الاستمرار في معالجة input size المعتاد لديه.

مفاهيميًا:

```text
صورة عالية الدقة (high-resolution image)
      ↓
قسّمها إلى tiles
      ↓
نفّذ encoding لكل tile
      ↓
ادمج visual tokens
```

يحافظ ذلك على التفاصيل المحلية.

### 21.1 التكلفة: انفجار عدد Visual tokens

لنفترض أن tile واحدة بحجم 256 × 256 تنتج:

```text
256 visual tokens — عدد visual tokens لكل tile
```

إذًا تنتج 15 tiles:

```text
15 × 256 = 3840 visual tokens — الإجمالي
```

يمكن أن يستهلك ذلك جزءًا ضخمًا من context window الخاصة بـ language model.

كما يجعل attention أعلى تكلفة بكثير.

### الفكرة الحدسية لتكلفة Attention

يتدرج Self-attention تقريبًا وفق:

```text
O(n²)
```

بالنسبة إلى sequence length `n`.

إذا تضاعف عدد visual tokens:

```text
n → 2n
```

فقد ينمو عمل attention تقريبًا:

```text
n² → 4n²
```

لذلك قد يكون الحفاظ على resolution عبر إضافة visual tokens بصورة عمياء
مكلفًا للغاية.

## 22. Pixel shuffle: ضغط Spatial tokens إلى Channels

يقدم الفصل pixel shuffle كطريقة لتقليل عدد visual
tokens الممررة إلى LLM.

الفكرة المهمة هي:

```text
مواضع spatial أكثر (more spatial positions)
        ↓
إعادة ترتيب (rearrange)
        ↓
مواضع spatial أقل (fewer spatial positions)
+
عمق channel أكبر (more channel depth)
```

لا يُفترض من حيث المبدأ التخلص من المعلومات بسبب rearrangement
نفسه؛ بل يعاد تنظيمها.

### 22.1 قبل Compression

تخيّل feature grid:

```text
H × W × C
```

يوجد:

```text
H × W
```

من مواضع spatial tokens.

### 22.2 بعد Spatial compression

يمكن لعملية shuffle أن تستبدل جزءًا من:

```text
spatial resolution — الدقة المكانية
```

بـ:

```text
channel width — عرض القنوات
```

وبذلك يرى language model عددًا أقل من visual sequence positions.

ويصبح projector أعرض لأن كل compressed token تحتوي على معلومات channel
أكثر.

### 22.3 لماذا هذا مفيد؟

تكون Attention مكلفة في **sequence length**.

يتدرج linear projector أعرض بصورة ألطف من تضخيم عدد
attention tokens.

لذلك يفضل النظام:

```text
visual tokens أقل وأكثر ثراءً
```

على:

```text
آلاف visual tokens دقيقة التفاصيل
```

عندما يكون ذلك ممكنًا.

### 22.4 الجمع بين Tiling و Compression

هاتان الفكرتان متكاملتان.

قد ينفذ high-resolution pipeline حديث مفاهيميًا:

```text
صورة كبيرة (large image)
  ↓
adaptive tiling / resizing — تقسيم تكيفي وتغيير حجم
  ↓
vision encoder — مشفّر الرؤية
  ↓
spatial compression — ضغط مكاني
  ↓
projector — طبقة الإسقاط
  ↓
عدد يمكن التحكم فيه من visual tokens
  ↓
LLM — النموذج اللغوي
```

[[IMAGE_NEEDED: Pixel-shuffle token compression |
Show a 2D grid of visual tokens before compression and a smaller grid after
compression where each remaining token has a deeper channel representation |
Learner should understand the spatial-token versus channel-width trade-off]]

### تفصيل مهم

يصف المصدر rearrangement بأنه يحافظ على المعلومات.

عمليًا، ما تزال فائدة aggressive compression تعتمد على:

- كيفية إنتاج vision features؛
- compression ratio؛
- سعة downstream projector؛
- التدريب.

لذلك حتى لو كانت عملية rearrangement نفسها information-preserving،
فقد تنخفض جودة representation إذا ضغط النظام ككل المعلومات
بشدة أكبر من اللازم بالنسبة إلى المهمة.

## 23. تجميع نظام التدريب الكامل

mental model مفيد للفصل كاملًا هو:

```text
1. البيانات (DATA)
multimodal conversation dataset كبيرة
        ↓
بث الأمثلة (stream examples)

2. المعالجة المسبقة (PREPROCESSING)
chat template — قالب المحادثة
        ↓
أدرج image placeholders
        ↓
نفّذ tokenization
        ↓
نفّذ packing للـ samples
        ↓
نفّذ padding للـ packed rows

3. الرؤية (VISION)
الصور (images)
        ↓
vision processor — معالج الرؤية
        ↓
vision encoder — مشفّر الرؤية
        ↓
spatial compression اختياري
        ↓
projector — طبقة الإسقاط

4. الدمج (FUSION)
اعثر على مواضع image placeholders
        ↓
استبدل placeholder embeddings
        ↓
multimodal embedding sequence — تسلسل embeddings متعدد الوسائط

5. النموذج اللغوي (LANGUAGE MODEL)
causal transformer — Transformer سببي
        ↓
next-token logits — درجات token التالية

6. الخسارة (LOSS)
أزح labels
        ↓
تجاهل visual positions
        ↓
تجاهل padding
        ↓
أبقِ EOS قابلة للتعلم
        ↓
cross entropy — دالة الخسارة

7. التحسين (OPTIMIZATION)
صفّر gradients
        ↓
backward — المرور الخلفي
        ↓
optimizer step — خطوة optimizer

8. الفحص (CHECK)
loss curve — منحنى الخسارة
+
qualitative generations — مخرجات توليد نوعية

9. الاستدلال (INFERENCE)
prefill — الملء الأولي
        ↓
KV cache — الذاكرة المؤقتة للمفاتيح والقيم
        ↓
autoregressive decode — فك ترميز autoregressive
```

هذا هو فصل التدريب في diagram واحدة.

## 24. دروس هندسية عملية مخفية داخل الفصل

يؤكد المصدر مرارًا أن نجاح تدريب VLM لا يتعلق فقط
باختيار model architecture.

فالعديد من حالات الفشل تأتي من تفاصيل pipeline.

### 24.1 جودة Data مهمة

لا تضمن dataset كبيرة الحصول على Model جيد.

لا يستطيع Training التعلم إلا من جودة وتنوع
الأمثلة المتاحة.

### 24.2 افتراضات Shape يجب أن تكون صريحة

يجب أن تعرف:

- عرض visual embedding؛
- عرض LLM embedding؛
- عدد visual tokens؛
- max sequence length؛
- شكل الـ batch (batch shape).

تتحول shape mismatches الصامتة سريعًا إلى runtime errors.

### 24.3 Semantics الخاصة بالـ Tokens مهمة

لكل من `PAD` و `EOS` و `<|image|>` معنى مختلف.

التعامل معها كأنها قابلة للاستبدال قد يفسد objective.

### 24.4 كفاءة Compute جزء من جودة Model

لا يقتصر أثر Padding المهدِر على التكلفة المالية.

بل قد يحد من:

- effective batch size؛
- sequence length؛
- عدد التجارب؛
- نطاق الـ Model (model scale).

لذلك يُعد Data packing technique تدريب مهمة.

### 24.5 Loss ضرورية لكنها غير كافية

قد تتناقص loss مع وجود:

- hallucinations؛
- repetition؛
- stopping behavior ضعيف؛
- grounding ضعيف.

افحص دائمًا generated samples.

### 24.6 بنية Inference مهمة أيضًا

تدريب Model ليس سوى جزء من النظام.

يحتاج Interactive deployment أيضًا إلى:

- decoding كفؤ؛
- caching؛
- إدارة memory.

### 24.7 Visual resolution جزء من Token budget

Pixels أكثر تعني غالبًا visual tokens أكثر.

لذلك تمثل context window الخاصة بـ LLM budget مشتركة بين:

- visual content؛
- prompt text؛
- conversation history؛
- generated response النهائي.

هذه المفاضلة محورية في تصميم multimodal systems.

## مفاهيم خاطئة مهمة

### المفهوم الخاطئ 1: "Pretraining هو Learning paradigm."

Pretraining هو **stage**.

ويمكن أن يستخدم objectives من نوع self-supervised أو contrastive أو supervised أو مزيجًا منها.

### المفهوم الخاطئ 2: "Projector يحوّل الصورة مباشرةً إلى كلمات."

يقوم Projector بتحويل visual feature vectors إلى embedding space متوافق
مع LLM.

ويظل LLM هو المسؤول عن language prediction.

### المفهوم الخاطئ 3: "إذا جُمعت Visual embeddings مع Text embeddings باستخدام concatenation، فسيفهم Model الصور تلقائيًا."

لا تفعل Concatenation أكثر من إتاحة المعلومات.

ويجب أن يعلّم Training الـ Model كيف ترتبط visual positions بـ language targets.

### المفهوم الخاطئ 4: "انخفاض Training loss يثبت أن VLM يعمل."

لا.

هو يثبت أن Model يتحسن بالنسبة إلى optimization objective.

وما زلنا بحاجة إلى qualitative behavior و held-out evaluation.

### المفهوم الخاطئ 5: "Padding لا يهم لأنه مُتجاهَل في Loss."

ما يزال Padding قادرًا على إهدار قدر كبير من forward/backward compute.

تجاهله داخل loss يمنعه من أن يصبح target، لكنه لا يجعل
الحساب مجانيًا.

### المفهوم الخاطئ 6: "Packing هو مجرد Padding باسم مختلف."

يملأ Packing كل fixed-length row بعدة samples حقيقية قبل إضافة
final padding.

وهدفه زيادة useful-token density.

### المفهوم الخاطئ 7: "يمكن إبقاء كل Image embeddings في البداية بعد Packing."

لا.

مع وجود عدة samples وصور، يجب أن تظل visual features محاذيةً مع
النص الذي تنتمي إليه.

### المفهوم الخاطئ 8: "من الآمن تجاهل `pad_token_id` دون فحص Token configuration."

ليس دائمًا.

إذا اشترك PAD و EOS في ID نفسه، فقد يؤدي تجاهل PAD أيضًا إلى منع Model من
تعلم EOS.

### المفهوم الخاطئ 9: "Greedy decoding هو Training."

Greedy decoding هو استراتيجية inference.

أما Training فيستخدم loss و gradients.

### المفهوم الخاطئ 10: "KV cache تغيّر ما ينتبه إليه Model."

KV cache هي في الأساس optimization للكفاءة.

ما يزال بإمكان Model تنفيذ attention على history السابقة؛ وتمنع K/V tensors المخزنة في cache
إعادة حساب معظمها.

### المفهوم الخاطئ 11: "High resolution بلا تكلفة إذا كان Vision encoder يدعمها."

غالبًا ما تنتج resolution الأعلى visual tokens أكثر بكثير، وبالتالي تكلفة
أكبر بكثير لـ LLM attention.

### المفهوم الخاطئ 12: "Pixel shuffle تحذف معلومات الصورة ببساطة."

تعيد العملية الموضحة في الفصل ترتيب spatial information إلى
channels لتقليل sequence length. قد يظل النظام الأكبر يفقد تفاصيل مفيدة
إذا أصبح compression عدوانيًا أكثر من اللازم، لكن العملية ليست مجرد
حذف tokens عشوائية.

## المصطلحات الأساسية

| المصطلح | المعنى |
|---|---|
| أسلوب الإشراف في التدريب (Training paradigm) | الطريقة التي يُبنى بها supervision |
| مرحلة التدريب (Training stage) | موضع عملية التدريب داخل دورة حياة Model |
| التعلم الخاضع للإشراف (Supervised learning) | التعلم من أزواج input-target صريحة |
| التعلم غير الخاضع للإشراف (Unsupervised learning) | تعلم البنية من دون labels صريحة |
| التعلم الذاتي الإشراف (Self-supervised learning) | إنشاء supervision من data نفسها |
| التعلم شبه الخاضع للإشراف (Semi-supervised learning) | دمج مجموعة labeled صغيرة مع مجموعة unlabeled كبيرة |
| التعلم التبايني (Contrastive learning) | تقريب representations المتطابقة وإبعاد غير المتطابقة |
| مرحلة ما قبل التدريب (Pretraining) | Training stage أساسية واسعة النطاق |
| التدريب الوسيط (Midtraining) | مرحلة وسيطة تستخدم datasets كبيرة أعلى جودة/اصطناعية |
| مرحلة ما بعد التدريب (Post-training) | تكييف يركز على المهام/instructions بعد broad pretraining |
| المواءمة السلوكية (Alignment) | مرحلة توجيه preferences/behavior |
| Dataset بالبث (Streaming dataset) | Dataset تُقرأ تدريجيًا بدل تنزيلها كاملة أولًا |
| مشفّر الرؤية (Vision encoder) | Network تحوّل الصور إلى visual representations |
| طبقة الإسقاط (Projector) | Layer تحوّل أبعاد visual embedding إلى space متوافق مع LLM |
| نموذج لغوي سببي (Causal LM) | Language model مدرّب للتنبؤ بـ future/next tokens من السياق السابق |
| الدرجات الخام (Logits) | Raw vocabulary scores غير المطبّعة التي ينتجها Model |
| خسارة Cross entropy | Loss قياسية للتصنيف/language modeling |
| إخفاء الخسارة (Loss masking) | استبعاد token positions مختارة من objective |
| الحشو (Padding) | Filler positions تُضاف لمساواة أطوال sequences |
| التعبئة (Packing) | دمج عدة samples حقيقية في row ذي token budget ثابتة |
| التعبئة الجشعة بالحقيبة (Greedy knapsack) | Heuristic تضع samples متغيرة الطول في rows مع هدر منخفض |
| التعبئة المتوازنة (Balanced packing) | Packing strategy تحاول موازنة استغلال rows |
| موضع الصورة المحجوز (Image placeholder) | Special token position محجوزة لـ real visual embeddings |
| رمز الصورة (Image token) | Sequence position تمثل visual information بالنسبة إلى LLM |
| نهاية التسلسل (EOS) | End-of-sequence token تعلّم Model متى يتوقف |
| فك الترميز الجشع (Greedy decoding) | اختيار next token ذات أعلى score في كل inference step |
| ذاكرة K/V المؤقتة (KV cache) | Transformer keys/values مخزنة ويُعاد استخدامها عبر autoregressive decoding steps |
| مرحلة الملء الأولي (Prefill) | أول inference phase تعالج prompt كاملًا وتنشئ cache |
| مرحلة فك الترميز (Decode) | مرحلة متكررة لتوليد next token باستخدام history المخزنة في cache |
| التقسيم إلى مربعات (Tiling) | تقسيم صورة عالية الدقة إلى أجزاء أصغر بحجم مناسب للـ encoder |
| إعادة ترتيب Pixel shuffle | Spatial/channel rearrangement تُستخدم هنا لتقليل visual token count |
| ميزانية السياق (Context budget) | أقصى مساحة multimodal sequence متاحة للـ language model |
