## 1. لماذا يهم Clustering عندما لا يعطينا أحد Labels؟

في supervised classification، نبدأ بأمثلة تحمل labels.

على سبيل المثال:

```text
"This movie was excellent."       → positive   — تسمية إيجابية
"This movie was disappointing."  → negative   — تسمية سلبية
```

تخبر labels الـ Model بالفئات الموجودة.

لكن الكثير من datasets الواقعية لا تأتي ومعها labels.

تخيل أنك تستقبل:

```text
50,000 بحثًا ملخصًا (research abstracts)
100,000 تذكرة دعم (support tickets)
ملايين من مراجعات المنتجات (product reviews)
آلاف من تعليقات العملاء (customer comments)
```

من دون category annotations.

وقد لا تعرف أصلًا ما الفئات الموجودة.

وهنا تصبح **unsupervised learning** مفيدة.

يسأل Text clustering:

> ما documents التي تبدو متشابهة بما يكفي لتكوين مجموعات، رغم أننا لم نحدد مسبقًا ما ينبغي أن تكون عليه هذه المجموعات؟

الهدف الأساسي هو:

```text
مستندات بلا Labels (unlabeled documents)
       ↓
اكتشاف بنية التشابه (discover similarity structure)
       ↓
مجموعات من المستندات المترابطة (groups of related documents)
```

[[IMAGE_NEEDED: Supervised classification versus unsupervised clustering | Left side shows labeled documents being assigned to predefined categories; right side shows unlabeled documents automatically forming semantic groups | Learner should notice that clustering discovers structure rather than learning predefined labels]]

### لماذا يمكن أن يكون Clustering مفيدًا؟

يسلط الفصل الضوء على استخدامات تتجاوز مجرد تجميع documents.

يمكن أن يدعم Clustering:

- exploratory data analysis،
- اكتشاف الأنماط الخفية،
- العثور على outliers،
- تسريع labeling اليدوي،
- اكتشاف labels التي قد تكون غير صحيحة،
- فهم مدى تعقيد dataset.

الفرق الأهم هو:

```text
التصنيف (classification):
الفئات معروفة (the categories are known)

التجميع (clustering):
المجموعات يتم اكتشافها (the groups are discovered)
```

## 4. Pipeline الشائع لـ Text clustering

يعرض الفصل pipeline مفيدًا جدًا من ثلاث مراحل:

```text
1. تحويل المستندات إلى Embeddings (Convert documents into embeddings)
2. تقليل أبعاد Embeddings (Reduce embedding dimensionality)
3. تجميع Embeddings منخفضة الأبعاد (Cluster the reduced embeddings)
```

بصورة مختصرة:

```text
المستندات (Documents)
    ↓
نموذج Embedding (Embedding model)
    ↓
متجهات دلالية عالية الأبعاد (High-dimensional semantic vectors)
    ↓
تقليل الأبعاد (Dimensionality reduction)
    ↓
متجهات منخفضة الأبعاد (Lower-dimensional vectors)
    ↓
خوارزمية Clustering (Clustering algorithm)
    ↓
مجموعات + Outliers محتملة (Groups and possible outliers)
```

هذا pipeline يستحق الحفظ لأنه يظهر في كثير من أنظمة unsupervised text العملية.

[[IMAGE_NEEDED: Three-step clustering pipeline | Show documents → embedding model → high-dimensional vectors → UMAP dimensionality reduction → low-dimensional vectors → HDBSCAN → clusters/outliers | Learner should memorize the order and role of the three stages]]

لماذا لا ننفذ clustering على raw text مباشرة؟

لأن clustering algorithms تحتاج إلى numerical features.

تمنحنا Embeddings هذه features مع محاولة الحفاظ على semantic information.

## 6. لماذا تأتي Dimensionality reduction قبل Clustering؟

تحتوي Embeddings لدينا على:

```text
384 بُعدًا (dimensions)
```

وهذا مفيد لتمثيل المعنى، لكن high-dimensional spaces قد تكون صعبة على clustering algorithms.

لذلك يضغط الفصل Embeddings قبل clustering.

يسمى ذلك **dimensionality reduction**.

من الناحية المفاهيمية:

```text
متجه من 384 بُعدًا (384-dimensional vector)
        ↓
نموذج تقليل الأبعاد (dimensionality-reduction model)
        ↓
متجه من 5 أبعاد (5-dimensional vector)
```

الهدف ليس مجرد حذف أعمدة عشوائية.

تحاول طريقة reduction الحفاظ على البنية المفيدة مع التعبير عن البيانات بعدد أقل من الأبعاد.

[[IMAGE_NEEDED: High-dimensional to low-dimensional representation | Show a cloud of conceptual high-dimensional document vectors being compressed into a lower-dimensional space while trying to keep neighboring groups together | Learner should see dimensionality reduction as structure-preserving compression rather than dropping random features]]

### قيد مهم

Dimensionality reduction عملية lossy.

ويحذر الفصل صراحة من أن:

```text
البنية عالية الأبعاد (high-dimensional structure)
≠
البنية منخفضة الأبعاد المحفوظة بصورة مثالية (perfectly preserved low-dimensional structure)
```

ستُفقد بعض المعلومات.

ولذلك يوجد دائمًا توازن:

```text
التقليل بما يكفي لمساعدة Clustering (reduce enough to help clustering)
لكن (but)
الاحتفاظ ببنية كافية لتظل ذات معنى (retain enough structure to remain meaningful)
```

## 13. لماذا يعود Bag-of-words للظهور؟

قدمت الفصول السابقة bag-of-words باعتباره تمثيلًا بسيطًا للنص.

يحسب Bag-of-words عدد مرات ظهور الكلمات.

بالنسبة إلى document:

```text

```

```text

models   → 1
process  → 1
```

بمفرده، يتجاهل هذا semantic context.

فلماذا نستخدمه في BERTopic بعد أن تعلمنا embeddings قوية؟

لأن bag-of-words لديه نقطة قوة مختلفة:

> إنه فعال وسهل التفسير لتحديد الكلمات كثيرة الظهور.


وهذا درس متكرر في machine learning:

> ليس من الضروري أن يستخدم النظام الحديث Model واحدًا لكل شيء.

## 14. الانتقال من Counts على مستوى Document إلى Counts على مستوى Cluster

يتم عادةً حساب bag-of-words لكل document.

لكن BERTopic يحتاج إلى وصف **cluster**.

لذلك تعامل مع جميع documents الموجودة داخل cluster واحد باعتبارها class-level document موحدًا.

افترض أن Cluster A يحتوي ثلاثة نصوص:

```text
speech recognition model   — ثلاثة مستندات قصيرة
automatic speech system
speech acoustic model
```

على مستوى cluster:

```text
speech       → تكرار مرتفع (high frequency)
model        → متكرر (recurring)
recognition  → موجود (present)
automatic    → موجود (present)
acoustic     → موجود (present)
```

يمثل cluster-level frequency جزء **class term frequency** من c-TF-IDF.

من الناحية المفاهيمية:

```text
مستندات منفردة (individual documents)
        ↓
تجميع المستندات حسب Cluster (group documents by cluster)
        ↓
تجميع أعداد الكلمات لكل Cluster (aggregate word counts per cluster)
```

## 15. استخدام c-TF-IDF للعثور على الكلمات المهمة لـ Cluster واحد

Raw frequency لديها مشكلة.

فكلمات مثل:

```text
the   — كلمات شائعة (Stop words)
and
of
to
```

قد تظهر في كل مكان.

الكلمة التي تظهر كثيرًا في كل cluster ليست مفيدة جدًا لتمييز topic واحد.

لذلك يستخدم BERTopic **class-based TF-IDF**، أو:

```text
c-TF-IDF
```

الفكرة العامة هي:

```text
وزن مرتفع (high weight)
=
متكرر في هذا Cluster (frequent in this cluster)
AND
ليس شائعًا بالدرجة نفسها عبر جميع Clusters (not equally common across all clusters)
```

وهذا يعني أن مصطلحًا مثل:

```text
translation — كلمة Topic محتملة
```

قد يحصل على وزن قوي داخل machine-translation cluster إذا كان شائعًا هناك لكنه أقل هيمنة في أماكن أخرى.

في المقابل:

```text
the — كلمة شائعة عامة
```

ينبغي أن تحصل على وزن تمييزي أقل بكثير لأنها تظهر عبر corpus كلها.

### الفكرة أهم من حفظ Formula

فكر في c-TF-IDF على أنه يسأل:

> ما الكلمات التي تميز هذا cluster بصورة خاصة مقارنةً بـ clusters الأخرى؟

والنتيجة هي vocabulary مرتبة لكل topic.

[[IMAGE_NEEDED: c-TF-IDF intuition | Show two clusters with word-frequency bars: common stop words are frequent in both and receive low discriminative weight, while a topic-specific word such as “translation” is frequent in one cluster and receives high weight | Learner should understand why frequency alone is not enough]]

## 21. لماذا قد تحتاج Topic keywords إلى Refinement؟

يأتي أول representation في BERTopic من c-TF-IDF.

وهذا سريع وقابل للتفسير.

لكنه ما يزال قائمًا أساسًا على word counts و weighting.

وقد ينتج:

- كلمات زائدة أو متكررة،
- كلمات عامة،
- اختصارات مفيدة لكنها غامضة،
- مصطلحات لا تكوّن وصفًا واضحًا وسهل القراءة لـ topic.

لذلك يقدم الفصل مرحلة **representation model** إضافية.

من الناحية المفاهيمية:

```text
كلمات Topic الأولية من c-TF-IDF (initial c-TF-IDF topic words)
            ↓
تحسين Representation (representation refinement)
            ↓
وصف Topic محسّن (improved topic description)
```

لا تحتاج هذه المرحلة إلى إعادة تشغيل clustering pipeline بالكامل.

وهذا مهم.

إذا كان لديك:

```text
1,000,000 مستند (documents)
100 موضوع (topics)
```

فليس من الضروري أن تجعل representation model مكلفًا يعالج مليون document.

يمكنك تنفيذ refinement تقريبًا على مستوى topic.

## مفاهيم خاطئة مهمة

### المفهوم الخاطئ 1

> Clustering هو مجرد classification من دون training loop.

### لماذا هذا خطأ؟

يبدأ Classification بـ target labels محددة مسبقًا. أما clustering فيحاول اكتشاف البنية من دون هذه labels.

---

### المفهوم الخاطئ 2

> إذا ظهر documentان قريبين في 2D plot، فلا بد أن يكونا بالدرجة نفسها من القرب في embedding space الأصلي.

### لماذا هذا خطأ؟

تفقد Dimensionality reduction بعض المعلومات. ويكون 2D visualization مجرد تقريب.

---

### المفهوم الخاطئ 3

> يجب على HDBSCAN دائمًا إسناد كل document إلى Topic.

### لماذا هذا خطأ؟

إحدى الخصائص المفيدة لـ density-based clustering هي إمكانية بقاء النقاط غير المؤكدة أو المعزولة باعتبارها outliers.

---

### المفهوم الخاطئ 4

> Topic modeling و clustering هما الشيء نفسه تمامًا.

### لماذا هذا خطأ؟

يقوم Clustering بتجميع documents. أما topic modeling فيحاول بالإضافة إلى ذلك اكتشاف themes قابلة للتفسير وتمثيلها.

---

### المفهوم الخاطئ 5

> يستخدم BERTopic مكتبة BERT فقط.

### لماذا هذا خطأ؟

يقدم الفصل BERTopic كإطار modular. ويمكن أن يجمع pipeline الخاص به embedding models و dimensionality reduction و clustering و representations مشتقة من bag-of-words و representation models أخرى.

---

### المفهوم الخاطئ 6

> أصبح Bag-of-words عديم الفائدة بعد ظهور Embeddings.

### لماذا هذا خطأ؟

يستخدم BERTopic semantic embeddings لتجميع documents، ويستخدم representation مشتقًا من bag-of-words عبر c-TF-IDF للحصول على topic words قابلة للتفسير. تقنيات مختلفة تحل أجزاء مختلفة من pipeline.

---

### المفهوم الخاطئ 7

> أكثر كلمة تكرارًا في Cluster هي تلقائيًا أفضل Topic word.

### لماذا هذا خطأ؟

الكلمات المتكررة في كل مكان قد تحمل قدرًا ضئيلًا من المعلومات الخاصة بـ topic. ويؤكد c-TF-IDF المصطلحات التي تميز cluster واحدًا مقارنة بالآخرين.

---

### المفهوم الخاطئ 8

> Generative topic label أكثر موثوقية تلقائيًا من Keywords.

### لماذا هذا خطأ؟

قد تكون generated labels عامة أكثر من اللازم أو مضللة. والاحتفاظ بعدة representations يجعل التفسير أكثر قوة.

---

## المصطلحات الأساسية

| المصطلح | المعنى |
|---|---|
| مصطلح Unsupervised learning | تعلم أو اكتشاف البنية من دون target labels محددة مسبقًا |
| مصطلح Text clustering | تجميع documents اعتمادًا على similarity |
| مصطلح Topic modeling | اكتشاف themes متكررة في مجموعة نصوص وتمثيلها |
| مصطلح Document embedding | Dense vector يمثل document كاملًا |
| مصطلح Dimensionality reduction | ضغط high-dimensional representations إلى أبعاد أقل مع محاولة الحفاظ على البنية المفيدة |
| مصطلح UMAP | طريقة dimensionality-reduction مستخدمة في الفصل |
| مصطلح Cluster | مجموعة من data points ترى clustering algorithm أنها متشابهة |
| مصطلح Density-based clustering | Clustering يعتمد على المناطق الكثيفة في البيانات بدلًا من centroids ثابتة |
| مصطلح HDBSCAN | Hierarchical density-based clustering algorithm يمكنها تحديد outliers |
| مصطلح Outlier | Data point لا يتم إسنادها بثقة إلى cluster مكتشف |
| مصطلح Bag-of-words | Representation يعتمد على عدد مرات ظهور الكلمات |
| مصطلح Term frequency | عدد مرات ظهور term في representation |
| مصطلح c-TF-IDF | Class-based TF-IDF weighting يستخدمه BERTopic لاكتشاف الكلمات التي تمثل cluster |
| مصطلح BERTopic | إطار modular لـ topic modeling يجمع semantic clustering و topic representation |
| مصطلح Topic representation | Keywords أو labels أو أوصاف أخرى تشرح محتوى topic |
| مصطلح Representation model | مكون BERTopic يقوم بتحسين topic representations أو توليدها |
| مصطلح KeyBERTInspired | طريقة BERTopic قائمة على embeddings لإعادة ترتيب topic keywords دلاليًا |
| مصطلح MMR | Maximal Marginal Relevance وتُستخدم لموازنة relevance وتنوع keywords |
| مصطلح Cosine similarity | مقياس similarity يُستخدم مع embedding vectors |
| مصطلح Representative document | Document يتم اختياره باعتباره ممثلًا بصورة خاصة لـ topic |
| مصطلح Topic label | وصف قصير سهل القراءة لـ topic |
| مصطلح Sequence packing | ليس محوريًا هنا؛ أُبقي من سياق الفصل السابق وليس مستخدمًا في هذا pipeline |
| مصطلح Cluster inspection | تقييم بشري لـ documents المسندة إلى cluster |
| مصطلح Topic hierarchy | تنظيم topics في علاقات أوسع وأضيق |

## احتفظ بهذه الفكرة

**يكتشف Text clustering البنية قبل أن تعرف labels. يحوّل pipeline الأساسي في الفصل documents إلى semantic embeddings، ثم يضغط هذه embeddings باستخدام UMAP، ويكتشف المجموعات الكثيفة باستخدام HDBSCAN. بعد ذلك يحوّل BERTopic هذه المجموعات إلى topics قابلة للتفسير باستخدام c-TF-IDF وتحسينات representation اختيارية مثل semantic reranking وتنويع keywords و generative labels. وأقوى workflow لا يثق بصورة عمياء في cluster ID أو plot أو قائمة keywords أو generated label واحدة؛ بل يجمع بين algorithms والفحص البشري.**
