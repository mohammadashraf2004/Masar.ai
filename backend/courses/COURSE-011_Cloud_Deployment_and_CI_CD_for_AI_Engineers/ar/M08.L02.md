### `-i`

### `ec2-user`

بالنسبة إلى Amazon Linux AMI في المصدر، يكون اسم مستخدم Linux هو:

```text
ec2-user    # اسم مستخدم Linux
```

هذا **ليس** مستخدم AWS IAM.

إنه حساب مستخدم داخل نظام التشغيل Linux على نسخة EC2.

### عنوان IP العام

الوجهة هي عنوان IP العام/Elastic IP للنسخة.

إذن نموذج الاتصال هو:

```text
الحاسوب المحلي
   ↓ المفتاح الخاص يُثبت الهوية
SSH عبر TCP 22
   ↓
security group يسمح بالمصدر الموثوق
   ↓
Amazon Linux EC2
   ↓
shell المستخدم ec2-user
```

## 2. استخدم VS Code Remote - SSH لسير عمل بعيد أغنى

يفضّل المصدر استخدام VS Code Remote - SSH بدلًا من كتابة أوامر SSH الطويلة مرارًا.

وينشئ إدخالًا في ملف إعداد SSH يشبه من حيث المفهوم:

```text
Host lb-ec2-mywebserver    # الاسم المستعار
HostName <EC2_PUBLIC_IP>
IdentityFile ~/Documents/config/my-web-server-key-pair.pem
User ec2-user
```

عندها تستطيع إضافة Remote - SSH في VS Code الاتصال باستخدام الاسم المستعار:

```text
lb-ec2-mywebserver    # الاسم المستعار
```

### لماذا هذا مفيد؟

تمنحك جلسة VS Code البعيدة:

- الوصول إلى الطرفية (terminal)،
- مستكشف ملفات بعيد،
- دعم المحرّر،
- تلوين الصياغة (syntax highlighting).

وهذا يحوّل الخادم من "shell تدخله عبر SSH أحيانًا" إلى بيئة تطوير بعيدة يمكن إدارتها.

### المتطلب الشبكي

يذكّرك الفصل بأن الـ security group يجب أن يسمح بـ:

```text
TCP 22
```

من عنوان IP الموثوق لديك أو من VPN.

وبدون إذن شبكي، لا تكفي مفاتيح SSH الصحيحة.

## 5. اضبط وصول GitHub من خادم EC2

يحتاج خادم EC2 إلى استنساخ الشيفرة المصدرية وتحديثها.

ويضبط المصدر GitHub باستخدام مفتاح SSH جديد من نوع ED25519.

### توليد المفتاح

⟦CODE_9⟧

وينتج عن ذلك:

```text
~/.ssh/id_ed25519    # المفتاح الخاص
~/.ssh/id_ed25519.pub    # المفتاح العام
```

### الخاص مقابل العام

```text
id_ed25519
→ مفتاح خاص
→ يبقى على خادم EC2

id_ed25519.pub
→ مفتاح عام
→ يُنسخ إلى GitHub
```

### وكيل SSH (SSH agent)

يستخدم المصدر:

⟦CODE_10⟧

حتى يصبح المفتاح الخاص متاحًا لعميل SSH.

### إعداد SSH

يضيف المصدر إدخالًا يشبه من حيث المفهوم:

```text
Host *.github.com    # لكل نطاقات GitHub
AddKeysToAgent yes
IdentityFile ~/.ssh/id_ed25519
```

### أضف المفتاح العام إلى GitHub

اعرضه:

⟦CODE_11⟧

ثم أضف هذه القيمة العامة ضمن إعدادات مفاتيح SSH في GitHub.

وبالنسبة إلى حساب GitHub مؤسسي، يشير المصدر إلى أنه قد يلزم أيضًا تفويض SSO.

### الاختبار

⟦CODE_12⟧

يتحقق من أن GitHub يتعرّف على المفتاح.

### مفتاح SSH لـ EC2 مقابل مفتاح SSH لـ GitHub

هاتان علاقتا ثقة مختلفتان.

```text
الحاسوب المحلي → EC2
يستخدم المفتاح الخاص .pem لـ EC2

EC2 → GitHub
يستخدم مفتاح ED25519 المولَّد على EC2
```

[[IMAGE_NEEDED: Two SSH trust relationships | A split diagram showing Local Laptop → EC2 using the downloaded EC2 PEM key, and EC2 → GitHub using the EC2-generated ED25519 key whose public half is registered in GitHub | Learner should notice these are separate key pairs for separate connections]]

### ترميز الصلاحيات

يعرض المصدر المنسوخ أوامر مثل:

```text
chmod 700.ssh/    # كما وردت في المصدر
chmod 400.ssh/config
```

ويبدو أن المسافات ناقصة فيها في النص المنسوخ.

وبنية أمر Linux المقصودة هي:

```text
chmod MODE PATH    # الصيغة العامة
```

ثم يشرح المصدر حساب الصلاحيات:

```text
read    = 4    # قراءة
write   = 2    # كتابة
execute = 1    # تنفيذ
```

و:

```text
7 = 4 + 2 + 1
```

إذن:

```text
700
```

تعني:

```text
user   = قراءة + كتابة + تنفيذ
group  = بلا أي صلاحيات
others = بلا أي صلاحيات
```

## مفاهيم خاطئة شائعة

### المفهوم الخاطئ 1
> "اسم مستخدم IAM للمطوّر و`ec2-user` هما الهوية نفسها."

إنهما في طبقتين مختلفتين: هوية AWS مقابل هوية نظام التشغيل Linux.

### المفهوم الخاطئ 2
> "إذا كان Docker يعمل الآن، فسيعمل تلقائيًا بعد كل إعادة تشغيل."

لا، إلا إذا كانت خدمته مفعّلة للبدء عند الإقلاع.

### المفهوم الخاطئ 3
> "يجب رفع المفتاح `.pem` الخاص بـ EC2 إلى GitHub."

لا. ينشئ المصدر زوج مفاتيح SSH منفصلًا لـ GitHub على مضيف EC2.

### المفهوم الخاطئ 4
> "البيئات الافتراضية مخصّصة فقط لتعدد إصدارات Python."

غرضها الرئيسي هنا هو عزل الاعتماديات.

### المفهوم الخاطئ 5
> "ظهور صفحة Streamlit يختبر Streamlit وحده."

إنه يتحقق من عدة طبقات في البنية التحتية في وقت واحد.

## المصطلحات الأساسية

| المصطلح | المعنى |
|---|---|
| SSH | بروتوكول shell بعيد آمن |
| `ec2-user` | حساب Linux الافتراضي المستخدم في نسخة Amazon Linux في المصدر |
| VS Code Remote - SSH | إضافة/سير عمل لتحرير جهاز بعيد وتشغيله |
| `systemctl start` | تشغيل خدمة الآن |
| `systemctl enable` | ضبط الخدمة لتبدأ عند الإقلاع |
| Docker Compose | أداة لتشغيل عدة حاويات (multi-container) التي يثبّتها المصدر |
| ED25519 | نوع المفتاح المستخدم في مفتاح SSH الخاص بـ GitHub في المصدر |
| وكيل SSH (SSH agent) | عملية تحتفظ بالمفاتيح الخاصة لمصادقة SSH |
| `chmod` | أمر Linux لتغيير الصلاحيات |
| البيئة الافتراضية (Virtual environment) | بيئة معزولة لحزم Python |
| Streamlit | Python framework مستخدم في تطبيق التحقق في المصدر |
