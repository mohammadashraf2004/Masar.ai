## 1. ما هو تصنيف النصوص (Text Classification)؟

تطلب مهمة text classification من Model إسناد label واحدة أو أكثر إلى نص.

أبسط نموذج ذهني هو:

```text
النص (Text)
  ↓
المصنّف (Classifier)
  ↓
التسمية (Label)
```

على سبيل المثال:

```text
"I loved this movie."

→ إيجابي (Positive)
```

أو:

```text
"This was boring and disappointing."

→ سلبي (Negative)
```

يركز الفصل على **sentiment classification**، لكن الفكرة الأساسية نفسها تظهر في مهام كثيرة:

```text
رسالة العميل (customer message) → النية (intent)
البريد الإلكتروني (email) → spam / not spam
المقال (article) → الموضوع (topic)
المراجعة (review) → positive / negative
النص (text) → اللغة (language)
المستند (document) → الفئة (category)
```

لا يُطلب من Model كتابة إجابة طويلة.

بل يُطلب منه أن يقرر:

> ما class التي تصف هذا input بأفضل شكل؟

[[IMAGE_NEEDED: Text classification overview | Show several example text inputs flowing into a language model/classifier and emerging as labels such as Positive, Negative, Billing Issue, and Shipping Issue | Learner should notice that classification converts unstructured text into a small predefined set of labels]]

### يمكن أن تكون Classification ثنائية أو متعددة الفئات

يستخدم الفصل sentiment labels اثنتين:

```text
0 → مراجعة سلبية (negative)
1 → مراجعة إيجابية (positive)
```

هذه مشكلة **binary classification** لأن هناك class اثنتين محتملتين.

أما مهمة multiclass فقد تستخدم بدلًا من ذلك:

```text
الفوترة (billing)
الدعم التقني (technical_support)
المبيعات (sales)
الوصول إلى الحساب (account_access)
أخرى (other)
```

وتظل الأفكار العامة نفسها قابلة للتطبيق.

## 2. أربعة مسارات عملية لتنفيذ Classification

هذا الفصل مفيد بصورة خاصة لأنه لا يعرض classification باعتبارها تقنية واحدة فقط.

بل يوضح عدة approaches مختلفة.

### المسار 1 — Task-specific representation model

```text
النص (text)
 ↓
مصنّف مُدرَّب مسبقًا (pretrained classifier)
 ↓
درجات الفئات (class scores)
 ↓
التسمية (label)
```

يكون Model بأكمله قد خضع مسبقًا لـ fine-tuning لمهمة classification.

### المسار 2 — Embeddings مع Lightweight supervised classifier

```text
النص (text)
 ↓
نموذج Embedding ثابت (frozen embedding model)
 ↓
متجه النص (text vector)
 ↓
خوارزمية Logistic regression
 ↓
التسمية (label)
```

هنا ينشئ embedding model الـ features، بينما يتم تدريب classifier صغير على labeled data الخاصة بك.

### المسار 3 — Zero-shot embeddings

```text
تمثيل المستند (document embedding)
        ↘
       التشابه (similarity) → أقرب تسمية (closest label)
        ↗
تمثيل وصف التسمية (label-description embedding)
```

لا توجد حاجة إلى labeled training examples.

### المسار 4 — Generative model

```text
التعليمات + المستند (instruction و document)
        ↓
نموذج توليدي (generative model)
        ↓
"positive" — التسمية النصية المولدة
        ↓
التحويل إلى label 1 (map to label 1)
```

يستكشف الفصل كلًا من encoder-decoder model و closed generative model.

[[IMAGE_NEEDED: Four classification routes | Four side-by-side pipelines showing task-specific model, frozen embeddings plus classifier, zero-shot label similarity, and generative prompting | Learner should see that the same classification goal can be solved with very different model architectures and training requirements]]

### لماذا نتعلم أكثر من مسار؟

لأن المشاريع الحقيقية تختلف من حيث:

- كمية labeled data،
- مقدار compute المتاح،
- متطلبات latency،
- قيود cost،
- متطلبات privacy،
- مدى توفر Models،
- accuracy المطلوبة،
- ومدى سهولة وصف classes باستخدام natural language.

ونادرًا ما توجد architecture واحدة هي الأفضل بصورة مطلقة.

## 4. استخدام Representation models في Classification

تركز representation models على تحويل النص إلى numerical representations مفيدة.

وتُعد architectures من نوع encoder مثل BERT أمثلة شائعة.

يعرض الفصل طريقتين لاستخدام representation models:

```text
A. نموذج Representation مخصص للمهمة (task-specific representation model)

B. نموذج Embedding عام الغرض (general-purpose embedding model)
```

### النموذج المخصص للمهمة (Task-specific model)

يمكن تنفيذ fine-tuning لـ foundation model مثل BERT لمهمة classification معينة.

بعد fine-tuning، يمكنك إعطاؤه نصًا والحصول مباشرةً على class scores.

### نموذج Embedding

أما general-purpose embedding model فينتج vector representation بدلًا من ذلك.

ثم يمكن تمرير هذا vector إلى classifier آخر.

والفرق مهم:

```text
نموذج مخصص للمهمة (TASK-SPECIFIC MODEL)
النص (text) → درجات التسمية (label scores) مباشرة
```

مقابل:

```text
نموذج Embedding (EMBEDDING MODEL)
النص (text) → vector → classifier آخر → label
```

## 8. مصفوفة الالتباس (Confusion Matrix)

في binary classification، يقع كل prediction في واحدة من أربع فئات.

افترض أن **positive review** هي positive class.

### النتيجة الإيجابية الصحيحة (True Positive — TP)

تكون المراجعة positive فعلًا.

ويتنبأ Model بأنها positive.

```text
القيمة الفعلية (actual): positive
التنبؤ (predicted): positive
```

وهذا صحيح.

### النتيجة السلبية الصحيحة (True Negative — TN)

تكون المراجعة negative فعلًا.

ويتنبأ Model بأنها negative.

```text
القيمة الفعلية (actual): negative
التنبؤ (predicted): negative
```

وهذا صحيح.

### النتيجة الإيجابية الخاطئة (False Positive — FP)

تكون المراجعة negative في الحقيقة.

لكن Model يتنبأ بأنها positive.

```text
القيمة الفعلية (actual): negative
التنبؤ (predicted): positive
```

وهذا غير صحيح.

### النتيجة السلبية الخاطئة (False Negative — FN)

تكون المراجعة positive في الحقيقة.

لكن Model يتنبأ بأنها negative.

```text
القيمة الفعلية (actual): positive
التنبؤ (predicted): negative
```

وهذا غير صحيح.

إليك matrix مختصرة:

```text
                     التنبؤ (Predicted)
                  Negative   Positive

Actual Negative      TN         FP

Actual Positive      FN         TP
```

## 9. مقاييس Precision و Recall و Accuracy و F1

تجيب هذه metrics عن أسئلة مختلفة.

### مقياس Accuracy

يسأل Accuracy:

> من بين جميع predictions، كم منها كان صحيحًا؟

من الناحية المفاهيمية:

```text
accuracy =
عدد التنبؤات الصحيحة (correct predictions)
-------------------
جميع التنبؤات (all predictions)
```

أو:

```text
(TP + TN) / (TP + TN + FP + FN)
```

يُعد Accuracy سهل الفهم، لكنه قد يكون مضللًا عندما تكون classes غير متوازنة بدرجة كبيرة.

### مقياس Precision

يسأل Precision:

> عندما يتنبأ Model بهذه class، كم مرة يكون هذا التنبؤ صحيحًا؟

بالنسبة إلى positive class:

```text
precision =
TP — النتائج الإيجابية الصحيحة
-------
TP + FP — جميع التنبؤات الإيجابية
```

يعني precision المرتفع وجود عدد قليل من false positive predictions.

### مقياس Recall

يسأل Recall:

> من بين الأمثلة التي تنتمي بالفعل إلى هذه class، كم مثالًا اكتشفه Model؟

```text
recall =
TP — النتائج الإيجابية الصحيحة
-------
TP + FN — جميع الأمثلة الإيجابية الفعلية
```

يعني recall المرتفع أن عددًا قليلًا من true positive examples قد تم تفويته.

### درجة F1

توازن F1 بين precision و recall.

من الناحية المفاهيمية:

```text
F1 = harmonic balance of precision and recall — توازن توافقي بين Precision و Recall
```

والمعادلة الدقيقة هي:

```text
2 × precision × recall — البسط
----------------------
 precision + recall — المقام
```

### حدس بسيط

تخيل أنك تكتشف support tickets العاجلة.

إذا صنّف Model عددًا كبيرًا من التذاكر العادية على أنها عاجلة:

```text
يتراجع Precision (precision suffers)
```

وإذا أخفق Model في اكتشاف عدد كبير من التذاكر العاجلة فعلًا:

```text
يتراجع Recall (recall suffers)
```

تصبح F1 مفيدة عندما يكون كلا نوعي الخطأ مهمًا.

[[IMAGE_NEEDED: Precision vs recall intuition | Show a collection of actual positive items and predicted-positive items as overlapping sets, with TP in the overlap, FP in predicted-only, and FN in actual-only; annotate precision as purity of predictions and recall as coverage of true positives | Learner should understand the different questions precision and recall answer]]


## 10. تنفيذ Classification باستخدام Frozen embeddings

سننتقل الآن إلى approach مختلف.

بدلًا من مطالبة pretrained model واحد بإخراج sentiment مباشرةً، استخدم general-purpose embedding model لتحويل كل review إلى numerical feature vector.

تصبح pipeline:

```text
نص المراجعة (review text)
    ↓
نموذج Embedding ثابت (frozen embedding model)
    ↓
متجه Embedding
    ↓
مصنّف خفيف قابل للتدريب (trainable lightweight classifier)
    ↓
التسمية (label)
```

يفصل هذا بوضوح بين:

```text
استخراج السمات (feature extraction)
```

و:

```text
التصنيف (classification)
```

### لماذا هذا مفيد؟

قد يتطلب fine-tuning لـ large language model مقدارًا كبيرًا من compute.

لكن تدريب logistic regression على embeddings محسوبة مسبقًا يكون أخف نسبيًا، ويمكن تشغيله بسهولة على CPU في كثير من الحالات.

وبذلك نستطيع إعادة استخدام pretrained model قوي دون تحديث weights الخاصة به.

```text
نموذج Embedding (Embedding model)
     ↓
تمثيل سمات ثابت (fixed feature representation)

المصنّف (Classifier)
     ↓
تدريب منخفض التكلفة مخصص للمهمة (cheap task-specific training)
```

إذا غيرت classifier لاحقًا، فقد تتمكن من إعادة استخدام embeddings.

وإذا أضفت مهمة جديدة تحتوي على labeled data، فقد تتمكن من إعادة استخدام embedding model.

وهذا يجعل embeddings بنية تحتية قوية.

## 15. استخدام Cosine similarity في Zero-shot classification

نحتاج إلى طريقة لمقارنة vectors.

يستخدم الفصل **cosine similarity**.

من الناحية الحدسية، تقارن cosine similarity اتجاه اثنين من vectors.

إذا كان اثنان من embeddings يشيران إلى اتجاهات متشابهة في semantic space، تكون cosine similarity بينهما أعلى.

من الناحية المفاهيمية:

```text
تمثيل المراجعة (review embedding)
        ↘
      تشابه Cosine (cosine similarity)
        ↗
تمثيل التسمية (label embedding)
```

بالنسبة إلى review واحدة:

```text
similarity(review, negative_label) = 0.41 — التشابه مع Label السلبية
similarity(review, positive_label) = 0.77 — التشابه مع Label الإيجابية
```

نتنبأ بـ:

```text
positive — التسمية ذات التشابه الأعلى
```

لأنها تمتلك similarity أعلى.

تحتوي matrix على:

```text

عمود واحد لكل Candidate label (one column per candidate label)
```

ثم يختار `argmax` الـ label الأكثر تشابهًا.

[[IMAGE_NEEDED: Cosine zero-shot classification | Show one document embedding as an arrow and two candidate-label vectors; one label vector has a smaller angle/higher similarity and is selected | Learner should understand that classification is performed by semantic proximity rather than a separately trained classifier]]

## 16. صياغة Label جزء من Input الخاص بـ Model

تظهر ملاحظة دقيقة لكنها قيّمة في نصيحة الفصل.

## 21. التكلفة و Rate limits وعدم اليقين في Benchmark

يضيف الفصل عدة تحذيرات هندسية.

### تكلفة API

قد يكون لاستدعاء Model تكلفة صغيرة لكل request.

لكن عبر آلاف أو ملايين المستندات تصبح هذه التكلفة مهمة.

فكر دائمًا وفقًا لـ:

```text
التكلفة لكل عنصر (cost per item)
×
عدد العناصر (number of items)
×
عدد مرات إعادة المحاولة / التجارب المتكررة (number of retries و repeated experiments)
```

### حدود المعدل (Rate limits)

قد تحد APIs الخارجية من عدد requests بمرور الوقت.

يذكر الفصل **exponential backoff** كإحدى الاستراتيجيات.

من الناحية المفاهيمية:

```text
يفشل Request بسبب Rate limit
        ↓
الانتظار لفترة قصيرة
        ↓
إعادة المحاولة (retry)
        ↓
إذا فشل مرة أخرى، انتظر مدة أطول
        ↓
أعد المحاولة حتى النجاح أو بلوغ الحد الأقصى للمحاولات
```

### تلوث Benchmark

يذكر الفصل نتيجة قوية لـ closed generative model، لكنه يحذر من أن training data الخاصة بـ Model غير معروفة بالكامل.

إذا ظهرت benchmark dataset ضمن training، فقد لا يعكس الأداء المقاس بصورة نظيفة generalization على أمثلة غير مرئية.

وهذا مبدأ مهم جدًا في evaluation:

> يكون تفسير benchmark score المرتفع أسهل عندما تعرف أن test data لم تكن موجودة فعلًا أثناء model training.

## 22. مقارنة Approaches الخاصة بـ Classification في الفصل

يقدم الفصل spectrum مفيدًا.

| النهج (Approach) | هل يتطلب Labeled training data منك؟ | ما الذي تدربه أنت؟ | الإخراج الرئيسي | مثال الفصل |
|---|---:|---|---|---|
| نموذج Task-specific مُدرَّب مسبقًا | لا | لا شيء | درجات الفئات (Class scores) | نموذج Twitter-RoBERTa sentiment |
| أسلوب Embeddings + classifier | نعم | Classifier صغير | تسمية الفئة (Class label) | نموذج MPNet embeddings + logistic regression |
| أسلوب Zero-shot embeddings | لا | لا شيء | Label الأكثر تشابهًا | أوصاف Labels + cosine similarity |
| نموذج توليدي (Generative model) | لا توجد حاجة إلى domain labels إضافية في المثال | لا شيء | Label نصية مولدة (Generated text label) | نموذج Flan-T5 / API |

### نتائج Weighted F1 المذكورة في الفصل

بالنسبة إلى التجارب المحددة في المصدر:

```text
نموذج Sentiment مخصص للمهمة (Task-specific sentiment model):
~0.80 — Weighted F1 تقريبية

Frozen embeddings + logistic regression:
~0.85 — Weighted F1 تقريبية

تشابه Zero-shot embeddings (Zero-shot embedding similarity):
~0.78 — Weighted F1 تقريبية

Flan-T5:
~0.84 — Weighted F1 تقريبية

Closed generative API model:
~0.91 — Weighted F1 تقريبية
```

هذه الأرقام **نتائج من إعداد الفصل المحدد**، وليست ranking تنطبق على كل مشكلة classification.

يمكن أن تختلف النتيجة باختلاف:

- مجموعات البيانات (datasets)،
- الموجهات (prompts)،
- تعريفات classes،
- نماذج Embedding،
- مدى تطابق Domain،
- إصدارات Models،
- وطرق evaluation.

يمكن لهذه العوامل أن تغيّر النتيجة.

### إطار اتخاذ القرار الأكثر فائدة

اسأل:

```text
هل لدي Labeled data؟
هل أحتاج إلى Latency منخفضة؟
هل يمكنني استضافة Model؟
هل أحتاج إلى Privacy؟
ما تكلفة Inference؟
ما مدى ثبات Output format المطلوب؟
هل يمكنني تحمل الاعتماد على API؟
هل يوجد بالفعل Task-specific model مناسب؟
هل يستطيع Embedding model فصل Classes جيدًا؟
هل يمكن وصف Labels بوضوح؟
```

هذا أكثر فائدة بكثير من السؤال عن Model واحد هو الأفضل بصورة مطلقة.

## مفاهيم خاطئة مهمة

### المفهوم الخاطئ 1

> تتطلب Text classification دائمًا fine-tuning لـ Model كبير.

### لماذا هذا خطأ؟

يعرض الفصل classification باستخدام Models خضعت بالفعل لـ fine-tuning، و frozen embeddings مع classifier صغير، و zero-shot embedding similarity، و generative models يتم توجيهها باستخدام prompts.

---

### المفهوم الخاطئ 2

> إذا استخدمت Embeddings، فيجب إعادة تدريب Embedding model نفسه.

### لماذا هذا خطأ؟

في مثال supervised embedding، يظل embedding model مجمدًا. ويتم تدريب logistic regression فقط.

---

### المفهوم الخاطئ 3

> يخبرني Accuracy بكل ما أحتاج إلى معرفته.

### لماذا هذا خطأ؟

تكشف precision و recall أنماط فشل مختلفة، بينما تلخص F1 التوازن بينهما. ويمكن لـ Accuracy إخفاء المشكلات، خصوصًا مع class imbalance.

---

### المفهوم الخاطئ 4

> تعني Zero-shot classification أن Model لم ير من قبل لغة مرتبطة بـ Labels.

### لماذا هذا خطأ؟

تعني zero-shot هنا أنك لا تقدم labeled examples لهذه target task. أما pretrained embedding model فقد تعلم بالفعل broad language representations من training سابق.

---

### المفهوم الخاطئ 5

> لا تهم أسماء Labels عند استخدام Zero-shot embeddings.

### لماذا هذا خطأ؟

يتم إنشاء embedding لنص label نفسه. ويمكن أن تنتج الأوصاف المختلفة vector representations مختلفة، وبالتالي similarities مختلفة.

---

### المفهوم الخاطئ 6

> يعرف Generative model تلقائيًا مهمة Classification التي تريدها.

### لماذا هذا خطأ؟

تحتاج إلى توصيل المهمة إلى Model من خلال prompt أو instruction.

---

### المفهوم الخاطئ 7

> تثبت نتيجة أعلى في إحدى تجارب الفصل أن هذا Approach متفوق دائمًا.

### لماذا هذا خطأ؟

تنتمي هذه النتائج إلى dataset و Model و prompt و domain وإعداد evaluation محددة.

## المصطلحات الأساسية

| المصطلح | المعنى |
|---|---|
| تصنيف النصوص (Text classification) | إسناد label أو class محددة مسبقًا إلى input text |
| التصنيف الثنائي (Binary classification) | Classification تحتوي على class اثنتين محتملتين |
| تحليل المشاعر (Sentiment analysis) | Classification لقطبية المشاعر أو الرأي، مثل positive مقابل negative |
| نموذج التمثيل (Representation model) | Model يُستخدم أساسًا لإنشاء representations مفيدة للنص |
| نموذج مخصص للمهمة (Task-specific model) | Pretrained model خضع لـ fine-tuning لتنفيذ downstream task محددة |
| نموذج Embedding | Model يحوّل النص إلى dense numerical vectors |
| نموذج ثابت (Frozen model) | Model لا يتم تحديث weights الخاصة به أثناء training الحالية |
| استخراج السمات (Feature extraction) | تحويل raw input إلى numerical features يستخدمها Model آخر |
| خوارزمية Logistic regression | Model تقليدي خفيف يُستخدم كثيرًا في classification |
| مصفوفة الالتباس (Confusion matrix) | جدول يلخص true positives و true negatives و false positives و false negatives |
| مقياس Precision | من بين predicted positives، النسبة التي تكون positive فعلًا |
| مقياس Recall | من بين actual positives، النسبة التي تم اكتشافها بصورة صحيحة |
| مقياس Accuracy | نسبة جميع predictions الصحيحة |
| درجة F1 | توازن توافقي بين precision و recall |
| التصنيف دون أمثلة (Zero-shot classification) | إسناد labels دون task-specific labeled training examples |
| تمثيل Label (Label embedding) | Vector representation لوصف class بلغة طبيعية |
| تشابه Cosine (Cosine similarity) | مقياس similarity يعتمد على الزاوية بين vectors |
| التصنيف التوليدي (Generative classification) | إعادة صياغة classification باعتبارها generation لـ textual label |
| هندسة Prompt (Prompt engineering) | تصميم صياغة instructions أو input بصورة تكرارية لتحسين model outputs |
| نموذج Encoder-decoder | Architecture تحتوي على encoder يعالج input و decoder يولد output |
| نموذج T5 | عائلة Text-to-Text Transfer Transformer |
| نموذج Flan-T5 | عائلة T5 من نوع instruction-tuned تم تدريبها عبر مهام كثيرة مصاغة في صورة prompts |
| حد المعدل (Rate limit) | قيد على عدد مرات استدعاء API خارجية خلال فترة زمنية |
| التراجع الأُسّي (Exponential backoff) | Retry strategy تزيد مدة الانتظار تدريجيًا بعد حالات الفشل المتكررة |
| تلوث Benchmark (Benchmark contamination) | احتمال وجود evaluation data ضمن training data الخاصة بـ Model |

## اختبار ذاتي

قبل المتابعة، تأكد من أنك تستطيع الإجابة عن الأسئلة الآتية:

1. ما هي text classification؟
2. لماذا تُعد sentiment classification في هذا الفصل binary task؟
3. ما الفرق بين task-specific model و embedding model؟
4. لماذا يمكن أن يضر domain mismatch بأداء pretrained classifier؟
5. ما TP و TN و FP و FN؟
6. ما السؤال الذي يجيب عنه precision؟
7. ما السؤال الذي يجيب عنه recall؟
8. لماذا يمكن أن تكون F1 أكثر إفادة من accuracy وحدها؟
9. في approach الخاص بـ embedding-classifier، أي Model يظل frozen وأي Model يتم تدريبه؟
10. ماذا يعني `(8530, 768)` بالنسبة إلى training embeddings؟
11. كيف تعمل zero-shot embedding classification؟
12. لماذا يمكن أن تغير label descriptions الأكثر ثراءً نتائج zero-shot؟
13. لماذا يحتاج generative classifier إلى prompt؟
14. لماذا تحتاج generated labels غالبًا إلى normalization أو mapping قبل evaluation؟
15. ما الفرق المفاهيمي بين T5 classification و BERT-style task-specific classifier؟
16. لماذا يجب أخذ API cost و rate limits في الاعتبار عند تصنيف datasets كبيرة؟
17. لماذا قد يجعل التداخل غير المعروف في training data تقييم benchmark لـ closed model صعب التفسير؟
18. في أي ظروف قد يكون embeddings + logistic regression اختيارًا جذابًا؟
19. لماذا ينبغي أن تقارن أيضًا مع classical baselines مثل TF-IDF + logistic regression؟
20. صف جميع مسارات classification الأربعة التي يغطيها هذا الدرس.

## احتفظ بهذه الفكرة

**Text classification ليست model architecture واحدة، بل هي هدف يمكن الوصول إليه بطرق متعددة. يستطيع task-specific encoder إخراج class scores مباشرةً؛ ويمكن لـ frozen embedding model توفير features قابلة لإعادة الاستخدام لـ lightweight supervised classifier؛ ويمكن لـ label descriptions تمكين zero-shot classification من خلال vector similarity؛ كما يستطيع generative model تحويل المشكلة إلى instruction-following text generation. ويعتمد أفضل اختيار هندسي على labels و data و domain و compute و cost و latency و privacy واحتياجات evaluation لديك.**
