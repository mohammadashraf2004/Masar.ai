## 1. Linear Regression: ما الذي يتعلمه Model بالضبط؟

إحدى الطرق المفيدة للتوقف عن التعامل مع machine learning كـ black box هي فصل أربع أفكار كثيرًا ما تختلط معًا:

1. **Model:** القاعدة التي تحول inputs إلى predictions.
2. **Parameters:** الأرقام داخل هذه القاعدة التي يتعلمها Model من data.
3. **Loss أوCost Function:** الكمية التي تخبرنا بمدى خطأ Model حاليًا.
4. **Training Algorithm:** الإجراء المستخدم للعثور على قيم أفضل للـ parameters.

في linear regression يكون Model بسيطًا. فهو يتنبأ بالـ target عبر أخذ weighted sum من input features ثم إضافة bias term.

لمثال واحد يحتوي features هي `x1, x2, ..., xn`:

```text
prediction = bias + weight_1*x_1 + weight_2*x_2 + ... + weight_n*x_n — صيغة التنبؤ
```

وباستخدام notation الخاصة بالـ parameters في الفصل، يمكن كتابة الفكرة نفسها كالتالي:

```text
ŷ = θ₀ + θ₁x₁ + θ₂x₂ + ... + θₙxₙ
```

يحرك bias المسمى `θ₀` قيمة prediction لأعلى أوأسفل. أما كل parameter أخرى فتتحكم في مدى تأثير feature معينة على prediction.

### المنظور Vectorized

نادراً ما تحسب machine-learning libraries كل weighted term باستخدام Python statement منفصلة. فهي تمثل features وparameters باستخدام vectors وmatrices، ما يسمح بتنفيذ الحساب نفسه بكفاءة لعدد كبير من features والأمثلة.

مع dummy feature قيمتها `x₀ = 1`، يمكن كتابة prediction بصورة مختصرة:

```text
ŷ = θᵀx
```

هذه notation المختصرة مهمة لأن matrix operations نفسها ستظهر مرة أخرى في gradient descent وneural networks وmodern deep-learning libraries.

### Training يعني تقليل Error

افترض أن Model يتنبأ بأسعار المنازل. لا تكون مجموعة parameters مفيدة إلا إذا كانت predictions قريبة من الأسعار الحقيقية. لذلك تحتاج linear regression إلى مقياس عددي للخطأ.

يستخدم الفصل **mean squared error (MSE)** أثناء training:

```text
MSE = average((prediction - target)²) — متوسط مربعات الأخطاء
```

للتربيع أثران عمليان:

- الأخطاء الموجبة والسالبة لا تلغي بعضها بعضًا؛
- الأخطاء الكبيرة تُعاقب بقوة أكبر من الأخطاء الصغيرة.

يشير الفصل إلى تمييز مهم: لا يلزم أن تكون metric التي تعرضها للمستخدمين أوstakeholders هي نفسها loss التي يُحسنها Model أثناء training. على سبيل المثال، قد تُحسن MSE لأنها مريحة رياضيًا، بينما تعرض RMSE لأنها أسهل في التفسير بوحدات target الأصلية.

### Closed-Form Training: معادلة Normal Equation

إحدى طرق تدريب linear regression هي حساب parameter vector التي تقلل MSE مباشرةً. يعرض الفصل **normal equation**:

```text
θ̂ = (XᵀX)⁻¹Xᵀy
```

يسمى هذا **closed-form solution** لأنه يحسب الإجابة مباشرةً بدلًا من تحسين parameters عبر training steps متكررة.

- قد يكون عدد features أكبر من عدد examples.
- تتعامل SVD-based methods مع هذه edge cases بدرجة أكبر من robustness.

تُعد closed-form/SVD approaches جذابة لأنها تحتاج تقريبًا إلى عدم ضبط أي hyperparameters، لكنها تصبح مكلفة عندما يصبح عدد features ضخمًا جدًا. تزداد training cost بقوة مع feature count. بعد تدريب linear model، تكون prediction نفسها رخيصة: بصورة تقريبية، مضاعفة عدد examples أوfeatures تعني نحو ضعف مقدار عمل prediction.

**النموذج الذهني:** يسأل closed-form training: *هل يمكنني حل أفضل parameters مباشرةً؟* بينما يسأل gradient descent: *هل يمكنني التحرك خطوة بخطوة نحو parameters أفضل؟*

## 2. Gradient Descent: التعلم عبر خطوات نحو الأسفل

تُعد gradient descent واحدة من أهم الأفكار في machine learning لأن الآلية الأساسية نفسها تظهر لاحقًا في تدريب neural networks.

تخيل أنك تقف على جبل وسط ضباب كثيف. لا تستطيع رؤية الوادي، لكنك تستطيع الإحساس بالاتجاه الذي ينحدر بأكبر حدة. تأخذ خطوة إلى الأسفل، ثم تقيس الميل مرة أخرى، وتكرر ذلك. تطبق gradient descent الفكرة نفسها على cost function.

تبدأ algorithm من parameter vector تسمى `θ`، وغالبًا ما تُهيأ عشوائيًا. ثم تكرر:

1. قياس كيفية تغير cost بالنسبة لكل parameter.
2. دمج هذه partial derivatives في **gradient vector**.
3. التحرك في الاتجاه المعاكس للـ gradient.
4. التكرار حتى يصبح التقدم ضئيلًا جدًا أوتتحقق stopping rule.

التحديث العام هو:

```text
θ ← θ - η ∇J(θ)
```

حيث:

- `J(θ)` هي cost function،
- `∇J(θ)` هو gradient الخاص بها،
- `η` (eta) هو **learning rate**.

### Learning Rate: ما حجم كل خطوة؟

يتحكم learning rate في سرعة training واستقرارها.

- **صغير جدًا:** training مستقرة لكنها بطيئة بصورة مؤلمة.
- **مناسب:** يصل Model إلى minimum بكفاءة.
- **كبير جدًا:** قد تتجاوز algorithm الـ minimum مرارًا وتبدأ في divergence.

{{image:gradient-descent-learning-rates}}

يترتب على ذلك درس عملي: optimization failures لا تكون دائمًا بسبب Model نفسه. أحيانًا يكون Model مناسبًا لكن training hyperparameters سيئة.

### Convexity وGlobal Minimum

يمكن أن تحتوي cost function عامة على local minima وridges وplateaus. لكن linear regression باستخدام MSE أسهل: cost function الخاصة بها convex. بصورة غير رسمية، يعني هذا أن لها global basin واحدة بدلًا من local minima متعددة متنافسة.

لذلك تستطيع gradient descent في linear regression مع MSE الاقتراب من global minimum ما دام learning rate ليس كبيرًا جدًا واستمر training وقتًا كافيًا.

### لماذا يهم Feature Scaling؟

افترض أن feature واحدة تتراوح من `0` إلى `1` بينما تتراوح أخرى من `0` إلى `100000`. تصبح cost surface ممدودة. وقد تتحرك gradient descent بطريقة zigzag داخل وادٍ طويل وضيق بدلًا من التوجه بكفاءة إلى minimum.

لهذا يوصي الفصل بعمل scaling للـ features قبل gradient-descent training، مثلًا باستخدام `StandardScaler`.

الهدف ليس جعل data "أفضل" من ناحية المعنى. الهدف هو جعل optimization geometry أسهل.

### إيقاف Training

اختيار epoch count ضخمة وثابتة يهدر computation بعد أن يكون Model قد وصل فعليًا إلى convergence. فكرة أفضل للإيقاف هي مراقبة gradient norm أوconvergence signal أخرى. عندما يصبح gradient صغيرًا جدًا، تصبح parameter updates صغيرة جدًا أيضًا.

تسمى threshold المستخدمة في stopping rule من هذا النوع غالبًا **tolerance**.

### 3.2 النسخة العشوائية: Stochastic Gradient Descent (SGD)

تتخذ SGD النهج المقابل: تعتمد كل update على **مثال واحد مختار عشوائيًا**.

هذه noise ليست سيئة بالكامل. في cost surfaces غير المنتظمة، قد تساعد optimizer على الهروب من local minima ضحلة. لكن العشوائية نفسها تجعل الاستقرار بدقة عند minimum أكثر صعوبة.

يقدم الفصل **learning schedule**: ابدأ بخطوات أكبر، ثم قلل learning rate تدريجيًا حتى يتمكن training من الاستقرار.

### لماذا يهم Shuffling في SGD؟

تعمل SGD بصورة أفضل عندما تتصرف examples تقريبًا كـ independent and identically distributed samples. إذا كانت dataset مرتبة حسب class أوtime block أونمط قوي آخر، ومررت عليها دون عناية مناسبة، فقد تصبح updates متحيزة منهجيًا عبر sequence.

عمل shuffling للبيانات بين epochs طريقة بسيطة لتقليل المشكلة عندما تسمح طبيعة task بذلك.

- أكثر استقرارًا من single-example SGD؛
- أرخص كثيرًا لكل update من full-batch gradient descent؛
- فعالة على GPUs وغيرها من hardware المحسنة لعمليات matrix.

## 4. Polynomial Regression وLearning Curves وBias/Variance Trade-Off

تنتج linear regression دالة خطية في input features. لكن هذا **لا** يعني أنها تستطيع نمذجة العلاقات الخطية فقط.

الحيلة هي transform للـ input أولًا.

افترض أن النمط الحقيقي يشبه علاقة quadratic:

```text
y ≈ 0.5x² + x + 2
```

⟦CODE_6⟧

ما زال Model **linear في parameters الخاصة به**، رغم أن prediction curve الخاصة به nonlinear في input الأصلي.

### تظهر Interactions تلقائيًا

مع عدة original features، تستطيع `PolynomialFeatures` إنشاء powers مثل `a²` و`b³`، وكذلك interaction terms مثل `ab` و`a²b` و`ab²`.

هذا قوي، لكن عدد generated features قد ينفجر بصورة combinatorial مع زيادة degree وfeature count. لذلك قد تصبح polynomial models عالية degree مكلفة وعرضة لـ overfitting.

### Underfitting مقابل Overfitting

زيادة model flexibility يمكن أن تنقلك عبر ثلاث حالات:

- **Underfitting:** Model أبسط من اللازم لتمثيل pattern الحقيقي.
- **Good fit:** يلتقط Model البنية المهمة دون مطاردة noise.
- **Overfitting:** ينحني Model حول training examples والـ noise، ما يضعف generalization.

{{image:polynomial-model-complexity}}

### Learning Curves

تقارن learning curve بين training error وvalidation error مع تغير كمية training data أوتقدم training.

النمط المعتاد لـ **underfitting** هو:

- training error مرتفع نسبيًا؛
- validation error مرتفع أيضًا؛
- يقترب المنحنيان من بعضهما.

عندما يحدث ذلك، فإن مجرد إضافة examples أكثر لا يحل المشكلة الأساسية عادةً. Model أوfeature representation أضعف من اللازم.

{{image:learning-curves-underfitting}}

يختلف نمط **overfitting** المعتاد:

- training error منخفض؛
- validation error أعلى بصورة ملحوظة؛
- توجد gap مستمرة بين المنحنيين.

قد تقلل زيادة training data هذه gap أحيانًا، لأنه يصبح من الأصعب على Model حفظ تفاصيل peculiarities لعينة صغيرة.

{{image:learning-curves-overfitting}}

### المفاضلة بين Bias وVariance

يمكن فهم generalization error من خلال ثلاثة مصادر:

**Bias**  
خطأ ناتج عن assumptions مقيدة أكثر من اللازم. Model عالي bias يفوّت بنية مهمة ويميل إلى underfitting.

**Variance**  
خطأ ناتج عن حساسية زائدة لعينة training المحددة. Model عالي variance يتغير أكثر من اللازم عندما تتغير data قليلًا ويميل إلى overfitting.

**Irreducible Error**  
Noise لا يمكن التخلص منها ببساطة باختيار Model أفضل. تقليلها يتطلب تحسين data-generating أوdata-cleaning process.

زيادة model complexity تقلل bias عادةً لكنها ترفع variance. أما regularization الأقوى فغالبًا يفعل العكس.

## 5. Regularization: التحكم في مرونة Model

تفرض regularization قيودًا عمدًا على Model حتى تقل رغبته في fitting للـ noise.

في polynomial regression، يعد تقليل polynomial degree شكلًا بسيطًا من regularization. أما في linear models، فيركز الفصل على تقييد learned weights.

قبل مقارنة الطرق، تذكر قاعدة عملية:

> **نفّذ Feature Scaling قبل معظم Regularized Linear Models.**

من دون scaling، قد تؤثر penalty في features بصورة غير عادلة فقط لأن الوحدات الرقمية مختلفة.

### 5.1 Ridge Regression: تقليص Weights باستخدام ℓ2 Penalty

تضيف ridge regression penalty مبنية على squared ℓ2 norm للـ feature weights.

مفاهيميًا:

```text
training objective = MSE + α × squared_weight_size — هدف التدريب
```

لا يتم regularize للـ bias term.

يتحكم hyperparameter المسمى `α` في قوة regularization:

- `α = 0` تتصرف مثل unregularized linear regression؛
- `α` الأكبر تدفع weights لتصبح أقرب إلى zero؛
- `α` المفرطة قد تجعل Model أبسط من اللازم وترفع bias.

⟦CODE_7⟧

Ridge اختيار افتراضي قوي عندما تريد linear model مستقرة وتتوقع أن تسهم features كثيرة بدرجة ما.

### 5.2 Lasso Regression: تشجيع Sparse Solutions باستخدام ℓ1 Penalty

تضيف lasso penalty مبنية على ℓ1 norm للـ feature weights.

أبرز سلوك لها أن بعض coefficients يمكن أن تصبح **zero بالضبط**. وهذا يعني أن lasso يمكنها تنفيذ شكل من automatic feature selection.

⟦CODE_8⟧

هذه sparsity مفيدة عندما تتوقع أن subset فقط من features يجب أن تكون مهمة. لكن lasso regularization القوية جدًا قد تزيل signal مفيدة أيضًا.

### لماذا تقلص Ridge بينما يمكن لـ Lasso حذف Weights؟

تختلف geometry الخاصة بـ ℓ1 وℓ2 penalties. تجعل ℓ1 geometry الخاصة بـ Lasso الوصول إلى solutions على parameter axes أمرًا شائعًا، وهو ما يقابل exact zeros. أما ℓ2 geometry السلسة الخاصة بـ Ridge فتميل إلى تقليص parameters تدريجيًا نحو zero دون جعلها zero بالضبط عادةً.

تمزج elastic net بين العقوبتين. تتحكم mix ratio في مقدار تشابه penalty مع lasso أوridge.

- mix ratio `0` → أقرب إلى ridge؛
- mix ratio `1` → أقرب إلى lasso؛

- elastic net غالبًا أكثر أمانًا من pure lasso عندما تكون features شديدة الارتباط أوعندما يفوق عدد features عدد training instances.

### 5.4 Early Stopping: Regularization عبر التوقف في الوقت المناسب

لا تحتاج regularization دائمًا إلى penalty term صريحة. في iterative models، توجد strategy أخرى هي تتبع validation performance والتوقف عندما تتوقف عن التحسن.

النمط المعتاد:

1. training error تستمر في الانخفاض؛
2. validation error تنخفض في البداية؛
3. validation error تصل إلى minimum؛
4. validation error تبدأ في الارتفاع مع زيادة overfitting.

## 6. Logistic Regression: تحويل Linear Score إلى Probability

رغم اسمها، تُستخدم logistic regression أساسًا في **classification**.

في binary problem مثل spam مقابل not spam، تحسب logistic regression أولًا linear score المألوفة:

```text
t = θᵀx
```

بدلًا من إعادة `t` مباشرةً، تمرر score عبر **logistic sigmoid**:

```text
σ(t) = 1 / (1 + e⁻ᵗ)
```

تكون output بين `0` و`1`، لذلك يمكن تفسيرها كـ estimated probability للـ positive class.

### من Probability إلى Class

باستخدام default threshold وهي 50%:

```text
if estimated_probability >= 0.5:
    تنبّأ بالفئة الموجبة (positive class)
else:
    تنبّأ بالفئة السالبة (negative class)
```

ولأن sigmoid تصل إلى `0.5` عندما تكون linear score مساوية للصفر، فهذا يكافئ توقع positive class عندما `θᵀx >= 0`.

تسمى raw linear score غالبًا **logit**. ويمكن النظر إلى logit أيضًا باعتبارها log-odds للـ positive class.

### Training باستخدام Log Loss

ينبغي أن تعاقب training objective الاحتمالات الخاطئة والواثقة بقوة.

إذا كانت true class موجبة، فيجب أن يكون prediction لـ probability قريبة من `0` مكلفًا جدًا. وإذا كانت true class سالبة، فيجب أن يكون prediction لـ probability قريبة من `1` مكلفًا جدًا. تحقق **log loss** هذا السلوك بالضبط.

عبر dataset كاملة، تقلل logistic regression متوسط negative log-likelihood للـ labels الصحيحة.

بعكس normal equation في linear regression، لا تملك logistic regression direct closed-form solution للـ optimal parameters. لكن log-loss objective الخاصة بها convex، لذلك تستطيع gradient-based optimization إيجاد global minimum تحت optimization settings مناسبة.

### Decision Boundaries

يمكن لـ logistic classifier إنتاج probabilities في كل مكان، لكن class prediction تحتاج threshold. مجموعة feature values التي يكون فيها Model عند threshold بالضبط تشكل **decision boundary**.

في logistic regression العادية، تكون هذه boundary خطية في feature space.

## 7. Softmax Regression: Multiclass Classification داخل Model واحدة

تسأل binary logistic regression: "ما احتمال class 1؟"

توسع softmax regression، التي تسمى أيضًا **multinomial logistic regression**، الفكرة إلى عدة classes **mutually exclusive**.

بالنسبة إلى input هي `x`، يحسب Model linear score واحدة لكل class:

```text
score_class_1 = θ₁ᵀx
score_class_2 = θ₂ᵀx
...
score_class_K = θ_Kᵀx
```

إذًا لكل class parameter vector خاصة بها.

### Softmax تحول Scores إلى Probabilities

raw class scores ليست probabilities. تقوم Softmax بعمل exponentiation وnormalization لها بحيث:

- تكون probability لكل class بين `0` و`1`؛
- مجموع probabilities لكل classes يساوي `1`.

مفاهيميًا:

```text
probability(class k) = exp(score_k) / sum(exp(all class scores)) — احتمال الفئة k
```

يتنبأ Model بالـ class ذات أعلى estimated probability باستخدام `argmax`.

نقطة دقيقة ومهمة: لا تحتاج winning class إلى probability أكبر من 50%. مع ثلاث classes، ما زالت probabilities مثل `0.40` و`0.35` و`0.25` تنتج winner واضحة.

### Softmax هي Multiclass وليست Multioutput

استخدم softmax عندما يجب اختيار class واحدة بالضبط من بدائل mutually exclusive، مثل ثلاثة أنواع من الزهور.

لا تستخدم softmax output واحدة عندما يمكن أن تكون عدة labels صحيحة في الوقت نفسه. مثلًا، قد تكون صورة "outdoor" و"nighttime" معًا؛ هذان targetان binary مستقلان، وليسا classes متنافية.

### دالة Cross-Entropy Loss

لتدريب softmax regression، يقدم الفصل **cross entropy**. وهي تعاقب Model عندما يعطي probability منخفضة للـ correct class.

مع one-hot targets، تركز loss على probability المعطاة للـ true class:

```text
cross-entropy = -log(probability assigned to the correct class) — سالب لوغاريتم احتمال الفئة الصحيحة
```

تُحسب هذه losses عبر dataset كاملة ثم يؤخذ المتوسط.

عندما توجد classان فقط، تختزل هذه الفكرة إلى log-loss نفسها المستخدمة في binary logistic regression.

يربط الفصل أيضًا cross entropy بـ information theory: إذا اختلف predicted probability distribution بشدة عن true distribution، تصبح coding cost أكبر.

## 8. تجميع الفصل معًا: كيف تختار ما الذي تجربه؟

يسهل تذكر الفصل إذا نظرت إليه كسلسلة من engineering decisions.

### إذا كان Target مستمرًا

ابدأ بـ regression model.

- العلاقة خطية تقريبًا وعدد features manageable → `LinearRegression` baseline مفيدة.
- feature space ضخمة أوdata streaming/ضخمة جدًا → يصبح gradient-based training جذابًا.
- يوجد nonlinear curvature واضح → فكّر في polynomial features، لكن تحكم في complexity.

### إذا كان Optimization بطيئًا أوغير مستقر

افحص:

1. هل features على scales مختلفة جدًا؟
2. هل learning rate صغيرة جدًا؟
3. هل learning rate كبيرة لدرجة تجعل loss diverge؟
4. هل full-batch training مكلفة جدًا بالنسبة إلى dataset size؟
5. هل mini-batches أوSGD أنسب للـ hardware/data setting؟

### إذا كان Training Error وValidation Error مرتفعين

فكر في **underfitting / high bias**.

استجابات ممكنة:

- استخدام Model أكثر expressive؛
- عمل feature engineering أفضل؛
- تقليل regularization المفرطة.

إضافة data أكثر وحدها لن تصلح غالبًا Model لا تستطيع حتى ملاءمة training set الخاصة بها بصورة مناسبة.

### إذا كان Training Error منخفضًا لكن Validation Error أعلى بكثير

فكر في **overfitting / high variance**.

استجابات ممكنة:

- جمع training data أكثر؛
- تبسيط Model؛
- زيادة regularization؛
- استخدام early stopping مع iterative learners.

### اختيار Linear Regularizer

| الطريقة | التأثير الرئيسي | أفضل نموذج ذهني |
|---|---|---|
| Ridge | تقلص كل weights | "حافظ على Model مستقرة ومعتدلة" |
| Lasso | يمكنها جعل weights تساوي zero بالضبط | "فضّل مجموعة sparse من features المفيدة" |
| Elastic net | تمزج ridge وlasso | "احصل على sparsity مع stability أكبر عند وجود correlated features" |
| Early stopping | تحد مدة استمرار fitting | "توقف قبل أن يبدأ validation performance في التدهور" |

### إذا كان Target Categorical

- فئتان mutually exclusive → logistic regression.
- أكثر من فئتين mutually exclusive → softmax regression.
- يمكن أن تكون عدة labels مستقلة صحيحة معًا → استخدم binary outputs/classifiers مستقلة بدلًا من softmax choice واحدة.

### أعمق رابط في الفصل

قد تبدو linear regression وlogistic regression وsoftmax regression كـ algorithms مختلفة، لكنها تشترك في architecture عامة:

```text
الـ Features
   ↓
درجات خطية من المعاملات المتعلَّمة
   ↓
تحويل الدرجات إلى احتمالات عند الحاجة
   ↓
حساب Loss قابلة للاشتقاق
   ↓
تحسين المعاملات
```

يهيئك هذا pattern لفهم neural networks. تغير neural network الدالة التي تنشئ scores، لكن training ما زالت تدور حول parameters وdifferentiable losses وgradients وlearning rates وmini-batches وregularization وvalidation.

## مفاهيم خاطئة مهمة (Important Misconceptions)

### المفهوم الخاطئ 1

> "Gradient descent هي Model."

### لماذا هذا خطأ؟

Gradient descent هي **training algorithm**. أما linear regression وlogistic regression وneural networks فهي models. وقد يمكن تدريب Model نفسها باستخدام algorithms مختلفة.

### المفهوم الخاطئ 2

> "Training error الأقل تعني دائمًا Model أفضل."

### لماذا هذا خطأ؟

يمكن لـ Model تحقيق training error منخفضة جدًا عبر fitting للـ noise. تساعد validation performance وlearning curves في تحديد ما إذا كانت Model تعمم بصورة جيدة.

### المفهوم الخاطئ 3

> "Logistic regression تتنبأ بـ Class مباشرةً."

### لماذا هذا خطأ؟

هي تقدّر probability أولًا باستخدام sigmoid function. بعد ذلك تحول decision threshold هذه probability إلى class.

### المفهوم الخاطئ 4

> "Softmax هي الاختيار الصحيح متى كان للـ Task عدة Labels."

### لماذا هذا خطأ؟

تفترض Softmax اختيار class واحدة mutually exclusive. أما multi-label problems فتحتاج output formulation مختلفة، غالبًا independent sigmoid outputs أوbinary classifiers.

## المصطلحات الأساسية (Key Terminology)

| المصطلح | المعنى |
|---|---|
| Parameter | قيمة يتعلمها Model من training data، مثل weight أوbias |
| Hyperparameter | إعداد يُختار خارج learned parameters، مثل learning rate أوregularization strength |
| Cost function | كمية scalar تحاول training algorithm تقليلها |
| MSE | Mean squared error، وهي regression training objective شائعة |
| Gradient | vector من partial derivatives توضح كيف تتغير cost مع كل parameter |
| Learning rate | تحكم في step size تستخدمه gradient-based optimization |
| Epoch | مرور training واحد أوround تقليدية على dataset |
| Batch GD | Gradient descent تستخدم training set كاملة لكل update |
| SGD | Gradient descent تستخدم example واحدة لكل update |
| Mini-batch GD | Gradient descent تستخدم subset صغيرة لكل update |
| Learning schedule | قاعدة تغير learning rate أثناء training |
| Polynomial features | powers وinteractions من original features لنمذجة علاقات nonlinear |
| Learning curve | plot تقارن training وvalidation behavior مع تغير training data أوtraining progress |
| Bias | خطأ ناتج عن Model أوassumptions مقيدة بصورة زائدة |
| Variance | خطأ ناتج عن حساسية مفرطة لعينة training |
| Regularization | constraint يقلل model flexibility لتحسين generalization |
| Ridge | Linear model مع ℓ2 penalty |
| Lasso | Linear model مع ℓ1 penalty يمكن أن تنتج sparse coefficients |
| Elastic net | Regularization تجمع ℓ1 وℓ2 penalties |
| Early stopping | الاحتفاظ بـ Model عند نقطة أفضل validation performance |
| Sigmoid | دالة على شكل S تحول real score إلى range من 0 إلى 1 |
| Logit | Linear score / log-odds المستخدمة في logistic regression |
| Decision boundary | boundary في feature space تتغير عندها predicted class |
| Softmax | دالة تحول عدة class scores إلى probabilities مجموعها 1 |
| Cross entropy | Classification loss تعاقب probability المنخفضة على correct class |

## المراجعة الذاتية (Self-Check)

قبل المتابعة، تأكد أنك تستطيع الإجابة عن الآتي:

1. ما الفرق بين model وparameter وloss function وtraining algorithm؟
2. لماذا يمكن أن يؤدي تقليل MSE وتقليل RMSE إلى أفضل linear-regression parameters نفسها؟
3. لماذا يجعل feature scaling gradient descent تتقارب أسرع غالبًا؟
4. ما الفرق computational الأساسي بين batch GD وSGD وmini-batch GD؟
5. ما نمط learning curves الذي يشير إلى underfitting؟ وما النمط الذي يشير إلى overfitting؟
6. لماذا يمكن لـ lasso جعل coefficients تساوي zero بينما تقوم ridge غالبًا بتقليصها فقط؟
7. لماذا ينبغي أن يعتمد early stopping على validation performance وليس training loss وحدها؟
8. كيف تحول logistic regression linear score إلى probability؟
9. لماذا يمكن لـ softmax توقع class باحتمال أقل من 50%؟
10. متى تكون binary classifiers منفصلة أنسب من softmax classifier واحدة؟
