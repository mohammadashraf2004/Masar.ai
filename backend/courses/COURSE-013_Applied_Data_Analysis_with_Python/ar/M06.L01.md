لا يبدأ تحليل البيانات دائمًا بـ DataFrame مثالية محمّلة بالفعل في الذاكرة.

قد توجد البيانات الحقيقية في:

- ملفات CSV،

- مستندات JSON،
- جداول HTML،
- مخازن HDF5،
- ملفات Parquet،
- كائنات Pickle،
- قواعد بيانات Relational،
- قواعد بيانات NoSQL،
- Cloud object storage،
- REST APIs،
- GraphQL APIs.

لذلك يحتاج متخصص البيانات إلى الإجابة عن ثلاثة أسئلة عملية:

```text
أين توجد البيانات؟
        ↓
كيف أسترجعها؟
        ↓
كيف ينبغي أن أخزنها أوأمررها إلى النظام التالي؟
```

يتعامل الفصل مع هذه المهارات بوصفها جزءًا أساسيًا من Analytics الحديثة لأن البيانات قد تأتي من Websites وIoT systems وEmail/FTP systems وDatabases وExperiments وSurveys وExternal services.

خريطة مفيدة للفصل هي:

```text
ملفات محلية
CSV / Excel / JSON / HTML
        ↓
صيغ تحليلية
HDF5 / Parquet / Pickle
        ↓
قواعد بيانات علائقية
SQLite / MySQL
        ↓
قواعد بيانات NoSQL
MongoDB / Cassandra / Redis / Neo4j
        ↓
تخزين كائنات سحابي
Amazon S3 / Azure Blob Storage
        ↓
خدمات خارجية
REST / GraphQL APIs
        ↓
تجريد على مستوى التطبيق
Pony ORM
```

هدف التعلم الأساسي ليس حفظ APIs.

بل فهم **أي Storage model تتعامل معها، وكيف تتصل Python بها، وما Object التي تستقبلها، وكيف تنتقل البيانات إلى Pandas أوتخرج منها**.

إلى أين يجب أن تذهب Result بعد ذلك؟

ما تزال ORM تتصل بـ Relational database.

وهي توفر Python object/entity layer تُترجم إلى Database operations.

## ملاحظات اتساق المصدر

يتضمن الفصل المقدم عدة حالات عدم اتساق تستحق الانتباه.

### اسم Variable في HTML

ينشئ الفصل:

⟦CODE_89⟧

ثم يعرض لاحقًا:

⟦CODE_90⟧

والـ Table list المقصودة هي `df_list`.

### صياغة Parquet fallback engine

يسمي المصدر أولًا Engineين:

```text
pyarrow    # محرّك Parquet
fastparquet    # محرّك Parquet بديل
```

لكنه يذكر لاحقًا أن Pandas تعود إلى `tparquet`.

وهذه صياغة غير متسقة مع اسم Engine المذكورة مباشرة قبلها. يحتفظ هذا الدرس بالـ Engine pair التي صرح بها المصدر ويشير إلى الاختلاف بدل اختراع Engine ثالثة.

### أسماء MySQL databases

ينشئ الفصل:

```text
database employee    # قاعدة بيانات الموظفين
```

لكن الأمثلة اللاحقة تتصل بـ:

```text
database emp    # قاعدة بيانات emp
```

تبقى Workflow الاتصال واضحة، لكن الأسماء غير متسقة بين الأمثلة.

### Redis output

تخزن Redis Code:

```text
'eid' → '101'    # مفتاح إلى قيمة
```

وتسترجع هذه Value.

بينما تعرض Output في المصدر:

```text
101 Steve Smith 42    # سجل موظف
```

وهي تطابق سجلًا على نمط Cassandra السابق أكثر من Code الخاصة بـ Redis.

### أمثلة Cloud

تستخدم أمثلة S3 وAzure Placeholder credential/configuration strings مثل:

```text
your_access_key_here
your_secret_key_here
your_azure_storage_connection_string
```

وهي Instructional placeholders في المصدر المقدم.
