## 1. النص نوع مختلف من مُدخَلات Machine Learning

تتوقع معظم خوارزميات Machine Learning أن يُمثَّل كل مثال (sample) بمجموعة ثابتة من الـ features الرقمية. والنص لا يبدو بطبيعته هكذا.

تأمّل هذه الأمثلة:

```text
"Great movie. I loved the ending."              # فيلم رائع. أحببت النهاية.
"The product stopped working after two days."   # توقّف المنتج عن العمل بعد يومين.
"Please reset my password."                     # من فضلك أعد تعيين كلمة المرور الخاصة بي.
```

للسلاسل النصية أطوال مختلفة وكلمات مختلفة وبنى مختلفة. وقبل أن يستطيع model تقليدي في Machine Learning استخدامها، نحتاج إلى تحويلها إلى أرقام.

### ليست كل سلسلة نصية نصًا حرًا

قد يمثّل عمود ذو قيم نصية عدة أشياء مختلفة:

1. **بيانات فئوية (Categorical)** — مجموعة ثابتة مثل `red` و`green` و`blue`.
2. **سلاسل حرة ينبغي تعيينها إلى فئات** — قيم مُدخَلة يدويًا مثل `grey` أو `gray` أو أسماء فئات بها أخطاء إملائية.
3. **سلاسل منظَّمة (Structured)** — تواريخ، أو أرقام هواتف، أو عناوين، أو أسماء، أو معرّفات.
4. **نص حر (Free-form text)** — مراجعات، ورسائل بريد إلكتروني، ورسائل دردشة، ومقالات، ومستندات.

وتعتمد طريقة معالجة الحقل على ما تعنيه السلسلة، لا على مجرد أن Python يخزّنها على أنها سلسلة نصية.

### المدوّنة (Corpus) والمستند (Document)

في تحليل النصوص:

- **المستند (document)** هو مثال نصي واحد،
- و**المدوّنة (corpus)** هي المجموعة الكاملة من المستندات.

وفي تحليل المشاعر لمراجعات الأفلام، تكون كل مراجعة مستندًا وتشكّل المراجعات كلها معًا المدوّنة.

### مثال متواصل: تحليل المشاعر (Sentiment analysis)

يستخدم الفصل 7 مراجعات أفلام IMDb مثالًا متواصلًا. المراجعات موسومة بأنها إيجابية أو سلبية، ولذلك فالمهمة النهائية هي Classification ثنائي خاضع للإشراف (supervised).

لكن التحدي الأول هو التمثيل:

```text
نص المراجعة الخام (raw review text)
      |
      v
متجه features رقمي (numeric feature vector)
      |
      v
المصنّف (classifier)
      |
      v
إيجابي أو سلبي (positive / negative)
```

## 2. Bag-of-words: تحويل النص إلى أرقام

Bag-of-words من أبسط تمثيلات النص التقليدية وأكثرها فائدة.

وهو يتجاهل عمدًا جزءًا كبيرًا من البنية الأصلية للمستند ويركّز على الكلمات التي تظهر وعدد مرات ظهورها.

وللعملية ثلاث خطوات رئيسية.

### الخطوة 1 — التجزئة (Tokenization)

قسّم المستند إلى وحدات تُسمّى tokens.

```text
"machine learning is useful"                # التعلّم الآلي مفيد

-> ["machine", "learning", "is", "useful"]
```

### الخطوة 2 — بناء المفردات (Vocabulary)

اجمع الـ tokens الفريدة التي رُصدت في مدوّنة التدريب.

لنفترض أن مدوّنتنا تحتوي على:

```text
"good movie"     # فيلم جيد
"bad movie"      # فيلم سيئ
"good acting"    # تمثيل جيد
```

ومن المفردات الممكنة:

```text
acting   # التمثيل
bad      # سيئ
good     # جيد
movie    # فيلم
```

يصبح كل مصطلح في المفردات feature واحدًا.

### الخطوة 3 — ترميز كل مستند

احسب عدد مرات ظهور كل كلمة من المفردات.

وباستخدام المفردات أعلاه:

```text
المستند (document): "good movie"

acting = 0
bad    = 0
good   = 1
movie  = 1

المتجه (vector) = [0, 0, 1, 1]
```

### CountVectorizer

تنفّذ scikit-learn الأداة bag-of-words بـ `CountVectorizer`.

⟦CODE_0⟧

تتعلّم `fit` المفردات من مستندات التدريب. وتستخدم `transform` تلك المفردات المتعلَّمة لترميز المستندات.

### لماذا تهمّ المصفوفات المتناثرة (Sparse matrices)

قد تحتوي مفردات النصوص الواقعية على عشرات الآلاف من الـ features، بينما يستخدم كل مستند جزءًا صغيرًا منها فقط.

وقد يبدو متجه المستند مفاهيميًا هكذا:

```text
[0, 0, 0, 3, 0, 0, 1, 0, 0, 0, ...]
```

معظم القيم أصفار. وتخزّن المصفوفة المتناثرة (sparse matrix) أساسًا القيم غير الصفرية بدلًا من إهدار الذاكرة على كل صفر.

وفي مثال IMDb في الفصل، ينتج bag-of-words عشرات الآلاف من features المفردات، وهذا بالضبط نوع التمثيل المتناثر عالي الأبعاد الذي تعمل فيه الـ models الخطية مثل logistic regression جيدًا.

### الكلمات المجهولة وقت التنبؤ

إذا احتوى مستند جديد على كلمة لم تكن موجودة حين تعلّم الـ vectorizer مفرداته، فإن تلك الكلمة لا يمثّلها أي feature موجود وتُتجاهل في مسار عمل CountVectorizer الأساسي.

وهذا سبب آخر لتعلّم المفردات من بيانات التدريب ثم إعادة استخدام ذلك التمثيل المضبوط على البيانات اللاحقة.

## 4. تفسير الـ model وn-grams

من مزايا الـ models النصية التقليدية أن features فيها غالبًا ما تكون مقروءة للبشر.

### فحص معاملات الـ model

في model خطي لتحليل المشاعر بـ logistic regression، يتلقى كل feature نصي معاملًا (coefficient) متعلَّمًا.

وتشير المعاملات الموجبة الكبيرة إلى features تدفع التنبؤات نحو فئة المراجعات الإيجابية. أما المعاملات السالبة الكبيرة فتدفع نحو فئة المراجعات السلبية.

وهذا يتيح لنا فحص ما إذا كان الـ model قد تعلّم إشارات معقولة، أو اختصارات مريبة، أو آثارًا خاصة بالـ dataset.

فمثلًا، قد تتلقى كلمات مثل `excellent` و`wonderful` معاملات موجبة، بينما قد تتلقى `worst` و`disappointment` معاملات سالبة.

### ضعف bag-of-words بالكلمات المفردة

تأمّل:

```text
"bad, not good"    # سيئ، ليس جيدًا
"good, not bad"    # جيد، ليس سيئًا
```

يرى تمثيل bag-of-words بالكلمات المفردة (unigram) الكلمات المفردة نفسها تقريبًا في الجملتين ويتجاهل ترتيبها.

### n-grams

الـ n-gram هو تسلسل من الـ tokens المتجاورة.

```text
1 رمز (token)    -> unigram
2 رمزان (tokens) -> bigram
3 رموز (tokens)  -> trigram
```

وللجملة:

```text
"this movie is not good"    # هذا الفيلم ليس جيدًا
```

تكون بعض الـ bigrams:

```text
"this movie"    # هذا الفيلم
"movie is"      # الفيلم هو
"is not"        # ليس
"not good"      # ليس جيدًا
```

يحفظ `not good` معلومات سياقية لا تستطيع الكلمة المعزولة `good` التقاطها وحدها.

⟦CODE_5⟧

وهذا يُبقي كلًّا من الـ unigrams والـ bigrams.

وتنشئ الـ n-grams الأطول features أكثر بكثير. وقد تلتقط عبارات مفيدة، لكنها قد تنشئ أيضًا features شديدة التخصص وتزيد الحساب أو خطر Overfitting.

وفي تجربة IMDb في الفصل، حسّنت إضافة الـ bigrams أداء التحقق بوضوح، بينما لم تضف الـ trigrams إلا فائدة إضافية صغيرة.

## 5. التجزئة المتقدمة وStemming وLemmatization

قد تعبّر الأشكال السطحية المختلفة للكلمة عن أفكار وثيقة الصلة:

```text
draw       # يرسم (الأصل)
drawing    # الرسم (صيغة -ing)
draws      # يرسم (الغائب المفرد)
drawn      # مرسوم (اسم المفعول)
```

ومعاملة كل هذه الأشكال على أنها features غير مترابطة قد تكبّر المفردات وتقلّل مقدار الدليل الذي يناله كل feature.

### Stemming

يطبّق Stemming تحويلات قائمة على القواعد تختصر الكلمات إلى جذع (stem) مشترك.

ولا يشترط أن تكون النتيجة كلمة صحيحة في القاموس.

من الناحية المفاهيمية:

```text
meeting -> meet   # الجذع (stem) لكلمة meeting هو meet
worse   -> wors   # الجذع قد لا يكون كلمة صحيحة
```

وStemming بسيط وسريع نسبيًا، لكن مخرجاته قد تكون فجّة.

### Lemmatization

تحاول Lemmatization تعيين الكلمة إلى صيغة أساسية ذات معنى لغوي تُسمّى lemma.

ويمكنها استخدام معلومات عن دور الكلمة في الجملة.

فمثلًا، قد تبقى كلمة مثل `meeting` على حالها `meeting` حين تُستخدم اسمًا لكنها تصبح `meet` حين تُستخدم فعلًا.

وLemmatization أكثر تعقيدًا من Stemming لكنها قد تنتج تطبيعًا (normalization) أكثر دلالة لغوية.

### لماذا قد يفيد التطبيع

إن دمج صيغ الكلمات المترابطة يقلّل عدد الـ features المستقلة. وقد يتصرف هذا إلى حد ما كأنه تنظيم (regularization) لأن الـ model يتلقى دليلًا مشتركًا أكثر للصيغ المترابطة.

وقد خفّضت تجربة الفصل المفردات تخفيضًا كبيرًا بـ lemmatization ووجدت تحسنًا متواضعًا في إعداد بيانات صغيرة عمدًا. ويعتمد الأثر الدقيق على الـ dataset.

## 6. نمذجة المواضيع (Topic modeling) بـ Latent Dirichlet Allocation

يمكن أيضًا تحليل النص دون استخدام labels.

تحاول نمذجة المواضيع (Topic modeling) اكتشاف أنماط متكررة من الكلمات عبر المدوّنة. ويمكن ربط المستند بموضوع واحد أو بعدة مواضيع.

### حدس LDA

يفترض Latent Dirichlet Allocation، ويُختصر في هذا السياق إلى LDA، أن المستندات يمكن تمثيلها على أنها مزيج من المواضيع، وأن المواضيع تتميّز بمجموعات من الكلمات التي تميل إلى الظهور معًا.

تخيّل مدوّنة أخبار. قد يعطي أحد المكوّنات المكتشَفة وزنًا قويًا لكلمات مثل:

```text
team, score, season, player    # الفريق، النتيجة، الموسم، اللاعب
```

وقد يركّز آخر على:

```text
vote, government, election, party    # التصويت، الحكومة، الانتخابات، الحزب
```

وقد نفسّر هذين المكوّنين على أنهما الرياضة والسياسة.

لكن LDA لا يعرف هذه التسميات البشرية. فهو يكتشف فقط أنماطًا إحصائية في التواجد المشترك للكلمات.

وقد يقابل مكوّن ما بدلًا من ذلك أسلوب كتابة مؤلف، أو لغة المراجعات الإيجابية، أو نمطًا آخر لا يسميه البشر عادةً موضوعًا.

### تفسير المواضيع بمسؤولية

يُفحص الموضوع عادةً بالنظر إلى أعلى كلماته وزنًا ثم قراءة المستندات التي تنال وزنًا عاليًا لذلك الموضوع.

وهذه الخطوة الثانية مهمة. فالأسماء المقروءة للبشر مثل `music` أو `horror` أو `negative reviews` هي تفسيراتنا نحن، لا تسميات تقدّمها الخوارزمية.

والـ topic models عشوائية، وتغيير الإعدادات أو البذرة العشوائية (random seed) قد ينتج مكوّنات مختلفة. لذلك ينبغي التحقق من الاستنتاجات بمقارنتها بالمستندات الفعلية لا استنتاجها من قائمة قصيرة بأعلى الكلمات فقط.

## 7. خطوة إلى الوراء: عرِّف مسألة Machine Learning أولًا

ينتقل الفصل 8 من التقنيات الفردية إلى درس أوسع: خوارزمية Machine Learning ليست إلا جزءًا واحدًا من عملية صنع قرار أكبر.

قبل اختيار الخوارزمية، اسأل:

```text
ما السؤال الذي أحاول الإجابة عنه؟
كيف سيُقاس النجاح؟
هل لديّ البيانات الصحيحة؟
ماذا يحدث إذا نجح النظام؟
ماذا يحدث حين يرتكب أخطاء؟
```

### ابدأ بالأثر لا بـ model مفضّل

لنفترض أن الهدف هو كشف الاحتيال.

لا يكفي أن نسأل ما إذا كان المصنّف يستطيع تحقيق دقة عالية. بل نحتاج أيضًا إلى معرفة ما إذا كان لكشف مزيد من الاحتيال قيمة عملية كافية تبرّر بناء النظام وصيانته.

والمقياس الأفضل هو، مثاليًا، المقياس المرتبط بالهدف التجاري أو البحثي الحقيقي، مثل تقليل الخسائر أو زيادة الإيرادات أو تقليل زمن الاستجابة أو منع النتائج الضارة.

### تطوير الـ model حلقة تغذية راجعة

كثيرًا ما يبدو مسار العمل الواقعي هكذا:

```text
حدّد المسألة (define problem)
    |
اجمع البيانات (collect data)
    |
نظّف ومثّل البيانات (clean / represent data)
    |
درِّب الـ model (train model)
    |
حلّل الأخطاء (analyze errors)
    |
أعد صياغة المهمة أو اجمع بيانات أفضل (reformulate task or collect better data)
    |
كرّر (repeat)
```

وقد يكشف تحليل الأخطاء معلومات ناقصة أو نقاط ضعف في صياغة المسألة. وأحيانًا تنتج البيانات الأفضل قيمة أكبر من ضبط الـ hyperparameter بلا نهاية.

### البشر في الحلقة (Humans in the loop)

لا يحتاج كل model إلى اتخاذ كل قرار تلقائيًا.

ويمكن لنظام مفيد أن يعالج تلقائيًا الحالات السهلة عالية الثقة وأن يرسل الحالات غير المؤكدة أو عالية المخاطر إلى إنسان.

مثلًا:

```text
ثقة الـ model عالية (model confidence high) -> إجراء آلي (automated action)
الـ model غير متأكد (model uncertain)       -> مراجعة بشرية (human review)
```

ويعتمد إمكان ذلك على التطبيق. فالنظام الذي يجب أن يتفاعل فورًا له قيود مختلفة عن نظام يمكن لإنسان فيه مراجعة الحالات الصعبة قبل اتخاذ الإجراء.

## 8. من النموذج الأولي إلى الإنتاج والتقييم الحي

دفتر (notebook) ينتج تنبؤات دقيقة ليس تلقائيًا نظام ML جاهزًا للإنتاج.

ويُدخل الإنتاج متطلبات إضافية مثل:

- الموثوقية،
- السلوك المتوقَّع،
- زمن التشغيل،
- استخدام الذاكرة (memory usage)،
- التكامل مع الأنظمة القائمة،
- قابلية الصيانة،
- والتعقيد التشغيلي.

وقد لا يستحق تحسّن صغير في الدقة زيادة كبيرة في تعقيد النظام.

### التقييم غير المتصل (Offline evaluation)

التقييم على dataset اختبار محجوز هو **Offline evaluation**.

وهو يجيب عن أسئلة مثل:

```text
ما مدى دقة تنبؤ الـ model بالأمثلة المخزَّنة؟
```

التقييم غير المتصل ضروري، لكن الأنظمة التي يتعامل معها المستخدمون كثيرًا ما تحتاج إلى مستوى آخر من الاختبار.

### الاختبار المتصل (Online testing)

حين يبدأ المستخدمون بالتفاعل مع model، يمكن أن يغيّر الـ model سلوكهم بطرق لم يلتقطها dataset غير متصل.

فمثلًا، قد يغيّر تغيير التوصيات ما ينقر عليه المستخدمون أو يشترونه أو يشاهدونه أو يتجاهلونه.

### A/B testing

يقارن A/B testing بين نسختين من نظام على مستخدمين حقيقيين.

```text
المجموعة A -> النظام/الـ model A
المجموعة B -> النظام/الـ model B

قِس النتيجة ذات الصلة للمجموعتين
```

والنقطة المهمة أن النجاح يُقيَّم بمقياس من العالم الحقيقي لا بدرجة model غير متصلة فحسب.

ويمكن للاختبار المتصل أن يكشف آثارًا سلوكية غير متوقعة لا تظهر في مجموعة اختبار ثابتة.

## 9. الـ Estimators المخصصة والتوسع خارج حدود الذاكرة

أحيانًا لا تكون المعالجة المسبقة أو منطق التنبؤ لديك متاحة كمكوّن جاهز في scikit-learn.

وإذا كانت تلك المعالجة تعتمد على بيانات التدريب ويجب أن تشارك في cross-validation أو grid search، فإن تغليفها بواجهة estimator في scikit-learn قد يجعل مسار العمل أكثر أمانًا وأسهل في إعادة الاستخدام.

### transformer مخصص بسيط

⟦CODE_7⟧

ونمط الواجهة المهم هو:

```text
__init__ -> تخزين الإعدادات (store configuration)
fit      -> التعلّم من بيانات التدريب وإرجاع self
transform -> تحويل X
```

ويستخدم المصنّف أو الـ regressor المخصص واجهة مشابهة لكنه ينفّذ سلوك التنبؤ.

وهذا يتيح للمكوّنات المخصصة المشاركة في الـ pipelines وcross-validation والبحث في المعاملات بدلًا من تنفيذها معالجةً مسبقة غير آمنة خارج مسار التقييم.

### ماذا لو لم يعد الـ dataset يتسع في الذاكرة؟

يناقش الكتاب استراتيجيتين عريضتين.

#### التعلّم خارج الذاكرة (Out-of-core learning)

اقرأ البيانات في أجزاء تتسع في الذاكرة وحدّث model متوافقًا تدريجيًا.

```text
القرص/الشبكة
    |
    v
جزء صغير (small chunk) -> تحديث الـ model -> تجاهل الجزء
    |
    v
الجزء التالي (next chunk)
```

وهذا يتيح لجهاز واحد أن يتعلّم من بيانات أكثر مما يستطيع حمله في الـ RAM دفعة واحدة، وإن لم تدعم كل خوارزمية التحديثات التدريجية.

#### المعالجة الموزَّعة (Distributed processing)

استراتيجية أخرى هي توزيع العمل على عدة أجهزة في عنقود حوسبة (compute cluster).

وهذا يستطيع معالجة datasets أكبر بكثير لكنه يتطلب بنية تحتية أكثر بكثير وتعقيدًا تشغيليًا أكبر.

والحل الصحيح يعتمد على ما إذا كان التوسع الإضافي يبرّر التعقيد.

## 10. النموذج الذهني المتكامل

يتكامل الفصلان في مسار عمل شامل واحد مفيد.

```text
1. حدّد المسألة الحقيقية ومقياس النجاح.
2. افحص البيانات وافهم ما يعنيه كل feature فعلًا.
3. ابنِ تمثيلًا مناسبًا.
4. درِّب model أساسيًا بسيطًا (baseline).
5. قيّم بصورة صحيحة ببيانات محجوزة أو ببيانات cross-validation.
6. افحص الأخطاء وسلوك الـ model.
7. حسّن التمثيل أو اجمع بيانات أفضل.
8. اضبط المعاملات فقط حين يكون إجراء التقييم جديرًا بالثقة.
9. غلّف المعالجة المسبقة والتنبؤ في pipeline قابل لإعادة الإنتاج.
10. قيّم النظام النهائي بصورة غير متصلة (offline).
11. انشر فقط حين تُستوفى متطلبات الموثوقية والتشغيل.
12. قِس الأثر الواقعي بتقييم متصل (online) مناسب حين ينطبق ذلك.
13. راقب ما تتعلمه وأعده إلى التكرار التالي.
```

وفي المسائل النصية تحديدًا، قد يكون خط أساس تقليدي قوي بسيطًا على نحو مفاجئ:

```text
النص الخام (raw text)
   |
TfidfVectorizer
   |
unigrams + bigrams مفيدة (useful bigrams)
   |
مصنّف خطي (linear classifier)
   |
cross-validation
   |
فحص الأخطاء والمعاملات (error / coefficient inspection)
```

والدرس الأوسع أن Machine Learning الجيد يعتمد على التمثيل والتقييم وتعريف المسألة وتصميم النظام بقدر ما يعتمد على اختيار الخوارزمية.

## مغالطات شائعة

### المغالطة 1

> أي عمود مخزَّن على أنه سلسلة نصية ينبغي معالجته بتقنيات NLP.

### لماذا هذا خطأ

قد تمثّل السلسلة النصية في الواقع فئة أو معرّفًا أو تاريخًا أو رقم هاتف أو مفهومًا منظَّمًا آخر. ويجب أن يتبع التمثيل المعنى الدلالي للحقل.

### المغالطة 2

> Bag-of-words يفهم معنى الجملة.

### لماذا هذا خطأ

يعدّ bag-of-words الأساسي الـ tokens ويتجاهل إلى حد كبير الترتيب والنحو. وتستعيد n-grams بعض السياق المحلي، لكن التمثيل ما يزال لا يفهم اللغة بالمعنى البشري.

### المغالطة 3

> يخبرنا tf-idf أي الكلمات هي الأكثر تنبؤًا بتسمية الهدف.

### لماذا هذا خطأ

tf-idf مخطط أوزان غير خاضع للإشراف (unsupervised) يقوم على أنماط ورود الكلمات عبر المستندات. والوزن العالي في tf-idf يعني أن المصطلح مميِّز للمستند، لا أنه بالضرورة تنبّؤي بالمشاعر أو بهدف آخر.

### المغالطة 4

> لموضوع LDA المكتشَف معنى بشري صحيح موضوعيًا.

### لماذا هذا خطأ

يتعلّم الـ model مكوّنات إحصائية. وأسماء المواضيع تفسيرات بشرية ينبغي التحقق منها بفحص مستندات تمثيلية.

### المغالطة 5

> بمجرد أن يؤدي الـ model أداءً جيدًا على مجموعة الاختبار، ينتهي مشروع Machine Learning.

### لماذا هذا خطأ

يجب أن تستوفي أنظمة الإنتاج أيضًا متطلبات مثل الموثوقية وزمن التشغيل وقابلية الصيانة والأثر الواقعي. وقد تتطلب الـ models التي يتعامل معها المستخدمون تقييمًا متصلًا بعد الاختبار غير المتصل.

## المصطلحات الرئيسية

| المصطلح | المعنى |
|---|---|
| Corpus | مجموعة من المستندات تُستخدم في تحليل النصوص |
| Document | مثال نصي واحد في المدوّنة |
| Token | وحدة نصية أساسية تُستخدم feature، وهي غالبًا كلمة |
| Vocabulary | مجموعة الـ tokens المتعلَّمة من مدوّنة التدريب |
| Bag-of-words | تمثيل قائم على أعداد ورود الـ tokens |
| Sparse matrix | تمثيل مصفوفي يخزّن أساسًا القيم غير الصفرية |
| Stopword | كلمة شائعة جدًا قد تحمل معلومات قليلة خاصة بالمهمة |
| tf-idf | إعطاء أوزان يركّز على المصطلحات المتكررة في مستند والأقل شيوعًا عبر المستندات |
| Unigram | feature من token واحد |
| Bigram | رمزان (tokens) متجاوران يُستخدمان feature واحدًا |
| Trigram | ثلاثة tokens متجاورة تُستخدم feature واحدًا |
| Stemming | اختزال قائم على القواعد لصيغ الكلمات إلى جذع |
| Lemmatization | تطبيع لغوي إلى lemma أساسية |
| Topic modeling | اكتشاف غير خاضع للإشراف لأنماط كلمات كامنة متكررة في المستندات |
| LDA | Latent Dirichlet Allocation، طريقة احتمالية لنمذجة المواضيع |
| Human in the loop (الإنسان في الحلقة) | مسار عمل يراجع فيه الناس أو يعالجون الحالات التي لا ينبغي للـ model أن يقرر فيها وحده |
| Offline evaluation | تقييم على بيانات محجوزة مخزَّنة |
| Online testing | تقييم بعد أن يتفاعل النظام مع مستخدمين حقيقيين أو مع البيئة |
| A/B testing | مقارنة مضبوطة بين نسختين من النظام على مجموعات مستخدمين مختلفة |
| Estimator | كائن بأسلوب scikit-learn يوفّر methods مثل fit أو transform أو predict |
| Out-of-core learning (التعلّم خارج الذاكرة) | تعلّم تدريجي من أجزاء بيانات لا تتسع كلها في الذاكرة |
