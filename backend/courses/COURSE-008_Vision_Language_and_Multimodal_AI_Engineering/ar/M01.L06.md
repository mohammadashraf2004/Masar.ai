## لماذا تهم Architecture؟

في هذه المرحلة، أنت تعرف بالفعل أن VLM يمكنه:

- ترميز Image؛
- معالجة Text؛
- توليد Language؛
- التعلم من Multimodal training data.

لكن سؤال Architecture أكثر تحديدًا:

> **كيف ينبغي أن تدخل Visual information إلى Language model؟**

غالبًا ما تبدأ نماذج VLM الحديثة بمكونين قويين مُدرَّبين مسبقًا:

```text
مرمّز الرؤية (vision encoder)
+
نموذج اللغة (language model)
```

الجزء الصعب هو الجسر بينهما.

يركز هذا الفصل على نمطي تصميم مهيمنين:

```text
1. محول Cross-attention (CROSS-ATTENTION ADAPTER)
   Vision encoder (vision encoder)
        ↓
   Visual tokens مضغوطة (compressed visual tokens)
        ↓
   طبقات Cross-attention مخصصة (dedicated cross-attention layers)
        ↓
   Language model (language model)

2. تسلسل موحد (UNIFIED SEQUENCE)
   Vision encoder (vision encoder)
        ↓
   Linear projection (linear projection)
        ↓
   Visual tokens مدخلة بجوار Text tokens (visual tokens inserted beside text tokens)
        ↓
   Self-attention عادية في LLM (ordinary LLM self-attention)
```

ولفهم سبب نجاح هذه Architectures، نحتاج
أولًا إلى فهم Attention نفسه.

## 2. Query وKey وValue

يتم تحويل كل عنصر في Sequence إلى ثلاثة Learned vectors.

### الاستعلام (Query — Q)

فكر:

```text
"What information am I looking for?"   — ما المعلومات التي أبحث عنها؟
```

### المفتاح (Key — K)

فكر:

```text
"What kind of information do I contain?"   — ما نوع المعلومات التي أحتويها؟
```

### القيمة (Value — V)

فكر:

```text
"What information should I contribute if selected?"   — ما المعلومات التي ينبغي أن أقدمها إن تم اختياري؟
```

إذا كانت Input embedding matrix هي:

```text
X
```

فإن Learned matrices تنتج:

```text
Q = XW_q
K = XW_k
V = XW_v
```

يؤكد المصدر أن كل Word أو Image patch يمكنه إنتاج:

- Query؛
- Key؛
- Value.

بالنسبة إلى Sequence من ستة Tokens، تحصل إذن على:

```text
6 queries — ستة Queries
6 keys — ستة Keys
6 values — ستة Values
```

### نموذج ذهني مفيد

بالنسبة إلى Token واحد:

```text
Query (query)
  ↓
قارنه بكل Keys (compare against all keys)
  ↓
أنشئ Relevance scores (produce relevance scores)
  ↓
استخدم Scores لدمج كل Values (use scores to mix all values)
  ↓
Representation سياقية جديدة (new contextual representation)
```

ينفذ Code في الفصل Scaled dot-product attention القياسية.

```text

=
softmax(QKᵀ / √d_k) V — الصيغة القياسية لـ Scaled dot-product attention
```

حيث:

```text
d_k = key/query feature dimension — بُعد Features الخاص بالمفتاح والاستعلام
```

> بالنسبة إلى هذا Query، ما مدى صلة كل Key؟

يقسم Code على:


## 4. قراءة Attention matrix

يعرض المصدر Example matrix لست كلمات.

التفسير:

```text
الصفوف = Queries
الأعمدة = Keys
```

لذلك إذا كان:

```text
row = AI — صف Query الخاص بـ AI
column = future — عمود Key الخاص بـ future
weight = 0.30 — وزن Attention
```

فإن Representation الحالية لـ `AI` تستقبل مساهمة
ذات معنى من Value vector الخاصة بـ `future`.

### الأوزان القطرية (Diagonal weights)

يعطي مثال المصدر العديد من الكلمات Self-attention weights كبيرة.

وهذا يعني أن Token يحتفظ بمساهمة قوية من محتواه نفسه.

### الأوزان خارج القطر (Off-diagonal weights)

غالبًا ما تكون العلاقات المثيرة للاهتمام خارج القطر.

وهي تعرض Contextual dependencies مثل:

```text
AI → future — علاقة Attention
community → building — علاقة Attention
future → AI — علاقة Attention
```

### تنبيه مهم

تُعد Attention matrix مفيدة لفهم Computation، لكن لا
ينبغي التعامل مع Head أو Layer واحدة تلقائيًا بوصفها
تفسيرًا كاملًا لـ Reasoning الخاصة بـ Model.

في هذا الدرس، استخدمها بوصفها:

```text
مصفوفة تفاعل موزونة (a weighted interaction matrix)
```

لا بوصفها تفسيرًا سببيًا مثاليًا.


- Vision Transformers؛

### لماذا يمكن أن تصبح Self-attention متعددة الوسائط؟

```text

[image_3]
[text_1]
[text_2]
[text_3]
```

## 11. Gated cross-attention: أدخل Vision تدريجيًا

بعد الحصول على Compact visual tokens، يحتاج LLM إلى استخدامها.

في Cross-attention layer:

```text
Q = حالات LLM المخفية الحالية (current LLM hidden states)
K = Image tokens المدمجة (compact image tokens)
V = Image tokens المدمجة (compact image tokens)
```

يسمح ذلك لـ Text state الحالية باسترجاع Visual content ذات الصلة.

### لماذا نستخدم Gate؟

تبدأ طبقات Cross-attention الجديدة بـ Random weights.

إذا أدخلت فورًا Random activations قوية إلى LLM مُدرَّب
مسبقًا، فقد تفسد Language representations المفيدة.

يستخدم المصدر Learned gates مهيأة إلى صفر.

على المستوى المفاهيمي:

```text
text_hidden
+
gate × visual_cross_attention — مساهمة Visual يتم التحكم فيها بـ Gate
```

عند Initialization:

```text
gate ≈ 0 — Gate تبدأ قرب الصفر
```

لذلك:

```text
output ≈ original text_hidden — Output يبدأ قريبًا من Representation الأصلية
```

ومع تقدم Training، يتعلم Model فتح Gate.

## 12. Unified sequence: اجعل Images تبدو مثل Tokens

تطرح Architecture الثانية السؤال:

> ماذا لو أصبحت Image features ببساطة جزءًا من Input sequence الخاصة بـ LLM؟

يكون Pipeline:

```text
Image (image)
  ↓
Vision encoder (vision encoder)
  ↓
Visual embeddings (visual embeddings)
  ↓
Modality projector (modality projector)
  ↓
Visual tokens بحجم Embedding الخاص بـ LLM (LLM-sized visual tokens)

Text (text)
  ↓
طبقة Token embedding (token embedding layer)
  ↓
Text tokens (text tokens)

ثم (then):

[visual tokens][text tokens]
        ↓
Self-attention عادية في LLM (ordinary LLM self-attention)
```

لا يوجد Cross-attention adapter مخصص.

تتولى Self-attention الموجودة أصلًا في LLM عملية Fusion.

### لماذا نحتاج إلى Projection layer؟

إذا كان Vision encoder ينتج:

```text
768-dimensional vectors — Visual features بأبعاد 768
```

لكن LLM يتوقع:

```text
576-dimensional embeddings — Embeddings بأبعاد 576
```

فيجب Project الـ Visual tokens:

```text
768 → 576
```

بعد ذلك يمكن للـ Modalities أن توجد داخل Sequence نفسها.

## 14. لا تزال Unified architectures تحتاج إلى Visual-token compression

قد يصبح Unified sequence بسيط طويلًا جدًا.

وقد تنتج High-resolution images مئات أو آلاف Visual tokens.

ولأن Self-attention في LLM تصبح مكلفة مع زيادة Sequence
length، غالبًا ما تضغط الأنظمة الحديثة Visual tokens.

يشير المصدر مرة أخرى إلى **Pixel shuffle**.

على المستوى المفاهيمي:

```text
عدد كبير من Spatial positions (many spatial positions)
      ↓
أعد ترتيب Spatial information داخل Channels (rearrange spatial information into channels)
      ↓
عدد أقل من Visual token positions (fewer visual token positions)
      ↓
Linear projection (linear projection)
      ↓
LLM
```

إذًا تحتاج كلتا Architectures الرئيسيتين إلى حل لـ Token budget:

```text
نهج Cross-attention (cross-attention approach)
→ Perceiver resampling (perceiver resampling)

نهج Unified sequence (unified sequence approach)
→ Pixel shuffle / Pooling / Compression أخرى
```

تختلف Mechanisms، لكن المشكلة الهندسية واحدة:

> قد تطغى Visual information على Sequence الخاصة بـ LLM إذا تُركت دون Compression.

## 15. Cross-attention مقابل Unified self-attention

يقارن المصدر بين التصميمين مفاهيميًا وتجريبيًا.

### محوّل الانتباه المتقاطع (Cross-attention adapter)

نقاط القوة:

- قوي عندما تظل Backbones الرئيسية Frozen؛
- يحافظ على Pretrained language behavior بشكل نظيف؛
- يوفر طبقات Visual fusion مخصصة؛
- يوفر Perceiver واجهة Visual ثابتة الحجم.

التكاليف:

- Trainable fusion parameters أكثر؛
- Forward pass أكثر تعقيدًا؛
- Interleaving صريح Layer-by-layer؛
- يجب إدارة Masks وPositions وCache بعناية.

### Unified sequence

نقاط القوة:

- Architecture بسيطة؛
- Fusion parameters جديدة أقل؛
- تستخدم Self-attention العادية في LLM؛
- Forward integration أبسط بكثير.

التكاليف:

- غالبًا ما تستفيد من السماح لـ Backbones بالتكيف؛
- Visual sequences الطويلة تزيد Attention cost في LLM مباشرةً؛
- Fine-tuning قد يسبب Forgetting إذا أُدير Training بشكل سيئ.

### Architecture ليست المتغير الوحيد

يوضح المصدر نقطة مهمة بشكل خاص:

```text
Data (data)
Learning rate (learning rate)
Batch size (batch size)
Token budget (token budget)
Training duration (training duration)
قابلية تدريب Backbone (backbone trainability)
```

قد تكون مهمة بقدر Architecture نفسها أو أكثر.

## 19. لماذا قد تخفي Language-model loss الفروق Visual؟

يقدم المصدر ملاحظة دقيقة.

في Multimodal sequences، يمكن توقع كثير من Language tokens بدرجة كبيرة من:

- Language structure؛
- صياغة Question؛
- Generated words السابقة.

مثال Answer:

```text
"In this image, we can see a monkey eating a banana."   — جملة وصف مثال
```

يجادل المصدر بأن بعض Tokens فقط تعتمد بقوة على Image، مثل:

```text

eating — Token تعتمد على Visual evidence
```

بينما يكون جزء كبير من الجملة قابلًا للتوقع لغويًا.

لذلك قد تهيمن Text behavior على Total language-model loss.

### النتيجة

قد تمتلك VLM architectures مختلفة Total loss متقاربة جدًا بينما تختلف في:

- Grounding؛
- Fine visual recognition؛
- OCR؛
- Spatial reasoning.

لذلك ينبغي أن تتضمن Architecture evaluation مهام
Multimodal downstream، لا Training loss فقط.

## 22. Early fusion

تجمع Early fusion الـ Modalities قبل
أو قرب بداية Joint reasoning.

على المستوى المفاهيمي:

```text
خصائص الرؤية (vision features) ─┐
                 ├→ combined representation → joint model   — تمثيل مدمج ثم نموذج مشترك
خصائص النص (text features) ───┘
```

المزايا:

- Cross-modal interactions عميقة؛
- Shared representation واحدة؛
- يمكن تعلم Relationships الدقيقة مبكرًا.

التكاليف:

- Combined representation أكبر؛
- مكونات أكثر ترابطًا؛
- Modularity أقل.

يربط المصدر نهج Unified sequence / SmolVLM-style بـ Early fusion.

```text
visual tokens + text tokens   — رموز بصرية ورموز نصية
        ↓
الانتباه الذاتي المشترك (joint self-attention)
```

---

## 23. Intermediate fusion

يضع المصدر Flamingo-style cross-attention ضمن **Intermediate fusion**.

لماذا؟

تبدأ Modalities بصورة منفصلة:

```text
image → vision encoder   — الصورة ثم مرمّز الرؤية
text  → language model   — النص ثم نموذج اللغة
```

لكنها تتبادل المعلومات بشكل متكرر داخل Network:

```text
طبقة LLM (LLM layer)
↓
الانتباه المتقاطع (cross-attention)
↓
طبقة LLM (LLM layer)
↓
الانتباه المتقاطع (cross-attention)
...
```

يوفر ذلك Interaction أغنى من Late fusion التقليدية
دون دمج كل شيء في Sequence واحدة منذ البداية.

---

## 24. Late fusion

تبقي Late fusion الـ Modalities منفصلة حتى تتوفر High-level decisions.

مثال:

```text
Vision model (vision model)
→ "angry gesture: 0.86"

Text model (text model)
→ "abusive language: 0.91"

ثم (then):
ادمج كلا Score (combine both scores)
→ قرار Toxicity (toxicity decision)
```

المزايا:

- Modular؛
- من السهل استبدال Specialist واحد؛
- من السهل إضافة Signals أخرى.

الضعف:

- قد تضيع Cross-modal information التفصيلية قبل Final combination.

على سبيل المثال، إذا ضغط Vision model Frame إلى Label واحدة:

```text
"person"   — الفئة المطلوبة
```

فلن يستطيع Text system اللاحق استعادة Visual details التي تم التخلص منها.

## 27. مقارنة ثلاثة أجيال من VLM architecture

يقارن المصدر التصميمات تقريبًا كما يلي.

| الخاصية | نموذج Show and Tell | Flamingo-style | SmolVLM-style |
|---|---|---|---|
| Vision encoder | ResNet CNN | SigLIP-like ViT | SigLIP-like ViT |
| Visual representation | Vector واحدة | Compact tokens ثابتة مثل 64 | عدد كبير من Projected visual tokens |
| Decoder | LSTM | LLM مُجمّد + Gated cross-attention | LLM self-attention |
| Visual injection | الحالة المخفية الأولية (Initial hidden state) | طبقات Cross-attention مختارة | مدمجة مباشرة داخل Sequence |
| Fusion | Late-ish | Intermediate | Early |
| Main bottleneck | Visual vector واحدة | تعقيد Fusion layers | Sequence length |

التطور واضح:

```text
Visual vector واحدة (one image vector)
      ↓
عدة Compact visual tokens (multiple compact visual tokens)
      ↓
Visual token sequence غنية (rich visual token sequence)
```

ويبقى الهيكل العام Encoder-decoder موجودًا.

الذي يتغير هو **Connection**.

## 28. كيفية اختيار Architecture

لا توجد Architecture هي الأفضل في كل Setting.

ابدأ من Constraints الخاصة بك.

### إذا كان يجب أن يبقى LLM مُجمّدًا

قد يكون Dedicated cross-attention adapter جذابًا.

فهو يسمح للـ Model بالوصول إلى Vision مع حماية Language backbone.

### إذا كان يمكن لـ Backbones التكيف

قد توفر Unified sequence:

- Parameters جديدة أقل؛
- Implementation أبسط؛
- سلوكًا تنافسيًا في مقارنة المصدر.

### إذا كانت Modularity هي الأولوية الأعلى

قد تكون Late fusion مناسبة.

إذ يمكن استبدال Models المنفصلة بشكل مستقل.

### إذا كان Deep cross-modal interaction ضروريًا

فعادةً تكون Early أو Intermediate fusion أكثر ملاءمة.

### إذا كان عدد Visual tokens كبيرًا جدًا

خطط لـ Compression:

```text
Perceiver resampler (perceiver resampler)
Pixel shuffle (pixel shuffle)
Pooling (pooling)
أو استراتيجية أخرى لتقليل Tokens (or another token-reduction strategy)
```

### إذا كانت Engineering simplicity مهمة

لا تقلل من شأن Implementation complexity.

Architecture أنيقة نظريًا لكنها صعبة في:

- Training؛
- Caching؛
- Batching؛
- Deployment؛
- Debugging؛

قد تكون خيارًا عمليًا أسوأ من تصميم أبسط ذي جودة متقاربة.

## مفاهيم خاطئة مهمة

### المفهوم الخاطئ 1: «Attention تختار Token واحدة فقط.»

لا.

تنشئ Attention Weighted mixture على Values.

### المفهوم الخاطئ 2: «Q وK وV هي Features ثابتة صممها البشر.»

يتم إنتاجها من خلال Learned projections.

### المفهوم الخاطئ 3: «لا تعمل Self-attention إلا داخل Modality واحدة.»

إذا وُضعت Image وText embeddings في Compatible sequence واحدة،
يمكن لـ Self-attention تمثيل Cross-modal interactions.

### المفهوم الخاطئ 4: «تتطلب Cross-attention تساوي طول Text sequence وImage sequence.»

لا.

يمكن أن يختلف Query length عن Key/Value length.

ولهذا تحديدًا يمكن لـ Learned queries ضغط Visual features.

### المفهوم الخاطئ 5: «Perceiver resampler مجرد Modality bridge.»

إنه يعمل أيضًا بوصفه Sequence compressor.

### المفهوم الخاطئ 6: «تعني Zero-initialized cross-attention gates أن Vision سيظل متجاهلًا للأبد.»

لا.

فهي تحمي LLM المُدرَّب مسبقًا في البداية، ثم تصبح قابلة للتعلم.

### المفهوم الخاطئ 7: «Unified sequence تعني عدم الحاجة إلى Visual encoder.»

لا تزال Image بحاجة إلى Encoding.

يشير الجزء Unified إلى كيفية دخول Projected visual tokens وText tokens إلى LLM.

### المفهوم الخاطئ 8: «تكون مقارنة Architecture عادلة إذا اختلفت أسماء Models لكن Dataset هي نفسها.»

ليس بالضرورة.

يجب أيضًا ضبط Token budgets وعدد Trainable parameters
وBackbone freezing وOptimizer settings.

### المفهوم الخاطئ 9: «انخفاض Multimodal language-model loss يثبت Visual understanding أفضل.»

ليس دائمًا.

فقد يكون جزء كبير من Loss قابلًا للتوقع من Language
context دون الحاجة إلى Visual evidence.

### المفهوم الخاطئ 10: «Early fusion أفضل دائمًا من Late fusion.»

لا.

تحسن Early fusion الـ Cross-modal interaction لكنها تقلل Modularity.

وتحافظ Late fusion على Modularity لكنها قد تتخلص من Fine-grained relationships مفيدة.

### المفهوم الخاطئ 11: «تخلت VLMs الحديثة عن Encoder-decoder architecture.»

لا.

يبقى هيكل Reader/Writer مؤثرًا.

لكن Connection بين Vision وLanguage أصبحت أغنى بكثير.

### المفهوم الخاطئ 12: «يمكن نسخ Cross-attention pseudocode مباشرةً إلى Production decoder.»

ليس من المثال المقدم.

يحذف المصدر صراحةً تفاصيل Implementation مهمة مثل Causal
masks وPosition handling وKV-cache management.

## المصطلحات الأساسية

| المصطلح | المعنى |
|---|---|
| Attention | تجميع معلومات موزون بين عناصر Sequence |
| Query (Q) | Vector يمثل ما يبحث عنه عنصر |
| Key (K) | Vector يُستخدم لتحديد الصلة بـ Query |
| Value (V) | Information vector يتم دمجه وفق Attention weights |
| الانتباه بالضرب النقطي المُقيَّس (Scaled dot-product attention) | `softmax(QKᵀ/√d_k)V` |
| Attention matrix | Matrix لأوزان الصلة من Query إلى Key |
| Self-attention | تنشأ Q وK وV من Sequence نفسها |
| Cross-attention | تنشأ Queries وKey/Value features من Streams مختلفة |
| Visual token | Representation مُرمَّزة لمنطقة/Patch بصرية |
| Modality projector | Layer تحول Visual feature dimension إلى LLM embedding dimension |
| Perceiver resampler | Learned-query cross-attention module تضغط Visual features |
| الانتباه المتقاطع ذو البوابة (Gated cross-attention) | Visual fusion layer يتم التحكم في تأثيرها باستخدام Learned gates |
| Unified sequence | Architecture تضع Projected image embeddings وText embeddings في Sequence واحدة لـ LLM |
| Image placeholder | Token position محجوز لـ Projected visual embedding |
| Frozen backbone | مكون مُدرَّب مسبقًا لا يتم تحديث Parameters الخاصة به |
| Trainable backbone | مكون مُدرَّب مسبقًا مسموح له بالتكيف أثناء Multimodal training |
| Early fusion | تتفاعل Modalities قرب بداية Joint processing |
| Intermediate fusion | تتفاعل Modalities عند Internal layers مختارة |
| Late fusion | تُدمج Outputs الخاصة بكل Modality قرب النهاية |
| Encoder-decoder | نمط يقوم فيه Network بترميز Input وتولد Network أخرى Output |
| عنق الزجاجة أحادي المتجه (Single-vector bottleneck) | ضغط Image كاملة إلى Vector واحدة قبل Decoding |
| Token budget | مقدار Model context الذي تشغله Representations الخاصة بـ Image وText |
| KV cache | Attention keys/values مخزنة مؤقتًا أثناء Autoregressive inference |

## احتفظ بهذه الفكرة

**يتمحور تصميم VLM الحديثة أساسًا حول الجسر بين مكونات Vision وLanguage
القوية المُدرَّبة مسبقًا. توفر Cross-attention وصولًا Visual صريحًا من
خلال Fusion layers مخصصة؛ بينما تقوم Unified-sequence models بإسقاط Visual
features إلى Token space الخاصة بـ LLM وإعادة استخدام Self-attention.
لا يعتمد أفضل تصميم على Architecture وحدها، بل أيضًا على أي Backbones
يمكنها التكيف، وكيف تُضغط Visual tokens، وكيف يُضبط Training، ومقدار
Implementation complexity الذي يمكنك تبريره.**
