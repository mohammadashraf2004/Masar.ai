## 1. خريطة لتطبيقات VLM الحديثة

لا تقتصر Vision-Language Model الحديثة على الإجابة عن:

> "What is in this image?"   — أي: ما الذي توجد في هذه الصورة؟

فالأساس Multimodal نفسه يمكنه دعم مهام متعددة ومختلفة جدًا.

إليك خريطة مفيدة لهذه المهام:

```text
                    VISION + LANGUAGE   (الرؤية واللغة)
                               |
        ------------------------------------------------
        |              |             |                |
   وصف (describe)   إجابة (answer)  استرجاع (retrieve)  تحديد موضع (localize)
   صورة (an image)  سؤال (a question) معلومات (information) كائنات (objects)
        |              |             |                |
   Image Captioning     VQA       صورة/مستند Object Detection
                       |     استرجاع (Retrieval)      عد الكائنات (Object Counting)
            استدلال (Reasoning)         |          تقسيم (Segmentation)
                                    |
                 نظام Multimodal RAG

                               +
                            فيديو (VIDEO)
                               |
                   فهم زمني (temporal understanding)
       استرجاع / تحديد زمني
```

تتطلب كل مهمة شكلًا مختلفًا من Output.

| المهمة | Input المعتاد | Output المعتاد |
|---|---|---|
| مهمة Image Captioning | صورة | وصف بلغة طبيعية |
| مهمة VQA | صورة + سؤال | إجابة مركزة |
| مهمة Visual Reasoning | صورة + سؤال معقد | إجابة قائمة على Reasoning |
| مهمة Retrieval | استعلام صورة/نص + Database | عناصر موجودة مرتبة حسب الصلة |
| مهمة Document Understanding | صورة/صفحة مستند | تفسير منظم أو إجابة |
| مهمة Video Understanding | Video مع Prompt | وصف/إجابة/Timestamps |
| مهمة Object Detection | صورة + Text Prompt للكائن | مخرجات Bounding Boxes + Labels |
| مهمة Counting | صورة/Video + Prompt للكائن | العدد وغالبًا Points/Boxes |
| مهمة Segmentation | صورة + Prompt | منطقة/Mask على مستوى Pixels |

إحدى الأفكار الرئيسية في هذا الفصل هي:

> صيغة Output تخبرك بالمشكلة التي تحلها فعليًا.

فالـ Model الذي يولد نصًا يحل مشكلة مختلفة عن Model يعيد
Ranked List أو Bounding Boxes أو Timestamps أو Masks.

## 2. Image Captioning: تحويل المحتوى البصري إلى لغة

ينتج **Image Captioning** وصفًا بلغة طبيعية لصورة.

ويجب على Model أن يتعرف على أكثر من مجرد الكائنات المنفصلة.

قد يحتاج Caption جيد إلى تمثيل:

- الكائنات؛
- الخصائص؛
- الأفعال؛
- العلاقات؛
- سياق المشهد.

على سبيل المثال:

```text
Input: — الإدخال
An image showing a child holding an umbrella beside a yellow bus.

Weak caption: — Caption ضعيف
"Child. Bus."

Better caption: — Caption أفضل
"A child holding an umbrella is standing beside a yellow school bus."
```

الـ Caption الأفضل يعبّر عن العلاقات والسياق.

### 2.1 Image Captioning المبكر باستخدام Encoder-Decoder

كانت أنظمة Neural Captioning المبكرة تستخدم عادةً:

```text
صورة (image)
  ↓
مشفّر بصري باستخدام CNN (CNN Visual Encoder)
  ↓
تمثيل بصري (Visual Representation)
  ↓
مفكك نصي باستخدام RNN / LSTM
  ↓
Tokens الخاصة بالـ Caption (Caption Tokens)
```

كان Visual Encoder يلخص الصورة.

ثم كان Text Decoder يولد Caption Token بعد Token.

أثناء Training، تعلم Decoder التنبؤ بنص Caption كتبه
بشر، بالاعتماد على Visual Features والنص السابق.

[[IMAGE_NEEDED: Early image-captioning architecture |

RNN/LSTM decoder, and a caption being generated word by word |
Learner should understand image captioning as an encoder-decoder mapping from
visual representation to language]]

### 2.2 Image Captioning الحديث

تستبدل الأنظمة الحديثة عادةً تلك المكونات القديمة بـ:

- Visual Encoders أقوى ومدرّبة مسبقًا؛
- Large Pretrained Language Models؛
- Multimodal Connectors؛
- Pretraining واسع على أزواج Image-Text.

وهذا يسمح لـ Generalist VLMs بتوليد:

- Captions قصيرة؛
- أوصاف مفصلة للمشاهد؛
- أوصاف غنية بالخصائص؛
- تفسيرات سياقية.

### Image Captioning ليس VQA

يسأل Image Captioning:

> "Describe this image."   — أي: صِف هذه الصورة

بينما يسأل VQA:

> "Answer this specific question about the image."   — أي: أجب عن هذا السؤال المحدد عن الصورة

هذا الاختلاف مهم لأن المهمة الثانية تخبر Model
تحديدًا بأي Visual Evidence يكون ذا صلة.

## 3. الإجابة عن الأسئلة البصرية (Visual Question Answering — VQA)

يجمع **Visual Question Answering** بين:

```text
صورة (image) + سؤال بلغة طبيعية (natural-language question) → إجابة (answer)
```

مثال:

```text
Image: two cars parked beside a building — المشهد المعروض

Question: — السؤال
"Which car is closer to the entrance?"

Answer: — الإجابة
"The blue car."
```

يجب على Model ربط اللغة بالـ Visual Evidence الصحيح.

### 3.1 لماذا يكون VQA أصعب من Object Recognition؟

قد لا يكون التعرف على الكائنات كافيًا.

قد يحتاج VQA Model إلى:

- عد الكائنات؛
- مقارنة الكائنات؛
- تحديد الخصائص؛
- تحديد Regions؛
- تفسير المواضع النسبية؛
- فهم التفاعلات؛
- استخدام World Knowledge عادية.

تأمل السؤال التالي:

```text
Question: — السؤال
"Which cup is likely to spill first if the table tilts left?"
```

مجرد اكتشاف "cups" لا يكفي.

يجب على Model الجمع بين Visual Geometry و Reasoning.

### 3.2 تطور أنظمة VQA

كانت أنظمة VQA المبكرة تبدو غالبًا كالتالي:

```text
صورة (image) → CNN Features ─┐
                             ├→ Fusion → Classifier → إجابة (answer)
سؤال (question) → RNN Text ──┘
```

نجح هذا مع الأسئلة الأبسط.

لاحقًا، أضافت الأنظمة **Attention**، ما سمح للسؤال بتوجيه
Regions التي ينبغي التركيز عليها في الصورة.

فسؤال مثل:

```text
"What color is the traffic light?" — سؤال يتم تحليله
```

ينبغي أن يجعل النظام يركز على Traffic Light بدلًا من التعامل مع المشهد كله بالدرجة نفسها.

تستخدم VQA Models الحديثة Multimodal Architectures مبنية على
Transformers ومدرّبة على Image-Text Data واسعة النطاق.

[[IMAGE_NEEDED: VQA evolution |
Show three stages: CNN+RNN fusion, attention-guided VQA, and transformer-based
multimodal VQA |
Learner should notice how question-conditioned visual focus becomes more
explicit and representations become more general]]

### 3.3 ما زال VQA غير كامل

يؤكد المصدر وجود عدة نقاط ضعف مستمرة:

- Multistep Reasoning؛
- المفاهيم المجردة؛
- أسئلة Counterfactual من نوع "what if"؛
- Dataset Bias؛
- غياب Rationale شفاف؛
- محادثات Multi-turn Visual Conversations.

كما يمكن لـ Model أن يجيب إجابة صحيحة لسبب خاطئ.

ولهذا يجب أن تختبر Evaluation ما إذا كانت الصورة ضرورية فعلًا للوصول إلى الإجابة.

### 3.4 MMMU و MMMU-Pro

يعرض الفصل **MMMU** باعتباره Multimodal Benchmark يغطي
تخصصات واسعة متعددة ويستخدم مواد بصرية معقدة مثل:

- Charts؛
- Tables؛
- Diagrams؛
- Figures من الكتب الدراسية؛
- مواد Infographics.

ويرفع **MMMU-Pro** مستوى الصعوبة من خلال:

- تصفية الأسئلة التي يستطيع Text-only Model الإجابة عنها؛
- جعل Answer Choices أصعب في التخمين؛
- تضمين حالات يكون فيها السؤال نفسه مضمّنًا بصريًا.

الفكرة التي ينبغي الاحتفاظ بها ليست رقمًا على Leaderboard.

بل هي:

> يجب أن يجعل Benchmark بصري جاد Visual Perception ضرورية فعلًا.

## 4. Visual Reasoning: عندما لا تكفي الرؤية وحدها

يمكن أحيانًا الإجابة عن VQA انطلاقًا من ملاحظة موضعية واحدة.

لكن **Visual Reasoning** يصبح مهمًا عندما تتطلب
الإجابة عدة علاقات أو حسابات وسيطة.

من أمثلة ذلك:

- تفسير ملصق Supplement وإجراء Reasoning حول تفاعلات المكونات؛
- حساب الإجماليات من Invoice؛
- مقارنة القيم عبر Chart؛
- حل Geometry من Diagram؛
- الجمع بين عدة Visual Clues.

Workflow مفاهيمي لذلك هو:

```text
دليل بصري (visual evidence)
      ↓
تحديد العناصر ذات الصلة (identify relevant elements)
      ↓
ربطها أو مقارنتها (relate or compare them)
      ↓
تنفيذ Logic/Calculation
      ↓
توليد الإجابة (generate answer)
```

### 4.1 لماذا يكون Visual Reasoning صعبًا؟

قد يدرك Model الصورة فقط من خلال تمثيل بصري (Visual Representation) محدودة.

ثم قد يواصل Reasoning الخاص به بصورة أساسية في النص.

إذا فاتت Detail مهمة في المرحلة البصرية، فلن يستطيع
Reasoning اللاحق استعادتها بشكل موثوق.

كما يتطلب Reasoning الطويل والمعقد:

- Context Length كافيًا؛
- Grounding مستقرًا؛
- Memory للأدلة الوسيطة؛
- تفاعلًا دقيقًا بين تمثيل بصري (Visual Representation)s و Language Representations.

### 4.2 تعتمد Evaluation على نوع Reasoning

تحتاج مهام Visual Reasoning المختلفة إلى Benchmarks مختلفة.

يسمي الفصل المقدم أمثلة مثل:

- **MathVista** لـ Visual Mathematics و Diagram Reasoning؛
- **MMMU / MMMU-Pro** لـ Multimodal Reasoning العام؛
- **OSWorld** لتفاعلات GUI و Computer Use.

المبدأ الأساسي هو:

> "Visual reasoning" ليست مشكلة واحدة فقط. اختر Evaluation التي تطابق
> النوع الفعلي من Reasoning المطلوب.

## 5. استرجاع المحتوى باستخدام Visual-Language Retrieval

تنشئ المهام Generative Output جديدًا.

أما مهام Retrieval فتفعل شيئًا مختلفًا:

> العثور على أكثر عنصر موجود صلةً داخل مجموعة.

تقوم Multimodal Retrieval Model بتحويل Inputs إلى Shared Representation Space.

مفاهيميًا:

```text
صورة (image) → Encoder → Vector
نص (text)   → Encoder → Vector
```

ينبغي أن تكون العناصر المرتبطة دلاليًا قريبة من بعضها.

يمكن قياس Distance أو Similarity باستخدام:

- Cosine Similarity؛
- مقياس Euclidean Distance.

### 5.1 استرجاع الصور باستخدام Text-to-Image Retrieval

Input:

```text
"a red sneaker with white laces" — استعلام نصي (text query)
```

Output:

```text
صور مرتبة بحسب صلتها بالنص (ranked images most relevant to the text)
```

### 5.2 استرجاع النص باستخدام Image-to-Text Retrieval

Input:

```text
صورة (an image)
```

Output:

```text
Captions/Descriptions مرتبة
```

### 5.3 استرجاع الصور باستخدام Image-to-Image Retrieval

Input:

```text
صورة استعلام (query image)
```

Output:

```text
صور متشابهة بصريًا أو دلاليًا (visually or semantically similar images)
```

### Retrieval هو Ranking Problem

لا يسأل النظام فقط:

> "Is this result relevant?"   — أي: هل هذه النتيجة ذات صلة؟

بل يسأل:

> "Which relevant results should appear first?"   — أي: ما النتائج ذات الصلة التي ينبغي أن تظهر أولًا؟

ولهذا تكون Ranking Metrics مهمة.

## 6. يصبح Retrieval أصعب مع Documents

تحتوي الصورة الطبيعية على Visual Concepts.

أما Document فقد يحتوي على:

- Paragraphs؛
- نص صغير؛
- Charts؛
- Tables؛
- Diagrams؛
- Formulas؛
- Layout؛
- Headers؛
- Footnotes؛
- تراكيب متعددة الأعمدة.

وهذا يجعل Document Retrieval مهمة Multimodal أكثر ثراءً.

يصف المصدر اتجاهًا رئيسيًا في Document Retrieval الحديثة:
**معالجة الصفحة كاملة بصريًا بدلًا من الاعتماد كليًا على OCR أولًا**.

### 6.1 استرجاع الصفحات باستخدام Multi-vector Page Retrieval

يصف الفصل Models مثل ColPali و ColQwen2 بأنها تستخدم تمثيل بصري (Visual
Representation)s على مستوى الصفحة مع Matching أكثر دقة.

بدلًا من ضغط الصفحة بأكملها في Vector واحد فقط، يستطيع
Model الاحتفاظ بعدة Visual Token Representations.

وهذا يتيح Matching أكثر تفصيلًا بين Query والصفحة.

Mental Model مبسط هو:

```text
صفحة مستند (document page)
     ↓
مكوّن Vision-Language Encoder
     ↓
[v1, v2, v3, ... vn]
     ↑
مطابقة دقيقة (fine-grained matching)
     ↑
متجهات Query (Query Vectors)
```

### 6.2 الاسترجاع باستخدام Single-vector Retrieval

يضغط تصميم آخر Input بالكامل في Embedding واحد.

هذا أبسط وغالبًا أقل تكلفة في Indexing،
لكنه قد يفقد بعض المعلومات الدقيقة.

لذلك يمكن لأنظمة Retrieval المفاضلة بين:

- الكفاءة؛
- Storage؛
- Matching Granularity؛
- مستوى Accuracy.

### 6.3 معيار ViDoRe

يحدد الفصل المقدم **ViDoRe** باعتباره Benchmark
رئيسيًا لـ Visual Document Retrieval.

الفكرة التعليمية هي:

> استخدم Benchmark خاصًا بـ Document Retrieval عندما يكون Input الفعلي لديك
> صفحات مستندات، لا صورًا فوتوغرافية عادية.

## 7. NDCG@k: تقييم نتائج Retrieval المرتبة

ينبغي لنظام Retrieval أن يضع النتائج شديدة الصلة بالقرب من أعلى Ranking.

تقيس **NDCG** ذلك.

لنبنِ الفكرة جزءًا بعد جزء.

### 7.1 مفهوم Gain

افترض أن مقيمًا بشريًا يخصص درجات صلة:

```text
3 = شديد الصلة (highly relevant)
2 = ذو صلة (relevant)
1 = ضعيف الصلة (weakly relevant)
0 = غير ذي صلة (irrelevant)
```

تسمى هذه الدرجة **Gain**.

### 7.2 مفهوم Cumulative Gain

إذا كانت Gains لأعلى النتائج هي:

```text
[3, 2, 0, 1]
```

فإن Plain Cumulative Gain سيجمع ببساطة:

```text
3 + 2 + 0 + 1 = 6
```

لكن هذا يعامل الموضع 1 والموضع 4 بالطريقة نفسها.

عادةً يهتم مستخدمو Search أكثر بالنتائج الموجودة في الأعلى.

### 7.3 تطبيق Discount على المواضع الأدنى

يقدم الفصل Logarithmic Discount.

إحدى الصيغ البسيطة هي:

```text
gain_i / log2(i + 1) — Discount لـ Gain حسب موضع النتيجة
```

عند الموضع 1:

```text
log2(2) = 1 — قيمة المقام للموضع الأول
```

لذلك لا تتلقى النتيجة الأولى أي Positional Penalty.

وفي المواضع اللاحقة، يزداد Denominator.

### 7.4 حساب DCG

باستخدام الصياغة المبسطة في الفصل:

```text
DCG@k = Σ gain_i / log2(i + 1) — Discounted Cumulative Gain حتى الموضع k
```

للمواضع `i = 1 ... k`.

### 7.5 تنفيذ Normalization

قد تحتوي Queries المختلفة على أعداد ودرجات مختلفة من العناصر ذات الصلة.

لذلك نقارن DCG الفعلي مع **Ideal DCG (IDCG)**.

ترتب القائمة Ideal النتائج ترتيبًا مثاليًا حسب الصلة.

ثم:

```text
NDCG@k = DCG@k / IDCG@k
```

تتراوح الدرجة بين 0 و 1.

- `1.0` يعني ترتيبًا مثاليًا.
- القيم الأقل تعني أن Ranking أبعد عن الترتيب المثالي.

### مثال محلول

افترض أن النظام يعيد Gains التالية:

```text
[3, 1, 2]
```

إذًا:

```text
DCG@3 = — حساب DCG لأول 3 نتائج
3/log2(2) — مساهمة النتيجة الأولى
+ 1/log2(3) — مساهمة النتيجة الثانية بعد Discount
+ 2/log2(4) — مساهمة النتيجة الثالثة بعد Discount
```

تقريبًا:

```text
3/1
+ 1/1.585
+ 2/2

= 3 + 0.631 + 1
= 4.631
```

أما Ideal Ordering فهو:

```text
[3, 2, 1]
```

إذًا:

```text
IDCG@3 = — حساب Ideal DCG لأول 3 نتائج
3/log2(2) — مساهمة النتيجة الأولى في Ideal Ranking
+ 2/log2(3) — مساهمة النتيجة الثانية في Ideal Ranking
+ 1/log2(4) — مساهمة النتيجة الثالثة في Ideal Ranking

≈ 3 + 1.262 + 0.5 — جمع الحدود تقريبيًا
≈ 4.762 — قيمة IDCG التقريبية
```

وبالتالي:

```text
NDCG@3 ≈ 4.631 / 4.762 ≈ 0.972
```

تخبرنا الدرجة العالية أن Ranking قريب من الترتيب المثالي.

## 8. Document Understanding: ما بعد قراءة النص

يعثر Retrieval على صفحة.

أما **Document Understanding** فيفسر الصفحة.

تجمع Documents عدة أنواع من المعلومات:

```text
نص (text)
+
تخطيط الصفحة (Layout)
+
جداول (Tables)
+
مخططات (Charts)
+
أشكال (Figures)
+
علاقات مكانية (spatial relationships)
```

كانت الأنظمة التقليدية تبدو غالبًا كالتالي:

```text
مستند (document)
  ↓
مرحلة OCR
  ↓
نص معروف + Bounding Boxes
  ↓
قواعد Parsing مصممة يدويًا (handcrafted parsing rules)
  ↓
Output منظم (structured output)
```

يمكن أن يعمل هذا جيدًا مع Templates المتوقعة.

لكن الحالات الصعبة تشمل:

- Scans رديئة؛
- Layouts غير معتادة؛
- Handwriting؛
- Infographics؛
- Nested Tables؛
- Diagrams؛
- خليطًا من Text Semantics و Visual Semantics.

يمكن لأنظمة Deep Learning الحديثة دمج المعلومات
البصرية واللغوية بصورة أكثر مباشرة.

### 8.1 Pipeline هرمي لـ Document Understanding

يصف الفصل Document Understanding على عدة Layers.

#### الطبقة 1 — Recognition

اكتشف:

- النص؛
- العناصر البصرية؛
- مناطق Layout Regions.

#### الطبقة 2 — Structure

حدد:

- Paragraphs؛
- Tables؛
- Figures؛
- العلاقات بين المكونات.

#### الطبقة 3 — Meaning

نفّذ مهام مثل:

- Question Answering؛
- Summarization؛
- عملية Knowledge Extraction.

Mental Model جيد هو:

```text
Pixels المدخلة
  ↓
التعرف على العناصر (recognize elements)
  ↓
فهم Layout/Structure
  ↓
دمج Visual + Textual Evidence
  ↓
استخراج المعنى (extract meaning)
```

### 8.2 ما زال OCR مفيدًا

لا يدّعي الفصل أن OCR أصبح قديمًا.

ما زال OCR مهمًا، خاصةً في:

- Transcription؛
- Structured Extraction؛
- تحويل صور Documents إلى Text/Markdown/HTML.

كما يظل صعبًا في حالات:

- Handwriting؛
- Scans المشوشة؛
- حالات Complex Media.

يشير الفصل إلى OCR-focused Benchmarks مثل:

- OmniDocBench؛
- Benchmark من نوع OlmOCRBench.

الدرس العام هو:

> اختر Evaluation بناءً على ما إذا كنت تحتاج جودة Transcription أم Semantic
> Document Understanding.

## 9. Document VQA و Multimodal RAG

تبدو مهمة Document VQA كالتالي:

```text
صفحة مستند (document page) + سؤال (question) → إجابة (answer)
```

كانت الأساليب الأقدم تتطلب غالبًا:

- نص OCR؛
- Bounding Boxes؛
- Layout Features مصممة هندسيًا.

يذكر الفصل LayoutLM باعتباره تصميمًا تمثيليًا أقدم.

يمكن لـ Generalist VLMs الآن الإجابة عن كثير من أسئلة
Documents بصورة أكثر مباشرة من Visual Input.

لكن هناك حالة أصعب:

> ماذا لو كانت الإجابة موجودة في مكان ما داخل مجموعة ضخمة من Documents؟

عندها يحتاج النظام إلى Retrieval أولًا.

### 9.1 بناء Pipeline باستخدام Multimodal RAG

Pipeline مبسط هو:

```text
سؤال (question)
  ↓
مكوّن Multimodal Retriever
  ↓
استرجاع الصفحة أو الصفحات ذات الصلة
  ↓
السؤال + الصفحة أو الصفحات ذات الصلة
  ↓
Model من نوع VLM
  ↓
إجابة مولدة (generated answer)
```

هذا هو **Multimodal RAG**.

الفكرة مماثلة في جوهرها لـ Text RAG:

- Retrieval يضيّق نطاق Evidence؛
- Generation يفسر Evidence المسترجعة.

لكن Evidence المسترجعة هنا قد تكون صفحة غنية
بصريًا بدلًا من Text Chunks عادية.

### لماذا يهم Retrieval؟

من دون Retrieval، قد تحتاج VLM إلى معالجة كل صفحة.

وقد يكون ذلك:

- بطيئًا؛
- مكلفًا؛
- مستهلكًا لـ Context؛
- صعب التوسع.

يركز Retrieval خطوة Multimodal Reasoning المكلفة على Evidence المرجح ارتباطها بالسؤال.

## 10. Video Understanding: إضافة الزمن

Video هو سلسلة من Frames، لكن التعامل معه على
أنه "مجرد صور كثيرة" يتجاهل التحدي الأساسي:

> الزمن يغير المعنى.

يجب على Video Model تمثيل:

- Motion؛
- ترتيب الأحداث؛
- Actions؛
- Interactions؛
- علاقات Temporal Dependencies.

مثال:

```text
Frame 1: person places cup on table — الشخص يضع الكوب على الطاولة
Frame 2: person leaves — الشخص يغادر
Frame 3: cat knocks over cup — القطة تسقط الكوب
```

لا يشرح Frame واحد بالكامل:

> "Who caused the cup to fall?"   — أي: من تسبب في سقوط الكوب؟

فالإجابة تعتمد على Temporal Sequence.

### 10.1 أخذ عينات باستخدام Frame Sampling

يحتوي Video على عدد كبير جدًا من Frames بحيث لا يكون من العملي معالجة كل Frame بصورة ساذجة.

لذلك تستخدم الأنظمة Sampling غالبًا.

إذا كان Sampling **متباعدًا أكثر من اللازم**:

- قد تختفي أحداث مهمة.

أما إذا كان Sampling **كثيفًا أكثر من اللازم**:

- ترتفع Compute Cost؛
- تصبح كثير من Frames المتجاورة Redundant.

وهذا يخلق Engineering Trade-off:

```text
التغطية الزمنية (temporal coverage) ↔ الكفاءة الحسابية (computational efficiency)
```

### 10.2 استرجاع Video باستخدام Text-to-Video Retrieval

Input:

```text
"a deer crossing the road" — استعلام نصي (Text Query)
```

Output:

```text
Videos أو Clips مرتبة (ranked videos or clips)
```

يشبه ذلك Image-Text Retrieval، لكن يجب أن تلتقط تمثيل
بصري (Visual Representation) المحتوى الزمني.

### 10.3 تحديد اللحظة باستخدام Temporal Grounding

يسأل Temporal Grounding:

> "Where in the video does this event happen?"   — أي: أين يحدث هذا الحدث في الفيديو؟

قد يكون Output:

```text
start: 02:14 — بداية الحدث
end:   02:23 — نهاية الحدث
```

وهذا يختلف عن Video QA العام.

### 10.4 فئات Evaluation

يجمع الفصل Video Evaluation في:

- General Video Understanding؛
- Long-video Understanding؛
- مهام Temporal Grounding/Reasoning.

ويذكر Benchmarks مثل:

- VideoMME؛
- LVBench؛
- Benchmark من نوع TemporalBench.

الدرس هو:

> يجب تقييم Video Systems وفق السلوك الزمني
> الذي يُتوقع منها تنفيذه فعليًا.

## 12. اكتشاف الكائنات باستخدام Zero-shot Object Detection

يعني **Zero-shot Object Detection** تحديد مواقع الكائنات الموصوفة باستخدام
Open-ended Text Prompts من دون تدريب Detector جديد خصيصًا لتلك Labels.

مثال:

```text
صورة (image) + ["bee", "pink flower"]
           ↓
       مكوّن Detector
           ↓
bee          → Bounding Box — Box للكائن bee
pink flower  → Bounding Box — Box للزهرة الوردية
```

يتضمن Output معلومات مكانية.

### 12.1 Detectors متخصصة ضمن Open-vocabulary Detection

يسلط الفصل الضوء على Models مثل:

- OWLv2؛
- Model من نوع GroundingDINO.

تصميم OWLv2-style عالي المستوى هو:

```text
صورة (image) → Vision Encoder ─┐
                               ├→ مطابقة Cross-modal Matching → Boxes + Labels
نص (text)   → Text Encoder  ───┘
```

يستخدم GroundingDINO أسلوب Multimodal Detection
ذا صلة، مع تفاعل أغنى بين Features.

### 12.2 Detection باستخدام Generalist VLM

يمكن لـ Generalist VLM أحيانًا الاستجابة لـ Prompts مثل:

```text
"detect the bee" — Prompt للكشف
```

وإنتاج Coordinate Tokens أو Structured Coordinates.

الاختلاف الأساسي هو:

- Specialized Detectors مبنية أساسًا من أجل Localization؛
- Generalist VLMs تستطيع تنفيذ مهام إضافية كثيرة.

### 12.3 Trade-off في Production

يوضح الفصل المقدم نقطة عملية مهمة:

> قد تكون Generalist VLM أقل كفاءة من ناحية التكلفة في Production مقارنةً بـ
> Computer-Vision Detector متخصص.

ومع ذلك، يمكن أن تكون VLM مفيدة للغاية في **Annotation**.

مثال على Workflow:

```text
صور Factory غير معنونة (unlabeled factory images)
       ↓
Generalist VLM عام
"label only plastic caps" — Prompt يطلب عنونة الأغطية البلاستيكية فقط
       ↓
Bounding Boxes تلقائية (automatic bounding boxes)
       ↓
مراجعة بشرية (human review)
       ↓
تدريب Detector متخصص صغير (train small specialized detector)
       ↓
Production Inference منخفض التكلفة (cheap production inference)
```

هذا Engineering Pattern مهم:

> استخدم General Model قويًا لإنشاء Training Data لـ Specialist أقل تكلفة.

- قد تتضمن False Positives أكثر.

## 14. عد الكائنات باستخدام Object Counting

يبدو Counting بسيطًا:

```text
اكتشاف كل الكائنات (detect all objects)
  ↓
عد Detections (count detections)
```

لكن جودة Count تعتمد على جودة Localization.

تحدث الأخطاء عندما يقوم النظام بـ:

- تفويت Instances؛
- اكتشاف الكائن نفسه عدة مرات؛
- الخلط بين كائنات متشابهة؛
- الفشل عند Occlusion؛
- فقدان الكائنات عبر Video Frames.

قد تنفذ VLMs الحديثة Counting من خلال:

- الإشارة إلى Instances؛
- اكتشاف Boxes؛
- Tracking للكائنات في Video؛
- Aggregating للـ Localized Instances.

### مثال

افترض أن المهمة هي:

```text
"How many boats are in the marina?" — سؤال Counting
```

ينبغي لنظام موثوق أن يُظهر Localized Instances الخاصة به بصورة مثالية.

وهذا أقوى من إرجاع:

```text
"45"
```

لأن Localization تجعل Count أسهل في التحقق.

### Counting في Video

تضيف Video عملية Tracking.

القارب نفسه إذا ظهر في 30 Frame فلا ينبغي عده 30 مرة.

لذلك يصبح Video Counting غالبًا:

```text
اكتشاف (detect)
  ↓
ربط عبر الزمن (associate across time)
  ↓
تتبع الهوية (track identity)
  ↓
عد Instances الفريدة (count unique instances)
```

## 16. كيفية اختيار Model للتطبيق

لا تبدأ بالسؤال:

> "Which model is best?"   — أي: ما أفضل نموذج؟

ابدأ بالسؤال:

> "What output does my application need?"   — أي: ما المخرجات التي يحتاجها تطبيقي؟

### الخطوة 1 — تعريف المهمة (Define the Task)

اسأل ما إذا كان التطبيق يحتاج إلى:

- Caption؛
- إجابة مركزة؛
- Multistep Reasoning؛
- Ranked Retrieval؛
- Document Extraction؛
- Video Timestamps؛
- Bounding Boxes؛
- Count؛
- مخرجات Segmentation Masks.

### الخطوة 2 — تحديد ما إذا كانت Generation ضرورية

إذا كان الهدف هو استرجاع عناصر موجودة، فقد لا تكون Generative VLM ضرورية.

لـ Retrieval، استخدم Embedding Model و Vector Index.

أما إذا كان الهدف هو Open-ended Language Output، فتصبح Generation أكثر ارتباطًا بالمهمة.

### الخطوة 3 — مراعاة Specialization

توفر Generalist VLM مرونة.

لكن Specialized Model قد توفر:

- Latency أقل؛
- تكلفة أقل؛
- Deployment أبسط؛
- سلوكًا أفضل خاصًا بالمهمة.

### الخطوة 4 — مطابقة Benchmark مع المهمة

أمثلة من الفصل المقدم:

| التطبيق | أمثلة Evaluation |
|---|---|
| فهم Multimodal عام | معيار MMMU |
| Multimodal Reasoning أصعب | معيار MMMU-Pro |
| تقييم Visual Mathematics | معيار MathVista |
| تقييم GUI/Computer Use | معيار OSWorld |
| تقييم Visual Document Retrieval | معيار ViDoRe |
| تقييم OCR | معايير OmniDocBench, OlmOCRBench |
| تقييم General Video Understanding | معيار VideoMME |
| تقييم Long-video Understanding | معيار LVBench |
| تقييم Temporal Video Reasoning | معيار TemporalBench |
| تقييم Ranked Retrieval | مقياس NDCG@k |

### الخطوة 5 — التحقق على بياناتك الخاصة

Benchmarks مفيدة، لكن أداء التطبيق يعتمد على:

- Domain؛
- جودة الصورة؛
- Prompt Style؛
- اللغة؛
- قيود Latency؛
- قيود التكلفة؛
- Hardware؛
- Error Modes المقبولة.

وجود Evaluation Set خاصة بك أمر أساسي.

### إذا كنت تحتاج لحظات محددة في Video

استخدم:

```text
Video + Text Query — Video مع Query نصية
  ↓
Model زمني (Temporal Model)
  ↓
Clip/Timestamps ذات صلة
```

### إذا كنت تحتاج Locations

استخدم:

```text
صورة (image) + Text Prompt
  ↓
Detector من نوع Open-vocabulary Detector
  ↓
Boxes — مخرجات Bounding Boxes
```

### إذا كنت تحتاج Regions دقيقة

استخدم:

```text
صورة (image) + Prompt
  ↓
Model يدعم Segmentation (Segmentation-capable Model)
  ↓
Mask — قناع المنطقة الناتجة
```

العادة الهندسية الأساسية هي:

> طابق Model Architecture و Output Format و Evaluation Metric و Deployment
> Strategy مع المهمة الفعلية بدلًا من التعامل مع كل مشكلة بصرية على أنها
> "send an image to a VLM."

## مفاهيم خاطئة مهمة

### المفهوم الخاطئ 1: "Image Captioning و VQA هما الشيء نفسه تقريبًا."

يشتركان في Multimodal Understanding، لكن المهمة مختلفة.

ينتج Captioning وصفًا عامًا.

أما VQA فيجعل الإجابة مشروطة بسؤال محدد.

### المفهوم الخاطئ 2: "إذا أجابت VLM بشكل صحيح عن سؤال في Reasoning Benchmark، فلا بد أنها نفذت Reasoning بصورة صحيحة."

الإجابة الصحيحة لا تثبت أن Reasoning Process كان Faithful.

يمكن لـ Models استغلال Biases أو Shortcuts.

### المفهوم الخاطئ 3: "Retrieval هو مجرد Classification."

يقوم Retrieval بترتيب العناصر الموجودة حسب الصلة.

أما Classification فيحوّل Input إلى Class Label واحدة أو أكثر.

### المفهوم الخاطئ 4: "OCR و Document Understanding متطابقان."

يقوم OCR بنسخ النص.

أما Document Understanding فيجمع النص مع Layout
و Tables و Figures و Semantic Relationships.

### المفهوم الخاطئ 5: "Video مجرد Batch من صور مستقلة."

Temporal Order و Motion و Tracking وعلاقات الأحداث عناصر أساسية.

### المفهوم الخاطئ 6: "Detection Threshold الأقل أفضل دائمًا لأنها تجد كائنات أكثر."

تزيد Threshold الأقل عدد Candidate Detections،
لكنها قد تزيد أيضًا False Positives.

### المفهوم الخاطئ 7: "ينبغي لـ Generalist VLM استبدال جميع Vision Models المتخصصة."

Generalist VLMs مرنة، لكن Specialized Models قد تكون
أقل تكلفة بكثير وأكثر كفاءة في Production.

### المفهوم الخاطئ 8: "Object Counting مستقل عن Object Localization."

تعتمد جودة Counting غالبًا بدرجة كبيرة على اكتشاف Instances
أو الإشارة إليها أو Tracking لها بصورة صحيحة.

### المفهوم الخاطئ 9: "يجب على Segmentation Model إخراج كل Pixel مباشرة كنص."

تولد بعض الأنظمة Geometric Representations مدمجة
أو Learned Mask Tokens تُفك بعد ذلك.

## المصطلحات الأساسية

| المصطلح | المعنى |
|---|---|
| مصطلح Image Captioning | توليد وصف بلغة طبيعية لصورة |
| مصطلح VQA | الإجابة عن سؤال بلغة طبيعية باستخدام Visual Evidence |
| مصطلح Visual Reasoning | دمج عدة ملاحظات بصرية مع Logic لاشتقاق إجابة |
| مصطلح Retrieval | ترتيب العناصر الموجودة حسب صلتها بـ Query |
| مصطلح Joint Embedding Space | Vector Space تُمثَّل فيه الصور والنصوص المرتبطة بالقرب من بعضها |
| مصطلح Text-to-Image Retrieval | ترتيب الصور استجابةً لـ Text Query |
| مصطلح Image-to-Text Retrieval | ترتيب Text Descriptions استجابةً لـ Image Query |
| مصطلح Image-to-Image Retrieval | ترتيب الصور استجابةً لـ Image Query |
| مصطلح Cosine Similarity | Similarity تعتمد على الزاوية بين Vectors |
| مقياس NDCG@k | Ranking Metric تكافئ النتائج شديدة الصلة عندما تظهر بالقرب من أعلى أول k مواضع |
| مصطلح OCR | تحويل النص الظاهر إلى Text قابل للقراءة آليًا |
| مصطلح Document Understanding | تفسير النص و Layout و Tables و Figures ودلالات Document |
| مصطلح Document VQA | الإجابة عن الأسئلة باستخدام محتوى Document و Layout الخاص به |
| مصطلح Multimodal RAG | استرجاع Visual/Document Evidence قبل توليد إجابة باستخدام VLM |
| مصطلح Temporal Dimension | العلاقات الزمنية بين Video Frames/Events |
| مصطلح Text-to-Video Retrieval | ترتيب Video Clips باستخدام Text Query |
| مصطلح Temporal Grounding | تحديد وقت بداية/نهاية حدث موصوف بالنص |
| مصطلح Zero-shot Detection | اكتشاف كائنات موصوفة بـ Open-ended Prompts من دون إعادة Training لتلك Classes |
| مصطلح Bounding Box | مستطيل يحدد الموضع التقريبي لكائن |
| مصطلح Confidence Threshold | الحد الأدنى للدرجة المطلوبة للاحتفاظ بـ Detection |
| مصطلح Open-vocabulary Detection | Detection يمكن فيها تحديد Categories باستخدام Natural Language |
| مصطلح Object Counting | تقدير عدد Object Instances |
| مصطلح Tracking | الحفاظ على هوية الكائن عبر Video Frames |
| مصطلح Segmentation | إسناد عضوية Object/Region على مستوى Pixels |
| مصطلح Mask | تمثيل على مستوى Pixels لمنطقة Segmented |
| مصطلح Model Card | Documentation تصف استخدام Model وقيوده والإعدادات الموصى بها |

## تحقق ذاتي

قبل المتابعة، تأكد من أنك تستطيع الإجابة عن الآتي:

1. ما الفرق بين Image Captioning و VQA؟
2. لماذا يمكن أن يتطلب VQA أكثر من Object Recognition؟
3. ما الذي يجعل Visual Reasoning مختلفًا عن VQA البسيط؟
4. لماذا يجب على Multimodal Benchmark جيد أن يجبر Model على استخدام الصورة؟
5. ما اتجاهات Retrieval الثلاثة التي نوقشت في هذا الدرس؟
6. لماذا يكون Multimodal Document Retrieval أصعب من Image Retrieval العادي؟
7. ما الذي تكافئه NDCG؟
8. لماذا نقسم DCG على Ideal DCG؟
9. ما الفرق بين OCR و Document Understanding؟
10. ما المرحلتان الرئيسيتان في Multimodal RAG؟
11. لماذا يكون Frame Sampling ضروريًا لـ Video Models؟
12. ما Temporal Grounding؟
13. ما الذي يعيده Zero-shot Object Detection؟
14. لماذا يمكن أن تكون Generalist VLM مفيدة في Annotation حتى إذا لم تنشرها في Production؟
15. ماذا يحدث عندما تخفض Detection Confidence Threshold؟
16. لماذا يستفيد Object Counting من Localization؟
17. كيف تكون Segmentation أدق مكانيًا من Detection؟
18. لماذا يجب أن يبدأ Model Selection من Output Format المطلوب؟
