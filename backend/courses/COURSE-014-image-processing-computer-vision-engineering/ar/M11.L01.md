## 1. الانتقال من Fixed-label segmentation إلى Promptable segmentation



يُدرَّب Semantic model تقليدي على التحويل التالي:



```text
صورة (image) -> خريطة تسميات كثيفة (dense label map)
```



لمجموعة ثابتة من Classes.



تغيّر Promptable segmentation طبيعة المشكلة:



```text
(image, prompt) -> mask — تُنتج Mask اعتمادًا على الصورة وPrompt
```



يمكن أن يكون Prompt:



- Positive أو Negative point،

- Bounding box،

- Rough mask،

- Text description، بحسب Model.



وهذا يحوّل Segmentation من السؤال:



```text
"أي Class محددة مسبقًا ينتمي إليها كل Pixel؟" ("Which predefined class is each pixel?")
```



إلى:



```text
"أي Region تطابق طلب المستخدم أو Model؟" ("Which region matches this user/model request?")
```



يركز الفصل المصدر على:



- Interactivity،

- Zero-shot behavior،

- Generalization،

- تقليل الحاجة إلى إعادة تدريب Model لكل Object category منفردة.

## 2. نظام SAM لـ Image Segmentation



يُعرض SAM بوصفه Prompt-driven segmentation foundation model.



تتكون بنيته المفاهيمية من ثلاثة أجزاء رئيسية:



```text
الصورة (image)
  ↓
Image encoder
  ↓
Image embedding
        **\**
Prompt -> Prompt encoder
          **\**
        Mask decoder
             ↓
          Masks
```



### مُرمّز الصورة (Image encoder)



تتحول الصورة إلى Visual representation قابلة لإعادة الاستخدام.



هذه العملية مكلفة حسابيًا، ولكن بعد حساب Image embedding يمكن تقييم عدة Prompts بكفاءة.



### مُرمّز Prompt (Prompt encoder)



يُحوَّل Prompt إلى Representation تصف Region التي يريدها المستخدم.



من أمثلة Prompts:



- Points،

- Boxes،

- أقنعة (Masks).



### مفكك ترميز Mask (Mask decoder)



يجمع Decoder بين:



```text
خصائص الصورة (image features) + خصائص Prompt (prompt features)
```



للتنبؤ بـ Binary mask ومخرجات مرتبطة بالجودة أو Confidence.



### التوليد التلقائي للأقنعة (Automatic mask generation)



يعرض المصدر أيضًا Automatic segmentation عبر أخذ عينات من عدد كبير من Prompt points فوق الصورة.



Pipeline مبسطة هي:



⟦CODE_0⟧



يمكن أن تحتوي Candidate masks على معلومات مثل:



- Segmentation،

- Area،

- تقديرات Confidence/quality.



[[IMAGE_NEEDED: SAM architecture and prompt types | Show image encoder producing reusable embedding, prompt encoder receiving a point and box, mask decoder, and several candidate masks with quality scores | Learner should understand why the same image representation can answer different segmentation prompts]]



### التحسين العملي



يوصي المصدر بأفكار مثل:



- تغيير حجم الصور شديدة الكبر،

- GPU inference،

- FP16/autocast،

- ترشيح الأقنعة (Mask filtering).



هذه تحسينات هندسية وليست تغييرات في مفهوم Segmentation نفسه.



### دمج SAM مع Vision-language understanding



يعزل الفصل Object مقسمة ثم يمررها إلى Vision-language model.



مفاهيميًا:



```text
SAM
-> يقسم Object (segment object)

قص / Object مع Mask (crop, masked object)
-> Vision-language model

Vision + Language
-> وصف (description)
```



ينشئ هذا Pipeline من النوع:



```text
تقسيم (Segment) -> فهم (Understand) -> وصف (Describe)
```



على هيئة Pipeline.



والفكرة المهمة هي أن Segmentation يمكن أن تصبح Tool واحدة داخل نظام Multimodal أكبر.

## 3. MaskCLIP ومحاذاة CLIP وOpen-vocabulary segmentation



تتعلم الأنظمة بأسلوب CLIP مساحة Embedding مشتركة لـ:



- Images،

- النصوص (Text).



يُشجَّع زوج Image-text المتطابق على امتلاك Embeddings متشابهة.



وهذا يتيح Zero-shot semantic matching.



### المحاذاة اللغوية الكثيفة (Dense language alignment)



تمد أساليب MaskCLIP هذه الفكرة من Global image embedding واحدة نحو:



- Pixel embeddings،

- Region embeddings،

- تمثيلات الأقنعة (Mask embeddings).



بعد ذلك يمكن توجيه Segmentation وفق Similarity مع Text.



مفاهيميًا:



```text
embedding لمنطقة الصورة
          ↘
        التشابه -> تطابق دلالي
          ↗
embedding للنص
```



بدلًا من الحاجة إلى Output neuron متعلَّمة لكل Class ممكنة، يستطيع Model التعامل مع Text concept.



### التجزئة ذات المفردات المفتوحة (Open-vocabulary segmentation)



الفائدة الأساسية هي:



> لا يلزم أن تظل Labels محصورة في قائمة Classes صغيرة وثابتة تم تحديدها خلال عملية تدريب Segmentation واحدة.



يمكن للمستخدم طلب Concepts من خلال Language.

### ملاحظة حول تنفيذ المصدر



يناقش المصدر MaskCLIP بصورة مفاهيمية، ويعرض Universal segmentation مرتبطة بها باستخدام مكونات Mask2Former.



الفكرة القابلة للنقل هي **Vision-language alignment**، وليست Wrapper API محددة بعينها.

## 5. Monocular depth estimation باستخدام DPT



يمد الفصل Segmentation بعد ذلك نحو فهم المشهد ثلاثي الأبعاد.



لا تحتوي صورة RGB واحدة على قياس Depth صريح.



تتنبأ Monocular depth estimation بالآتي:



```text
صورة (image) -> خريطة Depth كثيفة (dense depth map)
```



حيث يحصل كل Pixel على قيمة Depth تقديرية.



### لماذا هذه المشكلة صعبة؟



المشكلة Ill-posed.



يمكن لمشاهد 3D مختلفة أن تنتج إسقاطات 2D متشابهة.



تتعلم Models الحديثة إشارات هندسية مثل:



- Perspective،

- Texture gradients،

- Relative object size،

- Occlusion،

- Shadows،

- السياق الدلالي (Semantic context).



### بنية DPT



يستخدم المصدر Dense Prediction Transformer مدربًا مسبقًا.



مفاهيميًا:



```text
صورة RGB (RGB image)
  ↓ Transformer feature extraction
Global + Multiscale reasoning
  ↓ Dense decoder
Depth map
```



يُعاد Upsample لتنبؤ Depth منخفض Resolution إلى حجم الصورة الأصلية لأغراض Visualization.



### المعنى Relative مقابل Metric



يقوم المصدر بتطبيع القيم لأغراض العرض.



لذلك قد تمثل خريطة Bright/dark ترتيبًا نسبيًا للـ Depth دون أن توفر تلقائيًا مسافة Metric معايرة بالمتر.

## 6. من Depth إلى Point clouds وSemantic 3D



بعد توفر Depth، يمكن إسقاط كل Pixel في الصورة إلى 3D.



بالنسبة إلى Pixel عند `(x, y)` وDepth مقدارها `z` وCamera intrinsics:



```text
X = (x - cx) * z / fx
Y = (y - cy) * z / fy
Z = z
```



حيث:



- `fx` و`fy` هما Focal lengths،

- `cx` و`cy` هما إحداثيا Principal point.



ينتج عن ذلك:



```text
Pixel + Depth -> نقطة 3D (3D point)
```



### سحابة النقاط (Point cloud)



Point cloud هي مجموعة:



```text
{(X, Y, Z, color)} — نقاط 3D مع Color اختيارية لكل نقطة
```



لعدد كبير من Pixels الصورة.



يستخدم المصدر بنى Open3D ويعرض:



- إنشاء Point cloud،

- Multi-view fusion،

- Voxel downsampling،

- Normal estimation،

- العرض التفاعلي ثلاثي الأبعاد (Interactive 3D visualization).



[[IMAGE_NEEDED: Depth to point-cloud projection | Show image pixel (x,y), camera intrinsic model, depth z, back-projection ray, resulting XYZ point, and a colored point cloud reconstructed from all pixels | Learner should connect the depth map with actual 3D geometry]]



### الدمج الدلالي ثلاثي الأبعاد (Semantic 3D fusion)



تمنح Depth معلومات Geometry.



وتمنح Semantic segmentation المعنى.



ودمجهما ينتج:



```text
(X, Y, Z, class) — نقطة 3D مرفقة بـ Class دلالية
```



يستخدم الفصل SegFormer للحصول على Semantic label map ثم يسقط هذه Labels داخل Point cloud.



النتيجة:



```text
صورة RGB (RGB image)
   ├─> Depth
   └─> Semantic segmentation
          ↓
إسقاط 3D (3D projection)
          ↓
Semantic point cloud
```



يدعم ذلك تطبيقات مثل:



- Robotics،

- Autonomous navigation،

- AR/VR،

- Scene mapping،

- التوائم الرقمية (Digital twins).



### ملاحظة مهمة حول Calibration



يستخدم مثال المصدر Intrinsics تقريبية في العرض التوضيحي.



تتطلب إعادة البناء Metric الدقيقة Camera parameters معايرة بصورة صحيحة وDepth scale متسقة.

```text
الصورة (image)
  ↓ Lightweight segmentation
Foreground/background mask
  ↓
```

```text

(1 - Mask) * Blurred
```

- AR effects،

## 8. تدريب U-Net مخصص



لا تكفي Pretrained generic segmentation models دائمًا.



يصبح Custom training مهمًا عندما يختلف Domain عن Datasets الشائعة.



تشمل أمثلة الفصل:



- Autonomous driving،

- Medical imaging،

- صور الأقمار الصناعية (Satellite imagery).



### بنية U-Net



تتكون U-Net من:



```text
المشفِّر
   ↓
عنق الزجاجة
   ↓
المُفكِّك
```



مع Skip connections تربط Resolutions المتناظرة.



### المرمّز (Encoder)



يطبق Encoder بصورة متكررة:



- Convolutions،

- Nonlinear activation،

- خفض الدقة المكانية (Downsampling).



ومع زيادة Depth:



```text
Spatial resolution تنخفض (spatial resolution decreases)
Semantic abstraction تزداد (semantic abstraction increases)
```



### مفكك الترميز (Decoder)



يقوم Decoder بعمل Upsample للـ Features حتى تقترب من Resolution الأصلية.



### الوصلات الاختصارية (Skip connections)



ترسل Skip connections معلومات Spatial دقيقة من مراحل Encoder مباشرة إلى مراحل Decoder المناظرة.



وهذا يعالج مشكلة مهمة في Dense prediction:



```text
الطبقات العميقة تعرف ماذا (deep layers know WHAT)
الطبقات السطحية تعرف أين (shallow layers know WHERE)
```



[[IMAGE_NEEDED: U-Net architecture | Show contracting encoder, bottleneck, expanding decoder, skip connections at matching scales, and final 1×1 pixel-classification layer | Learner should understand how U-Net combines semantic context and boundary detail]]



### المصنّف النهائي (Final classifier)



تحول `1×1` convolution خصائص Decoder إلى:



```text
C من Class logits لكل Pixel (C class logits per pixel)
```



ثم:



```text
argmax(logits) -> Class المتوقعة (predicted class)
```



في Multiclass segmentation.

## 9. Data pipelines وLoss وTraining وTransfer learning

### مسار Dataset (Dataset pipeline)



يتضمن مثال مشهد القيادة في الفصل:



- Image paths،

- Mask paths،

- تغيير حجم Image/mask،

- Normalization،

- Batching،

- Caching،

- الجلب المسبق (Prefetching).



تفصيل بالغ الأهمية:



> ينبغي تغيير حجم Masks باستخدام Nearest-neighbor interpolation عندما تحتوي على Class IDs.



يمكن لـ Bilinear interpolation العادي أن ينشئ Label values وسيطة غير صالحة.

```text

Logits

Gradient
```

قد تشمل الفوائد:



- Convergence أسرع،

- استخراج أقوى للـ Low-level features،

- أداء أفضل عندما تكون Labeled data محدودة.

- مقاييس بأسلوب IoU/Dice،

## 10. تجزئة ورم الدماغ في MRI (Brain-tumor MRI segmentation)



تُعد Medical segmentation شديدة الحساسية لجودة Boundaries.



فقد يكون خطأ هندسي صغير أكثر أهمية مما يكون عليه في مهمة Photographic عادية.



يدرّب المصدر U-Net باستخدام:



- ResNet34 encoder،

- Binary tumor mask،

- Sigmoid output،

- أوزان Encoder مدربة مسبقًا على ImageNet (Pretrained ImageNet encoder weights).



### التجزئة الثنائية (Binary segmentation)



بالنسبة إلى Foreground class واحدة:



```text
احتمال الناتج p(x,y) (output probability p(x,y))
```



ثم:



```text
p > العتبة -> ورم
وإلا          -> الخلفية
```



### عدم توازن Classes (Class imbalance)



قد تشغل Tumor pixels جزءًا صغيرًا من الصورة.



لذلك يمكن أن تكون Pixel accuracy وحدها مضللة.



يجمع الفصل بين:



```text
Binary Cross-Entropy
+
خسارة Dice
```



لتحقيق توازن بين:



- Per-pixel classification،

- تداخل Region (Region overlap).

### ضوابط Training

- ModelCheckpoint،

- Validation metrics،

## 11. 3D CT segmentation باستخدام Swin-UNETR



تعالج 2D medical segmentation كل Slice على حدة.



أما 3D segmentation فتعالج البنية Volumetric كاملة.



يمكن تمثيل CT scan بالشكل:



```text
H × W × D
```



حيث `D` تمثل Depth عبر Slices.



### لماذا يُعد 3D context مهمًا؟



العضو ليس مجموعة من 2D slices غير المرتبطة.



يمتد شكله عبر Volume.



يمكن لـ 3D model الاستدلال حول:



- Continuity،

- Anatomical shape،

- Neighboring slices،

- سياق حجمي بعيد المدى (Long-range volumetric context).



### بنية Swin-UNETR



يستخدم الفصل Swin-UNETR.



وهو يجمع بين:



- Hierarchical Swin Transformer encoder،

- Shifted-window self-attention،

- U-Net-style decoder،

- وصلات اختصارية متعددة المقاييس (Multiscale skip connections).



التفسير:



```text
Swin Transformer
-> سياق بعيد المدى / هرمي (long-range, hierarchical context)

U-Net decoder
-> إعادة بناء مكاني (spatial reconstruction)

Skip connections
-> الحفاظ على Localization (preserve localization)
```

### المعالجة المسبقة للبيانات الطبية (Medical preprocessing)



تتضمن Pipeline المصدر:



- NIfTI loading،

- Channel setup،

- Orientation normalization،

- Voxel spacing/resampling،

- Hounsfield-unit intensity scaling،

- Padding لتحقيق التوافق مع Architecture.



هذا مهم لأن Medical volumes يجب أن تُوحَّد هندسيًا قبل Inference.



### Inference بالنافذة المنزلقة (Sliding-window inference)



قد لا تتسع CT volume كاملة في GPU memory.



يستخدم الفصل 3D windows متداخلة:



```text
Volume كاملة (full volume)
  ↓ تقسيمها إلى Cubes متداخلة (split into overlapping cubes)
Model inference لكل Cube
  ↓ دمج Predictions (merge predictions)
Segmentation كاملة (full segmentation)
```



وهذه استراتيجية عامة للتعامل مع Volumetric data كبيرة.

## 15. IoU وDice: قياس Mask overlap



قبل اختيار Metric، عرّف:



- `TP` — Foreground تم التنبؤ بها بصورة صحيحة،

- `FP` — Foreground زائفة،

- `FN` — Foreground لم يتم اكتشافها،

- `TN` — Background تم التنبؤ بها بصورة صحيحة.



### مقياس Intersection over Union



يقيس IoU:



```text
التقاطع
------------
الاتحاد
```



في Binary segmentation:



```text
IoU =
TP / (TP + FP + FN)
```



التفسير:



```text
1 -> تطابق كامل (perfect overlap)
0 -> لا يوجد تطابق (no overlap)
```



في Multiclass segmentation:



1. احسب IoU لكل Class،

2. احسب المتوسط عبر Classes.



ينتج عن ذلك Mean IoU أو mIoU.



### معامل Dice (Dice coefficient)



يُحسب Dice كالآتي:



```text
معامل Dice =
2 * TP / (2*TP + FP + FN)
```



ويتراوح أيضًا من `0` إلى `1`.



ترتبط Dice وIoU ارتباطًا وثيقًا.



يقيس كلاهما Region overlap، لكن Dice تمنح وزنًا نسبيًا أكبر قليلًا للتداخل وتستخدم على نطاق واسع مع Medical structures الصغيرة.



[[IMAGE_NEEDED: IoU versus Dice geometry | Show ground-truth and predicted binary masks with intersection/union regions highlighted, plus formulas for IoU and Dice | Learner should understand both metrics from set overlap rather than memorizing equations only]]



### دالة Dice loss



يمكن تحسين صيغة Soft Dice القابلة للاشتقاق مباشرة.



يكون ذلك مفيدًا بصورة خاصة عندما:



- تكون Foreground صغيرة،

- يكون Class imbalance شديدًا.

## 16. Pixel accuracy وPrecision/recall وAP وmAP



### دقة Pixels (Pixel accuracy)



Pixel accuracy هي:



```text
الـ pixels الصحيحة / كل الـ pixels
```



في Binary segmentation:



```text
(TP + TN)
--------------------
TP + TN + FP + FN
```



### لماذا قد تفشل Accuracy؟



افترض أن 1% فقط من Pixels تمثل Tumor.



Model يتنبأ بـ:



```text
Background في كل مكان (background everywhere)
```



قد يحقق تقريبًا:



```text
99% دقة pixel
```



مع أنه يفشل في المهمة تمامًا.



لذلك لا ينبغي استخدام Pixel accuracy وحدها مع Segmentation شديدة عدم التوازن.



### Precision وRecall



بالنسبة إلى Object/instance prediction:



```text
الدقة (Precision) =
TP / (TP + FP)

الاستدعاء (Recall) =
TP / (TP + FN)
```



تجيب Precision عن السؤال:



> من كل ما تنبأت به، كم كان صحيحًا؟



وتجيب Recall عن السؤال:



> من كل ما يوجد فعلًا، كم اكتشفت؟



### متوسط الدقة (Average Precision)



عبر Confidence thresholds مختلفة، ينتج Model منحنى Precision-recall.



تلخص AP هذا المنحنى لـ Class واحدة.



### متوسط Average Precision (Mean Average Precision)



تحسب mAP متوسط AP عبر Classes.



كما تحسب Evaluation بأسلوب COCO المتوسط عبر عدة IoU thresholds، ما يجعل تقييم Instance segmentation أكثر صرامة.



[[IMAGE_NEEDED: Segmentation metric selection | Show four panels: IoU/Dice overlap for semantic masks, class-imbalance example exposing accuracy weakness, precision-recall curve and AP area, and instance masks evaluated across IoU thresholds for mAP | Learner should know which metric matches which segmentation problem]]



### ربط Metrics بالـ Domain وفق المصدر



```text
التصوير الطبي
-> Dice + IoU

التجزئة الدلالية للقيادة الذاتية
-> mIoU

الاستشعار عن بُعد
-> IoU + F1/Dice-style overlap

تجزئة الحالات (instance segmentation)
-> mAP
```



### استخدم عدة Metrics



لا يمكن لرقم واحد أن يروي القصة كاملة.



غالبًا ما يتضمن Evaluation قوي:



- Class-wise scores،

- Aggregate scores،

- Visual inspection،

- Boundary errors،

- Rare-class performance،

- تكلفة Runtime والموارد (Runtime/resource cost).

## مفاهيم خاطئة مهمة



### المفهوم الخاطئ 1



> تعني Promptable segmentation أن Model لا تحتاج مطلقًا إلى Image features.



### لماذا هذا خطأ؟



تجمع الأنظمة Promptable بين Visual representation وPrompt representation؛ ويخبر Prompt الـ Model بما يجب استخراجه.



### المفهوم الخاطئ 2



> يقوم SAM تلقائيًا بإسناد أسماء Semantic لكل Mask.



### لماذا هذا خطأ؟



ينتج SAM أساسًا Object/region masks من Prompts أو من Automatic mask generation. أما Semantic naming فتتطلب Classifier إضافية أو خطوة Vision-language.



### المفهوم الخاطئ 3



> تعني Open-vocabulary segmentation أن Model تفهم كل Text phrase ممكنة على نحو مثالي.



### لماذا هذا خطأ؟



تزيد Language alignment المرونة، لكن الجودة ما زالت تعتمد على Training وVisual ambiguity وصياغة Prompt وModel capacity.



### المفهوم الخاطئ 4



> تمنح Monocular depth map تلقائيًا 3D geometry Metric دقيقة.



### لماذا هذا خطأ؟



يقوم مثال المصدر بتطبيع Predicted depth لأغراض Visualization، كما تعتمد إعادة البناء Metric الدقيقة على Camera intrinsics الصحيحة وDepth scale معايرة.



### المفهوم الخاطئ 5



> تجعل Skip connections في U-Net الـ Network أعمق فحسب.



### لماذا هذا خطأ؟



غرضها الأساسي هو نقل Spatial detail من مراحل Encoder إلى إعادة البناء في Decoder.



### المفهوم الخاطئ 6



> Bilinear resizing آمن دائمًا لـ Segmentation masks.



### لماذا هذا خطأ؟



يمكن أن ينتج Interpolation لـ Categorical class IDs تسميات وسيطة غير صالحة؛ لذلك يناسب Nearest-neighbor interpolation الـ Discrete masks.



### المفهوم الخاطئ 7



> تضمن Pixel accuracy المرتفعة Medical segmentation مفيدة.



### لماذا هذا خطأ؟



قد تؤدي هيمنة Background class إلى Accuracy مرتفعة حتى عندما لا يتم اكتشاف Foreground object مطلقًا.



### المفهوم الخاطئ 8



> تعادل 3D segmentation model تطبيق 2D model بصورة مستقلة على كل Slice.



### لماذا هذا خطأ؟



يمكن لـ Volumetric model الاستفادة من Cross-slice context وLong-range 3D context.



### المفهوم الخاطئ 9



> يعني Patch-based satellite training أن النظام النهائي لا يستطيع التنبؤ إلا بـ Patches صغيرة.



### لماذا هذا خطأ؟



يعيد المصدر بناء Full-image output باستخدام Tiled inference وStitching.



### المفهوم الخاطئ 10



> تقيس IoU وDice وmAP الشيء نفسه تمامًا.



### لماذا هذا خطأ؟



IoU وDice هما Overlap metrics للـ Masks، بينما تقيّم mAP أيضًا Instance localization/classification المرتبة حسب Confidence عبر معايير IoU.
