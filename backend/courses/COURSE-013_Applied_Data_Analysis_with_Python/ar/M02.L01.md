### لماذا تختلف NumPy arrays عن Python lists

صُممت NumPy array حول **Homogeneous data**.

وهذا يعني أن Elements الخاصة بها تشترك عادة في Underlying data type واحدة.

على سبيل المثال:

```text
[1, 2, 3, 4]       → Integer array — Array من أعداد صحيحة
[1.5, 2.5, 3.5]    → Floating-point array — Array من أعداد عشرية
```

يؤكد الفصل عدة فوائد:

- Storage أكثر Compact،
- Numerical computation أسرع،
- Contiguous memory layout،
- Vectorized operations،
- تنفيذ منخفض المستوى ومُترجم مسبقًا (Compiled low-level implementation).

الفكرة المهمة للدراسة ليست فقط أن "NumPy أسرع".

بل هي:

> **تمثّل NumPy البيانات العددية بطريقة مصممة لتنفيذ Computation على Array كاملة.**

وبدلًا من كتابة Python loops تمر على كل Value، يمكنك غالبًا التعبير عن Operation مباشرة على Array كاملة.

NumPy array متجانسة، لذلك يكون Underlying numeric type مهمًا.

يجمع الفصل أهم Types في:

- Boolean،
- Signed integer،
- Unsigned integer،
- Floating point،
- الأعداد المركبة (Complex).

---

### 2.2 أنواع الأعداد الصحيحة الموقعة (Signed integer types)

تشمل Integer widths الشائعة:

```text

int32
int64
```

يمكن لـ Width أكبر تمثيل Range أوسع من Integer values، لكنه يستخدم أيضًا Memory أكثر لكل Element.

### 2.3 أنواع الأعداد الصحيحة غير الموقعة (Unsigned integer types)

```text

uint64
```

```text
arr_copy  → نسخة مستقلة
```

لا يؤدي تغيير Original تلقائيًا إلى تعديل Copy.

---

### 5.3 العرض المشترك للبيانات (View)

⟦CODE_60⟧

View هي Array object منفصلة تشارك Underlying data مع Original.

مفاهيميًا:

```text
arr object -----------\
                       > Memory مشتركة
arr_view object ------/
```

يمكن أن تختلف Python object identities بينما تظل Underlying data مشتركة.

---

### 5.4 ملاحظة الفرق

لنفترض:

⟦CODE_61⟧

تصبح Original:

```text
[[ 1  2]
 [99 89]]
```

وتعكس View التعديل:

```text
[[ 1  2]
 [99 89]]
```

بينما تظل Independent copy:

```text
[[1 2]
 [3 4]]
```

لهذا يمكن أن تكون Views سريعة وموفرة للـ Memory، لكنها تحتاج إلى الحذر.

### احتفظ بهذا التمييز

```text
Assignment → Object نفسها
View       → Array object مختلفة و Data مشتركة
Copy       → Object مختلفة و Data مستقلة
```

## مفاهيم خاطئة مهمة

### المفهوم الخاطئ 1

> “NumPy array مجرد Python list أسرع.”

### لماذا هذا غير مكتمل

تمتلك NumPy array أيضًا:

- Numerical representation ثابتة عبر `dtype`،
- Dimensions و Shape،
- Vectorized operations،
- Broadcasting،
- سلوك View/Copy،
- Indexing متعدد الأبعاد (Multidimensional indexing).

إنها Computational model مختلفة، وليست مجرد بديل لـ List.

---

### المفهوم الخاطئ 2

> “`type(arr)` و `arr.dtype` تخبرانني الشيء نفسه.”

### لماذا هذا خطأ

تصف `type(arr)` الـ Python object.

أما `arr.dtype` فتصف Representation الخاصة بالـ Stored elements.

---

### المفهوم الخاطئ 3

> “`flatten()` و `ravel()` قابلتان للتبادل في كل معنى عملي.”

### لماذا هذا خطأ

تنشئ كلتاهما One-dimensional representation، لكن الفصل يميزهما من حيث Memory behavior: تستطيع `ravel()` إعادة Reference/View-like representation وتجنب Memory إضافية، بينما تنتج `flatten()` نتيجة Flattened منفصلة.

---

### المفهوم الخاطئ 4

> “NumPy view هي Backup مستقلة.”

### لماذا هذا خطأ

يمكن لـ View مشاركة Data مع Original array.

قد تظهر التغييرات على Shared underlying data في كلتيهما.

استخدم Copy عندما تحتاج Independent replica.

---

### المفهوم الخاطئ 5

> “`arr[2:7]` تتضمن Index 7.”

### لماذا هذا خطأ

يتوقف Python/NumPy slicing قبل Stop index.

لذلك تتضمن `2:7` الـ Indices:

```text
2,3,4,5,6
```

---

### المفهوم الخاطئ 6

> “Fancy indexing تختار Rectangular blocks دائمًا.”

### لماذا هذا خطأ

يمكن لـ Paired row و Column index arrays اختيار Individual coordinates.

على سبيل المثال:

⟦CODE_137⟧

تختار `(1,2)` و `(2,3)`.

### المفهوم الخاطئ 7

### لماذا هذا خطأ

تركز NumPy arrays على Homogeneous array computation.

وتركز Pandas DataFrames على Labeled tabular data، ويمكن أن تحتوي Columns بأنواع مختلفة.

### المفهوم الخاطئ 8

> “اختيار Column في Pandas يعيد DataFrame أخرى دائمًا.”

### المفهوم الخاطئ 9
