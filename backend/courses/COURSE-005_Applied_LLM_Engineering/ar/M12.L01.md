## 1. المسار المكوّن من ثلاث مراحل من Base Model إلى Aligned Assistant

يبدأ الفصل بنموذج ذهني مفيد جدًا.

عادةً ما تُنشأ LLM توليدية عالية الجودة عبر ثلاث مراحل عامة:

```text
1. التدريب المسبق (Pretraining) / نمذجة اللغة
2. الضبط الدقيق الخاضع للإشراف (SFT)
3. ضبط التفضيلات (Preference tuning) / المواءمة
```

تحل كل مرحلة مشكلة مختلفة.

### المرحلة 1 — تعلم اللغة

تتعلم Model:

```text
ما الـ Token المحتملة التالية؟ (What token is likely to come next?)
```

### المرحلة 2 — تعلم اتباع Instructions

تتعلم Model:

```text
بالنظر إلى طلب المستخدم هذا،
ما الاستجابة التي ينبغي أن أولّدها؟
```

### المرحلة 3 — تعلم السلوك المفضل

تتعلم Model:

```text
من بين الاستجابات المقبولة،
ما الأنواع التي يفضلها البشر أو النظام المستهدف؟
```

الفكرة المهمة هي:

> يعلم Pretraining قدرات لغوية واسعة؛ بينما تعلم SFT سلوك تنفيذ Task؛ ثم تشكل Preference Tuning أي السلوكيات المقبولة ينبغي تفضيلها.

## 2. المرحلة 1 — ينشئ Pretraining الـ Base Model

أثناء Causal Language Modeling، تستقبل Model نصًا مثل:

```text
Large language models are trained to   — جملة ناقصة
```

وتتنبأ بـ:

```text
the next token   — الـ Token التالية
```

ثم تكرر العملية.

هذا **Self-supervised Learning** لأن Target Token تأتي من النص نفسه.

لا يحتاج الإنسان إلى كتابة Label منفصلة لكل Training Example.

مفاهيميًا:

```text
نص ضخم غير موسوم (massive unlabeled text)
      ↓
التنبؤ بالـ Token التالية (next-token prediction)
      ↓
نموذج أساسي (base / foundation model)
```

تتعلم Base Model:

- Syntax.
- Semantics.
- Factual Associations.
- Writing Patterns.
- البنية اللغوية العامة (Broad Linguistic Structure).

لكن ذلك لا يجعلها Assistant جيدة تلقائيًا.

## 3. Base Model هي Completion Engine وليست Instruction Follower تلقائيًا

افترض أنك تسأل:

```text
What is the capital of France?   — سؤال مثال
```

دُربت Pure Base Model على متابعة النص.

لذلك قد تنتج شيئًا مثل:

```text
What is the capital of Germany?   — أسئلة مشابهة قد يكملها Model

...
```

بدلًا من:

```text
Paris.   — إجابة مثال
```

هذا السلوك ليس بالضرورة فشلًا في Language Modeling.

فالـ Model تنفذ ما علمها إياه Pretraining:

```text
predict plausible continuation   — التنبؤ باستمرار معقول
```

بدلًا من:

```text
obey user intent   — اتباع نية المستخدم
```

## 5. يحدّث Full Fine-tuning جميع Model Parameters

في **Full Fine-tuning**:

```text
كل أوزان النموذج القابلة للتدريب (all trainable model weights)
→ تتلقى تحديثات التدرج (receive gradient updates)
```

يعطي ذلك أقصى Adaptation Capacity.

لكنه مكلف.

تشمل التكاليف:

- GPU Memory.
- Training Time.
- ذاكرة حالة المُحسِّن (Optimizer-state Memory).
- Checkpoint Storage.
- Deployment Complexity للـ Task-specific Variants المتعددة.

يقارن الفصل ذلك بالـ Labeled Datasets الأصغر المستخدمة في Fine-tuning.

Pretraining:

```text
very large unlabeled corpus   — مدونة ضخمة جدًا غير موسومة
```

Fine-tuning:

```text
smaller labeled task dataset   — بيانات مهمة موسومة أصغر
```

## 6. PEFT: كيّف جزءًا أقل من Model

تطرح PEFT السؤال:

> هل يمكننا تكييف Model Behavior من دون تحديث كل Original Parameter؟

بدلًا من Training لمليارات Weights، نقوم بـ Training لعدد صغير من Parameters الإضافية أو المشتقة.

مفاهيميًا:

```text
نموذج أساسي كبير (large base model)
مجمّد في معظمه (mostly frozen)

+
مكوّن صغير قابل للتدريب (small trainable component)
```

الفوائد:

- GPU Memory أقل.
- Training أسرع.
- Task-specific Checkpoints أصغر.
- سهولة أكبر في التبديل بين Specializations.

## 7. Adapters: أضف Modules صغيرة قابلة للتدريب

يضيف Adapter Approach Neural Modules صغيرة داخل Transformer Blocks.

مفاهيميًا:

```text
كتلة Transformer (Transformer block)
├── الانتباه (attention)
├── محوّل صغير (small adapter)
├── الشبكة الأمامية (feedforward)
└── محوّل صغير (small adapter)
```

تبقى معظم Original Transformer Parameters مجمّدة.

يتم تحديث Adapter Parameters فقط.

يشير الفصل إلى Early Adapter Work أظهر أن نسبة صغيرة من Trainable Parameters يمكن أن تقترب من أداء Full Fine-tuning في Benchmark Tasks.

الفكرة الأساسية هي:

> يمكن غالبًا تمثيل Task Specialization بواسطة Parameter Update أصغر بكثير من Base Model كاملة.

## 9. LoRA: مثّل Weight Updates بمصفوفات Low-rank

تتخذ **LoRA** نهجًا مختلفًا.

بدلًا من إدخال Conventional Adapter Layers، تقرّب LoRA **التغير** في Weight Matrix كبيرة باستخدام مصفوفتين أصغر بكثير.

افترض أن Base Model تحتوي على Matrix:

```text
W
```

تبقي LoRA `W` مجمّدة وتتعلم Update:

```text
ΔW = B × A
```

حيث `A` و `B` مصفوفتان Low-rank.

تصبح Effective Weight:

```text
W' = W + ΔW
```

[[IMAGE_NEEDED: LoRA matrix update | Show large frozen matrix W plus a low-rank update ΔW formed by multiplying two narrow matrices A and B, producing effective weight W + ΔW | Learner should understand that LoRA learns a compact weight change rather than replacing the full matrix]]

## 10. لماذا توفر Low Rank عدد Parameters

تخيل Matrix بحجم:

```text
10 × 10
```

Matrix.

تحتوي على:

```text
100 values   — عدد القيم
```

يمكن لـ Rank-1-style Decomposition استخدام:

```text
10 × 1   — أبعاد المصفوفة الأولى
and
1 × 10   — أبعاد المصفوفة الثانية
```

وهذا يستخدم:

```text
20 values   — عدد القيم
```

بدلًا من 100.

وبصورة عامة، بالنسبة إلى Matrix بحجم:

```text
d × d
```

تستخدم Rank-`r` Update تقريبًا:

```text
d × r
+
r × d
```

Parameters.

عندما:

```text
r << d
```

يمكن أن تكون Savings كبيرة جدًا.

### ملاحظة اتساق في المصدر

يعطي الفصل المقدم Example لـ Large Model يقول “rank 8” ثم يصف Matrices بحجم `12,288 × 2` مع ذكر نحو `197K` Parameters. يطابق Parameter Count المذكور Rank 8 وليس Rank 2.

الفكرة التي ينبغي الاحتفاظ بها هي علاقة Low-rank Scaling، وليس النص غير المتسق للأبعاد في ذلك Example.

## 11. لا تحتاج LoRA إلى تعديل كل Matrix

يحتوي Transformer على Weight Matrices كثيرة، منها Projections المستخدمة في Attention و Feedforward Layers.

يمكن لـ LoRA استهداف Modules محددة فقط.

على سبيل المثال:

```text
query projection   — إسقاط الاستعلام
value projection   — إسقاط القيمة
key projection   — إسقاط المفتاح
output projection   — إسقاط المخرجات
feedforward projections   — إسقاطات الشبكة الأمامية
```

يغير الاختيار:

```text
trainable parameter count   — عدد المعاملات القابلة للتدريب
training cost   — تكلفة التدريب
adaptation capacity   — سعة التكيّف
```

وهذه مفاضلة أخرى في PEFT.

## 12. فهم LoRA Hyperparameters الرئيسية

يستخدم الفصل لاحقًا Configuration تحتوي على:

```text
r
lora_alpha
lora_dropout
target_modules
```

### `r`

هي Rank الخاصة بـ Low-rank Update.

`r` الأعلى:

```text
more trainable capacity   — سعة تدريب أكبر
more memory   — ذاكرة أكثر
more parameters   — معاملات أكثر
```

`r` الأقل:

```text
more compression   — ضغط أكبر
less adaptation capacity   — سعة تكيّف أقل
```

### `lora_alpha`

تتحكم في Scaling الخاصة بـ LoRA Update.

مفاهيميًا، تحدد مدى قوة مساهمة Learned Update مقارنة بـ Frozen Base Weights.

### `lora_dropout`

تضيف Regularization إلى LoRA Training.

### `target_modules`

تحدد أي Model Matrices تحصل على LoRA Updates.

## 13. تقلل Quantization الـ Memory المطلوبة لـ Base Weights

```text
32-bit float   — فاصلة عائمة بطول 32 بت

8-bit representations   — تمثيلات بطول 8 بت
```

```text
fewer bits per weight   — عدد بتات أقل لكل وزن

```

ولكن أيضًا:

```text
less numerical precision   — دقة عددية أقل
```

## 16. Blockwise و Distribution-aware Quantization

بدلًا من معاملة كل Weight بالطريقة نفسها عبر Model كاملة، تعالج Blockwise Quantization مجموعات من Values.

فكرة الفصل هي:

```text
different local ranges   — نطاقات محلية مختلفة
→ different quantization mappings   — تعيينات تكميم مختلفة
```

يمكن أن يمثل ذلك Weights بأمانة أكبر من Global Mapping واحدة.

كما يناقش الفصل الاستفادة من Distribution المعتادة لـ Neural-network Weights عند تصميم Low-bit Representations.

النتيجة هي توازن أفضل بين:

```text
compression   — الضغط
and
reconstruction accuracy   — دقة إعادة البناء
```

## 21. حمّل Base Model بصيغة 4-bit

يحمّل المصدر Model باستخدام Quantization Configuration.

يذكر الفصل أن Quantization تقلل بدرجة كبيرة VRAM المطلوبة لمجرد تحميل Model.

تعتمد Exact Memory Usage على:

- Model Size.
- Implementation.
- Device.
- Optimizer أو Training State.

الفكرة المفاهيمية هي:

```text
quantized loading   — التحميل المكمَّم
→ lower base-model memory   — ذاكرة أقل للنموذج الأساسي
→ more room for training   — مساحة أكبر للتدريب
```

لا تخلط بين:

```text
memory to load the model   — الذاكرة اللازمة لتحميل النموذج
```

وبين:

```text
total memory required during training   — إجمالي الذاكرة المطلوبة أثناء التدريب
```

```text
frozen/quantized base   — الأساس المجمّد والمكمَّم
+
trainable LoRA update   — تحديث LoRA القابل للتدريب
```

لكن Training Objective الآن Preference-based بدلًا من Instruction Imitation.

## 51. تضيف DPO Training إعداداتها الخاصة

يستخدم الفصل DPO Configuration تشمل:

```text
learning rate   — معدل التعلم
max training steps   — أقصى عدد خطوات تدريب
warmup ratio   — نسبة الإحماء
gradient accumulation   — تجميع التدرجات
FP16
gradient checkpointing   — نقاط تحقق التدرجات
```

وDPO-specific Trainer Settings تشمل:

```text
beta   — معامل beta
max prompt length   — أقصى طول للتعليمة
max total length   — أقصى طول كلي
```

### Warmup

يصف المصدر زيادة Learning Rate تدريجيًا خلال الجزء المبكر من Training.

يمكن لذلك تقليل Instability في بداية Optimization.

### `beta`

على مستوى عام، تتحكم `beta` في DPO في مدى قوة موازنة Optimization بين Preference Changes و Reference Behavior.

تعامل معها بوصفها Tuning Parameter وليست Constant عامة.

## 52. ادمج Adaptations الخاصة بـ SFT و DPO

ينتهي الفصل بمرحلتين من Adaptation:

```text
SFT LoRA adapter   — محوّل LoRA الخاص بـ SFT
DPO LoRA adapter   — محوّل LoRA الخاص بـ DPO
```

ويقوم بدمجهما بالتتابع.

مفاهيميًا:

```text
base model   — النموذج الأساسي
+
SFT adapter   — محوّل SFT
→ SFT model   — نموذج SFT

SFT model   — نموذج SFT
+
DPO adapter   — محوّل DPO

```

يعطي ذلك Final Model تعلمت:

```text
how to follow instructions   — كيفية اتباع التعليمات
and
which response styles/preferences to favor   — أي أساليب وتفضيلات للاستجابة ينبغي تفضيلها
```

```text

+
DPO training   — تدريب DPO
```

أي مرحلتا Optimization.

ويعني ذلك:

- Compute أكثر.
- Tuning أكثر.
- Data Preparation أكثر.
- Checkpoints أو Adapters أكثر.

تحاول Methods أحدث تبسيط العملية.

يذكر المصدر:

```text
ORPO
```

بوصفها Example تجمع جوانب من SFT و Preference Optimization.

تعامل مع ذلك بوصفه مثالًا على الاتجاه الأوسع نحو Alignment Pipelines أبسط.

## 54. لا تنشئ Preference Tuning تعريفًا موضوعيًا لـ "الجيد"

هذه نقطة مفاهيمية شديدة الأهمية.

تتعلم Preference Tuning من:

```text
the preferences encoded in its data   — التفضيلات المشفّرة في بياناته
```

إذا فضّل Evaluators:

```text
verbosity   — الإسهاب
```

فقد تصبح Model أكثر Verbose.

وإذا احتوت Labels على:

- Bias.
- Inconsistent Standards.
- Domain Mistakes.
- فرص التلاعب بالمكافأة (Reward Hacking Opportunities).

فقد يعكس Trained Behavior هذه المشكلات.

تعني Alignment:

```text
align to a preference signal   — المواءمة مع إشارة تفضيل
```

ولا تعني:

```text
discover universal truth   — اكتشاف حقيقة عالمية
```

ولهذا يكون تصميم Preference Data و Evaluation شديدي الأهمية.

## 55. قارن Fine-tuning Methods الرئيسية

| الطريقة | ما الذي يتغير؟ | الميزة الرئيسية | التكلفة/المخاطرة الرئيسية |
|---|---|---|---|
| الضبط الدقيق الكامل (Full Fine-tuning) | معظم/كل Model Parameters | أقصى Adaptation Capacity | Memory و Compute و Storage مرتفعة |
| Adapters | Modules صغيرة يتم إدخالها | Task Specialization بصورة Modular | Components معمارية إضافية |
| LoRA | تحديثات الأوزان منخفضة الرتبة (Low-rank Weight Updates) | عدد صغير من Trainable Parameters | Capacity تعتمد على Rank و Targets |
| QLoRA | أساس مجمّد مكمَّم + LoRA (Quantized Frozen Base + LoRA) | Memory Requirement أقل بكثير | تعقيد إضافي من Quantization |
| SFT | Behavior تتعلم من Instruction-response Pairs | تعلم Instruction Following | تنسخ Patterns وقيود SFT Data |
| Reward-model + PPO | Policy يتم تحسينها من Learned Reward | Preference Optimization مرنة | معقدة ومكلفة |
| DPO | تحسين مباشر للمختار مقابل المرفوض (Direct Chosen-vs-rejected Optimization) | Preference Tuning أبسط | تعتمد بقوة على Preference Data و Reference Setup |

## 56. دليل عملي لاتخاذ القرار

### لديك Compute كبيرة وتحتاج أقصى Task Adaptation

فكر في:

```text
full fine-tuning   — ضبط دقيق كامل
```

### تحتاج عدة Specializations صغيرة على Base Model واحدة

فكر في:

```text
adapters   — المحوّلات
or
LoRA
```

### GPU Memory هي القيد الرئيسي

فكر في:

```text
QLoRA   — LoRA مع نموذج مكمَّم
```

### Base Model لا تتبع Instructions بموثوقية

استخدم:

```text
SFT / instruction tuning   — الضبط الدقيق الخاضع للإشراف وضبط التعليمات
```

### Model تتبع Instructions لكنها تنتج Response Styles غير مرغوبة

فكر في:

```text
preference tuning   — ضبط التفضيلات
```

### تريد Preference Tuning دون Reward Model منفصلة

فكر في:

```text
DPO-style training   — تدريب بأسلوب DPO
```

يعتمد الاختيار الصحيح على:

- Data.
- Compute.
- Desired Behavior.
- Deployment Architecture.
- Evaluation Requirements.

## مفاهيم خاطئة مهمة

### المفهوم الخاطئ 1

> Base Language Model هي بالفعل Instruction-following Assistant.

### لماذا هذا خطأ

يعلم Pretraining بصورة أساسية Next-token Prediction. أما Instruction Following فتتعلمها Model عبر Adaptation لاحقة مثل SFT.

---

### المفهوم الخاطئ 2

> تستخدم SFT Prediction Mechanism مختلفة تمامًا عن Language Modeling.

### لماذا هذا خطأ

تظل SFT تدرب Next-token Prediction؛ والتغيير المهم هو أن Training Sequence منظمة حول Labeled Instruction-response Examples.

---

### المفهوم الخاطئ 3

> تعني PEFT أن Base Model صغيرة.

### لماذا هذا خطأ

يمكن أن تظل Base Model ضخمة. تعني PEFT أن Subset صغيرة فقط من Parameters يتم Training لها.

---

### المفهوم الخاطئ 4

> تستبدل LoRA الـ Original Base Weight Matrices.

### لماذا هذا خطأ

تظل Base Matrices عادةً مجمّدة، وتتعلم LoRA Low-rank Update تضاف إليها.

---

### المفهوم الخاطئ 5

> LoRA Rank الأعلى أفضل دائمًا.

### لماذا هذا خطأ

تزيد Rank الأعلى Adaptation Capacity لكنها تزيد أيضًا Memory و Parameter Count و Compute.

---

### المفهوم الخاطئ 6

> تهم Quantization في Inference فقط.

### لماذا هذا خطأ

تستخدم QLoRA Quantized Base Weights تحديدًا لتقليل Fine-tuning Memory Requirements.

---

### المفهوم الخاطئ 7

> Model ذات Perplexity منخفضة يجب أن تكون أكثر فائدة.

### لماذا هذا خطأ

تقيس Perplexity Language-model Predictive Confidence، وليس كل أبعاد الجودة مثل Correctness أو Helpfulness أو Safety أو Creativity.

---

### المفهوم الخاطئ 8

> الترتيب المرتفع في Public Leaderboard يضمن أن Model هي الأفضل لتطبيقي.

### لماذا هذا خطأ

قد تختلف Public Benchmarks عن Domain الخاصة بك، وقد تتأثر بـ Overfitting أو Contamination.

---

### المفهوم الخاطئ 9

> يلغي LLM-as-a-judge الحاجة إلى Human Evaluation.

### لماذا هذا خطأ

تمتلك Judge Models انحيازاتها وقيودها الخاصة. ويظل البشر مهمين لـ Domain-specific و Preference-sensitive Evaluation.

---

### المفهوم الخاطئ 10

> تكتشف Preference Tuning تفضيلات صحيحة عالميًا.

### لماذا هذا خطأ

هي تتعلم Preferences الممثلة في Training Data و Evaluators.

---

### المفهوم الخاطئ 11

> تتطلب DPO تدريب Scalar Reward Model منفصلة.

### لماذا هذا خطأ

تحسن DPO مباشرةً Chosen مقابل Rejected Responses باستخدام Trainable Model و Reference Model.

---

### المفهوم الخاطئ 12

> تحل SFT و DPO المشكلة نفسها.

### لماذا هذا خطأ

تعلم SFT Desired Response Behavior من Demonstrations؛ بينما تعدّل DPO أي Responses يتم تفضيلها بين Alternatives.

## المصطلحات الأساسية

| المصطلح | المعنى |
|---|---|
| نموذج Base Model | Pretrained Generative Model محسنة بصورة أساسية عبر Language Modeling |
| عملية Language Modeling | تعلم Prediction للـ Tokens من Previous Context |
| مرحلة SFT | Supervised Fine-tuning باستخدام Labeled Instruction-response Examples |
| عملية Instruction Tuning | SFT تركز على تعليم Model اتباع User Instructions |

| عملية Quantization | تمثيل Weights بدقة عددية أقل |

| عملية Double Quantization | Quantization لقيم إضافية مرتبطة بـ Quantization لتحقيق Memory Savings أكبر |
| أسلوب Gradient Accumulation | جمع Gradients عبر Mini-batches متعددة قبل Optimizer Step واحدة |
| أسلوب Gradient Checkpointing | توفير Memory عبر إعادة حساب بعض Activations أثناء Backward Passes |
| مقياس Perplexity | Metric تعكس مدى مفاجأة Language Model بالنص المرصود |

| معيار Benchmark | Standardized Evaluation Dataset أو Task |

| التقييم البشري (Human Evaluation) | أشخاص يحكمون على Outputs وفق Task Quality أو Preference |
| قانون Goodhart’s Law | تحذير من أن التحسين المباشر لـ Measure يمكن أن يشوه فائدتها |
| عملية Preference Tuning | Fine-tuning اعتمادًا على Preferred مقابل Less-preferred Behavior |
| مفهوم Alignment | تكييف Model Behavior نحو Human أو System Preferences محددة |
| نموذج Reward Model | Model تنتج Scalar Preference أو Quality Score لـ Response |
| Response مختارة (Chosen Response) | Preferred Response داخل Preference Pair |
| Response مرفوضة (Rejected Response) | Less-preferred Response داخل Preference Pair |
| أسلوب RLHF | التعلم المعزز من ملاحظات البشر (Reinforcement Learning from Human Feedback) |
| خوارزمية PPO | تحسين السياسة القريبة (Proximal Policy Optimization) |
| أسلوب DPO | التحسين المباشر للتفضيلات (Direct Preference Optimization) |
| نموذج Reference Model | Frozen Model تُستخدم بوصفها Behavioral Baseline أثناء DPO |
| أسلوب ORPO | Preference-optimization Approach ذكرها الفصل وتجمع أفكار SFT و Preference في Process واحدة |

## الفكرة التي ينبغي الاحتفاظ بها

**لا يُعد Fine-tuning لـ Generative Model عملية واحدة، بل سلسلة من مراحل تشكيل السلوك. يمنح Pretraining الـ Model قدرة لغوية واسعة. ويعلمها Supervised Fine-tuning كيفية الاستجابة لـ Instructions. وتقلل PEFT Methods مثل LoRA عدد Trainable Parameters، بينما تقلل QLoRA الـ Memory أكثر عبر Quantization للـ Frozen Base Model. ويجب أن تجمع Evaluation بين Task-specific Metrics و Benchmarks و Automated Judges و Human Judgment بدل الاعتماد على Score واحدة. ثم تحسن Preference Tuning أي Responses مقبولة ينبغي أن تفضلها Model، إما عبر Reward-model-based RLHF/PPO أو Methods مباشرة مثل DPO. وتعتمد جودة كل مرحلة بدرجة كبيرة على Data و Objective و Evaluation الخاصة بها، وليس على Model Size فقط.**
