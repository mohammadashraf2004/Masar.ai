# مسار كوميرس — تحليل أداء الأعمال

انضممت للتو إلى **مسار كوميرس** بصفتك محلّل بيانات مبتدئًا.

مسار كوميرس متجر إلكتروني يبيع الإلكترونيات، والأدوات المنزلية، والأزياء،
ومنتجات التجميل، والكتب، والمعدات الرياضية لعملاء في مصر والخليج والشام وشمال
أفريقيا. تغيّرت المبيعات بوضوح خلال 2025، لكن الإدارة لا تعرف *لماذا*. لذلك
طلبت منك التحقيق في بيانات الشركة وتقديم تقرير تنفيذي يجيب عن الأسئلة الآتية:

1. كيف كان أداء الشركة إجمالًا في 2025؟
2. كيف تحرّكت الإيرادات والطلبات شهرًا بعد شهر؟
3. من هم عملاؤنا — كم منهم يعود، ومن الأهم؟
4. أي الفئات والمنتجات تحرّك الإيرادات، وأيها لا يفعل؟
5. كيف تتقارن مناطقنا؟
6. ما المخاطر التي تراها، وماذا يجب أن نفعل بعد ذلك؟

أصحاب المصلحة هم الرئيس التنفيذي ورئيس المبيعات ورئيس التسويق. يقرؤون
الاستنتاجات والرسوم، لا الشيفرة.

> هذا الملف ترجمة لـ README.md. أسماء الملفات والأعمدة والجداول تبقى بالإنجليزية
> لأنها كذلك في البيانات والشيفرة.

كل المسارات نسبية إلى جذر المشروع: اقرأ البيانات بـ
`pd.read_csv("data/orders.csv")`. ويمكن للملفات إعادة استخدام شيفرة التنظيف بـ
`from analysis.clean_data import load_clean_data`.

في ملفات SQL، كل ملف بيانات خام جدول يحمل اسم الملف: `customers` و`orders`
و`order_items` و`products`. لغة SQL هنا هي لهجة DuckDB.

كل المبالغ بالجنيه المصري (EGP)، والبيانات تغطي الطلبات المقدّمة خلال سنة 2025.

## قاموس البيانات

**customers.csv** — صف لكل عميل مسجّل

| العمود | المعنى |
| --- | --- |
| customer_id | معرّف فريد للعميل، مثل `C0042` |
| city | المدينة في الحساب (قد تكون مفقودة) |
| country | الدولة في الحساب (انظر *مشكلات البيانات المعروفة*) |
| region | منطقة المبيعات: `Egypt` أو `Gulf` أو `Levant` أو `North Africa` |
| segment | `consumer` (فرد) أو `business` (شركة) |
| signup_date | تاريخ إنشاء الحساب |

**orders.csv** — صف لكل طلب

| العمود | المعنى |
| --- | --- |
| order_id | معرّف فريد للطلب، مثل `O00042` |
| customer_id | صاحب الطلب |
| order_date | تاريخ تقديم الطلب (`YYYY-MM-DD`) |
| status | `completed` أو `cancelled` أو `returned` أو `pending` |
| payment_method | `card` أو `cash_on_delivery` أو `wallet` |
| channel | `web` أو `app` |

**order_items.csv** — صف لكل سطر منتج في طلب

| العمود | المعنى |
| --- | --- |
| order_item_id | معرّف فريد للسطر |
| order_id | الطلب الذي ينتمي إليه السطر |
| product_id | المنتج المبيع |
| quantity | عدد القطع في هذا السطر |
| unit_price | السعر المدفوع فعلًا للقطعة بعد أي خصم |

**products.csv** — صف لكل منتج

| العمود | المعنى |
| --- | --- |
| product_id | معرّف فريد للمنتج، مثل `P007` |
| product_name | اسم المنتج |
| category | فئة المنتج |
| list_price | سعر الكتالوج قبل الخصومات |

العلاقات: `orders.customer_id → customers.customer_id`،
`order_items.order_id → orders.order_id`،
`order_items.product_id → products.product_id`.

## قواعد العمل

* **الإيرادات المعترف بها** تشمل الطلبات **المكتملة** (`completed`) فقط. الطلبات
  الملغاة والمرتجعة لم تجلب مالًا، والطلبات المعلّقة لم تُدفع بعد.
* إيرادات سطر الطلب هي `quantity × unit_price`.

## مشكلات البيانات المعروفة

حذّرك فريق هندسة البيانات من أن ملفات التصدير ليست نظيفة. جزء من عملك هو
اكتشاف هذه المشكلات ومعالجتها قبل أن تثق بأي رقم. ترشدك المرحلتان 2 و3 خلالها.

## الأدوات المتاحة

Python مع `pandas` و`numpy` و`matplotlib` و`duckdb`، وSQL (DuckDB). لا يوجد
اتصال بالإنترنت ولا تثبيت لحزم جديدة.

## طريقة العمل

1. اقرأ المهمة على الجانب؛ تبدأ كل مهمة بسؤال عمل.
2. عدّل الملف الذي تذكره المهمة واضغط **تشغيل** كلما أردت.
3. اضغط **تحقق من الخطوة** عندما تظن أن المهمة انتهت. يشغّل الفحص ملفاتك
   المحفوظة على البيانات — وعلى نسخة معدّلة منها، لذا يجب أن تحسب شيفرتك
   الإجابات بدل أن تحتوي أرقامًا مكتوبة يدويًا. ولا يبحث الفحص أبدًا عن شيفرة
   بعينها.
