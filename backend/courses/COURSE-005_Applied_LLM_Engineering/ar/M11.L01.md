## 15. المفاضلة الحقيقية في Freezing

الدرس من الفصل ليس:

```text
جمّد دائمًا (always freeze)
```

ولا:

```text
لا تجمّد أبدًا (never freeze)
```

بل:

```text
Layers أكثر قابلة للتدريب
→ Adaptation Capacity أكبر
→ Compute أكبر

Layers أكثر مجمّدة
→ Adaptation Capacity أقل
→ Training أسرع/أرخص
```

تُظهر تجارب المصدر تحسن Performance كلما سُمح لأجزاء مفيدة أكثر من Encoder بالتعلم، ثم استقرارها لاحقًا.

بالنسبة إلى المشاريع محدودة Resources، يمكن أن يكون Selective Freezing حلًا عمليًا وسطًا.

## 18. المرحلة 1 — أنشئ أزواجًا إيجابية وسلبية


```text
زوج من Class نفسها
→ Positive

زوج من Classes مختلفة
→ Negative
```

```text

"Java has static typing."

→ Positive إذا كان كلاهما ضمن Programming Class
```

```text
"Python supports decorators."   — جملة مثال
"My dog loves long walks."   — جملة مثال

→ negative   — التسمية
```

## 19. Pair Generation تضخم Dataset صغيرة

إذا احتوت Class واحدة على:

```text
16 examples   — عدد الأمثلة
```

فإن عدد Unique Within-class Pairs هو:

```text
16 × 15 / 2 = 120
```

ومع وجود Classes متعددة، يمكن أيضًا إنشاء Cross-class Negative Pairs إضافية.

وهذا يعني:

```text
عدد قليل من Labeled Examples
→ عدد كبير من Contrastive Relationships
```

وهذا أحد أسباب Data Efficiency في SetFit.

---

## 20. المرحلة 2 — Fine-tune للـ Embedding Model

تُستخدم الأزواج المولدة في Contrastive Learning.

الهدف هو إعادة تشكيل Embedding Space بحيث:

```text
Examples من Class نفسها
→ أقرب

Examples من Classes مختلفة
→ أبعد
```

وهذا يعني أن Representation Model تصبح مكيّفة بصورة خاصة مع Classification Task.

يربط الفصل هذه الخطوة عمدًا بمواد Contrastive Learning من الفصل 10.

## 48. قارن استراتيجيات Adaptation في الفصل

| الحالة | الطريقة الرئيسية | ما الذي يتغير؟ | احتياج Data |

| Compute محدودة | Partial Freezing | Selected Layers + Classifier فقط | متوسط/مرتفع |

### Sequence Classification

```text

+
رأس تصنيف (classification head)
+
مراجعات موسومة (labeled reviews)
→

```

### Partial Freezing

```text
Pretrained BERT
+
بعض Layers مجمّدة
+
بعض Layers قابلة للتدريب
+
Classifier
→
Task Adaptation أقل تكلفة
```

### SetFit

```text
عدد قليل من Labeled Examples
→ Positive/Negative Pairs
→ Contrastive Embedding Fine-tuning
→ Classifier
```

```text
BERT عام (general BERT)
+
نص مجال غير موسوم (unlabeled domain text)
+
نمذجة اللغة المقنَّعة (masked language modeling)
→ BERT متكيف مع المجال (domain-adapted BERT)
→ ضبط دقيق خاضع للإشراف للمهمة (supervised task fine-tuning)
```

```text

```

## مفاهيم خاطئة مهمة

### المفهوم الخاطئ 1

> Fine-tuning تعني فقط Training لـ Classifier جديدة فوق Frozen Embeddings.

### لماذا هذا خطأ

في Full Fine-tuning، تقوم Gradients بتحديث Pretrained Representation Model إضافة إلى Classification Head.

---

### المفهوم الخاطئ 2

> تجميد Layers أكثر لا يمكن إلا أن يحسن Training.

### لماذا هذا خطأ

يقلل Freezing مقدار Computation، لكنه يحد أيضًا من مقدار Adaptation التي يمكن لـ Representation Model أن تتعلمها للمهمة المستهدفة.

---

### المفهوم الخاطئ 3

> إذا تدربت Frozen Model بسرعة أكبر، فهي تلقائيًا أفضل اختيار لـ Production.

### لماذا هذا خطأ

Training Cost ليست Metric الوحيدة. تُظهر تجربة Classifier-only في الفصل انخفاضًا كبيرًا في Performance مقارنة بـ Full Fine-tuning.

---

### المفهوم الخاطئ 4

> Few-shot Learning تعني عدم استخدام Supervised Labels.

### لماذا هذا خطأ

لا تزال Few-shot Classification تستخدم Labeled Examples؛ لكنها تستخدم عددًا صغيرًا جدًا لكل Class.

---

### المفهوم الخاطئ 5

> SetFit تدرّب Logistic Regression فقط.

### لماذا هذا خطأ

تقوم SetFit أولًا بـ Contrastive Adaptation لـ Sentence Embedding Model، ثم تدرب Classifier فوق Adapted Embeddings.

---

### المفهوم الخاطئ 6

> Continued Pretraining و Classification Fine-tuning هما Task نفسها.

### لماذا هذا خطأ

تستخدم Continued Pretraining Objective غير مشرفة أو Self-supervised مثل MLM. أما Classification Fine-tuning فتستخدم Labeled Task Targets.

---

### المفهوم الخاطئ 7

> Continued MLM Pretraining تحتاج Sentiment Labels.

### لماذا هذا خطأ

يزيل المصدر Labels صراحةً لأن Training Target تأتي من Predicting Masked Text.

---

### المفهوم الخاطئ 8

> تعطي NER Label واحدة للجملة كاملة.

### لماذا هذا خطأ

تتنبأ NER بـ Labels على مستوى Token حتى تتمكن Spans مختلفة من تمثيل People و Organizations و Locations وغيرها.

---

### المفهوم الخاطئ 9

> يمكن نسخ Word-level NER Label نفسها كما هي إلى كل Subtoken.

### لماذا هذا خطأ

في BIO Tagging، تحتاج Subtokens اللاحقة داخل Entity إلى Labels من نوع `I-...` بدلًا من تكرار `B-...`.

---

### المفهوم الخاطئ 10

> ينبغي أن تحصل Special Tokens مثل `[CLS]` و `[SEP]` على Entity Labels عادية.

### لماذا هذا خطأ

هي لا تقابل Labeled Words أصلية، ولذلك يتم تجاهلها باستخدام Value مثل `-100`.

## المصطلحات الأساسية

| المصطلح | المعنى |
|---|---|
| عملية Fine-tuning | تحديث Parameters الخاصة بـ Pretrained Model من أجل Downstream Task |
| نموذج Representation Model | Model مثل BERT تنشئ Contextual Representations للنص |
| طبقة Classification Head | Task-specific Neural Layer تحول Representations إلى Class Logits |
| تصنيف Sequence | توقع Label واحدة لـ Input Sequence أو Document كاملة |
| Parameter مجمّدة (Frozen Parameter) | Parameter مستبعدة من Training Updates |
| التجميد الجزئي (Partial Freezing) | Training لـ Selected Layers فقط مع إبقاء البقية ثابتة |
| إشارة Gradient | Signal تستخدمها Backpropagation لتحديث Trainable Parameters |

## الفكرة التي ينبغي الاحتفاظ بها

**يتعلق Fine-tuning لـ Representation Models بتحديد مقدار ما ينبغي أن يتكيف من Pretrained Model، وما نوع Supervision المتاحة، وعلى أي Granularity يتم إنتاج Predictions. مع توفر Labeled Data كثيرة، يسمح Full BERT Fine-tuning للـ Representation Model و Task Head بالتخصص معًا. وعندما تكون Compute محدودة، يبادل Selective Freezing بعض القدرة على Adaptation مقابل Efficiency. وعندما تكون Labels قليلة، تحول SetFit Class Labels إلى Contrastive Pairs وتتعلم Task-specific Embedding Space. وعندما تختلف اللغة نفسها عن Pretraining Data، يمكن لـ Continued MLM تكييف Model قبل Supervised Fine-tuning. وعندما تكون Task هي Entity Extraction، تتحول المشكلة من Label واحدة لكل Document إلى Label محاذية لكل Subword Token.**
