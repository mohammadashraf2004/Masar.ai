## لماذا يهم هذا الدرس؟

يُعد Supervised learning من أكثر طرق Machine learning استخدامًا في تطبيقات Business الحقيقية.

الفكرة الأساسية بسيطة:

```text
أمثلة تاريخية (Historical examples)
مع Inputs + إجابات معروفة
        ↓
تتعلم Model علاقة
        ↓
تُعمِّم Model على حالات جديدة
        ↓
تتنبأ بإجابات لبيانات لم ترها من قبل
```

يعطي الفصل نوعين واسعين من Problems:

```text
Regression — الانحدار
→ التنبؤ بقيمة رقمية مستمرة

Classification — التصنيف
→ التنبؤ بفئة واحدة أو أكثر من فئات محددة مسبقًا
```

أمثلة:

```text
Regression — الانحدار:
تقدير Salary
التنبؤ بقيمة Insurance claim
تقدير House price

Classification — التصنيف:
Spam مقابل Not Spam
Churn مقابل Not Churn
إسناد واحدة من عدة Categories
```

لكن بناء Model ليس سوى جزء من العمل.

يحتاج Data professional أيضًا إلى الإجابة عن:

```text
هل تناسب Assumptions الرياضية للـ Model هذه Data؟
هل Model أبسط أوأعقد من اللازم؟
أي Evaluation metric تتوافق مع Business risk؟
هل قيّمنا Model على Data سبق أن رأتها؟
هل ستتمكن Model من Generalize على حالات جديدة؟
```

لذلك يتبع الفصل مسار التعلم التالي:

```text
أساسيات Supervised learning
        ↓
Regression — الانحدار
        ↓
Linear regression + Assumptions
        ↓
Multiple وPolynomial regression
        ↓
Classification — التصنيف
        ↓
Logistic regression / KNN / Trees / Naive Bayes — خوارزميات Classification
        ↓
Metrics الخاصة بالـ Regression
        ↓
Metrics الخاصة بالـ Classification
        ↓
تقسيم Train-test
        ↓
التقسيم الطبقي (Stratification)
        ↓
التحقق المتقاطع K-fold
```

الدرس الأساسي هو:

> **Model مفيدة في Supervised learning ليست مجرد Model تناسب Training data. يجب أن تحل Problem الصحيحة، وتحترم بنية Data، وتستخدم Preprocessing مناسبًا، وأن يتم تقييمها على Unseen data باستخدام Metrics تتوافق مع التكلفة الحقيقية للأخطاء.**


## 4. الانحدار الخطي البسيط (Simple linear regression)

تمثّل Linear regression علاقة خطية بين Input و Target.

المعادلة المفاهيمية:

```text
y = β₀ + β₁x + ε
```

حيث:

```text
x
→ Independent variable

y
→ Dependent variable

β₀
→ Intercept — الثابت

β₁
→ Slope / Coefficient — الميل والمعامل

ε
→ Error term — حد الخطأ
```

---

### 4.1 الثابت (Intercept)

يمثل Intercept القيمة Baseline المتوقعة لـ `y` عندما:

```text
x = 0
```

يعتمد ما إذا كانت هذه Baseline لها Interpretation حقيقي مفيد على ما إذا كانت `x=0` ذات معنى.

---

### 4.2 المعامل (Coefficient)

يمثل Coefficient التغير المتوسط المقدر في `y` عندما تزيد `x` بوحدة واحدة.

مثال:

```text
β₁ = 5000
```

قد يعني:

> ترتبط كل سنة إضافية من الخبرة بزيادة تقارب 5,000 وحدة في Salary، مع ثبات بقية Conditions الموجودة داخل Model.

مهم:

> يوضح Regression coefficient ارتباطًا Association ما لم يدعم Causal design صالح Claim سببية.

يحذر Source صراحةً من أن Non-zero coefficient لا يثبت Cause and effect.

---

### 4.3 Prediction و Residual

افترض:

```text
Salary الفعلية    = 80,000
Salary المتوقعة = 75,000
```

إذًا Residual هي الفرق بين Actual و Predicted values.

مفاهيميًا:

```text
Residual — الباقي
=
Actual — الفعلي
-
Predicted — المتوقَّع
```

تعد Residuals محورية لكل من Model fitting وفحص Assumptions.

## 5. Ordinary Least Squares و SSE

يقدم الفصل Ordinary Least Squares (OLS) باعتبارها Technique لإيجاد أفضل Linear relationship ملاءمة.

هدفها هو تقليل:

```text
مجموع مربعات الأخطاء (Sum of Squared Errors)
```

أو:

```text
SSE
```

مفاهيميًا:

```text
SSE    # مجموع مربعات الأخطاء
=
Σ(actual - predicted)²
```

---

### 5.1 لماذا نربّع الأخطاء؟

يفعل Squaring شيئين:

```text
الأخطاء السالبة والموجبة
→ كلاهما يصبح موجبًا

الأخطاء الكبيرة
→ تحصل على عقوبة أكبر بكثير
```

مثال:

```text
الخطأ = 2
مربع الخطأ = 4

الخطأ = 10
مربع الخطأ = 100
```

يحصل الخطأ الكبير على عقوبة أكبر بكثير تحت SSE.

---

### 5.2 خط أفضل ملاءمة (Best-fit line)

تختار OLS قيم Coefficients التي تقلل Total squared residual error.

نموذج ذهني:

```text
Candidate line A → SSE 900 — خط مرشح A
Candidate line B → SSE 450 — خط مرشح B
Candidate line C → SSE 200 — خط مرشح C
```

يُفضّل Line ذات SSE الأصغر بين هذه Candidates.

---

### 9.1 مشكلة في تفسير Source

يذكر الفصل بعد ذلك أن `p-value` أقل من `0.05` تشير إلى أن Residuals طبيعية.

يتعارض ذلك مع Shapiro–Wilk decision rule التي دُرّست سابقًا في المقرر، حيث تكون Null hypothesis هي Normality و:

```text
p < 0.05
→ ارفض Null الخاصة بالـ Normality
```

لذلك ينبغي التعامل مع النتيجة المبلغ عنها:

```text
0.0206
```

باعتبارها **Source inconsistency**، وليس دليلًا موثوقًا على تحقق Normality.

يقول وصف Histogram في Source إن Residuals تبدو تقريبًا Bell-shaped، لكن ينبغي تفسير Visual appearance و Statistical-test result بصورة منفصلة.

وهذا درس ممتاز في Model diagnostics:

> لا تنسخ Conclusion مكتوبة دون التحقق من أنها تتفق مع Decision rule الخاصة بالـ Test.

### 11.1 معامل التحديد (R-squared)

تصف R² نسبة Variance في Target التي تفسرها Predictors.

مفاهيميًا:

```text
R² قريبة من 1
→ نسبة كبيرة من Variation مفسَّرة

R² قريبة من 0
→ نسبة قليلة من Variation مفسَّرة
```

يحذر الفصل من أن R² **لا** تخبرك بمقدار Prediction error بوحدة Target الأصلية.

وقد ترتفع أيضًا عند إضافة Features أكثر حتى إذا لم تكن هذه Features مفيدة.

---

### 11.2 معامل التحديد المعدّل (Adjusted R-squared)

تأخذ Adjusted R² Model complexity في الاعتبار.

يشدد الفصل عليها عند مقارنة Models ذات أعداد مختلفة من Predictors.

مفاهيميًا:

```text
Feature جديدة مفيدة
→ قد ترتفع Adjusted R²

Feature جديدة غير ذات صلة
→ قد تبقى Adjusted R² ثابتة أوتنخفض
```

---

### 11.3 إحصائية F (F-statistic)

يستخدم الفصل F-statistic و p-value الخاصة بها لاختبار Regression ككل.

Null hypothesis:

```text
جميع Slope coefficients
=
0
```

تشير Model-level p-value صغيرة جدًا إلى أن Predictor واحدة على الأقل مرتبطة بالـ Target.

---

### 11.4 المعامل (Coefficient)

يقدّر Coefficient اتجاه وقوة Association.

مثال:

```text
Coefficient موجبة
→ تميل Target إلى الارتفاع
   مع ارتفاع Predictor

Coefficient سالبة
→ تميل Target إلى الانخفاض
```

مرة أخرى:

```text
الارتباط (Association) ≠ السببية (Causation)
```

---

### 11.5 الخطأ المعياري (Standard error)

تعكس Standard error مقدار عدم اليقين في Coefficient estimate.

يفسر Source القيم الأصغر للـ Standard errors باعتبارها Coefficient estimates أكثر دقة.

---

### 11.6 t-statistic و p-value

تقيّم هذه Individual predictor significance.

يستخدم الفصل:

```text
→ دليل على ارتباط Predictor بالـ Target
```

## 22. CART و Gini impurity

تعني CART:

```text
شجرة التصنيف والانحدار (Classification and Regression Tree)
```

يصف الفصل CART بأنها تقسم Data بصورة Recursive إلى Binary branches.

الهدف هو إنشاء Child nodes أكثر نقاءً.

---

### 22.1 شوائب Gini (Gini impurity)

مفاهيميًا:

```text
Gini    # مقياس عدم النقاء
=
1
-
Σ pᵢ²
```

حيث:

```text
pᵢ
→ نسبة Class i داخل Node
```

مثال Source:

```text
3 Churn    # فقدان
2 Not Churn    # عدم فقدان
```

إذًا:

```text
p_churn     = 3/5 = 0.6
p_notchurn  = 2/5 = 0.4
```

Gini:

```text
1 - 0.6² - 0.4²
=
0.48
```

---

### 22.2 عقدة نقية (Pure node)

إذا كانت جميع Samples تنتمي إلى Class واحدة:

```text
Gini = 0    # عقدة نقية
```

تعني Gini الأقل Purity أعلى.

---

### 22.3 شوائب الانقسام الموزونة (Weighted split impurity)

تدمج CART Child impurity وفق حجم كل Child.

ينتج Split جيد:

```text
Weighted impurity منخفضة
```

وتختار Algorithm أفضل Candidate.

---

### 22.4 التقسيم التكراري (Recursive splitting)

بعد Split واحدة:

```text
Child يسار
Child يمين
```

تعيد Algorithm العملية داخل كل Child.

---

## 24. ID3 و Entropy و Information gain

ID3 هي Decision-tree algorithm أخرى.

بدل Gini impurity، يستخدم الفصل:

```text
Entropy — الإنتروبيا
```

ويختار Splits من خلال:

```text
Information gain — كسب المعلومات
```

---

### 24.1 الإنتروبيا (Entropy)

مفاهيميًا:

```text
Entropy — الإنتروبيا
=
-Σ pᵢ log₂(pᵢ)
```

مثل Gini، تقيس Entropy مقدار اختلاط Classes.

تكون Node الأنقى ذات Entropy أقل.

---

### 24.2 كسب المعلومات (Information gain)

مفاهيميًا:

```text
Information Gain — كسب المعلومات
=
Entropy الخاصة بالـ Parent
-
Weighted Entropy للـ Child
```

يقلل Split قوي مقدار Uncertainty بدرجة كبيرة.

يختار الفصل Split ذات:

```text
أعلى Information gain
```

---

### 24.3 CART مقابل ID3

| CART | ID3 |
|---|---|
| Gini impurity في الفصل | Entropy |
| تقليل Weighted impurity | تعظيم Information gain |
| تركيز على Binary splitting | يركز Source على ملاءمة Categorical |
| يدعم Pruning/Stopping controls | يصف Source معيار Split أبسط |

لا يعلن الفصل أن أحدهما متفوق دائمًا.

بل يقول إن Model choice ينبغي اختباره على Dataset الفعلية.

## 25. خوارزمية Naive Bayes

Naive Bayes هي Probabilistic classification method مبنية على Bayes' theorem.


- اكتشاف الرسائل المزعجة (Spam detection).

### 25.1 لماذا "Naive"؟

تفترض Model أن Features مستقلة Conditional independence بالنظر إلى Class.

مثال:

```text
Age
Income
استخدام Product
```

تبسّط Naive Bayes الحساب بمعاملتها كأنها Conditionally independent بعد معرفة Class.

## 26. مبرهنة Bayes (Bayes' theorem)

مفاهيميًا:

```text
Posterior — الاحتمال اللاحق
∝
Likelihood — دالة الاحتمال
×
Prior — الاحتمال السابق
```

الفكرة كاملة:

```text
P(C | X)
=
P(X | C) × P(C)
/
P(X)
```

حيث:

```text
P(C)
→ Prior — الاحتمال السابق

P(X | C)
→ Likelihood — دالة الاحتمال

P(C | X)
→ Posterior — الاحتمال اللاحق

P(X)
→ Evidence — الدليل
```

يستخدم Source تشبيه Profession:

```text
Prior — الاحتمال السابق
→ مدى شيوع Profession

Likelihood — دالة الاحتمال
→ مدى احتمال Observed clues لتلك Profession

Posterior — الاحتمال اللاحق
→ Belief محدّثة بعد Clues
```

---

### 26.1 مثال Churn

مفاهيميًا:

```text
P(Churn | Urban)    # احتمال الفقدان في المدينة
```

تعتمد على:

```text
P(Urban | Churn)    # صيغة Bayes
P(Churn)
P(Urban)
```

تجيب Posterior عن:

> بالنظر إلى Evidence الملحوظة، ما مدى احتمال هذه Class؟

## 29. Metric للـ Regression: MAE

Mean Absolute Error: متوسط الخطأ المطلق.

```text
MAE    # متوسط الخطأ المطلق
=
average(
    |actual - predicted|
)
```


## 30. Regression metrics: MSE و RMSE

---

### 30.1 متوسط مربع الخطأ (MSE)

Mean Squared Error: متوسط مربع الخطأ.

```text
MSE    # متوسط مربع الخطأ
=
average(
    (actual - predicted)²
)
```

يستخدم الفصل Squared errors لمعاقبة الأخطاء الكبيرة.

مثال Source:

```text
MSE ≈ 15,634,705.79
```

لأن Error يتم Squaring لها، تصبح Unit مربعة وأقل Intuitive.

---

### 30.2 الجذر التربيعي لمتوسط مربع الخطأ (RMSE)

Root Mean Squared Error: الجذر التربيعي لمتوسط مربع الخطأ.

```text
RMSE    # الجذر التربيعي لمتوسط مربع الخطأ
=
sqrt(MSE)
```

Source:

```text
RMSE ≈ 3954.07
```

يعيد ذلك Error إلى Unit الأصلية الخاصة بالـ Target.

يقول Source إن RMSE ما تزال تعاقب Large errors بدرجة أكبر من MAE.

---

### 30.3 مقارنة MAE و RMSE

إذا كانت:

```text
RMSE
>>
MAE
```

فقد توجد بعض Prediction errors كبيرة نسبيًا.

أما إذا كانتا متقاربتين:

```text
قد تكون أحجام الأخطاء أكثر تجانسًا
```

فتعطي هذه المقارنة Insight أكبر من استخدام Metric واحدة وحدها.

## 33. مصفوفة الالتباس (Confusion matrix)

تعد Confusion matrix أربعة Outcomes.

| | موجب فعلي (Actual Positive) | سالب فعلي (Actual Negative) |
|---|---:|---:|
| موجب متوقَّع (Predicted Positive) | TP | FP |
| سالب متوقَّع (Predicted Negative) | FN | TN |

---

### 33.1 إيجابي صحيح (True Positive)

تتنبأ Model بـ Positive وتكون صحيحة.

مثال:

```text
تنبؤ بـ Churn
Customer يقوم فعليًا بـ Churn
```

---

### 33.2 إيجابي كاذب (False Positive)

تتنبأ Model بـ Positive بصورة خاطئة.

يسمي الفصل هذا:

```text
Type I error — خطأ من النوع الأول
```

مثال Business:

```text
تنبؤ بـ Churn
Customer كان سيبقى
→ إهدار Budget الاحتفاظ
```

---

### 33.3 سلبي كاذب (False Negative)

تتنبأ Model بـ Negative بصورة خاطئة.

يسمي الفصل هذا:

```text
Type II error — خطأ من النوع الثاني
```

مثال Business:

## 34. الدقة الكلية (Accuracy)

تقيس Accuracy كل Classifications الصحيحة.

```text
Accuracy — الدقة الكلية
=
(TP + TN)
/
(TP + TN + FP + FN)
```

مثال Source:

```text
0.995
=
99.5%
```

يحذر الفصل:

> تعمل Accuracy بصورة أفضل عندما تكون Classes متوازنة نسبيًا وتكون تكاليف الأخطاء متشابهة.

---

### 34.1 لماذا قد تكون Class imbalance مضللة؟

افترض:

```text
Not Churn
للجميع
```

```text
Accuracy بنسبة 99%
```

بينما تكتشف:

```text
0% من Churners
```

لذلك يمكن لـ Accuracy مرتفعة أن تخفي فشلًا كاملًا في Minority class.

## 35. الإحكام (Precision)

تسأل Precision:

> من كل Observations التي تم Predict لها بأنها Positive، كم واحدة كانت Positive فعلًا؟

```text
Precision — الإحكام
=
TP
/
(TP + FP)
```

مثال Source:

```text
Precision = 1.0    # الدقة
```

المعنى Business:

> كل Predicted churn cases في ذلك المثال كانت Churn بالفعل.

تكون Precision مفيدة عندما تكون False positives مكلفة.

مثال:

```text
عرض Retention يكلف مالًا
→ تجنب استهداف Customers المخلصين دون حاجة
```

---

## 36. الاستدعاء (Recall)

تسأل Recall:

> من كل Actual positive cases، كم واحدة وجدتها Model؟

```text
Recall — الاستدعاء
=
TP
/
(TP + FN)
```

مثال Source:

```text
Recall = 0.9    # الاسترجاع
```

المعنى:

> وجدت Model نسبة 90% من Actual churners في ذلك المثال.

تكون Recall مهمة عندما تكون False negatives مكلفة.

مثال:

```text
Churner لم يتم اكتشافه
→ يغادر Customer من دون Intervention
```

## 37. المفاضلة بين Precision و Recall

يشرح الفصل أن أهداف Business تحدد Balance المفضلة.

### فضّل Recall

الهدف:

```text

```

الـ Trade-off:

```text

إنفاق أكبر على Retention
```

### فضّل Precision

الهدف:

```text

```

الـ Trade-off:

```text
قد يتم فقد بعض Churners الحقيقيين
```

وهذا يعني أنه لا يوجد Threshold واحدة هي الأفضل دائمًا.

يعتمد القرار على Cost النسبية لـ:

```text

مقابل
FN
```

## 38. مقياس F1

تجمع F1 بين Precision و Recall باستخدام Harmonic mean.

```text
F1    # درجة F1
=
2 ×
(Precision × Recall)
/
(Precision + Recall)
```

مثال Source:

```text
F1 ≈ 0.947
```

يستخدم الفصل F1 عندما يكون كل من:

- False positives،
- الحالات السلبية الكاذبة (False negatives)

مهمًا.

تكون F1 مفيدة بصورة خاصة عندما تجعل Class distribution أو Business problem الـ Accuracy غير كافية.

## 44. دليل اختيار Evaluation metric

### Regression — الانحدار

اسأل:

```text
هل أحتاج Average error
بوحدات Target؟
→ MAE

هل تستحق الأخطاء الكبيرة
عقوبة إضافية؟
→ RMSE / MSE

كم مقدار Variance المفسَّرة؟
→ R²

هل أقارن أعدادًا مختلفة
من Predictors؟
→ Adjusted R²
```

---

### Classification — التصنيف

اسأل:

```text
هل Classes متوازنة
وتكاليف الأخطاء متشابهة؟
→ Accuracy

هل False positives مكلفة؟
→ Precision

هل False negatives مكلفة؟
→ Recall

هل أحتاج Metric واحدة توازن
بين Precision وRecall؟
→ F1
```

وهذا من أهم Business lessons في الفصل:

> أفضل Metric تعتمد على تكلفة أخطاء Model.

## احتفظ بهذه الفكرة

**Supervised learning ليست مجرد Fitting لـ Algorithm. حدّد أولًا ما إذا كانت Task هي Regression أو Classification، ونفّذ Preprocessing بما يتوافق مع سلوك Model، وافهم Assumptions و Complexity الخاصة بها، وقيّم النوع الصحيح من Error، وقدّر Performance دائمًا على Unseen data بدل الثقة في Results الخاصة بـ Training set.**
