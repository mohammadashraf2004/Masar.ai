## 1. ما هي LLMs و Generative AI؟

يقدم الفصل Large Language Models بوصفها Language systems حديثة يمكنها دعم مهام كثيرة انطلاقًا من Pretrained foundation واحدة.

تشمل الأمثلة:

- Summarization،
- Question answering،
- Code generation،
- Sentiment classification،
- Entity extraction،
- الاستدلال متعدد الوسائط (Multimodal reasoning).

اعتمدت NLP الأقدم بدرجة كبيرة على:

```text
Rules — قواعد
Statistical features — خصائص إحصائية
Task-specific pipelines — مسارات خاصة بالمهمة
```

أما LLMs فتُعيد استخدام Broad language representations تعلمتها أثناء Large-scale pretraining.

تعالج Recurrent architectures الأقدم مثل RNNs معلومات Sequence خطوة بخطوة.

```text
  ↓
```

```text
Parallelism محدودة

```

غيّرت Transformers هذا باستخدام:


## 4. الانتباه الذاتي (Self-attention)

تسمح Self-attention لكل Token بفحص علاقتها مع Tokens الأخرى في Sequence نفسها.

مثال على نمط المصدر:

```text
The cat sat on the mat because it was tired.    # الجملة المثال
```

بالنسبة إلى Token:

```text
it
```

ينبغي للتمثيل المفيد أن يرتبط بقوة مع Antecedent المناسب:

```text
cat    # قطة
```

بدلًا من التعامل مع كل Token أخرى بالوزن نفسه.

تحسب Attention هذه Relevance relationships عدديًا.

## 5. Query و Key و Value

ينشئ Transformer لكل Token ثلاثة Learned representations.

### الاستعلام (Query)

يمثل:

```text
ما الذي تبحث عنه هذه Token؟ (what this token is looking for)
```

### المفتاح (Key)

يمثل:

```text
ما الذي تقدمه هذه Token للمطابقة؟ (what this token offers for matching)
```

### القيمة (Value)

تمثل:

```text
المعلومات التي يمكن تمريرها للأمام (the information that can be passed forward)
```

يقارن Model:

```text
Query
مع
Keys
```

لتحديد مدى قوة دمج:

```text
Values    # القيم
```

## 6. الانتباه بحاصل الضرب النقطي المُقاس (Scaled dot-product attention)

يقدم الفصل Attention على الصورة:

```text
Attention(Q, K, V)
=
softmax(
    QKᵀ / √dₖ
)
V    # معادلة الانتباه
```

قسّم Formula إلى Steps.

### الخطوة 1 — Similarity

```text
QKᵀ
```

تقيس مدى Alignment لكل Query مع Keys.

### الخطوة 2 — Scaling

```text
القسمة على √dₖ
```

حتى لا تصبح Raw dot products كبيرة بصورة مفرطة مع نمو Vector dimension.

### الخطوة 3 — Normalization

```text
softmax    # دالة التطبيع
```

تحول Scores إلى Weights مجموعها يساوي 1 عبر كل Query row.

### الخطوة 4 — مزج المعلومات

```text
أوزان attention × V
```

تنشئ Context-aware representation جديدة.

## 8. تفسير مثال Attention

يستخدم المصدر:

```text
3 tokens
متجهات Q/K رباعية الأبعاد (4-dimensional)
متجهات V ثنائية الأبعاد (2-dimensional)
```

مثال لـ Attention weights:

```text
[0.506, 0.186, 0.307]
[0.186, 0.506, 0.307]
[0.274, 0.274, 0.452]
```

تمثل كل Row Query token واحدة.

تجيب Row عن السؤال:

> ما مقدار المعلومات التي ينبغي أن تتلقاها هذه Token من Value الخاصة بكل Token؟

لذلك لا يصبح New token representation مجرد Original vector الخاصة بها.

بل هو Weighted mixture من معلومات Sequence.

## 10. الانتباه متعدد الرؤوس (Multi-head attention)

قد تتعلم Attention calculation واحدة Pattern مفيدة واحدة.

لكن Transformers تستخدم Heads متعددة.

مفاهيميًا:

```text
Input representation
        ↓
┌─────────┬─────────┬─────────┐
│ Head 1  │ Head 2  │ Head 3  │
└─────────┴─────────┴─────────┘
        ↓
Concatenate — دمج
        ↓
Output projection — إسقاط Output
```

يمكن لـ Heads المختلفة تعلم Relationships مختلفة.

يقدم المصدر أمثلة مثل:

- Syntactic relationships،
- Semantic similarity،
- أنماط مرجعية/موضعية (Referential/positional patterns).

## 13. لماذا تحتاج Transformers إلى Positional information

لا تعرف Self-attention وحدها ترتيب Tokens بصورة فطرية.

قارن:

```text
dog bites man    # الكلب يعضّ الرجل
```

و:

```text
man bites dog    # الرجل يعضّ الكلب
```

الكلمات نفسها.

لكن المعنى مختلف.

لذلك تضيف Transformers:

- Positional encodings،
- أو Learned position embeddings.

تضيف هذه Sequence-order information إلى Token representations.

## 15. Feed-forward network داخل Transformer block

بعد Attention، تمر كل Token position عبر Feed-forward neural network.

مفاهيميًا:

```text
FFN(x)
=
W₂ activation(
    W₁x + b₁
)
+ b₂    # الشبكة التغذوية
```

تُطبق Feed-forward transformation نفسها بصورة مستقلة على كل Token position.

Attention:

```text
تمزج Information عبر Tokens
```

الطبقة التغذوية (Feed-forward layer):

```text
تحوّل Representation الخاصة بكل Position
```

## 16. Residual connections و Layer normalization

نمط Transformer sublayer مبسط هو:

```text
LayerNorm(
    x + Sublayer(x)
)    # التطبيع بعد الاتصال المتبقي
```

يشرح المصدر أن هذه Components تساعد على:

- Stabilize training،
- الحفاظ على Information مفيدة،
- دعم Deep stacks.

توفر Residual connections مسارًا مباشرًا للمعلومات.

وتعمل Layer normalization على Stabilize لـ Representation scale/statistics.

## 22. التوليد التلقائي الانحدار (Autoregressive generation)

يصف المصدر Joint probability الخاصة بـ Sequence بوصفها Product من Conditional next-token probabilities.

مفاهيميًا:

```text
P(x₁, ..., xₙ)
=
Π P(
    x_t
    |
    x₁ ... x_{t-1}
)
```

تتنبأ Decoder-only model بصورة متكررة بـ:

```text
Next token
بناءً على
Previous tokens
```

هذه هي Basic generation loop.

## 31. التعلم بالنقل (Transfer learning)

بدلًا من:

```text
Language model مهيأة Randomly
```

نبدأ بـ:

```text
المعاملات المدرَّبة مسبقًا (pretrained parameters)
```

ثم نكيّفها لـ Downstream task.

يلخص المصدر:

```text
مجموعة نصية كبيرة (corpus)
→ transformer مدرَّب مسبقًا
→ بيانات خاصة بالمهمة
→ نموذج مكيَّف
```

الفوائد المذكورة:

- Labeled data أقل،
- Starting representation أفضل،
- Development time أقصر،
- عدم الحاجة إلى تدريب Language model من Zero.

يكتب الفصل Task-specific optimization بصورة مفاهيمية:

```text
=
```

```text

=
```

الجزء المهم هو Initialization.

لا تبدأ Fine-tuning من Model فارغة.

بل تبدأ من Language representations تم تعلمها بالفعل أثناء Pretraining.

## 47. قيود Prompting

يحذر الفصل من أن:

- تغييرات Wording يمكن أن تغير Output،
- Prompt واحدة قد تتصرف بصورة مختلفة عبر Models،
- Domain adaptation قد تظل ضعيفة،
- Strict business rules قد تكون صعبة،
- Consistent formatting قد تتطلب Controls أقوى.

لذلك يمكن أن تكون Prompting أول Adaptation layer، وليست بالضرورة الأخيرة.

## 48. الضبط الموفّر للمعاملات (Parameter-Efficient Fine-Tuning — PEFT)

PEFT هي Strategy أوسع:

```text
كيّف Large model
دون تدريب كل Parameters
```

بدلًا من تحديث مليارات Parameters، درّب Subset أصغر بكثير أو Small additional modules.

الهدف:

- Memory use أقل،
- Training cost أقل،
- Task-specific checkpoints أصغر.

---

## 49. LoRA

تعني LoRA:

```text
Low-Rank Adaptation: التكيّف منخفض الرتبة
```

يكتب المصدر Adapted weight بصورة مفاهيمية:

```text
W'
=
W
+
BA
```

حيث:

```text
W
→ الوزن المدرَّب مسبقًا المجمَّد

A, B
→ مصفوفات أصغر قابلة للتدريب
```

ويقرّب حاصل الضرب:

```text
BA
```

الـ Task-specific weight update.

[[IMAGE_NEEDED: Full fine-tuning versus LoRA | Full FT duplicates and updates all base weights; LoRA freezes base and trains two small low-rank matrices attached to selected layers | Learner should understand parameter-efficiency visually]]

---

## 50. لماذا تساعد Low rank

يحتوي Full dense update على Trainable values كثيرة.

تقيّد LoRA الـ Update من خلال Matrices أصغر.

إذا كانت Rank المختارة:

```text
r
```

أصغر بكثير من Full hidden dimension، فقد يكون عدد Trainable parameters أقل بصورة كبيرة.

المفاضلة هي أن Adaptation capacity تصبح مقيدة بهذا Low-rank update.

## 55. Prompting مقابل Full fine-tuning مقابل LoRA

| الطريقة (Method) | هل تتغير Model weights؟ | التكلفة النسبية | الدور المعتاد |
|---|---|---:|---|
| هندسة Prompt (Prompt engineering) | لا | منخفضة | تحكم سلوكي سريع |
| الضبط الكامل (Full fine-tuning) | عدد كبير/الكل | مرتفعة | Adaptation أعمق للمهمة/المجال |
| تكييف LoRA / PEFT | مجموعة Adapter صغيرة (Small adapter subset) | متوسطة/منخفضة | Adaptation فعالة |

تدرّج مفيد هو:

```text
ابدأ بـ Prompt
↓
إذا لم تكفِ
↓
PEFT / LoRA
↓
Full fine-tuning
عندما تكون مبررة
```

هذه ليست Law عامة، لكنها تعكس Adaptation spectrum في الفصل.

## 77. اختيار LLM adaptation strategy

### استخدم Prompting عندما:

- تكون Task قريبة من Pretrained capability،
- تكون Labels محدودة،
- يكون Rapid iteration مهمًا،
- يمكن وصف Behavior عبر Instructions.

### استخدم Retrieval عندما:

- تعتمد Answers على External/private documents،
- يجب Grounding للـ Facts،
- تتغير Corpus أكثر من Model weights.

### استخدم LoRA/PEFT عندما:

- تحتاج Behavior/Domain adaptation،
- تكون Full fine-tuning مكلفة أكثر من اللازم،
- تحتاج عدة Task variants إلى مشاركة Base model واحدة.

### استخدم Full fine-tuning عندما:

- تكون Deeper parameter adaptation مبررة،
- تتوفر Data/Compute كافية،
- تتجاوز Operational benefits التكلفة.

## مفاهيم خاطئة مهمة

### المفهوم الخاطئ 1

> “Transformer هي مجرد Self-attention.”

تتضمن Transformer block أيضًا Positional information و Feed-forward layers و Residual connections و Normalization.

### المفهوم الخاطئ 2

> “تعطي Attention كل Token الوزن نفسه.”

تنتج Softmax أوزان Relevance مختلفة.

### المفهوم الخاطئ 3

> “Query و Key و Value قواعد لغوية ثابتة.”

هي Learned vector projections.

### المفهوم الخاطئ 4

> “يُستخدم Dot product دون Scaling.”

تقسم Scaled attention على `√dₖ`.

### المفهوم الخاطئ 5

> “تعني Multi-head attention تكرار الحساب نفسه تمامًا.”

تتعلم Heads الحقيقية Projections مختلفة.

### المفهوم الخاطئ 6

> “تعرف Self-attention ترتيب الكلمات تلقائيًا.”

يجب إضافة Position information.

### المفهوم الخاطئ 7

> “تؤدي Encoder-only و Decoder-only transformers الأدوار نفسها.”

يربط المصدر Encoder-only بمهام Understanding، و Decoder-only بـ Autoregressive generation.

### المفهوم الخاطئ 8

> “تولد LLM الإجابة كاملة في Step واحدة.”

تتقدم Decoder-only generation Token by token.

### المفهوم الخاطئ 9

> “جدول Model families في الفصل هو Ranking.”

يقول المصدر صراحة إنه ليس Strict ranking.

### المفهوم الخاطئ 10

> “تبدأ Transfer learning من Random weights.”

تبدأ من Pretrained parameters.

### المفهوم الخاطئ 11

> “تقوم Prompt engineering بتحديث Model weights.”

هي تغيّر Model input، لا Weights.

### المفهوم الخاطئ 12

> “Few-shot prompting تعني Fine-tuning باستخدام عدد قليل من الأمثلة.”

توضع Examples داخل Prompt؛ ولا تتغير Model weights.

### المفهوم الخاطئ 13

> “Structured output مجرد Preference للتنسيق.”

يمكن للبنية القابلة للتوقع أن تجعل Downstream parsing و Automation أسهل كثيرًا.

### المفهوم الخاطئ 14

> “تعني PEFT أن كل Pretrained parameter يتم Fine-tune لها.”

تهدف PEFT تحديدًا إلى تدريب Parameter subset/addition صغيرة.

### المفهوم الخاطئ 15

> “تستبدل LoRA الـ Pretrained model.”

تحافظ على Base weights وتضيف Low-rank learned update.

### المفهوم الخاطئ 16

> “Retrieval و Generation هما Step نفسها.”

تسترجع Semantic search الـ Text؛ ثم تستخدم Answering/Generation model الـ Retrieved context.

### المفهوم الخاطئ 17

> “Similarity score بقيمة 0.34 جيدة عالميًا.”

تعتمد Magnitude الخاصة بـ Similarity على Embedding model و Corpus و Task.

### المفهوم الخاطئ 18

> “تتطلب Retrieve-then-answer دائمًا Generative LLM.”

يوضح المصدر نفسه Pattern باستخدام Extractive QA model.

### المفهوم الخاطئ 19

> “AI-generated code التي تعمل آمنة تلقائيًا.”

لا يثبت Correct execution وجود Secure engineering.

### المفهوم الخاطئ 20

> “تلغي AI coding tools الحاجة إلى Human judgment.”

يؤكد الفصل مرارًا Context control و Review و Testing و Validation.
