## 1. التنقل في مشهد تحليل البيانات

نعيش في عالم تُنتج فيه كميات هائلة من البيانات باستمرار.

تشمل الأمثلة:

- المشتريات عبر الإنترنت،
- نشاط Social media،
- Streaming behavior،
- Online learning،
- Digital payments،
- Business operations،
- Government services،
- Transportation systems،
- Logistics،
- Healthcare systems،
- وManufacturing systems.

التحدي المهم ليس مجرد جمع هذه البيانات.

التحدي الحقيقي هو:

> **كيف نحوّل Raw data إلى معلومات مفيدة تساعد الناس على اتخاذ قرارات أفضل؟**

هذا هو الهدف المركزي من Data analysis.

### 1.1 ما تحليل البيانات؟

يجمع Data analysis بين Statistical thinking وComputing لدعم القرارات.

قد يتضمن التحليل المعتاد:

1. جمع البيانات ذات الصلة،
2. استكشاف البيانات،
3. تنظيفها وPreprocessing،
4. وصف ما تحتويه البيانات،
5. Visualizing للأنماط،
6. تحديد العلاقات،
7. بناء Predictive models عند الحاجة،
8. تفسير النتائج،
9. توصيل النتيجة.

نموذج ذهني مفيد هو:

```text
البيانات الخام (Raw data)
   ↓
الجمع
   ↓
التنظيف
   ↓
التحضير
   ↓
الاستكشاف
   ↓
التحليل / النمذجة
   ↓
التفسير
   ↓
التصوير البصري (Visualization)
   ↓
القرار
```

قد يتغير الترتيب في المشروعات الحقيقية، وغالبًا ما تتحرك الفرق للخلف وللأمام بين الخطوات.

### 1.2 لماذا يعد Data analysis متعدد التخصصات؟

لا ينتمي Data analysis إلى تخصص واحد.

بل يستخدم أفكارًا من:

- Statistics،
- Mathematics،
- Computer science،
- Programming،
- Databases،
- Visualization،
- Machine learning،
- وDomain knowledge.

على سبيل المثال، يجب على Analyst جيد في Retail فهم البيانات ومعنى Business concepts مثل Customers وOrders وReturns وDiscounts وInventory.

قد تكون Calculation صحيحة تقنيًا لكنها عديمة الفائدة إذا لم تجب عن السؤال الصحيح.

### 1.3 من Analysis إلى Production

يشدد الفصل أيضًا على أن Modern data work يمتد بصورة متزايدة إلى ما بعد Analysis نفسها.

قد تحتاج المؤسسات إلى:

- ETL pipelines،
- Data engineering،
- Machine-learning models،
- APIs،
- Containerized applications،
- Production deployment،
- وMonitoring.

هذا يعني أن Data ecosystem تحتوي Roles مترابطة عديدة، لا "Data person" واحدة.

### 1.4 مثال: متجر إلكتروني

تخيل متجرًا إلكترونيًا لديه ملايين Transaction records.

قد تحتوي Raw records على:

- Customer ID،
- Product ID،
- Price،
- Quantity،
- Order time،
- Shipping location،
- Discount،
- حالة الإرجاع: Returned/not returned.

لا تجيب هذه Records مباشرةً عن Business questions مفيدة.

قد يسأل Analyst:

- ما Products التي تُشترى معًا كثيرًا؟
- أي Customers توقفوا عن الشراء؟
- ما Average order value؟
- أي Season تحقق أعلى Revenue؟
- ما Products ذات Return rates مرتفعة؟
- ما Customer groups ذات Lifetime value مرتفعة؟

يحوّل Data analysis الـ Records إلى Evidence للإجابة عن هذه الأسئلة.

## 2. استكشاف بيئة Python لتحليل البيانات

تعد Python مفيدة في Data work لأنها تمتلك مكتبات متخصصة كثيرة.

أفضل طريقة لتعلمها ليست حفظ الأسماء، بل تذكر المشكلة التي تحلها كل مكتبة.

### 2.1 مكتبة Pandas

تعد **Pandas** من المكتبات الرئيسية للعمل مع Tabular وRelational data.

بنيتا البيانات الأساسيتان فيها هما:

- بنية `Series`.
- بنية `DataFrame`.

استخدم Pandas عندما تحتاج إلى:

- تحميل Tabular data،
- فحص Columns،
- Filter للـ Rows،
- اختيار Fields،
- تنظيف Missing values،
- Grouping للـ Records،
- Aggregating للـ Values،
- Merge للـ Tables،
- Transform للبيانات.

فكر في Pandas باعتبارها أداة **Table manipulation** الرئيسية في Python analytics ecosystem.

### 2.2 مكتبة NumPy

تعني **NumPy** Numerical Python.

وهي مصممة للعمليات العددية التي تتضمن:

- Arrays،
- Vectors،
- Matrices،
- بيانات متعددة الأبعاد (Multidimensional data).

تعد NumPy مهمة بصورة خاصة لأن كثيرًا من Scientific وMachine-learning libraries مبنية فوق Array model الخاصة بها.

تمييز مفيد:

```text
Pandas → بيانات جدولية معنونة
NumPy  → مصفوفات عددية وعمليات بنمط المصفوفات
```

### 2.3 مكتبة SciPy

توسع **SciPy** قدرات Scientific computing في Python.

تكون مفيدة من أجل:

- Scientific computation،
- Engineering problems،
- Mathematical methods،
- إجراءات عددية (Numerical routines).

يمكنك التفكير في SciPy كـ Scientific toolkit أوسع مبني حول Numerical computing.

### 2.4 مكتبة Statsmodels

تركز **Statsmodels** بصورة قوية على Statistical analysis.

يسلط الفصل الضوء على:

- Hypothesis testing،
- ANOVA،
- Time-series analysis،
- نمذجة الانحدار (Regression modeling).

تكون Statsmodels مفيدة عندما تهتم ليس فقط بالتنبؤ، بل أيضًا بـ Statistical interpretation وInference.

### 2.5 مكتبة Scikit-learn

تعد **Scikit-learn** إحدى أهم مكتبات Machine learning في Python.

يربطها الفصل بـ:

- Feature engineering،
- Supervised learning،
- Unsupervised learning،
- النمذجة التنبؤية (Predictive modeling).

تشمل الفئات الشائعة:

- Regression،
- Classification،
- Clustering،
- Preprocessing،
- تقييم Model.

### 2.6 مكتبة Matplotlib

تعد **Matplotlib** مكتبة أساسية للـ Visualization.

تدعم Charts مثل:

- Line charts،
- Bar charts،
- Scatter plots،
- Histograms،
- وVisualizations كثيرة قابلة للتخصيص.

وغالبًا ما تكون Foundation منخفضة المستوى وراء مكتبات Plotting أخرى.

### 2.7 مكتبة Seaborn

توفر **Seaborn** Statistical visualizations بمستوى أعلى.

تعمل جيدًا من أجل:

- Distributions،
- Relationships،
- Categorical comparisons،
- مخططات إحصائية (Statistical plots).

يقدمها الفصل كطبقة Visualization أبسط وأعلى مستوى مبنية حول Python data stack.

### 2.8 مكتبة Plotly

صُممت **Plotly** للـ Interactive visualizations.

تكون مفيدة من أجل:

- Interactive charts،
- Web-based visualizations،
- لوحات معلومات (Dashboards).

الفرق المهم هو Interactivity.

قد تسمح Plotly chart للمستخدم بعمل Hover أوZoom أوFilter أواستكشاف Values ديناميكيًا.

### 2.9 مكتبة NLTK

تعني **NLTK** Natural Language Toolkit.

يقدمها الفصل كمكتبة لـ Textual data وLanguage processing.

تشمل Tasks:

- Tokenization،
- Stopword removal،
- Stemming،
- Lemmatization،
- Parsing،
- Entity recognition،
- تصنيف النصوص (Text classification).

### 2.10 مكتبة OpenCV

تعني **OpenCV** Open Source Computer Vision.

وترتبط بـ:

- Image processing،
- Feature detection،
- Face recognition،
- Object detection،
- Gesture recognition،
- تتبع الأجسام (Object tracking).

لذلك تعد OpenCV جزءًا من جانب Computer vision في Data ecosystem.

### 2.11 مكتبة Dask

تدعم **Dask** Parallel وDistributed computing.

يقدمها الفصل كطريقة لتوسيع Python code ومعالجة Workloads كبيرة باستخدام Parallelism.

الفكرة الأساسية هي:

> عندما تصبح Task كبيرة أو مكلفة أكثر مما يلائم Simple single-process workflow، يمكن لأدوات Distributed أن تساعد في تقسيم العمل.

### 2.12 خريطة المكتبات

| المجال | المكتبات المقدمة |
|---|---|
| Numerical computing | NumPy |
| Tabular data | Pandas |
| Scientific computing | SciPy |
| Statistical modeling | Statsmodels |
| Machine learning | Scikit-learn |
| تصوير بصري ثابت/إحصائي | Matplotlib، Seaborn |
| Interactive visualization | Plotly |
| معالجة اللغة الطبيعية | NLTK |
| Computer vision | OpenCV |
| الحوسبة المتوازية/الموزّعة | Dask |

### 2.13 كيف تعمل المكتبات معًا؟

قد يستخدم مشروع واقعي عدة Libraries.

مثال:

```text
Pandas
تحميل بيانات العملاء وتنظيفها
        ↓
NumPy
إجراء تحويلات عددية
        ↓
Scikit-learn
بناء نموذج تنبؤ
        ↓
Matplotlib / Seaborn
تصوير سلوك النموذج وأنماطه
        ↓
Plotly
إنشاء لوحة معلومات تفاعلية للأعمال
```

### فكرة مهمة

Library هي **Tool**.

Methodology هي **Process**.

لا تخلط بينهما.

معرفة Pandas تخبرك كيف Manipulate للبيانات.

أما معرفة CRISP-DM فتخبرك كيف تنظم Data project كاملة موجهة للأعمال.

## 3. منهجيات Process الخاصة بتحليل البيانات

قد تصبح Data projects فوضوية إذا لم توجد Structure واضحة.

توفر Process methodologies خطوات قابلة للتكرار لتنظيم العمل.

يقدم الفصل:

- KDD،
- SEMMA،
- CRISP-DM،
- وStandard data-analysis process.

تتداخل هذه Frameworks، لكنها تؤكد أهدافًا مختلفة.

---

### 3.1 KDD — اكتشاف المعرفة من البيانات (Knowledge Discovery from Data)

تركز **KDD** على اكتشاف Patterns ومعرفة ذات معنى من البيانات.

يصف الفصل سبع مراحل رئيسية.

#### المرحلة 1 — تنظيف البيانات

الهدف هو تحسين Data quality.

تشمل المشكلات المعتادة:

- Missing values،
- Duplicates،
- Noise،
- Outliers،
- قيم غير متسقة (Inconsistent values).

إذا كانت البيانات ضعيفة، فسيكون Final insight غير موثوق أيضًا.

#### المرحلة 2 — دمج البيانات

غالبًا ما تخزن المؤسسات المعلومات في Systems مختلفة.

على سبيل المثال:

```text
نظام CRM
+
قاعدة بيانات المدفوعات
+
تحليلات الموقع
+
سجلات الدعم
=
مجموعة بيانات تحليلية متكاملة
```

الغرض من هذه المرحلة هو جمع Sources ذات الصلة معًا.

#### المرحلة 3 — اختيار البيانات

ليست كل Column أوRecord متاحة مفيدة.

يختار Analyst:

- Relevant records،
- Relevant fields،
- Relevant periods،
- مجموعات Customers ذات الصلة.

ينبغي أن يقود Problem المراد حلها عملية الاختيار هذه.

#### المرحلة 4 — تحويل البيانات

قد تحتاج Raw data إلى التحويل إلى Form أكثر فائدة للتحليل.

أمثلة:

- تحويل Text dates إلى Timestamps،
- Normalizing للقيم العددية،
- Encoding للـ Categories،
- Aggregating للـ Transactions،
- إنشاء Derived variables.

#### المرحلة 5 — Data mining

هنا يتم اكتشاف Patterns.

يعطي Source أمثلة مثل:

- Regression،
- Classification،
- Clustering،
- Anomaly detection،
- Association-rule mining،
- أنظمة التوصية (Recommender systems).

#### المرحلة 6 — تقييم الأنماط

ليست كل Pattern مفيدة.

يجب أن يسأل الفريق:

- هل Pattern موثوقة؟
- هل لها معنى؟
- هل يمكن التصرف بناءً عليها؟
- هل Generalize؟
- هل هي مجرد Random noise؟

#### المرحلة 7 — عرض المعرفة

يجب توصيل Patterns المفيدة.

تشمل Formats المحتملة:

- Charts،
- Dashboards،
- Reports،
- Presentations،
- تفسيرات مكتوبة (Written interpretations).

### مثال: Market-basket analysis

افترض أن Retailer يريد معرفة Products التي تُشترى معًا كثيرًا.

قد يكون KDD flow:

```text
تنظيف سجلات المعاملات
        ↓
دمج السجلات من المتاجر
        ↓
اختيار حقول المنتجات والمعاملات
        ↓
تحويل الطلبات إلى سلال
        ↓
استخراج قواعد الارتباط
        ↓
تقييم القواعد القوية
        ↓
عرض رؤى أنماط الشراء
```

قد يكشف ذلك علاقات مثل ظهور Productين بصورة متكررة في Basket نفسها.

### لماذا تكون KDD مفيدة؟

تكون KDD مفيدة بصورة خاصة عندما يكون الهدف الرئيسي:

> **اكتشاف Patterns خفية وتحويلها إلى Knowledge قابلة للاستخدام.**

### 3.2 SEMMA — أخذ عينة واستكشاف وتعديل ونمذجة وتقييم (Sample, Explore, Modify, Model, Assess)

تعد **SEMMA** Process موجهة للـ Modeling ومرتبطة بـ SAS.

ويصف اسمها مراحلها.

#### أخذ عينة (Sample)

حدّد Data sources واختر البيانات المطلوبة.

الهدف هو بناء Dataset مناسبة للـ Modeling.

#### الاستكشاف (Explore)

استكشف البيانات.

ابحث عن:

- Correlations،
- Patterns،
- Unusual values،
- Relationships،
- اتجاهات مفيدة (Useful trends).

#### التعديل (Modify)

حضّر البيانات من أجل Model development.

يشمل الفصل:

- معالجة Missing values،
- التعامل مع Outliers،
- Transforming للـ Features،
- إنشاء Features جديدة.

#### النمذجة (Model)

درّب Predictive models.

يسرد Source أمثلة مثل:

- Decision trees،
- K-nearest neighbors،
- Support vector machines،
- Logistic regression،
- Linear regression،
- Neural networks،
- خوارزمية Random Forests.

#### التقييم (Assess)

قيّم Model واضبطها.

يصبح السؤال:

> ما مدى جودة Model، وهل يمكن تحسينها؟

### مثال: الموافقة على قرض

قد يستخدم Bank SEMMA لبناء Loan-approval model.

Workflow محتملة:

```text
Sample (العيّنة)
اختيار بيانات طلبات تاريخية
        ↓
Explore (الاستكشاف)
فحص الدخل والدَّين وسجل السداد وغيرها
        ↓
Modify (التعديل)
تنظيف الخصائص وهندستها
        ↓
Model (النمذجة)
تدريب نماذج التصنيف
        ↓
Assess (التقييم)
مقارنة أداء النماذج
```

### التركيز الرئيسي لـ SEMMA

تؤكد SEMMA بقوة المسار من:

> **اختيار البيانات → إعداد Features → بناء Model → تقييم Model**

### 3.3 CRISP-DM — العملية عبر الصناعات لتنقيب البيانات (Cross-Industry Process for Data Mining)

تعد CRISP-DM إحدى أكثر Workflows عملية في الفصل.

تتكون من ست مراحل:

1. فهم Business
2. فهم البيانات
3. إعداد البيانات
4. النمذجة (Modeling)
5. Evaluation
6. Deployment

قوتها الأساسية أنها تربط Technical modeling بالهدف Business الأصلي وبـ Final real-world application.

#### المرحلة 1 — فهم Business

قبل لمس البيانات، افهم:

- Goal الخاص بالـ Client،
- Problem statement،
- Constraints،
- كيف يبدو Success،
- ما Decisions التي ينبغي أن يدعمها Solution.

مثال:

```text
مشكلة ضعيفة:
"ابنِ نموذج تعلّم آلة."

مشكلة أفضل:
"قلّل فقدان العملاء بتحديد من يُرجَّح أن يغادروا مبكرًا بما يكفي كي يتصرف فريق الاحتفاظ."
```

#### المرحلة 2 — فهم البيانات

ادرس البيانات المتاحة.

تشمل الأسئلة:

- ما Datasets الموجودة؟
- ماذا تعني Columns؟
- هل توجد Missing data؟
- هل Values غير متسقة؟
- ما Variables التي تبدو مرتبطة؟
- هل توجد Data-quality issues واضحة؟

#### المرحلة 3 — إعداد البيانات

أنشئ Data جاهزة للتحليل.

يذكر Source:

- Missing-value handling،
- Anomaly detection،
- Transformations،
- Scaling،
- هندسة Features.

غالبًا ما تستهلك هذه المرحلة قدرًا كبيرًا من وقت المشروع.

#### المرحلة 4 — Modeling

اختر Model مناسبة ودرّبها.

تعتمد الطريقة على Problem.

على سبيل المثال:

```text
التنبؤ برقم       → regression
التنبؤ بفئة       → classification
إيجاد مجموعات طبيعية → clustering
إيجاد سلوك غير معتاد → anomaly detection
```

#### المرحلة 5 — Evaluation

يجب تقييم Model.

يعطي الفصل أمثلة للـ Regression:

- MSE،
- MAPE،
- RMSE،
- مقياس R-squared.

وللـ Classification:

- Accuracy،
- Precision،
- Recall،
- F1 score،
- مقياس AUC.

لا تحفظ كل هذه الآن.

الدرس الأساسي هو:

> Problems التنبؤ المختلفة تتطلب Evaluation measures مختلفة.

#### المرحلة 6 — Deployment

تصبح Model مفيدة عندما يتم دمجها داخل System حقيقي أوDecision process.

## 4. العملية القياسية لتحليل البيانات

يصف الفصل أيضًا Workflow مفيدة بصورة خاصة للـ Analysts وBusiness analysts.

لا يركز هذا المسار بالضرورة على Machine-learning deployment.

بل يركز على:

> **العثور على Insights قابلة للتفسير وتوصيلها بوضوح.**

المراحل هي:

1. جمع البيانات
2. معالجة البيانات مسبقًا (Preprocessing)
3. تحليل البيانات والعثور على Insights
4. تفسير Insights
5. سرد القصة بالبيانات (Storytelling)

### 4.1 جمع البيانات

اجمع المعلومات ذات الصلة من Sources مختلفة.

أمثلة:

- Databases،
- CSV files،
- Spreadsheets،
- APIs،
- أنظمة داخلية (Internal systems).

### 4.2 Preprocessing للبيانات

حضّر البيانات.

قد يشمل ذلك:

- Filtering،
- Cleaning،
- Transforming،
- Selecting columns،
- اختيار Records.

### 4.3 تحليل البيانات والعثور على Insights

استكشف البيانات.

تشمل الأنشطة:

- Inspecting للـ Distributions،
- Comparing للـ Groups،
- Calculating للـ Metrics،
- Finding trends،
- Identifying relationships،
- تصوير Patterns بصريًا.

### 4.4 تفسير Insights

Chart ليست Insight حتى تشرح ما تعنيه.

افترض أن Sales انخفضت في Region معينة.

قد يتطلب Interpretation طرح أسئلة مثل:

- متى بدأ الانخفاض؟
- أي Products تأثرت؟
- هل كان الانخفاض Seasonal؟
- هل تغير Pricing؟
- هل دخل Competitor إلى Market؟
- هل تغير Customer behavior؟

يربط Interpretation الـ Numerical result بالـ Real-world problem.

### 4.5 سرد القصة بالبيانات (Storytelling)

يشدد الفصل على Storytelling لأن Decision-makers قد لا يفهمون Technical details.

عادةً تحتوي Analytical story قوية على:

```text
المشكلة
   ↓
الدليل
   ↓
التفسير
   ↓
الأثر على الأعمال
   ↓
الإجراء التالي الموصى به
```

### مثال: Customer behavior في Online retail

Data sources محتملة:

- Transaction data،
- Customer data،
- بيانات Products.

KPIs محتملة:

- Average order value،
- Customer lifetime value،
- Customer acquisition cost،
- معدل تكرار الطلب (Repeat order rate).

Analysis محتملة:

- Seasonal trends،
- Customer segmentation،
- Products التي تُشترى معًا بصورة متكررة.

Final communication محتملة:

- تلخيص Findings،
- شرح ما تعنيه،
- اقتراح Actions.

## 7. نظرة سريعة إلى DevOps وMLOps

قبل MLOps، يقدم الفصل DevOps.

### 7.1 منهج DevOps

تساعد DevOps فرق Software على جعل Lifecycle الخاصة بـ Application أكثر موثوقية وكفاءة.

Lifecycle مبسطة هي:

```text
تصميم
  ↓
تطوير
  ↓
اختبار
  ↓
نشر
  ↓
مراقبة
  ↺
```

تؤكد DevOps على:

- Automation،
- Collaboration،
- Continuous integration،
- Continuous delivery،
- نشر قابل للتكرار (Repeatable deployment).

### 7.2 منهج MLOps

تعني **MLOps** Machine Learning Operations.

وهي تطبق Operational practices على Machine-learning systems.

قد تبدو Machine-learning lifecycle هكذا:

```text
جمع البيانات
    ↓
تحضير الخصائص
    ↓
تدريب النموذج
    ↓
تقييم النموذج
    ↓
نشر النموذج
    ↓
مراقبة النموذج
    ↓
إعادة التدريب / الاستبدال
    ↺
```

### 7.3 لماذا تحتاج Machine-learning systems إلى Operations؟

قد تصبح Model أقل فائدة بمرور الوقت.

تشمل الأسباب المحتملة:

- تغير Incoming data،
- تغير User behavior،
- تغير Business conditions،
- انخفاض Model performance.

يشير الفصل إلى أفكار مثل:

- Data drift،
- انجراف Model (Model drift).

ولهذا تحتاج Production ML إلى Monitoring.

### 7.4 فوائد MLOps من الفصل

#### سرعة التطوير

يمكن لـ Tools دعم:

- Feature stores،
- Experiment tracking،
- Monitoring،
- Containerization،
- ممارسات CI/CD.

#### Process موثوقة

تقلل Automated deployment practices العمل Manual وتزيد Repeatability.

#### التعاون

تساعد MLOps في تنسيق العمل بين:

- Data scientists،
- Frontend developers،
- Backend developers،
- مهندسو IT.

#### جودة Data وModel

يساعد Monitoring الفرق على اكتشاف التغيرات التي قد تقلل Model quality.
