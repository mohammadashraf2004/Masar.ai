## 1. ماذا يعني أن تُجري Image Manipulation على صورة؟

الصورة في Python هي في النهاية شبكة من القيم العددية. لذلك يمكن فهم معظم عمليات Image Manipulation على أنها تغيير لأحد ثلاثة أشياء:

1. **قيم Pixel** — مثل Brightness أو Inversion أو Thresholding أو Contrast.
2. **مواضع Pixel** — مثل Translation أو Rotation أو Scaling أو Perspective correction.
3. **طريقة دمج Channels أو الصور** — مثل تبديل Color channels أو Alpha compositing أو Blending.

هذا النموذج الذهني أكثر فائدة من حفظ الدوال كلًّا على حدة.

### ثلاث عائلات من العمليات

| العائلة | ما الذي يتغير؟ | أمثلة |
|---|---|---|
| عملية Intensity / Point operation | قيمة Pixel | Inversion، Gamma، Log transform |
| عملية Geometric operation | إحداثي Pixel | Rotate، Translate، Affine warp |
| عملية Compositing operation | مساهمة عدة صور/Channels | Masks، Alpha blend، Overlay |

وتوجد عائلة عملية رابعة هي **تغيير Sampling/Resolution**، وتظهر في Resizing و Downsampling و Pixelation وإعادة Sampling بعد Geometric Transformations.

### لماذا نستخدم عدة Libraries؟

يستخدم هذا الفصل ثلاث أدوات رئيسية:

- **NumPy** للتعامل المباشر مع Arrays و Boolean masks والعمليات العددية.
- **scikit-image** لدوال معالجة الصور الأعلى مستوى، و Transformations، و Exposure operations، ونماذج Noise.
- **Pillow (PIL)** لتحرير الصور بسهولة، و Resizing، و Point transforms، والرسم، و Transparency، و Compositing.

الهدف ليس تقرير أن Library واحدة هي الأفضل دائمًا. المهارة المفيدة هي التعرّف على العملية العددية ثم اختيار الأداة المناسبة لها.

### تشوّه Fish-eye

يؤدي Fish-eye أو Barrel distortion إلى انحناء الخطوط المستقيمة، خصوصًا قرب حواف الصورة. وتحاول خوارزمية التصحيح إرجاع Output pixels إلى مواضع في المصدر المشوَّه.

يمكن لتصحيح تعليمي مبسط أن يحسب المسافة الشعاعية من مركز الصورة ويطبق Nonlinear mapping:

```text
إحداثي الإخراج (output coordinate)
       ↓
المسافة من المركز (distance from center)
       ↓
قاعدة التصحيح الشعاعي (radial correction rule)
       ↓
إحداثي المصدر (source coordinate)
       ↓
أخذ عينة من Pixel المصدر (sample source pixel)
```

يعرض الفصل ذلك باستخدام دالة `undistort()` مخصصة ومعامل Zoom.

الحد العملي المهم هو:

> يُعد Radial mapping البسيط مفيدًا لتعلّم Geometric correction، لكن تصحيح التشوّه بدقة في كاميرا حقيقية يحتاج عادةً إلى Camera calibration parameters و Lens distortion model.

في Workflows المعتمدة على Calibration، تُقدَّر Camera intrinsics و Distortion coefficients وتُستخدم بواسطة دوال مخصصة مثل تلك التي يوفرها OpenCV.

## 4. Geometric Transformations و Inverse Warping

تغيّر Geometric Transformations **المكان الذي تظهر فيه معلومات الصورة**.

ومن أمثلتها الشائعة:

- Translation،
- Rotation،
- Scaling،
- Shearing،
- Similarity transforms،
- Affine transforms،
- Projective transforms،
- Nonlinear warps مثل Swirl.

### لماذا نستخدم Inverse mapping؟

لنفترض أننا ننقل Input pixels إلى الأمام نحو صورة جديدة.

تجيب Forward transform عن السؤال:

```text
إلى أين يذهب Input pixel هذا؟ (Where does this input pixel go?)
```

المشكلة أن بعض Output pixels قد لا تستقبل أي قيمة، بينما قد تصل عدة Input pixels إلى موضع Output نفسه أو إلى مواضع قريبة منه.

أما Inverse mapping فيطرح سؤال إعادة البناء الأكثر فائدة:

```text
بالنسبة إلى Output pixel هذا، من أين ينبغي أخذ العينة في Input image؟ (For this output pixel, where should I sample from in the input image?)
```

يضمن ذلك أن يكون لكل Output location إحداثي مصدر يمكن أخذ عينة منه.

### Interpolation

غالبًا ما يعيد Inverse mapping إحداثيات غير صحيحة مثل:

```text
(125.4, 88.7)
```

لا توجد Pixel فعلية تمامًا عند هذا الإحداثي، لذلك تقدّر Library قيمة بالاعتماد على Pixels القريبة.

ومن أساليب Interpolation الشائعة:

- Nearest-neighbor،
- Bilinear،
- Bicubic.

إذًا Interpolation جزء من Geometric transformation وليست تفصيلًا منفصلًا خاصًا بالعرض.

### Translation

تزيح Translation كل إحداثي بمقدار ثابت:

```text
x' = x + tx
y' = y + ty
```

في Homogeneous coordinates:

```text
[1  0  tx]
[0  1  ty]
[0  0   1]
```

### Rotation

يُمثَّل 2D rotation بواسطة:

```text
[ cos(theta)  -sin(theta) ] — الصف الأول من مصفوفة Rotation
[ sin(theta)   cos(theta) ] — الصف الثاني من مصفوفة Rotation
```

ومن التفاصيل الدقيقة والمهمة **Center of rotation**.

يعني Rotation حول `(0, 0)` الدوران حول Origin الخاص بالصورة، وهو عادةً الزاوية العلوية اليسرى. وللدوران حول مركز الصورة، فكريًا:

1. انقل المركز إلى Origin،
2. نفّذ Rotation،
3. أعد Translation إلى الموضع الأصلي.

### Rigid و Similarity و Affine و Projective transforms

تشكل هذه Transformations تدرجًا مفيدًا.

| Transformation | هل تدعم Translation؟ | Rotation؟ | Scale؟ | Shear؟ | ما الذي تحافظ عليه؟ |
|---|---:|---:|---:|---:|---|
| Rigid transform | نعم | نعم | لا | لا | المسافات والزوايا |
| Similarity transform | نعم | نعم | موحّد | لا | الشكل / الزوايا |
| Affine transform | نعم | نعم | غير موحّد | نعم | الخطوط المتوازية |
| Projective transform | نعم | نعم | نعم | نعم | الخطوط المستقيمة |

تجمع **Similarity transform** بين Uniform scaling و Rotation و Translation.

أما **Affine transform** فهي أكثر عمومية ويمكن أن تشمل Non-uniform scaling و Shear.

ويمكن لـ **Projective transform** أو Homography أن تمثل تغيّرات شبيهة بالـ Perspective بين Planes. وهي تحافظ على الخطوط المستقيمة لكنها لا تمثل Camera geometry ثلاثية الأبعاد بشكل عشوائي.

## 8. Transparency و Masks و Compositing و Blend Modes

### Alpha channel

تضيف صور RGBA **Alpha channel**:

```text
R, G, B, A
```

يتحكم Alpha في Visibility:

```text
alpha = 0     -> شفاف بالكامل
alpha = 255   -> معتم بالكامل
```

وذلك لـ Alpha القياسي من نوع 8-bit.

يدعم PNG الـ Transparency، بينما لا يدعم JPEG وجود Alpha channel.

### إنشاء Transparency من Mask

يمكن لصورة Grayscale أن تعمل كـ Alpha mask.

من حيث الفكرة:

```text
قيمة Mask ساطعة (bright mask value) -> أكثر عتامة
قيمة Mask داكنة (dark mask value)   -> أكثر شفافية
```

مثال:

⟦CODE_30⟧

يمكن أيضًا بناء Alpha mask من قواعد Color. فعلى سبيل المثال، يمكن لشروط Boolean على Channels R و G و B الاحتفاظ فقط بالـ Pixels المطابقة للون مختار.

### المزج بقيمة alpha ثابتة (Constant alpha blending)

تجمع `Image.blend()` بين صورتين لهما الحجم نفسه و Mode نفسه باستخدام قيمة Global واحدة هي `alpha`.

من حيث الفكرة:

```text
output = (1 - alpha) * image1 + alpha * image2 — صيغة Constant alpha blending
```

لذلك:

```text
alpha = 0 -> image1 — الناتج يساوي image1
alpha = 1 -> image2 — الناتج يساوي image2
```

### Alpha compositing

يختلف Alpha compositing عن Constant blending.

قد تكون لكل Pixel قيمة Alpha خاصة بها، لذلك يمكن لأجزاء مختلفة من Foreground أن تسهم بمقادير مختلفة.

### Watermarking

تُعد Watermark عملية Compositing شائعة:

1. حوّل Base image إلى RGBA،
2. غيّر حجم Watermark،
3. الصقها على Transparent layer،
4. خفّض Alpha الخاص بطبقة Watermark،
5. نفّذ Alpha-composite بين Layer و Base image.

الفكرة المفيدة ليست Logo نفسها، بل فكرة بناء Transparent overlay layer منفصلة.

### التركيب المعتمد على القناع (Mask-based compositing)

يمكن أن تتغير Mask بصورة مستمرة عبر الصورة.

فعلى سبيل المثال، يمكن لـ Horizontal gradient إنشاء انتقال سلس من صورة إلى أخرى.


### Hard Light و Soft Light و Overlay

تجمع Blend modes صورتين Pixel-by-pixel باستخدام قواعد Nonlinear.

**Hard Light**

- تميل قيم Blend الداكنة إلى سلوك شبيه بـ Multiply،
- تميل قيم Blend الساطعة إلى سلوك شبيه بـ Screen،
- يكون التأثير قويًا نسبيًا.

**Soft Light**

- تعمل أيضًا على جعل Shadows أغمق و Highlights أكثر سطوعًا،
- تكون Transitions أكثر نعومة،
- مفيدة لتأثيرات Lighting الأكثر لطفًا.

**Overlay**

- تجمع أيضًا بين سلوك شبيه بـ Multiply وسلوك شبيه بـ Screen،
- لكن Base image هي التي تحدد السلوك الغالب.

الصيغ الدقيقة مهمة عند التنفيذ، لكن الفرق المفاهيمي هو:

```text
الإضاءة القوية (hard light) -> Contrast أقوى تتحكم فيه Blend image
الإضاءة الناعمة (soft light) -> Contrast / Lighting ألطف
التراكب (overlay)            -> سلوك Contrast تتحكم فيه Base image
```

### تركيبات Lighter و Darker

يقارن نوع آخر من Composition بين Pixels مباشرة.

تحتفظ عملية "Lighter" بقيمة Channel الأكبر عند كل موضع.

من حيث الفكرة:

```text
output = max(image1, image2) — الاحتفاظ بالقيمة الأكبر Pixel-wise
```

أما عملية "Darker" فتستخدم:

```text
output = min(image1, image2) — الاحتفاظ بالقيمة الأصغر Pixel-wise
```

وهذه أمثلة بسيطة لكنها قوية على Image arithmetic.

### اختيار طريقة الدمج المناسبة

| الهدف | النموذج الذهني المناسب |
|---|---|
| مزج صورتين كاملتين بصورة موحّدة | مزج alpha ثابت (Constant alpha blend) |
| وضع Foreground شفافة فوق Background | Alpha composite |
| إظهار الصور وفق منطقة مكانية | Mask composite |
| إضافة Logo شبه شفافة | Overlay layer + تركيب Alpha |
| إنشاء تفاعل Lighting/Contrast | Blend mode |
| الاحتفاظ بالمساهمة الأكثر سطوعًا/الأكثر قتامة | القيمة العظمى/الصغرى لكل Pixel |

## مفاهيم خاطئة مهمة

### المفهوم الخاطئ 1

> تعني Geometric transformation نقل Input pixels مباشرة إلى مواضع Output الجديدة.

### لماذا هذا غير مكتمل؟

هذه هي رؤية **Forward mapping**، لكن إعادة بناء الصور تستخدم عادةً Inverse mapping: لكل Output pixel، نحدد الموضع الذي نأخذ منه العينة في Source. يساعد ذلك على تجنب Holes غير المملوءة ويدعم Interpolation.

### المفهوم الخاطئ 2

> لا يفعل Resizing للصورة سوى تغيير Width و Height.

### لماذا هذا غير مكتمل؟

يتطلب Resizing أيضًا Sampling strategy. يحتاج التكبير إلى Interpolation، وقد يؤدي التصغير إلى Aliasing ما لم تُعالج المعلومات عالية Frequency بصورة مناسبة.

### المفهوم الخاطئ 3

> Alpha blending و Alpha compositing هما الشيء نفسه.

### لماذا هذا خطأ؟

يستخدم Blend البسيط غالبًا قيمة Global ثابتة واحدة لـ `alpha`. أما Alpha compositing فيستخدم قيم Alpha مختلفة لكل Pixel، ما يسمح بـ Transparency متغيرة مكانيًا.

### المفهوم الخاطئ 4

> أي دالة لتصحيح Fish-eye مناسبة لعمل Camera calibration دقيق.

### لماذا هذا خطأ؟

يمكن لـ Radial transform مبسط أن يوضح الفكرة، لكن تصحيح العدسة بدقة يحتاج إلى Calibrated camera model و Distortion parameters.

### المفهوم الخاطئ 5

> إذا بدت عملية على الصورة صحيحة بصريًا، فلا بد أن يكون Representation العددي لها صحيحًا أيضًا.

### لماذا هذا خطير؟

ما زلت بحاجة إلى فحص Data type و Value range و Channel order و Coordinate convention و Interpolation behavior و Clipping. قد تخفي نتيجة تبدو منطقية بصريًا أخطاء عددية.

## المصطلحات الأساسية

| المصطلح | المعنى |
|---|---|
| تحويل من نوع Point transformation | Mapping لقيمة Pixel بحيث تعتمد كل Output pixel على Input pixel المقابلة |
| قناع Boolean mask | Array من قيم True/False تُستخدم لتحديد مناطق الصورة |
| فضاء HSV | Color space يفصل Hue و Saturation و Value |
| تحويل Geometric transform | عملية تغيّر Spatial pixel coordinates |
| أسلوب Inverse mapping | لكل Output coordinate، أوجد Input coordinate المقابل |
| عملية Interpolation | تقدير قيمة عند إحداثي غير صحيح بالاعتماد على Samples مجاورة |
| تمثيل Homogeneous coordinates | Representation للإحداثيات مناسب للمصفوفات ويُستخدم في Geometric transforms |
| تحويل Similarity transform | تحجيم منتظم + دوران + إزاحة |
| تحويل Affine transform | Transformation تدعم Translation و Rotation و Non-uniform scaling و Shear و Reflection |
| تحويل Projective transform | Transformation تعتمد على Homography وتحافظ على الخطوط المستقيمة |
| ظاهرة Aliasing | Distortion ناتج عن Sampling غير كافٍ عند تقليل Resolution |
| أسلوب Anti-aliasing | Filtering يُستخدم لتقليل Aliasing قبل Downsampling أو أثناءه |
| منطقة ROI | Region of Interest مختارة من صورة |
| تحويل Gamma / Power-law transform | Nonlinear mapping لقيم Intensity |
| Histogram | Frequency distribution لقيم Pixel intensity |
| CDF | Cumulative probability distribution لقيم Intensity |
| قناة Alpha channel | Channel لكل Pixel للتحكم في Transparency/Opacity |
| عملية Alpha blending | مزج الصور باستخدام Weighting factor |
| عملية Alpha compositing | دمج Transparent layers باستخدام Alpha لكل Pixel |
| نمط Blend mode | صيغة Pixel-wise لدمج Base image و Blend image |
