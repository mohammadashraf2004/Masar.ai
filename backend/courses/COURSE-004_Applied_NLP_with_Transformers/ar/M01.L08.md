## 6. فكرة Zero-shot رقم 1: حوّل Classification إلى Fill-mask Problem

عندما لا توجد Task Labels، أحد الخيارات الإبداعية هو إعادة استخدام Masked Language Model.

لنفترض أن Movie Description تتبعها الجملة:

```text
الفيلم يتحدث عن [MASK].
```

يمكن لـ Masked Language Model تقييم Candidate Words مثل:

```text
animals   — كلمة مرشحة: حيوانات
cars      — كلمة مرشحة: سيارات
```

هنا يتم إنشاء Classifier بصورة غير مباشرة من خلال Prompt بدلًا من Classification Head جديدة تم تدريبها.

يعلّمنا هذا المثال مبدأ أوسع:

> أحيانًا يمكن إعادة صياغة المهمة الأصلية لـ Pretrained Model بحيث تتصرف كما لو كانت تنفذ المهمة الجديدة، من دون تحديث Parameters.

هذه Fill-mask Trick سهلة الفهم، لكن Natural Language Inference تقدم طريقة أكثر عمومية لـ Zero-shot Classification.

## 8. تحويل Zero-shot Scores إلى Multilabel Predictions

تعيد NLI Zero-shot Model Score لكل Label، لكن ما زلنا بحاجة إلى Rule لتحويل Scores إلى Predicted Labels.

يعرض الفصل خيارين:

### Top-k

اختر دائمًا أعلى `k` Labels من حيث Score.

### Threshold

اختر كل Label تتجاوز Score الخاصة بها Threshold محددة.

تؤدي هذه القواعد إلى Precision/Recall Behavior مختلفة.

Threshold منخفضة تعطي Predictions أكثر:

```text
Recall أعلى
Precision أقل
```

Threshold مرتفعة جدًا تعطي Predictions أقل:

```text
Precision أعلى
Recall أقل
```

في هذه الـ Dataset، يجد الفصل أن Top-1 أفضل بين Top-k Rules التي تم اختبارها، لأن أغلب Labeled Issues لديها Label واحدة مختارة فقط.

الدرس الأوسع هو ضبط Output Rule على Validation Set صغيرة، حتى إذا كانت الـ Model نفسها تعمل بأسلوب Zero-shot.

## 9. عندما تملك Labels قليلة: ضاعف الأمثلة باستخدام Data Augmentation

عندما يتوفر عدد قليل من Labeled Examples، يمكن لـ Data Augmentation إنشاء Synthetic Variants مع الحفاظ على Original Label.

تشمل الطرق الشائعة:

### Back Translation

```text
English → لغة أخرى → English
```

### Token Perturbations

- Synonym Replacement،
- Word Insertion،
- Word Swapping،
- Word Deletion.

Text Augmentation أخطر من Image Augmentation لأن تغييرًا صغيرًا في ترتيب الكلمات قد يعكس المعنى بالكامل.

مثال:

```text
هل الأفيال أثقل من الفئران؟
هل الفئران أثقل من الأفيال؟
```

إعادة ترتيب بسيطة غيّرت الإجابة تمامًا.

لكن في GitHub Issues الطويلة، تكون Perturbations محدودة أقل احتمالًا لتغيير High-level Topic Label.

## 11. FAISS تجعل Vector Lookup قابلة للتوسع

في Brute-force Nearest-neighbor Search تتم مقارنة Query Vector بكل Stored Vector.

وتصبح هذه العملية مكلفة مع نمو الـ Dataset.

توفر FAISS هياكل فعالة لـ Similarity Search فوق Dense Vectors.

إحدى الأفكار التي يشرحها الفصل هي تقسيم الـ Vectors إلى Clusters:

```text
كل الـ Vectors
   ↓ k-means
Cluster 1   Cluster 2   Cluster 3 ...
   ↓
قارن Query مع Cluster Centers
   ↓
ابحث فقط داخل الـ Cluster(s) الواعدة
```

هذا قد يقلل عدد المقارنات بصورة كبيرة.

[[IMAGE_NEEDED: FAISS clustered vector index | A 2D embedding space partitioned into several regions around centroid points, with one query vector first matched to a centroid and then compared with vectors inside that region | Learner should notice how partitioning avoids comparing the query with every stored embedding]]

في Nearest-neighbor Classifier الخاصة بالفصل، هناك Hyperparameters أساسيتان:

- `k`: عدد Neighbors المسترجعة،
- `m`: عدد هذه Neighbors التي يجب أن تحتوي على Label حتى يتم إسنادها.

باستخدام Full Labeled Training Set، يجد الفصل إعدادًا قويًا قريبًا من `k=15` وm=5 في Validation Experiment.

## 13. In-context وFew-shot Learning باستخدام Prompts

هناك مساحة وسطى بين Zero-shot Prompting وParameter Fine-tuning.

يمكن لـ Language Model قوية بما يكفي أن تستنتج المهمة أحيانًا من أمثلة موجودة مباشرة داخل الـ Prompt.

Prompt الترجمة بلا أمثلة (Zero-shot Translation Prompt):

```text
Translate English to French:   — التعليمة
thanks =>                      — الـ Model يكمل الترجمة
```

النسخة ذات الأمثلة القليلة (Few-shot Version):

```text
Translate English to French:   — التعليمة
hello => bonjour               — مثال أول
goodbye => au revoir           — مثال ثانٍ
thanks =>                      — الـ Model يكمل الترجمة
```

Model Parameters لا تتغير؛ الأمثلة تصبح Temporary Context.

يناقش الفصل هذا كطريقة للاستفادة من عدد قليل من Labeled Examples من دون الحاجة بالضرورة إلى تدريب Task Head تقليدية.

## 14. Unlabeled Corpora الكبيرة لها قيمة

لنفترض أن لديك عددًا قليلًا من Labeled GitHub Issues لكن آلافًا من Unlabeled Issues.

يمكن للـ Unlabeled Corpus أن تعلّم الـ Model شكل Domain Language الخاص بك:

- Technical Terminology،
- Code Snippets،
- Framework Names،
- Issue-report Style،
- الصياغة الخاصة بالمجال (Domain-specific Phrasing).

تم Pretraining لـ BERT على General-purpose Corpora، وليس خصيصًا على GitHub Issue Text.

بدلًا من تدريب Language Model من الصفر، يمكننا متابعة Language-model Training على Target-domain Corpus.

هذا هو Domain Adaptation.

```text

        ↓

        ↓
Domain-adapted BERT
        ↓
```

## 16. طريقة متقدمة: Unsupervised Data Augmentation (UDA)

تستخدم UDA كلًا من Labeled Examples وUnlabeled Examples.

الافتراض المركزي هو:

> Perturbation صغيرة تحافظ على المعنى لمثال غير موسوم لا ينبغي أن تغيّر Prediction الخاصة بالـ Model بصورة جذرية.

تجمع Training Objective بين:

1. Ordinary Supervised Loss على Labeled Examples،
2. Consistency Loss على Unlabeled Examples وAugmented Variants الخاصة بها.

مفاهيميًا:

```text
نص غير موسوم (Unlabeled Text) ───────────────► Model ─► التوزيع A (Distribution A)
      │
      └─ Augmentation ────────► Model ─► التوزيع B (Distribution B)

                  تقليل الفرق بين A وB (Minimize Difference(A, B))
```

يصف الفصل KL Divergence باعتبارها الأداة المستخدمة لفرض Prediction Consistency.

[[IMAGE_NEEDED: Unsupervised data augmentation consistency training | One unlabeled example branches into original and augmented text; both enter the same model and their output distributions are connected by a consistency/KL loss, alongside a normal supervised loss from labeled examples | Learner should notice that UDA extracts a training signal from unlabeled text without inventing hard labels for every example]]

قد تعمل UDA جيدًا جدًا مع Labels قليلة، لكنها تحتاج إلى Augmentation Pipeline وForward Passes إضافية، لذلك تكون عملية التدريب أعلى تكلفة.

## 17. طريقة متقدمة: Uncertainty-aware Self-training (UST)

تستخدم UST أسلوب Teacher-Student.

### الخطوة 1

درّب Teacher على Labeled Data.

### الخطوة 2

استخدم Teacher لإنشاء Pseudo-labels لـ Unlabeled Examples.

### الخطوة 3

درّب Student باستخدام هذه Pseudo-labeled Examples.

### الخطوة 4

رقّ Student المدرّبة لتصبح Teacher الجديدة، ثم كرر العملية.

الميزة الخاصة في UST هي أنها تقدّر Uncertainty.

يتم تمرير المثال نفسه عبر الـ Model عدة مرات مع Dropout مفعّلة. إذا اختلفت Predictions كثيرًا، فهذا يعني أن الـ Model غير واثقة. وإذا بقيت مستقرة، تكون Confidence أقوى.

يصف الفصل استخدام Uncertainty Signal هذه مع BALD لتحديد أي Pseudo-labeled Samples أكثر فائدة.

[[IMAGE_NEEDED: Uncertainty-aware self-training loop | Labeled data trains a teacher; the teacher predicts pseudo-labels with uncertainty estimation on unlabeled data; selected pseudo-labeled examples train a student; the student becomes the next teacher and the loop repeats | Learner should notice both the iterative teacher-student cycle and the role of uncertainty in selecting pseudo-labels]]

يذكر الفصل أن هذه العائلة من الأساليب قد تقترب من أداء Models تم تدريبها على Labeled Examples أكثر بكثير، لكنها أعقد بدرجة كبيرة من Ordinary Domain Adaptation.

| الحالة | Methods جيدة للاختبار مبكرًا |
|---|---|
| لا توجد Task Labels | خط أساس Zero-shot NLI / Prompt-based |
| Labels قليلة جدًا | خط أساس مع Augmentation وEmbeddings وأساليب Few-shot |
| عشرات/مئات Labels | قارن Simple Models مع Vanilla Transformer Fine-tuning |
| Labels قليلة + كمية كبيرة من Unlabeled Domain Text | تدريب MLM التكيّفي مع المجال (Domain-adaptive MLM Training) |
| تحتاج إلى استغلال Unlabeled Data بصورة أكبر | UDA أو UST |

وهناك عوامل أخرى مهمة أيضًا:

- Label Noise،
- Domain Similarity مع الـ Pretrained Model،
- Class Imbalance،
- Compute Budget،
- Annotation Cost،
- Engineering Complexity.

التوصية العملية للفصل هي بناء Evaluation Pipeline والتجربة بسرعة.

أحيانًا يكون وسم بضع مئات من High-quality Examples أقل تكلفة وأكثر موثوقية من تنفيذ Semi-supervised Training Method شديدة التعقيد.

## مفاهيم خاطئة مهمة

### المفهوم الخاطئ 1: عدم وجود Training Labels يعني أن Machine Learning مستحيلة

> إذا لم نتمكن من Fine-tuning لـ Classifier، فلا توجد أي طريقة مفيدة يمكن تجربتها.

### لماذا هذا خطأ

يمكن لـ Pretrained Models دعم Zero-shot Classification وSemantic Embedding Lookup وأشكال أخرى من Transfer من دون Task-specific Parameter Updates.

### المفهوم الخاطئ 2: ينبغي تجربة Models المعقدة قبل Simple Baselines

> Transformer هي دائمًا نقطة بداية أفضل من Naive Bayes.

### لماذا هذا خطأ

Simple Baseline سريعة، ومفيدة في Debugging، وقد تحل المهمة بصورة جيدة بالفعل.

### المفهوم الخاطئ 3: Zero-shot Performance تعني أننا لا نحتاج أبدًا إلى أي Labeled Examples

> إذا كانت Zero-shot Pipeline تعمل، فلا نحتاج إلى Labeled Data إطلاقًا.

### لماذا هذا خطأ

قد لا تحتاج Model Parameters إلى Labeled Task Training، لكن Small Labeled Validation/Test Set تظل شديدة الفائدة للحكم على نجاح الـ Method وضبط Thresholds أو Prompt Wording.

### المفهوم الخاطئ 4: Data Augmentation تحافظ دائمًا على المعنى

> التغيير العشوائي للكلمات ينتج Training Data إضافية آمنة.

### لماذا هذا خطأ

يمكن لمعنى النص أن يتغير بعد Perturbations صغيرة جدًا. لذلك ينبغي اختبار Augmentation Policies حسب المهمة ونمط الـ Input.

### المفهوم الخاطئ 5: Unlabeled Data ليس لها قيمة في Supervised Classification

> الأمثلة التي تحمل Labels فقط هي التي يمكنها تحسين Classifier.

### لماذا هذا خطأ

يمكن لـ Unlabeled Domain Text تحسين Language Representation من خلال Domain Adaptation، كما يمكنها دعم Semi-supervised Methods مثل UDA وUST.

## المصطلحات الرئيسية

| المصطلح | المعنى |
|---|---|
| بيئة قليلة الموارد أو قليلة التسميات (Low-resource / Low-label Setting) | مهمة تحتوي على Training Data موسومة قليلة |
| Multilabel Classification | يمكن للمثال أن ينتمي إلى عدة Classes في الوقت نفسه |
| المتجه متعدد التفعيل (Multi-hot Vector) | Binary Vector توضح أي Labels موجودة |
| Micro F1 | F1 تُحسب عالميًا عبر القرارات وتتأثر أكثر بالـ Frequent Labels |
| Macro F1 | متوسط F1 لكل Label، ويعطي كل Label الوزن نفسه |
| التصنيف بلا أمثلة (Zero-shot Classification) | تطبيق Pretrained Model على مهمة جديدة من دون Task-specific Fine-tuning |
| NLI | Natural Language Inference: Entailment أو Neutral أو Contradiction بين Premise وHypothesis |
| Hypothesis Template | Natural-language Pattern تُستخدم للتعبير عن Candidate Labels في Zero-shot NLI |
| Data Augmentation | إنشاء Training Examples معدلة يُفترض أن تحافظ على Labels |
| Back Translation | الترجمة إلى لغة أخرى ثم العودة إلى Source Language |
| Embedding Lookup | التصنيف باسترجاع Similar Labeled Examples داخل Vector Space |
| Mean Pooling | أخذ Average لـ Token Embeddings لإنتاج Sequence Embedding واحدة |
| FAISS | مكتبة للبحث الفعال بالتشابه بين Dense Vectors |
| In-context Learning | استنتاج المهمة من Instructions/Examples داخل Prompt من دون تحديث Weights |
| Domain Adaptation | متابعة تدريب Pretrained Model على Target-domain Data |
| MLM | Masked Language Modeling؛ التنبؤ بـ Intentionally Masked Tokens |
| Pseudo-label | Label تولدها Model لمثال غير موسوم |
| UDA | Unsupervised Data Augmentation باستخدام Consistency Training |
| UST | Uncertainty-aware Self-training باستخدام Teacher/Student Pseudo-labeling |
| BALD | Uncertainty-based Sampling Method مستخدمة في وصف UST |

7. كيف تستطيع Embeddings تصنيف Text جديدة من دون Fine-tuning للـ Model؟
8. ما المشكلة التي تحلها FAISS؟
9. لماذا يمكن أن يكون Vanilla Transformer Fine-tuning غير مستقر مع عدد قليل جدًا من الأمثلة؟
10. ماذا تتعلم Domain-adaptive MLM Training من Unlabeled Text؟
11. ما Consistency Assumption التي تعتمد عليها UDA؟
12. كيف تستخدم UST الـ Uncertainty عند إنشاء Pseudo-labels؟
