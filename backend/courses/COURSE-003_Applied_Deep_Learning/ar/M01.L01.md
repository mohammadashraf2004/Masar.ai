## 1. ما هو Deep Learning فعلًا

الذكاء الاصطناعي مصطلح واسع لأنظمة حاسوبية تؤدي مهامًا تتطلب عادةً قدرات نربطها بالذكاء البشري. وDeep Learning نهج مهم واحد داخل هذا الميدان الأكبر.

ونموذج ذهني مفيد للمبتدئ هو:

> **يدرّب Deep Learning دوال رياضية كبيرة لتربط المُدخَلات بمخرَجات مفيدة عبر التعلّم من الأمثلة.**

والعبارة المهمة هي **التعلّم من الأمثلة**. فبدلًا من أن يكتب مبرمج كل قاعدة لازمة للتعرّف على صورة أو توليد نص أو تحويل كلام، يضبط نظام Deep Learning معاملات عددية داخلية بحيث تطابق مخرَجاته تدريجيًا السلوك المرغوب الذي تعرضه بيانات التدريب.

وهذا **لا** يتطلب منا أن ندّعي أن الآلة تفكّر مثل الشخص. فالإنجاز العملي أن الشبكات العصبية تستطيع تقريب علاقات لاخطية معقدة بصورة كافية لأتمتة مهام كان برمجتها يدويًا صعبًا للغاية في السابق.

### أمثلة على الربط بين المُدخَل والمخرَج

| المُدخَل | المخرَج المرغوب |
|---|---|
| صورة فوتوغرافية | الشيء أو الفئة الموجودة في الصورة |
| وصف نصي | صورة مولَّدة |
| نص مكتوب | كلام يبدو طبيعيًا |
| prompt | نص مولَّد |

وتبدو هذه التطبيقات مختلفة جدًا، لكن الفكرة المشتركة واحدة: تعلّم ربط مفيد من الأمثلة بدلًا من ترميز كل قرار بوصفه قاعدة مكتوبة يدويًا.

وهناك تفصيل آخر مهم مبكرًا: يمكن للـ models التوليدية إنتاج مخرَجات بصورة احتمالية. وهذا يعني أن الطلب العام نفسه قد لا ينتج النتيجة نفسها تمامًا في كل مرة.

## 2. من هندسة الـ features إلى تعلّم التمثيلات

لفهم لماذا غيّر Deep Learning ممارسة تعلّم الآلة، افهم أولًا **الـ features**.

**الـ feature الخام (raw feature)** قيمة مأخوذة مباشرةً من البيانات الأصلية. ففي الصورة، قد تكون الـ features الخام مجرد قيم البكسلات. وغالبًا لا تكشف القيم الخام النمط المفيد بوضوح كافٍ لخوارزمية تعلّم تقليدية.

### تعلّم الآلة التقليدي: هندس features مفيدة

في كثير من مسارات عمل تعلّم الآلة التقليدية، يستخدم الإنسان معرفة المجال لتصميم تحويلات تجعل المهمة أسهل. وهذا يُسمّى **هندسة الـ features (feature engineering)**.

لنفترض أننا نريد التمييز بين الرقم `0` المكتوب بخط اليد والرقم `1` المكتوب بخط اليد. قد يصمّم مسار عمل تقليدي features مثل:

- اتجاهات الحواف المهمة،
- وجود ثقوب مغلقة،
- إحصاءات الشكل التي تساعد على فصل رقم عن آخر.

ثم يتعلّم المصنِّف من تلك القياسات المهندسة بدلًا من الصورة الأصلية مباشرةً.

### Deep Learning: تعلّم التمثيل أيضًا

يقلّل Deep Learning الحاجة إلى ابتكار كل تلك الـ features الوسيطة يدويًا. فتستطيع الشبكة العصبية تعلّم تمثيلات داخلية مفيدة مباشرةً من أمثلة التدريب. وأثناء التدريب، تغيّر الشبكة معاملاتها الداخلية بحيث تصبح التمثيلات التي تبنيها أنفع للمهمة.

وهذا يُسمّى غالبًا **تعلّم التمثيلات (representation learning)**.

ويمكن تلخيص التحول هكذا:

```text
ML التقليدي (Traditional ML):
البيانات الخام -> features مصمَّمة بشريًا -> خوارزمية التعلّم -> التنبؤ

Deep Learning:
البيانات الخام -> تسلسل هرمي متعلَّم من التمثيلات -> التنبؤ
```

ولا يجعل Deep Learning معرفة المجال عديمة الفائدة. فما زلنا قد نتخذ خيارات بشأن تجهيز البيانات أو بنية الـ model أو الأهداف أو القيود. والتغيير المهم أن الـ model يستطيع تعلّم كثير من التمثيلات الخاصة بالمهمة تلقائيًا.

[[IMAGE_NEEDED: Feature engineering versus representation learning | A two-part diagram comparing a traditional ML pipeline where a practitioner manually creates features before a learning algorithm with a deep-learning pipeline where raw data enters a neural network that learns hierarchical features automatically during training | Learner should notice that deep learning reduces manual feature design but typically increases dependence on data, training, and computation]]

والمفاضلة العملية مهمة: فغالبًا يستبدل Deep Learning بعضًا من جهد هندسة الـ features اليدوية بمتطلبات أكبر من **البيانات** و**الحوسبة** و**التحسين**.

## 3. النموذج الذهني للتدريب: الـ model والخسارة والتحسين

تبدأ الشبكة العصبية العميقة دالة رياضية لم تصبح معاملاتها مفيدة للمهمة بعد. والتدريب هو العملية التي تحوّل هذه الدالة غير المدرَّبة إلى model مفيد.

ويمكنك فهم الحلقة الأساسية بأربع أفكار:

1. تُمرَّر **بيانات المُدخَل** عبر الـ model.
2. ينتج الـ model **مخرَجًا**.
3. تقارن **دالة الخسارة** ذلك المخرَج بالهدف المرغوب وتنتج عددًا.
4. يحدّث التدريب معاملات الـ model في اتجاه يُراد به تقليل تلك الخسارة.

وقد تُسمّى دالة الخسارة أيضًا **المعيار (criterion)** أو **دالة الهدف (objective function)** أو **دالة الكلفة (cost function)**. وفي Deep Learning التمهيدي، تشير كل هذه الأسماء إلى الإشارة العددية المستخدمة لقياس مدى بُعد سلوك الـ model عمّا نريد.

### مثال عددي صغير

تخيّل أن model ينبغي أن يُخرج `10`، لكنه يُخرج حاليًا `7`.

```text
المخرَج المطلوب = 10
مخرَج الـ model  = 7
الفرق           = 3
```

وقد تقيس دالة خسارة حقيقية الخطأ بطريقة مختلفة، لكن الغرض هو نفسه: تحويل جودة الـ model إلى قيمة عددية يستطيع التدريب محاولة تحسينها.

والهدف **ليس** مجرد خفض الخسارة على أمثلة رآها الـ model بالفعل أثناء التدريب. فينبغي أن يؤدي الـ model المفيد أداءً جيدًا أيضًا على بيانات ذات صلة لم يرها أثناء تحديث معاملاته. وهذه أول لمحة عن فكرة **التعميم (generalization)**.

ولذلك فنموذج ذهني موجز هو:

```text
تنبّأ -> قِس الخطأ -> حدّث المعاملات -> كرّر
```

## 4. لماذا PyTorch مناسبة لـ Deep Learning

PyTorch مكتبة Python مصمَّمة لجعل الحوسبة العددية وDeep Learning عمليين. ويؤكد فصل المصدر عدة أسباب تجعلها تعمل جيدًا بوصفها أول framework لـ Deep Learning.

### 4.1 تبدو مثل Python

صُمّمت PyTorch لتكون تعبيرية ومألوفة لمبرمجي Python. ويمكنك بناء الحسابات تدريجيًا، وفحص القيم الوسيطة، وتنقيح الكود باستخدام مسارات عمل Python العادية. وإذا كنت تعرف NumPy، فستبدو لك مفاهيم tensors كثيرة مألوفة.

### 4.2 تستطيع استخدام GPUs

يتطلب Deep Learning كميات كبيرة من الحوسبة العددية. وتستطيع PyTorch تنفيذ كثير من عمليات الـ tensors على GPUs المصمَّمة لأحمال عددية متوازية ضخمة. وهذا يمكن أن يقلّل وقت التدريب تقليلًا كبيرًا مقارنةً بتنفيذ الحمل الكبير نفسه على CPU فقط.

### 4.3 تدعم التحسين التلقائي

تتتبّع PyTorch العمليات العددية وتستطيع حساب المشتقات اللازمة أثناء التحسين تلقائيًا. وهذا ما يتيح تدريب شبكات عصبية معقدة دون أن تشتق وتكتب يدويًا كل حساب للتدرّج.

### 4.4 تتوسع إلى ما بعد التجارب

لا يقتصر الـ framework على تجارب الـ notebook. فيصف الفصل دعم PyTorch لـ deployment في الإنتاج وبيئات تشغيل C++ وتعدد الأجهزة والتدريب الموزَّع والتجميع وتصدير الـ models والـ deployment على الأجهزة المحمولة أو الطرفية.

### 4.5 المنظومة أوسع من framework واحد

تغيّرت منظومة Deep Learning بمرور الوقت. ويناقش الفصل أدوات أقدم مثل Theano والدور المستمر لـ TensorFlow وصعود JAX وHugging Face بوصفه منظومة عالية المستوى لـ models مدرَّبة مسبقًا. والنقطة التعليمية ليست حفظ جدول زمني لشعبية الـ frameworks. بل فهم أن **الـ frameworks تتطور بينما تنتقل مفاهيم Deep Learning الأساسية**.

## 5. الأساسان اللذان ينبغي أن تتعرّف عليهما فورًا: tensors وautograd

يبدأ معظم PyTorch العملي بمفهومين: **tensors** و**الاشتقاق التلقائي**.

### 5.2 Autograd

حين تنفّذ PyTorch عمليات رياضية على tensors مشاركة في حساب قابل للتعلّم، تستطيع الاحتفاظ بسجل العمليات. ويستخدم محرك الاشتقاق التلقائي لديها، **autograd**، ذلك السجل لتحديد كيف ستؤثر تغييرات سابقة في الحساب في المخرَجات اللاحقة.

وهذه المعلومات ضرورية للتحسين: فهي تخبر التدريب كيف ينبغي ضبط معاملات الـ model لتقليل الخسارة.

```text
tensors -> حساب الـ model -> الخسارة
                         |
                         v
                 تدرّجات autograd
                         |
                         v
                 تحديثات المعاملات
```

## 6. تشريح مشروع Deep Learning بـ PyTorch

المشروع الناجح أكبر من الشبكة العصبية نفسها. ويعرض الفصل مسار عمل عالي المستوى يتضمن تحميل البيانات وبناء الـ model والتدريب والـ deployment.

[[IMAGE_NEEDED: High-level PyTorch project workflow | A left-to-right pipeline showing raw data or storage, Dataset conversion to tensors, DataLoader batching, an untrained model, the training loop with loss and optimizer, a trained model, and deployment; include optional multi-GPU or multi-machine training beneath the training stage | Learner should notice that the neural network is only one component in a complete deep learning system]]

لنتتبّع الـ pipeline.

### 6.1 أدخل البيانات في شكل tensors باستخدام `Dataset`

قد تبدأ البيانات الحقيقية صورًا أو ملفات أو سجلات أو صيغة أخرى خاصة بالمسألة. وتحتاج models PyTorch في النهاية إلى tensors. ويوفّر المفهوم المجرَّد `Dataset` من `torch.utils.data` جسرًا بين البيانات المخزَّنة المخصصة وعيّنات tensors التي يستخدمها نظام التعلّم.

وغالبًا تنفّذ بنفسك الجزء الخاص بالمسألة لأن قراءة فحص طبي أو صورة فوتوغرافية أو dataset آخر قد تتطلب منطقًا مختلفًا جدًا.

### 6.2 غذِّ البيانات بكفاءة باستخدام `DataLoader`

يعالج التدريب عادةً عيّنات متعددة مرارًا. ويساعد `DataLoader` على تنظيم العيّنات في دفعات ويمكنه تحميل البيانات بالتوازي بحيث تقضي حلقة التدريب وقتًا أقل في انتظار عمليات التخزين.

### 6.3 ابنِ الـ model باستخدام `torch.nn`

توفّر PyTorch لبنات الشبكات العصبية الشائعة عبر `torch.nn`، ومنها الطبقات ودوال التنشيط ودوال الخسارة. وتُستخدم هذه المكونات لتعريف الدالة الرياضية التي ستصبح الـ model المدرَّب.

### 6.4 شغّل حلقة التدريب

على مستوى عالٍ، تكرر الحلقة التسلسل نفسه:

```text
لكل دفعة:
    1. شغّل الـ model على المُدخَلات
    2. قارن المخرَجات بالأهداف باستخدام دالة خسارة
    3. احسب التدرّجات باستخدام autograd
    4. دع المُحسِّن يحدّث معاملات الـ model
```

وتُوفَّر مُحسِّنات PyTorch عبر `torch.optim`.

### 6.5 وسّع حين تتطلب المسألة ذلك

قد يتدرّب مشروع أساسي على CPU أو GPU واحدة. ويمكن للمشاريع الأكبر توزيع التدريب عبر عدة GPUs أو عدة آلات. ويشير الفصل إلى `torch.distributed` بوصفه مجال PyTorch المستخدم لهذا النوع من التوسيع.

### 6.6 انشر الـ model المدرَّب

لا يكون الـ model المدرَّب مفيدًا إلا حين يستطيع أداء المهمة حيث تلزم. وقد يعني الـ deployment تشغيله على خادم أو دمجه في تطبيق أكبر أو تصديره لبيئة تشغيل أخرى أو استهداف عتاد محمول أو طرفي.

ويقدّم الفصل أيضًا عدة أدوات للـ deployment والأداء على مستوى عالٍ:

- `torch.compile` لتحسين تنفيذ PyTorch،
- تصدير ONNX لتمثيل model قابل للتشغيل البيني،
- ExecuTorch لسيناريوهات الأجهزة المحمولة والطرفية المدعومة.

## 7. العتاد والبرمجيات: ما الذي تحتاجه فعلًا

خطأ شائع لدى المبتدئين افتراض أن Deep Learning لا يمكن تعلّمه دون GPU باهظة. ويضع الفصل تمييزًا أكثر عملية.

### CPU تكفي لكثير من مهام التعلّم

يستطيع حاسوب محمول أو مكتبي حديث تشغيل شبكات مدرَّبة مسبقًا وكثير من الأمثلة التمهيدية. ويمكنك تعلّم الجزء الأول من مقرر PyTorch وفحص tensors وتجريب كود الـ model وإجراء حسابات أصغر دون عتاد متخصص.

### تهم GPUs حين يصبح التدريب ثقيلًا

ينفّذ التدريب عمليات عددية كبيرة مرارًا. وفي الشبكات والـ datasets الأكبر، يمكن لـ GPU تدعم CUDA أن تقلّل وقت التدريب تقليلًا كبيرًا. وقد تستخدم أحمال العمل الأكثر تقدمًا عدة GPUs أو موارد حوسبة سحابية.

وتفترض الأمثلة العملية اللاحقة في فصل المصدر عتاد GPU أقوى لجولات التدريب الكاملة، لكن الدرس الأوسع أنفع من رقم طراز GPU معيّن:

> **اختر العتاد بحسب حجم حمل العمل، لا بحسب عبارة 'deep learning'.**

### قد يصبح التخزين قيدًا هندسيًا حقيقيًا

قد تتطلب المشاريع الكبيرة سعة قرص كبيرة للبيانات الخام والبيانات المستخرجة وملفات التدريب المخزَّنة مؤقتًا. ويعطي فصل المصدر مثال مشروع تفوق متطلبات تخزينه بكثير كود الـ model. وهذا تذكير بأن هندسة تعلّم الآلة تشمل تخطيط البيانات والبنية التحتية، لا الشبكات العصبية فقط.

### أنظمة التشغيل

تستطيع PyTorch العمل على Linux وmacOS وWindows. وتختلف أوامر التثبيت الدقيقة بحسب المنصة والبيئة، ولذلك ينبغي أن يتبع التثبيت تعليمات PyTorch الرسمية المناسبة للجهاز المستخدم.

## مغالطات مهمة

### المغالطة 1: يعني Deep Learning أن الحاسوب يفكّر مثل الإنسان

> الشبكة العصبية التي تؤدي مهمة متطورة لا بد أن تمتلك فهمًا شبيهًا بفهم الإنسان.

### لماذا هذا خطأ

يصوغ الفصل Deep Learning بحذر أكبر: فهو يعطينا خوارزميات قوية لتقريب علاقات معقدة من الأمثلة. ولا يثبت الأداء القوي في مهمة وحده وجود وعي ذاتي أو تفكير شبيه بالبشر.

### المغالطة 2: يلغي Deep Learning الحاجة إلى كل معرفة بشرية

> إذا كانت الشبكة تتعلّم الـ features تلقائيًا، فلم يعد الممارس بحاجة إلى اتخاذ قرارات هندسية ذات معنى.

### لماذا هذا خطأ

يقلّل تعلّم التمثيلات الحاجة إلى بعض هندسة الـ features اليدوية، لكن الناس ما زالوا يتخذون قرارات بشأن البيانات والأهداف ومعمار الـ model والـ evaluation والعتاد والتدريب والـ deployment.

### المغالطة 3: لا بد من GPU قبل أن أبدأ تعلّم PyTorch

> بدون GPU تدعم CUDA، لا جدوى من بدء Deep Learning.

### لماذا هذا خطأ

يمكن تشغيل كثير من التجارب التمهيدية ومسارات عمل الـ models المدرَّبة مسبقًا على CPU عادية. وتصبح GPUs ذات قيمة خاصة مع نمو أحمال التدريب.

## المصطلحات الرئيسية

| المصطلح | المعنى |
|---|---|
| Artificial intelligence (AI) | مجال واسع لبناء أنظمة تؤدي مهامًا مرتبطة بالسلوك الذكي. |
| Deep learning | نهج تعلّم قائم على تدريب شبكات عصبية عميقة من الأمثلة. |
| Raw feature | قيمة مأخوذة مباشرةً من بيانات المُدخَل الأصلية. |
| Feature engineering | تحويل يصممه الإنسان للبيانات الخام إلى قياسات أنفع. |
| Representation learning | تعلّم features داخلية مفيدة من البيانات تلقائيًا. |
| Neural network | دالة رياضية ذات معاملات تُستخدم لربط المُدخَلات بالمخرَجات. |
| Loss function | مقياس عددي يقارن مخرَجات الـ model بالأهداف المرغوبة. |
| Training | عملية متكررة لضبط معاملات الـ model لتقليل هدف التعلّم. |
| Generalization | قدرة model مدرَّب على الأداء الجيد على بيانات ذات صلة لم يرها. |
| Tensor | المصفوفة العددية متعددة الأبعاد في PyTorch. |
| Autograd | محرك PyTorch الذي يحسب تلقائيًا المشتقات اللازمة للتحسين. |
| `torch.nn` | وحدة PyTorch التي تحتوي مكونات الشبكات العصبية الشائعة ودوال الخسارة. |
| `torch.optim` | وحدة PyTorch التي توفّر المُحسِّنات التي تحدّث المعاملات أثناء التدريب. |
| `Dataset` | مفهوم مجرَّد يربط البيانات الخاصة بالمسألة بعيّنات يمكن لـ PyTorch استخدامها. |
| `DataLoader` | أداة لتجميع العيّنات في دفعات وتحميلها بكفاءة من dataset. |
| Eager execution | تُنفَّذ العمليات أثناء تشغيل تعليمات Python بدلًا من تأجيلها بوصفها رسمًا بيانيًا منفصلًا مبنيًا مسبقًا. |
| CUDA | منصة حوسبة NVIDIA التي تستخدمها PyTorch عادةً لتسريع GPU. |
| Jupyter kernel | عملية قيد التشغيل تنفّذ كود الـ notebook وتحتفظ بحالته في memory. |
