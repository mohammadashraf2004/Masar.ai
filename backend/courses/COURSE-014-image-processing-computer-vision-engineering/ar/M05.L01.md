## 1. الالتفاف: عملية واحدة لمهام كثيرة في معالجة الصور (Convolution)

يُعد Convolution من أكثر العمليات القابلة لإعادة الاستخدام في Image Processing.

يتكوّن الإعداد الأساسي من:

- **صورة دخل (input image)**،
- مصفوفة صغيرة تسمى **Kernel** أو **Filter** أو أحيانًا **Mask**،
- **صورة خرج (output image)**.

عند كل موضع، تُوضَع Kernel فوق جوار محلي من Pixels. تُضرَب القيم المتناظرة في Kernel والصورة، ثم تُجمع النواتج لإنتاج قيمة خرج جديدة.

يبدو مثال مبسط بحجم 3×3 كما يلي:

```text
جوار الصورة (image neighborhood)        النواة (kernel)

[a b c]                  [k1 k2 k3]
[d e f]        ×         [k4 k5 k6]
[g h i]                  [k7 k8 k9]

الخرج (output) =
a*k1 + b*k2 + c*k3 + — الجزء الأول من المجموع الموزون
d*k4 + e*k5 + f*k6 + — الجزء الثاني من المجموع الموزون
g*k7 + h*k8 + i*k9 — الجزء الثالث من المجموع الموزون
```

ثم تتحرك Kernel إلى الموضع المكاني التالي.

### لماذا يُعد Convolution قويًا؟

يمكن للعملية نفسها إنشاء تأثيرات مختلفة جدًا بمجرد تغيير Kernel.

أمثلة:

- حساب متوسط القيم المجاورة → Smoothing،
- إبراز المركز بالنسبة إلى الجيران → Sharpening،
- قياس التغيّرات الاتجاهية → Edge detection،
- استخدام أوزان غير متناظرة → Embossing.

ولهذا يظهر Convolution في مجالات كثيرة، منها:

- مجال Classical image processing،
- مجال Computer vision،
- مجال Signal processing،
- شبكات Convolutional neural networks.

## 2. الالتفاف في المجال المكاني (Spatial-domain convolution)

يعمل Spatial-domain convolution مباشرة على Pixels الصورة.

عند كل موضع خرج:

1. ضع Kernel فوق الجوار المطلوب،
2. اضرب أوزان Kernel في قيم Pixels،
3. اجمع النواتج،
4. اكتب النتيجة،
5. حرّك Kernel إلى الموضع التالي.

### التكلفة الحسابية (Computational cost)

بالنسبة إلى صورة تحتوي على عدد كبير من Pixels و Kernel بحجم `K × K`، يحتاج كل موضع خرج تقريبًا إلى `K²` من عمليات الضرب/الجمع.

يكون ذلك مناسبًا مع Kernels صغيرة مثل:

```text
3×3
5×5
```

لكنه يصبح مكلفًا عندما يكبر حجم Kernel.

ولهذا يُفضّل Direct spatial convolution غالبًا مع Filters المحلية الصغيرة، بينما قد تستفيد Filters الكبيرة من الأساليب المعتمدة على FFT.

لماذا؟


## 3. أوضاع الخرج والتعامل مع الحدود (Output modes and boundary handling)

تصل Kernel في النهاية إلى حدود الصورة.

وعند الحدود، قد يقع جزء من Kernel خارج الصورة المتاحة.

لذلك يحتاج تنفيذ Convolution إلى قرارين منفصلين:

1. **أي منطقة من الخرج نحتفظ بها؟**
2. **ما القيم التي نفترض وجودها خارج حدود الصورة؟**

### أوضاع Convolution

لنفترض أن حجم الدخل هو:

```text
M × N
```

وأن حجم Kernel هو:

```text
K × L
```

#### وضع `valid`

يعيد فقط المواضع التي تتسع فيها Kernel بالكامل داخل الصورة الأصلية.

ولا يحتاج إلى Boundary padding.

ويصبح الخرج أصغر.

#### وضع `same`

يعيد خرجًا متمركزًا بحيث يملك نفس الحجم المكاني للدخل.

ويكون ذلك مناسبًا عندما نريد موضع خرج يقابل كل Pixel دخل.

#### وضع `full`

يعيد كل موضع تتداخل فيه الصورة و Kernel ولو جزئيًا.

ويصبح الخرج أكبر من الدخل.

[[IMAGE_NEEDED: Full same valid convolution modes | Use a simple 5×5 input grid and 3×3 kernel to show visually which output positions are retained for valid, same, and full modes and how their output dimensions differ | Learner should understand that mode controls output extent, not the kernel itself]]

### شروط الحدود (Boundary conditions)

في الأوضاع التي تحتاج معلومات خارج الحدود، تشمل الخيارات الشائعة ما يلي:

#### قيمة ثابتة / Fill

نفترض أن Pixels خارج الصورة لها قيمة ثابتة، وغالبًا تكون `0`.

```text
... 0 0 | الصورة (image) | 0 0 ...
```

وقد يؤدي ذلك إلى إنشاء حدود داكنة مصطنعة.

#### أسلوب Wrap

نتعامل مع الصورة كما لو كانت دورية:

```text
الحافة اليمنى تتصل بالحافة اليسرى (right edge connects to left edge)
الحافة السفلية تتصل بالحافة العلوية (bottom connects to top)
```

وقد يكون ذلك مناسبًا للبيانات الدورية أو القابلة للتكرار كـ Tiles.

#### أسلوب Symmetric / Reflection

نعكس قيم الصورة قرب الحدود.

وغالبًا ما يوفّر ذلك سلوكًا أكثر سلاسة عند الحواف في الصور العادية.

### لماذا تهم استراتيجية الحدود؟

لنفترض أن Edge detector يرى صورة ساطعة عادية تنتهي عند الحافة.

إذا افترضنا أن Pixels خارج الصورة تساوي `0`، فقد يفسر Algorithm الحدود على أنها انتقال قوي في شدة الإضاءة.

وهذا ينشئ **False edge**.

في كثير من Filters العامة للصور، يقلل Reflection أو Symmetric padding هذه الانتقالات المصطنعة.

## 5. الارتباط مقابل الالتفاف (Correlation versus Convolution)

يقوم كل من Correlation و Convolution بتمرير Kernel أو Template فوق الصورة وحساب مجاميع موزونة.

والفرق المحدِّد بينهما هو:

> **يقلب Convolution الـ Kernel قبل تطبيقها، بينما لا يفعل Correlation ذلك.**

في 2D Kernel، يقلب Convolution الـ Kernel:

- أفقيًا،
- ورأسيًا.

### لماذا قد تبدو النتيجتان متطابقتين؟

إذا كانت Kernel متناظرة، فلن يغيّر قلبها شيئًا.

فعلى سبيل المثال، تبقى Gaussian kernel متناظرة كما هي بعد قلبها 180 درجة.

إذًا:

```text
نتيجة Correlation (correlation result) = نتيجة Convolution (convolution result)
```

بالنسبة إلى Kernel المتناظرة.

أما مع Kernel غير متناظرة، فقد تختلف النتائج.

## 7. الارتباط المتقاطع المطبّع (Normalized cross-correlation — NCC)

يقارن Normalized cross-correlation بين Patterns بعد أخذ Mean و Scale في الحسبان.

الفكرة الأساسية هي:

1. طرح Means المحلية و Mean الـ Template،
2. قياس التغيّر المتوافق،
3. القسمة على Standard deviations.

يمكن تمثيل الفكرة بالشكل التالي:

```text
NCC = — درجة الارتباط المتقاطع المطبّع
تشابه بعد إزالة Mean (zero-mean similarity)
------------------------------
التباين المحلي * تباين Template (local contrast * template contrast)
```

تكون Scores عادة محصورة تقريبًا في:

```text
[-1, 1]
```

حيث:

```text
+1 -> تشابه موجب قوي (strong positive similarity)
 0 -> تشابه خطي ضعيف (weak linear similarity)
-1 -> تشابه عكسي قوي (strong inverse similarity)
```

### لماذا يساعد Normalization؟

تخيّل Pattern نفسه تحت إضاءة مختلفة:

```text
الرقعة A = نسخة داكنة
الرقعة B = نسخة ساطعة
```

تختلف القيم الخام.

لكن البنية بعد Normalization قد تكون متشابهة.

لذلك يكون NCC أكثر تحمّلًا لـ:

- التغيّرات الإضافية في السطوع،
- التغيّرات الضربية في التباين.

لكنه ليس Invariant تجاه كل Transformation، مثل Rotation عشوائي أو اختلافات كبيرة في Scale.

### بنية مخصصة لـ NCC

يبني الفصل NCC اعتمادًا على:

- Template بعد إزالة Mean،
- بسط Correlation،
- Mean المحلي للصورة،
- Standard deviation المحلي للصورة،
- Standard deviation للـ Template.

## 8. مبرهنة الالتفاف والترشيح في المجال الترددي (Convolution theorem)

قدّم الدرس السابق DFT/FFT.

والآن نستخدمه لحساب Convolution.

### مبرهنة Convolution

النتيجة المركزية هي:

```text
Convolution مكاني (spatial convolution)
        ↕ Fourier transform
ضرب ترددي (frequency multiplication)
```

إذا كان:

```text
F = FFT(image) — تحويل الصورة إلى Frequency domain
H = FFT(kernel) — تحويل Kernel إلى Frequency domain
```

فإن:

```text
FFT(image *convolved_with* kernel) — FFT لناتج Convolution
=
F * H — ضرب Element-wise في Frequency domain
```

حيث يكون الضرب في الطرف الأيمن Element-wise.

لذلك يتبع Frequency-domain filtering المسار التالي:

```text
الصورة (image) ----FFT----**\**
                   × ----IFFT---- الصورة المرشحة (filtered image)
Kernel (kernel) ---FFT----/
```

[[IMAGE_NEEDED: Convolution theorem pipeline | Show spatial image and kernel entering separate FFT blocks, element-wise multiplication of their spectra, then IFFT to produce the filtered image; alongside show the equivalent sliding spatial convolution | Learner should understand that spatial convolution and frequency multiplication are two representations of the same linear filtering operation]]

### لماذا نستخدم Frequency domain؟

تزداد تكلفة Direct convolution كلما كبر حجم Kernel.

ويتطلب FFT-based convolution:

1. FFT للصورة،
2. FFT للـ Kernel،
3. تنفيذ Element-wise multiplication،
4. تنفيذ Inverse FFT.

ومع Kernels كبيرة بما يكفي، قد يكون هذا أسرع بدرجة ملحوظة.

أما مع Kernels صغيرة، فقد تجعل تكلفة FFT الإضافية Direct spatial convolution أسرع.

لذلك تكون القاعدة الهندسية:

```text
Kernel صغيرة (small kernel) -> غالبًا يكون Direct spatial convolution فعالًا
Kernel كبيرة (large kernel) -> غالبًا يصبح FFT convolution خيارًا جذابًا
```

كما أن Memory usage و Padding مهمان أيضًا.

### Circular convolution مقابل Linear convolution

يناظر الضرب المباشر باستخدام FFT بطبيعته Circular/periodic convolution ما لم تُجرَ عملية Padding للـ Arrays بصورة مناسبة.

وهذه نقطة مهمة.

ولإعادة إنتاج Linear convolution المطلوب، يجب إيلاء Attention إلى:

- Padding للصورة و Kernel،
- محاذاة Kernel،
- Cropping للخرج.

وتتعامل Functions عالية المستوى مثل `fftconvolve()` مع كثير من هذه التفاصيل نيابة عنك.

## 9. Gaussian blur في المجال الترددي (Frequency domain)

Gaussian kernel هي Smoothing filter.

في Spatial domain، تحسب متوسط المحتوى القريب باستخدام أوزان تقل تدريجيًا مع المسافة.

أما في Frequency domain، فتتصرف Gaussian كـ **Low-pass filter**.

وهذا يعني:

```text
الترددات المنخفضة (low frequencies)  -> تُحافَظ عليها بقوة
الترددات العالية (high frequencies) -> تُخفَّض
```

وهذا يفسر لماذا يقلل Gaussian blur من:

- تفاصيل Fine texture،
- مكوّنات Noise،
- تفاصيل الحواف الحادة.

## 10. الاختيار بين Spatial convolution و FFT convolution

يقارن الفصل بين تطبيقات Spatial و FFT.

والاستنتاج المهم مشروط وليس مطلقًا.

### يميل Spatial convolution إلى العمل جيدًا عندما

- تكون Kernels صغيرة،
- تكون العمليات محلية بدرجة كبيرة،
- تكون تكلفة Transform الإضافية هي الغالبة،
- تستخدم Real-time operators Filters صغيرة وثابتة.

أمثلة:

- مرشح Sobel،
- مرشح Prewitt،
- Kernels صغيرة للـ Sharpening.

### يصبح FFT convolution جذابًا عندما

- تكون Kernels كبيرة،
- تكون الصور كبيرة،
- تتطلب العمليات لولا ذلك جوارات منزلقة كبيرة.

وقد تشمل الأمثلة Kernels كبيرة للـ Smoothing وبعض Restoration workflows.

### اعتبارات Memory

تتطلب أساليب FFT Arrays محوّلة، وغالبًا تكون Complex-valued.

ومع الصور الكبيرة جدًا، قد يصبح استهلاك Memory كبيرًا.

يمكن للطرق المقسمة إلى Blocks مثل:

- طريقة Overlap-add،
- طريقة Overlap-save،
- طريقة Tiled FFT،

معالجة Signals كبيرة على أجزاء.

### نفّذ Benchmark بصورة صحيحة

يجب أن يحافظ Benchmark العادل على ثبات:

- صورة الدخل،
- قيمة Kernel،
- إعداد Output mode،
- نوع Data type،
- بيئة Hardware،
- تأثيرات Warm-up،
- عدد التكرارات.

لا تقارن Functionين تستخدمان قواعد Boundary أو أحجام Output مختلفة ثم تعتبر النتيجة مقارنة عادلة للسرعة.

## 11. الالتفاف ثنائي وثلاثي الأبعاد (2D and 3D convolution)

قد تصبح كلمة "Dimension" مربكة عندما تحتوي الصور أيضًا على Channels.

### الالتفاف ثنائي الأبعاد (2D Convolution)

ينزلق 2D Convolution القياسي عبر:

```text
الارتفاع × العرض
```

وفي Deep-learning libraries، تكون Channels عادة أبعاد Features إضافية تستهلكها Kernel.

تتوقع PyTorch دخل 2D Convolution بالشكل:

```text
N × C × H × W
```

حيث:

- `N` = حجم Batch،
- `C` = عدد Channels،
- `H` = قيمة Height،
- `W` = قيمة Width.

مثال Grayscale:

⟦CODE_21⟧

### الالتفاف ثنائي الأبعاد (2D Convolution) متعدد القنوات

بالنسبة إلى RGB input:

```text
N × 3 × H × W
```

يمكن لـ Filter أن يحتوي على أوزان تمتد عبر قنوات الدخل الثلاث كلها.

وعند موضع مكاني واحد، القيم عبر:

```text
channel × kernel_height × kernel_width — أبعاد Channel وارتفاع Kernel وعرضها
```

تُضرَب هذه القيم وتُجمع.

لكن Kernel تظل **تنزلق عبر بعدين مكانيين**.

وهذا هو التعريف المهم لـ 2D Convolution في CNNs.

### الالتفاف ثلاثي الأبعاد (3D Convolution)

ينزلق 3D Convolution عبر ثلاثة أبعاد مكانية/عمقية.

تتوقع PyTorch الشكل:

```text
N × C × D × H × W
```

حيث يمكن أن يمثل `D`:

- عمق Volume،
- عمق Time/Frames،
- محورًا مكانيًا أو تسلسليًا ثالثًا حقيقيًا.

تشمل التطبيقات الشائعة:

- أحجام CT/MRI،
- مقاطع Video clips،
- بيانات Volumetric scientific data.

[[IMAGE_NEEDED: 2D versus 3D convolution | Show a 2D kernel sliding across H×W while spanning input channels, then a 3D kernel sliding across D×H×W for a volume/video; label channel versus depth axes carefully | Learner should not confuse RGB channels with the third sliding spatial dimension of a true 3D convolution]]

### ملاحظة مهمة

وجود ثلاث Channels في صورة RGB **لا يعني تلقائيًا** أنه ينبغي معالجتها باستخدام `Conv3d`.

تستخدم CNN عادية غالبًا `Conv2d` مع `in_channels=3`.

ويكون 3D Convolution مناسبًا عندما يوجد بُعد ثالث ذو معنى تنزلق عليه Kernel.

## 12. Upsampling مقابل Transposed convolution

يمكن لكلتا العمليتين زيادة Spatial resolution، لكنهما مختلفتان مفاهيميًا.

### Upsampling ثابت

تشمل الأمثلة:

- طريقة Nearest-neighbor interpolation،
- طريقة Bilinear interpolation.

ولا تحتوي هذه الطرق على Trainable parameters.

⟦CODE_22⟧

### Upsampling يتبعه Convolution

هناك Architecture شائعة على النحو التالي:

```text
تغيير حجم ثابت (fixed resize)
    ↓
Conv2d متعلَّم (learned Conv2d)
```

يتحكم Resize في Geometry، بينما يتعلم Convolution معالجة Features.

### الالتفاف المنقول (Transposed convolution)

يستخدم `ConvTranspose2d` Kernels قابلة للتعلم في عملية مصممة لإنتاج Feature map أكبر.

ويُستخدم غالبًا في:

- وحدات Autoencoder decoders،
- وحدات Segmentation decoders،
- تطبيقات Generative models،
- بنى Learned super-resolution architectures.

ولا ينبغي اعتباره ببساطة "المعكوس الرياضي لـ Convolution".

### تشوهات النمط الشبكي (Checkerboard artifacts)

قد ينتج Transposed convolution أنماط Checkerboard إذا كان تداخل Kernel غير متساوٍ.

ومن وسائل التخفيف العملية المذكورة في الفصل:

- اختيار علاقة Kernel/Stride بعناية،
- أو استخدام Explicit upsampling يتبعه Ordinary convolution.

## مفاهيم خاطئة مهمة (Important misconceptions)

### المفهوم الخاطئ 1

> تحدد Kernel فقط حجم الجوار المحلي.

### لماذا هذا خطأ؟

تحدد **أوزان Kernel** النمط المكاني الذي يبرزه Filter أو يخفّضه. ويمكن لـ Kernelين بحجم 3×3 إنتاج Outputs مختلفة تمامًا.

### المفهوم الخاطئ 2

> تصف `same` و `valid` و `full` أنواعًا مختلفة من Filters.

### لماذا هذا خطأ؟

إنها تصف **امتداد الخرج** في Convolution. ويمكن أن تبقى Kernel نفسها دون تغيير.

### المفهوم الخاطئ 3

> يمكن دائمًا استخدام Convolution و Correlation بالتبادل.

### لماذا هذا خطأ؟

يقلب Convolution الـ Kernel، بينما لا يفعل Correlation ذلك. ولا تتطابق النتيجتان تلقائيًا إلا مع Kernels لا تتغير عند قلبها، مثل Kernels المتناظرة.

### المفهوم الخاطئ 4

> FFT convolution أسرع دائمًا.

### لماذا هذا خطأ؟

لإعداد FFT تكلفة حسابية وتكلفة Memory. وغالبًا ما يكون Direct convolution أسرع مع Kernels صغيرة.

### المفهوم الخاطئ 5

> يستطيع Normalized cross-correlation العثور على Template تحت أي Transformation بصري.

### لماذا هذا خطأ؟

يحسن NCC المتانة تجاه Offset/Scale لشدة الإضاءة، لكن التغيّرات الكبيرة في Rotation أو Scale أو Viewpoint أو Deformation أو Occlusion قد تفسد المطابقة.

### المفهوم الخاطئ 6

> تحتاج صورة RGB إلى 3D Convolution لأنها تحتوي على ثلاث Channels.

### لماذا هذا خطأ؟

تعالج CNNs القياسية صور RGB باستخدام 2D Convolution تمتد Filters فيه عبر قنوات الدخل الثلاث، بينما تنزلق مكانيًا فقط عبر Height و Width.

### المفهوم الخاطئ 7

> Transposed convolution هو مجرد Image interpolation عادي.

### لماذا هذا خطأ؟

يستخدم أوزان Convolution قابلة للتعلم لإنتاج Feature maps موسعة، وقد يتصرف بصورة مختلفة جدًا عن Fixed interpolation.

## المصطلحات الأساسية (Key terminology)

| المصطلح | المعنى |
|---|---|
| مصطلح Convolution | تجميع موزون منزلق باستخدام Kernel مقلوبة |
| مصطلح Kernel / Filter | مصفوفة أوزان صغيرة تُطبّق على الجوار المحلي |
| مصطلح Spatial-domain filtering | تطبيق العمليات مباشرة على Samples الصورة |
| مصطلح Frequency-domain filtering | تعديل معاملات Frequency، وغالبًا باستخدام FFTs |
| مصطلح Box blur | Averaging filter بأوزان محلية متساوية |
| مصطلح Laplacian | Operator شبيه بالمشتقة الثانية يبرز تغيّرات شدة الإضاءة |
| مصطلح Sharpening | زيادة الاستجابة للتباين والتفاصيل المحلية |
| مصطلح Emboss | Filter اتجاهي ينشئ مظهرًا شبيهًا بالنقش البارز |
| وضع `valid` | خرج يُنتج فقط حيث تتداخل Kernel بالكامل مع المصدر |
| وضع `same` | خرج يُقتص أو يُمركز ليتطابق مع الأبعاد المكانية للدخل |
| وضع `full` | Convolution كامل يشمل حالات التداخل الجزئي |
| مصطلح Boundary condition | قاعدة تحدد القيم خارج حدود الصورة |
| مصطلح Correlation | تشابه منزلق أو مجموع موزون من دون قلب Kernel |
| مصطلح Cross-correlation | Correlation لمقارنة Template عبر مواضع الصورة |
| مصطلح NCC | يعني Normalized cross-correlation |
| مصطلح Correlation map | صورة Scores للتشابه ناتجة عن Template matching |
| مصطلح Convolution theorem | يقابل Spatial convolution عملية ضرب في Frequency domain |
| مصطلح FFT convolution | Convolution يُحسب عبر FFT → Multiply → IFFT |
| مصطلح Low-pass filter | Filter يحافظ على Low frequencies ويخفّض High frequencies |
| مصطلح Gaussian filter | Low-pass filter ناعم وقابل للفصل يعتمد على Gaussian function |
| مصطلح 2D Convolution | تنزلق Kernel عبر محورين مكانيين |
| مصطلح 3D Convolution | تنزلق Kernel عبر ثلاثة محاور مكانية/عمقية |
| ترتيب NCHW | ترتيب PyTorch: Batch و Channel و Height و Width |
| ترتيب NCDHW | ترتيب PyTorch ثلاثي الأبعاد: Batch و Channel و Depth و Height و Width |
| مصطلح Upsampling | تكبير ثابت لـ Spatial resolution |
| مصطلح Transposed convolution | عملية قابلة للتعلم يمكنها إنتاج Feature maps أكبر |
| مصطلح Checkerboard artifact | Pattern دوري ينتج عن تداخل غير متساوٍ في بعض عمليات Transposed convolution |

## احتفظ بهذه الفكرة (Retain this idea)

**Convolution هو Operator محلي قابل لإعادة الاستخدام لاكتشاف Patterns ومعالجتها. في Spatial domain يبدو كأنه Kernel تنزلق فوق الجوار المحلي، بينما تتحول Linear filtering نفسها في Frequency domain إلى عملية ضرب. يستخدم Correlation آلية مشابهة للمطابقة، وتمتد Deep-learning convolutions بالفكرة الأساسية نفسها عبر Channels و Volumes و Filters المتعلَّمة.**
