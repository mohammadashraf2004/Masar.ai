## 1. Decision Trees: Model مبنية من الأسئلة

تُعد Decision Tree من أسهل Machine-learning models في الفهم لأن طريقة Reasoning الخاصة بها تشبه سلسلة من القرارات البشرية.

تخيل أنك تريد تحديد نوع زهرة Iris باستخدام قياسات Petal. بدل حساب Equation معقدة واحدة، تطرح Tree أسئلة مثل:

```text
هل petal length <= 2.45 cm؟
    نعم -> تنبّأ بـ Iris setosa
    لا  -> هل petal width <= 1.75 cm؟
               نعم -> تنبّأ بـ Iris versicolor
               لا  -> تنبّأ بـ Iris virginica
```

يقسم كل سؤال Set الحالية من Examples إلى مجموعتين. وبتكرار هذه Process يتكون Tree.

المصطلحات المهمة هي:

- **Root node:** أول Node في أعلى Tree.
- **Split/internal node:** Node تطرح سؤالًا ولها Child nodes.
- **Leaf node:** Terminal node تنتج Final prediction.
- **Depth:** عدد Splits التي تفصل Node عن Root.
- **Branch:** مسار واحد ينتج عن إجابة Split question.

{{image:iris-decision-tree-anatomy}}

### لماذا تبدو Trees مختلفة عن Models كثيرة أخرى؟

تجمع Linear model كل Features مرة واحدة داخل Weighted equation. أما Tree فتختار **Feature واحدة في كل مرة** وتسأل هل هي أعلى أمأقل من Threshold.

لهذا نتيجتان مهمتان:

1. تستطيع Model تمثيل Nonlinear decision rules رغم أن كل Split منفردة بسيطة.
2. يمكن غالبًا فحص Final reasoning وشرحه بلغة عادية.

### نحتاج إلى قدر قليل جدًا من Preprocessing

إحدى المزايا المهمة التي يبرزها Chapter هي أن Training المعتاد لـ Decision trees **لا يحتاج** إلى Centering أوStandardization للـ Features.

لماذا؟ لأن Split مثل:

```text
petal width <= 1.75 — شرط التقسيم في هذه العقدة
```

تعتمد فقط على Ordering الخاصة بالـ Values. إذا ضُرب كل Petal width في 100، فإن Useful threshold ستُضرب أيضًا في 100، لكن ترتيب Training examples سيظل نفسه.

يختلف ذلك كثيرًا عن Algorithms مثل Gradient descent أوk-nearest neighbors أوModels المعتمدة على Distance وGeometry، حيث قد يؤثر Feature scale مباشرةً في Optimization أوComparison.

## 2. قراءة Tree: Samples وValues وImpurity وProbability

تخزن Trained tree أكثر من مجرد Split conditions. لفهم ما تعلمته Model، يجب أن تعرف معنى Statistics الشائعة داخل Nodes.

### عدد العينات (`samples`)

تخبرك قيمة `samples` بعدد Training examples التي وصلت إلى Node.

إذا وصلت 100 زهرة إلى Node، فإن كل Statistic معروضة هناك حُسبت من هذه الأمثلة المئة.

### توزيع الفئات (`value`)

بالنسبة إلى Classification tree، تصف `value` عدد Examples من كل Class وصلت إلى Node.

مثلًا:

```text
value = [0, 49, 5] — عدد العينات من كل فئة
```

تعني أن Node تحتوي:

- 0 Examples من Class 0،
- 49 Example من Class 1،
- 5 Examples من Class 2.

تتنبأ Tree عادةً بالـ Class ذات Count الأكبر.

### شوائب Gini (Gini Impurity)

تكون Node **نقية (Pure)** عندما تنتمي كل Examples التي تصل إليها إلى Class نفسها. عندها تكون Gini impurity تساوي `0`.

يمكن كتابة فكرة Gini في Chapter على النحو الآتي:

```text
Gini = 1 - sum(class_probability²) — مقياس عدم النقاء
```

افترض أن Node تحتوي 54 زهرة:

```text
0 من setosa
49 من versicolor
5 من virginica
```

تنتمي معظم Examples إلى Class واحدة، لذلك تكون Impurity منخفضة. وإذا توزعت Classes بصورة أقرب إلى التساوي، تصبح Impurity أعلى.

**النموذج الذهني:** Impurity تسأل: *إلى أي مدى Labels مختلطة داخل هذه Node؟*

### من Leaves إلى Class Probabilities

يمكن لـ Classification tree إرجاع Probabilities إضافةً إلى Hard predictions. فهي ترسل Instance أولًا إلى Leaf، ثم تستخدم Class proportions بين Training examples داخل تلك Leaf.

في Example الخاص بـ Chapter، تنتج Leaf تحتوي `[0, 49, 5]` تقريبًا:

```text
P(setosa)     = 0 / 54  = 0.000 — احتمال كل فئة في العقدة
P(versicolor) = 49 / 54 = 0.907
P(virginica)  = 5 / 54  = 0.093
```

تقطع كل Split مساحة Features باستخدام Threshold. في Problem ذات Featureين، تكوّن هذه Cuts مناطق مستطيلة لأن Splits القياسية للـ Tree تكون Parallel لأحد محوري Features.

## 3. لماذا تُسمى Decision Trees نماذج White-Box؟

تُوصف Decision trees غالبًا بأنها **white-box models** لأن Decisions الخاصة بها يمكن عادةً فحصها مباشرة.

بالنسبة إلى Tree صغيرة، يمكنك شرح Prediction كـ Rule قصيرة:

```text
petal length > 2.45
و (AND) petal width <= 1.75
-> Iris versicolor
```

هذا مفيد عندما يحتاج Human إلى مراجعة Reasoning الخاصة بـ Model.

تشمل Examples المذكورة في Chapter Domains مثل:

- Healthcare، حيث قد يحتاج Clinician إلى فحص Diagnosis.
- Finance، حيث قد يحتاج Analysts إلى فهم Risk decision.
- Judicial settings، حيث يجب أن يحتفظ Humans بالمسؤولية النهائية.
- Human resources، حيث قد تحتاج Decision rules إلى مراجعة Bias غير مرغوب فيه.

وعلى العكس، تكون Large neural networks وEnsembles كثيرة أصعب في اختصارها إلى عدة Rules بسيطة، حتى عندما تكون Predictions الخاصة بها ممتازة.

### Interpretability لها حدود عملية

لا تحول عبارة "Trees قابلة للتفسير" إلى "كل Tree سهلة الفهم".

قد تكون Tree تحتوي مئات أوآلاف Nodes قابلة للفحص تقنيًا لكنها مرهقة عمليًا. وهذا سبب إضافي يجعل الحد من Complexity مفيدًا: يمكن لـ Regularization تحسين **generalization** و**قابلية القراءة البشرية** معًا.

## 4. كيف تنمّي CART شجرة القرار؟

تدرّب Scikit-Learn أشجار القرار باستخدام خوارزمية **Classification and Regression Tree (CART)**.

المشكلة الأساسية عند كل Node هي:

> أي Feature وThreshold ينبغي أن أستخدم لتقسيم هذه Examples إلى مجموعتين أفضل؟

بالنسبة إلى Classification، تفحص CART أزواج Feature-threshold المرشحة وتفضل Split تنتج Child nodes ذات Impurity منخفضة، مع أخذ أحجامها في الاعتبار.

نموذج ذهني مبسط:

```text
لكل feature مرشحة:
    لكل threshold مرشحة:
        قسّم العقدة إلى مجموعتين يسرى ويمنى
        قِس عدم النقاء الموزون بعد التقسيم
اختر التقسيم صاحب أقل تكلفة
كرّر العملية تكراريًا على العقد الأبناء
```

### CART تنشئ Binary Trees

ينشئ Implementation الخاص بـ CART في Scikit-Learn **Binary splits**. كل Internal node لها Outcomeان:

```text
feature <= threshold — الفرع الأيسر
```

أو:

```text
feature > threshold — الفرع الأيمن
```

قد تسمح Tree algorithms أخرى بأكثر من Childين، لكن CART تستخدم قرارات Yes/No بصورة متكررة.

### متى يتوقف Recursion؟

قد يتوقف Growth لأن:

- Maximum depth تم الوصول إليها.
- لا يمكن Split للـ Node بطريقة تحسن Objective بدرجة كافية.
- Minimum sample requirement تمنع Split أخرى.
- Maximum leaf limit تم الوصول إليها.
- Rule أخرى من Rules الخاصة بـ Regularization تمنع النمو.

### CART خوارزمية Greedy

هذه من أهم أفكار Chapter.

تختار CART Split جيدة **الآن**. ولا تستكشف كل Future trees الممكنة لتسأل أي First split ستقود لاحقًا إلى أفضل Global structure بعد عدة Levels.

لهذا توصف CART بأنها **greedy algorithm**.

Greedy optimization عملية حسابيًا وتنتج Trees مفيدة عادةً، لكنها لا تضمن الوصول إلى Globally optimal tree.

يشرح Chapter لماذا نحتاج هذا Compromise: البحث عن Optimal tree صعب جدًا حسابيًا عمومًا. لذلك تقبل Tree-training algorithms الواقعية Solution جيدة يمكن العثور عليها فعليًا.

### تكلفة Training مقابل Prediction

بعد Training، تحتاج Prediction إلى تتبع Path واحدة فقط من Root إلى Leaf. في Tree متوازنة تقريبًا، ينمو عدد Nodes المزارة ببطء مع زيادة عدد Training examples، لذلك تكون Prediction سريعة عادةً.

أما Training فهو أكثر تكلفة لأن CART تحتاج إلى تقييم عدد كبير من Split choices أثناء نمو Tree.

## 5. Gini impurity أم Entropy؟

تستخدم `DecisionTreeClassifier` **Gini impurity** افتراضيًا، لكن Scikit-Learn تدعم أيضًا **entropy** بوصفها Split criterion.

تحاول الاثنتان الإجابة عن السؤال نفسه تقريبًا:

> إلى أي مدى Classes مختلطة داخل هذه Node؟

بالنسبة إلى Entropy أيضًا، تمتلك Pure node قيمة Impurity تساوي `0`. يستخدم Example الخاص بـ Chapter Class proportions داخل Node مع Expression معروفة من Information theory تعتمد على `-p log₂(p)`.

### هل يجب أن تقلق بشأن اختيار Criterion المثالية؟

غالبًا لا.

يشدد Chapter على أن Gini impurity وEntropy تنتجان Trees متشابهة عادةً. Gini أسرع قليلًا في الحساب، ولذلك هي Default منطقية.

عندما تختلفان، قد تظهر Tendencies مختلفة قليلًا:

- Gini تميل أحيانًا إلى عزل Most frequent class داخل Branch مستقلة.
- Entropy قد تنتج Trees أكثر Balance نسبيًا.

لكن في معظم Practical workflows، تكون Hyperparameters التي تتحكم في **Tree complexity** أهم بكثير من التركيز المفرط على Gini مقابل Entropy.

## 6. التحكم في Overfitting باستخدام Tree Regularization

Decision trees مرنة جدًا. إذا منحت Tree حرية كافية، يمكنها الاستمرار في إنشاء Regions صغيرة حتى تطابق Training data بدرجة شديدة.

قد يبدو هذا جذابًا، لكنه بالضبط كيف يحدث Overfitting.

تُوصف Tree بأنها **nonparametric** لأن Structure الخاصة بها ليست ثابتة مسبقًا عند عدد معين من Parameters قبل Training. تستطيع Tree إضافة Nodes وBranches بحسب الحاجة لتناسب Data.

لتحسين Generalization، نقيّد هذه الحرية.

### أقصى عمق (`max_depth`)

هذه أبسط Hyperparameter وغالبًا أول واحدة يتم Tuning لها.

⟦CODE_2⟧

قيمة `max_depth` أصغر:

- تقلل عدد Decisions المتتالية.
- تجعل Model أبسط.
- ترفع Bias عادةً.
- تقلل Variance عادةً.
- وتحسن Interpretability غالبًا.

### الحد الأدنى لعينات Split (`min_samples_split`)

يجب أن تحتوي Node على هذا العدد على الأقل من Samples حتى يُسمح لها بـ Split.

زيادتها تمنع Tree من اتخاذ Decisions اعتمادًا على Groups صغيرة جدًا.

### الحد الأدنى لعينات Leaf (`min_samples_leaf`)

يجب أن تحتوي كل Leaf جديدة على هذا العدد على الأقل من Samples.

وهذا مفيد خصوصًا مع Datasets صغيرة أوNoisy لأنه يمنع Tiny leaves تحفظ عددًا قليلًا من Examples.

### الحد الأقصى لعدد Leaves (`max_leaf_nodes`)

تضع حدًا مباشرًا لعدد Terminal regions التي يمكن أن تنشئها Tree.

### الحد الأقصى للـ Features (`max_features`)

تحد من عدد Features التي يجري النظر فيها عند البحث عن Split داخل كل Node. قد تسرّع Training في High-dimensional data وتدخل Randomness مفيدة في Tree-based methods.

### الحد الأدنى لانخفاض Impurity (`min_impurity_decrease`)

لا تُقبل Split إلا إذا حسنت Impurity بمقدار لا يقل عن القيمة المحددة.

### معامل Pruning (`ccp_alpha`)

تتحكم في **minimal cost-complexity pruning**. القيمة الأكبر تشجع Pruning أكثر، وبالتالي Tree أصغر.

قاعدة مفيدة من Chapter:

```text
لزيادة الـ Regularization:
- قلّل حدود max_*
- ارفع متطلبات min_*
- ارفع ccp_alpha
```

### Regularization أثناء العمل

يقارن Chapter Classifierين على Dataset noisy `make_moons()`: Tree غير مقيدة، وأخرى تستخدم `min_samples_leaf=5`.

### Pre-Pruning وPost-Pruning

تنفذ Scikit-Learn غالبًا Regularization أثناء نمو Tree باستخدام Limits مثل `max_depth` أو`min_samples_leaf`.

وهناك Family أخرى من Methods تنمّي Tree كبيرة أولًا ثم **تقص (Prune)** Branches لا تقدم Improvement كافيًا. يناقش Chapter Pruning معتمدًا على Statistical significance في Algorithms أخرى، كما يقدم `ccp_alpha` للـ Cost-complexity pruning.

الفكرة المشتركة هي:

> ينبغي أن تبقى Branch فقط إذا كانت Complexity الإضافية تمنح Predictive value كافية.

## 8. Limitation مهمة: Trees تفضل Axis-Aligned Splits

تطرح Standard decision trees أسئلة Threshold على Feature واحدة، مثل:

```text
x1 <= 2.7
```

أو:

```text
x2 <= 1.4
```

في Two dimensions، تنتج هذه الأسئلة Boundaries رأسية أوأفقية. وهذا يجعل Decision trees جيدة طبيعيًا في إنشاء Rectangular regions، لكنه يخلق Weakness: قد تمثل Model Pattern قطرية بطريقة غير فعالة جدًا.

تخيل Dataset يمكن فصلها بخط قطري واحد. لا تستطيع Tree القياسية رسم هذا الخط مباشرة. بدلًا من ذلك، قد تقربه باستخدام عدد كبير من Splits أفقية ورأسية على شكل Staircase.

{{image:decision-tree-axis-orientation-sensitivity}}

### هل يمكن أن تساعد PCA؟

يوضح Chapter أن Scaling للـ Data ثم تطبيق PCA يمكن أن يدوّر Feature space. وفي بعض الحالات يقلل ذلك Correlation بين Features ويجعل Structure المهمة أسهل على Tree لتمثيلها بعدد صغير من Axis-aligned splits.

⟦CODE_6⟧

هذا **لا** يعني أن عليك تطبيق PCA تلقائيًا قبل كل Tree. الهدف هو فهم أن Coordinate system نفسها قد تؤثر في كفاءة Representation الخاصة بـ Tree.

### Implementation detail مفيدة

يذكر Source أيضًا أن `DecisionTreeClassifier` و`DecisionTreeRegressor` في Scikit-Learn تدعمان Missing values بصورة Native، لذلك لا تكون Imputer مطلوبة دائمًا قبل هذه Estimators.

## 9. Limitation الأكبر: Decision Trees تمتلك High Variance

أهم Weakness في Decision Tree منفردة ليست أنها لا تستطيع Fitting لـ Complicated data. غالبًا تستطيع ذلك.

المشكلة الأكبر هي **عدم الاستقرار**.

تغيير صغير في Training data، أوHyperparameters، أوRandom choice مختلفة أثناء Training قد ينتج Tree مختلفة جدًا.

هذا هو معنى أن Decision trees تمتلك **high variance**.

لكن Reproducibility لا تزيل Statistical instability الأساسية للـ Model. إنها فقط تجعل Random choices نفسها تتكرر.

### الجسر نحو Random Forests

يختتم Chapter بفكرة مهمة:

> إذا كانت Tree واحدة تمتلك High variance، فادمج عددًا كبيرًا من Trees مختلفة وخذ Average أوVote من Predictions الخاصة بها.

قد تختلف Individual trees بقوة، لكن Average لعدد كبير منها يمكن أن يلغي جزءًا من Instability. تقود هذه الفكرة مباشرةً إلى **random forests**، وهي Topic رئيسية تالية.

---

## مفاهيم خاطئة مهمة

### المفهوم الخاطئ 1: "Tree التي تطابق Training data بصورة كاملة لا بد أن تكون ممتازة."

قد يعني Perfect training fit ببساطة أن Tree حفظت Noise. Decision trees مرنة بما يكفي لـ Overfitting بقوة إذا تركت بلا قيود.

### المفهوم الخاطئ 2: "Feature scaling مطلوبة قبل Decision Tree."

تعتمد Tree splits العادية على Thresholds وOrdering، لا على Euclidean distance أوGradient-descent geometry. لذلك لا تحتاج Trees عادةً إلى Scaling للسبب نفسه الذي يجعل Algorithms أخرى تحتاجها.

### المفهوم الخاطئ 3: "يجب أن تكون كل Child node أقل Impurity من Parent."

تحسن CART **Weighted split objective**. ينبغي أن تحسن Combined split الـ Objective، لكن ليس مضمونًا أن تكون كل Child بمفردها أكثر نقاءً من Parent في كل Split ممكنة.

### المفهوم الخاطئ 4: "Decision trees سهلة التفسير دائمًا."

Tree صغيرة قابلة للتفسير جدًا. أما Tree ضخمة فقد تحتوي عددًا من Branches يجعل Manual interpretation غير عملي.

### المفهوم الخاطئ 5: "إذا دوّرت Features أوغيّرت Scale، يجب أن تبقى Learned tree نفسها."

تغيير Scale لكل Feature بصورة مستقلة يحافظ على Ordering وعادةً لا يغير Essential threshold structure. أما Rotating للـ Coordinate system فهي مختلفة: فهي تغير Patterns التي يمكن التعبير عنها بسهولة باستخدام Axis-aligned splits.

## اختيار إعدادات Tree: دليل عملي

| الحالة | الإجراء المفيد | السبب |
|---|---|---|
| Training accuracy مرتفعة جدًا لكن Validation accuracy أسوأ | قلل `max_depth` | يجعل Tree أقل Flexibility |
| Leaves تحتوي عددًا قليلًا جدًا من Examples | زد `min_samples_leaf` | يمنع Tiny regions التي تحفظ Data |
| Tree تحتوي Terminal regions أكثر من اللازم | قلل `max_leaf_nodes` | يضع Limit مباشرًا على Model complexity |
| Training مكلفة مع Features كثيرة | قلل `max_features` | يفحص Candidate features أقل لكل Split |
| Improvements صغيرة في Impurity تستمر في إنشاء Branches | زد `min_impurity_decrease` | يجبر Splits على تبرير Complexity الإضافية |
| لديك Tree كبيرة بعد Fitting وتريد Simplification لاحقًا | زد `ccp_alpha` | يشجع Cost-complexity pruning |
| Results تتغير بين Runs متكررة | اضبط `random_state` لأجل Reproducibility | يجعل Stochastic choices قابلة للتكرار |
| Problem لها Geometry قطرية بقوة | فكّر في Feature engineering أوRotation مثل PCA | قد تحتاج Axis-aligned splits إلى Regions كثيرة وإلا |

## المصطلحات الأساسية

| المصطلح | المعنى |
|---|---|
| شجرة القرار (Decision Tree) | Model تقسم Data بصورة Recursive باستخدام أسئلة Feature-threshold |
| العقدة الجذرية (Root Node) | أول Node داخل Tree |
| عقدة التقسيم (Split Node) | Node تطرح سؤالًا وترسل Examples إلى Child nodes |
| العقدة الورقية (Leaf Node) | Terminal node تنتج Prediction |
| العمق (Depth) | عدد Split levels من Root حتى Node |
| شوائب Gini (Gini Impurity) | مقياس لمدى اختلاط Classes داخل Node |
| الانتروبيا (Entropy) | مقياس Impurity من Information theory يُستخدم بديلًا لـ Gini |
| خوارزمية CART | خوارزمية Classification and Regression Tree التي تستخدمها Scikit-Learn لتنمية Binary trees |
| الخوارزمية الجشعة (Greedy Algorithm) | Algorithm تختار Action جيدة محليًا من دون استكشاف Exhaustive لكل Future decisions |
| النموذج غير المعلمي (Nonparametric Model) | Model لا يكون Effective structure وعدد Parameters فيها ثابتين مسبقًا |
| التنظيم (Regularization) | تقييد Flexibility الخاصة بـ Model لتقليل Overfitting |
| التقليم (Pruning) | إزالة Branches التي لا تستحق Complexity الإضافية |
| الثبات على أجزاء (Piecewise Constant) | Prediction function تنتج Value ثابتة داخل كل Region |
| تقسيم بمحاذاة المحور (Axis-Aligned Split) | Boundary متعامدة مع أحد Feature axes |
| التباين المرتفع (High Variance) | حساسية قوية للـ Fitted model تجاه تغير Training data أوTraining process |

## التحقق الذاتي

قبل المتابعة، تأكد من قدرتك على الإجابة عن الآتي:

1. كيف تحول Decision Tree الـ Feature vector إلى Prediction؟
2. ما الفرق بين Split node وLeaf node؟
3. ماذا تقيس Gini impurity، وماذا يعني `gini = 0`؟
4. كيف تنتج Leaf الـ Class probabilities؟
5. لماذا توصف CART بأنها Greedy؟
6. لماذا تميل Unrestricted decision tree إلى Overfitting؟
7. ما Hyperparameters التي يمكنها جعل Tree أقل Complexity؟
8. كيف تختار Regression tree الـ Prediction داخل Leaf؟
9. لماذا قد يجعل Rotating لـ Dataset الـ Decision tree أكثر تعقيدًا بكثير؟
10. ماذا تعني High variance لـ Individual tree، وكيف تفسر الحاجة إلى Random forests؟

## احتفظ بهذه الفكرة

**تتعلم Decision Tree عبر طرح أسئلة Threshold بسيطة بصورة متكررة. قوتها تأتي من جمع Splits بسيطة كثيرة لتكوين Regions معقدة؛ أما خطرها الرئيسي فهو أن هذه Flexibility تجعل Tree غير المقيدة غير مستقرة ومعرضة لـ Overfitting، ولذلك يكون التحكم في نمو Tree مهمًا بقدر أهمية تنميتها.**
