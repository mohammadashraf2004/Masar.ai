## 1. لماذا لا تكفي Reasoning Patterns وحدها؟

عند هذه المرحلة، تستطيع agent بالفعل استخدام patterns مثل:

- reasoning بأسلوب Chain-of-Thought،
- ReAct،
- Tree-of-Thought،
- Reflexion،
- Sequential Thinking،
- الحلقات الوكيلية بعيدة الأفق.

هذه **reasoning primitives** قيّمة. لكن ما يزال هناك قرار مفقود:

```text
أي reasoning strategy ينبغي للـ agent استخدامها لهذه المشكلة،
وكيف ينبغي أن تعرف أن تلك strategy بدأت تفشل؟
```

إن تكديس كل reasoning pattern فوق كل task يؤدي ببساطة إلى complexity وcost وlatency.

لذلك ينتقل الفصل من reasoning skills منفصلة إلى **cognitive architecture** تستطيع:

- فهم نوع task التي استقبلتها،
- اختيار strategy مناسبة،
- مراقبة ما إذا كانت تلك strategy تعمل،
- إعادة توجيه نفسها عندما تتغير evidence،
- تذكر الخبرات المفيدة.

Right: a cognitive architecture that dynamically selects and monitors these primitives through feedback | Learner should notice that the new capability is strategy selection and adaptation, not simply more reasoning]]

## 2. خمسة Failure Modes لوكلاء قادرين لكن غير إدراكيين

يبدأ الفصل بخمسة production failures متكررة.

### 1. الإجابة الخاطئة الواثقة (The confident wrong answer)

تسترجع agent evidence منخفضة الجودة — مثل metadata أوصفحة table of contents — ثم تعاملها باعتبارها authoritative content.

القدرة المفقودة: **تقييم الأدلة (evidence evaluation)**.  
الإصلاح المعماري: **evaluation module**.

### 2. التكرار المستمر (The broken record)

تعيد agent بصورة متكررة تقريبًا search الفاشلة نفسها.

القدرة المفقودة: **الوعي بالركود (stagnation awareness)**.  
الإصلاح المعماري: **attention module**.

### 3. الخطة الجامدة (The rigid plan)

تتناقض evidence جديدة مع plan الأصلية، لكن agent تواصل اتباعها.

القدرة المفقودة: **تحديث النموذج (model updating)**.  
الإصلاح المعماري: **replanning** يتم تشغيله بواسطة evaluation.

### 4. التخمين المفرط في الثقة (The overcommitted guess)

تفتقر agent إلى evidence لكنها تعرض رغم ذلك answer تبدو واثقة.

القدرة المفقودة: **الوعي بحدود المعرفة (knowledge-boundary awareness)**.  
الإصلاح المعماري: **confidence gate**.

### 5. التركيب السطحي (The shallow composition)

تستطيع agent استدعاء tools منفصلة، لكنها تفشل في إدراك أن task تحتاج إلى تركيب جديد لعدة tools.

القدرة المفقودة: **الاستدلال التركيبي (compositional reasoning)**.  
الإصلاح المعماري: **perception + planning modules**.

## 3. Reasoning مقابل Cognition مقابل Metacognition

يفصل الفصل بين ثلاث أفكار.

### Reasoning

تساعد reasoning patterns على حل مشكلة محددة جيدًا.

### Cognition

تتعلق cognition ببناء وتحديث internal model لـ **ما المشكلة فعلًا**.

### Metacognition

تراقب metacognition عملية problem-solving الخاصة بالـ agent نفسها:

- هل تعمل approach الحالية؟
- هل ترتفع confidence أم تنخفض؟
- هل evidence متناقضة؟
- هل نحن عالقون؟
- هل نعرف فعلًا ما يكفي للإجابة؟

يصبح هذا التمييز مهمًا بصورة خاصة عندما تكون tasks غامضة أومتناقضة أوناقصة أوغير مألوفة.

## 4. أربع قدرات تحدد Cognition لدى Agent

يعرّف الفصل cognition من خلال أربع capabilities هندسية قابلة للملاحظة.

### تقسيم المهمة (Task decomposition)

هل تستطيع agent ابتكار مجموعة مفيدة من subtasks لمشكلة جديدة؟

### الاستدلال حول Dependencies (Dependency reasoning)

هل تستطيع تحديد أن task B تعتمد على task A بينما يمكن أن تعمل task C بصورة مستقلة؟

### الاستخدام التركيبي للـ Tools (Compositional tool use)

هل تستطيع دمج tools في configuration لم تُعرض عليها صراحة من قبل؟

### تحديث النموذج (Model updating)

هل تستطيع تعديل فهمها العامل عندما تتناقض evidence جديدة مع assumption الأصلية؟

| القدرة | السلوك الموجود | الفشل عند غيابها | الـ Primitive الداعمة |
|---|---|---|---|
| Task decomposition | تبتكر sequence جديدة من subtasks | تعامل task معقدة كـ flat lookup | CoT/planning |
| Dependency reasoning | ترتب الأعمال dependent بصورة صحيحة | تنفذ الخطوات عشوائيًا | ToT/sequential thinking |
| استخدام الأدوات التركيبي | تربط tools بطرق جديدة | تربط task بـ tool واحدة فقط | ReAct |
| Model updating | تعدل plan استنادًا إلى evidence | تواصل اتباع plan قديمة | Reflexion/replanning |

## 5. ثلاث قدرات تحدد Metacognition

يعرّف الفصل metacognition من خلال ثلاث قدرات عملية.

### معايرة الثقة (Confidence calibration)

ينبغي أن ترتبط confidence بدرجة الصحة الفعلية.

النقطة المهمة ليست ما إذا كانت Model تكتب كلمات مثل "أنا واثق". يميز الفصل بين verbal confidence وبين internal أوarchitectural signals مثل retrieval quality وevidence consistency وmodel-level uncertainty signals.

### اكتشاف الركود (Stagnation detection)

يلاحظ النظام عندما يتوقف العمل المتكرر عن تحسين النتيجة.

### الوعي بحدود المعرفة (Knowledge-boundary awareness)

تغير agent سلوكها عندما تكون evidence وcoverage غير كافيتين بدل اختراع answer تبدو معقولة.

هذه mechanisms الثلاث أساسية لـ production behavior الموثوقة لأنها تغير ما تفعله agent عندما تكون certainty ضعيفة.

## 6. ثلاثة أسس نظرية تتحول إلى Engineering Patterns

تستعير architecture أفكار design من ثلاثة frameworks.

### Minsky: مجتمع العقل (Society of Mind)

استخدم عدة specialized modules بدل توقع أن ينفذ مكوّن monolithic واحد كل cognitive function.

### Baars: مساحة العمل العالمية (Global Workspace)

امنح specialized modules shared workspace تصبح فيها state وsignals المهمة مرئية لبقية architecture.

### كانمان: النظام 1 / النظام 2

وجّه العمل البسيط والمألوف عبر fast path، واحتفظ بالمعالجة الأعمق للعمل الصعب أوالغامض.

لا يدعي الفصل أن agent تمتلك عقلًا بشريًا حرفيًا. بل يستخدم هذه frameworks بوصفها inspiration معمارية.

## 7. نظرة عامة على Cognitive Agent Architecture

تحتوي architecture الكاملة shared workspace إضافة إلى specialized modules.

في المركز:

- **Cognitive workspace** — shared state منظمة.

وحولها:

- **Perception** — تفهم المشكلة.
- **Planning** — تختار strategy وsubgoals.
- **Execution** — تتصرف باستخدام tools.
- **Evaluation** — تراقب progress وجودة evidence.
- **Attention** — تحدد أي module ينبغي تشغيلها تاليًا.
- **Memory** — تسترجع وتسجل long-term experience.

تدفع agentic loop خارجية التقدم المتكرر نحو convergence.

```text
                 Memory
                   |
                   v
Perception -> Cognitive Workspace <- Planning
                   ^      |
                   |      v
              Evaluation <- Execution
                   |
                   v
                Attention
                   |
                   +--> تختار الـ module التالية
```

لا تنفذ module واحدة المهمة كاملة. بل يظهر behavior من تفاعل modules عبر shared state.

## 8. Cognitive Workspace

ليست cognitive workspace مجرد chat history.

بل هي representation منظمة للحالة الإدراكية الحالية للـ agent.

يخزن الفصل ست فئات عامة:

1. **تمثيل Task (Task representation)** — ما المشكلة التي تعتقد agent أنها تحلها.
2. **Active hypotheses/strategy** — كيف تنوي حلها.
3. **Intermediate findings** — ما الذي تم تعلمه حتى الآن.
4. **Confidence state** — مدى certainty الحالية للـ architecture.
5. **Execution history** — ما الذي تمت تجربته بالفعل.
6. **Attention signals** — events تتطلب rerouting.

وهذا أغنى من research-state object في الفصل السابق لأنه يخزن information عن **reasoning process نفسها**، وليس فقط findings المتراكمة.

## 10. Attention Signals هي قناة التحكم في Workspace

أهم field في workspace هي active attention signal.

أمثلة:

```text
CONTRADICTION -> أعد planning باستخدام hypothesis testing
STAGNATION    -> أوقف تكرار strategy الفاشلة
LOW_CONFIDENCE-> اجمع المزيد أونفذ escalation
KNOWLEDGE_GAP -> استرجع memory / وسّع search
TASK_COMPLETE -> حضّر response
```

هذه هي فكرة global workspace في صورة هندسية: تكتب module واحدة signal مهمة، فتغير attention mechanism سلوك النظام استجابة لها.

## 11. Perception Module

تُعد Perception أول تفسير منظم للـ request من جانب agent.

لا ينبغي لها أن تجيب عن سؤال المستخدم. بل ينبغي أن تصنف المشكلة.

تحدد perception module في الفصل:

- task type،
- key entities،
- complexity estimate،
- ambiguities.

مجموعة instructions مبسطة:

```text
صنّف task باعتبارها simple_lookup أو multi_step أو contradictory،
ambiguous أو compositional أو unknown.

استخرج entities المهمة.
قدّر complexity من 0.0 إلى 1.0.
اعرض ambiguities.
لا تحل task بعد.
```

لذلك تعمل Perception مثل triage: فهي تخبر بقية architecture بمقدار processing الذي تستحقه task.

## 12. العمق الانتقائي: Fast Path مقابل Full Cognitive Cycle

إحدى أفكار efficiency الأساسية في architecture هي أن ليست كل query تستحق المقدار نفسه من التفكير.

يمكن لـ lookup بسيطة ومألوفة أن تسلك fast path.

```text
Simple + familiar
   -> استرجع memory معروفة / نفّذ مباشرة
   -> أعد response
```

أما task معقدة أوغامضة أومتناقضة فتدخل الدورة الأعمق.

```text
Complex task
   -> perceive
   -> استرجع memory
   -> plan
   -> execute
   -> evaluate
   -> ربما أعد planning
```

هذه هي فكرة routing الخاصة بـ System 1/System 2 في الفصل وقد تم تنفيذها معماريًا.

## 13. Planning Module تختار Strategy

غالبًا ما تمتلك agent قياسية behavior عامة واحدة: استقبل query، واستدعِ tools، ثم أجب.

أما cognitive planning module فتختار بين strategies.

| حالة Task | Strategy |
|---|---|
| بسيطة ومنخفضة complexity | DIRECT |
| Multi-step | DECOMPOSE |
| غامضة | EXPLORE |
| Evidence متناقضة | HYPOTHESIS_TEST |

وهذا يعني أن architecture لا تطبق reasoning primitive نفسها على كل task.

يمكن لـ planning module أيضًا استخدام memory hits من tasks سابقة.

ينبغي للخبرة السابقة أن **تسرّع planning**، لا أن تستبدل reasoning الحالية.

## 14. Planning مدعومة بـ Memory

افترض أن task الحالية تتعلق بـ intermittent failures تحت load.

قد يسترجع memory system خبرة سابقة:

```text
connection_pool_exhaustion
ملاحظة: تسبّب سابقًا في إخفاقات متقطعة أثناء الحمل العالي
```

يمكن للـ planner استخدام تلك الخبرة لتوليد hypothesis list أقوى.

لكن ينبغي أن تختبر hypothesis مع المشكلة الحالية رغم ذلك.

ويمنع هذا فشلين متعاكسين:

- تجاهل خبرة قيّمة،
- نسخ حل قديم بصورة عمياء إلى موقف جديد.

وهي لا تبحث عن facts جديدة بنفسها. بل تراقب trajectory الحالية.

- فشل جودة evidence،
- contradiction،
- stagnation،
- انخفاض confidence.

## 17. Evaluation ليست هي Reflexion

يوضح الفصل تمييزًا مهمًا.

### Reflexion

تعمل غالبًا بعد attempt وتغذي critique إلى attempt أخرى.

### Cognitive Evaluation

تراقب task **أثناء التنفيذ** ويمكنها إعادة توجيه trajectory الحالية قبل إنتاج answer كاملة.

```text
Reflexion  -> تصحيح بعد attempt
Evaluation -> مراقبة أثناء التنفيذ
```

كلاهما مفيد، لكن evaluation تستطيع إيقاف approach سيئة قبل أن تتراكم إلى failure أكبر.

## 18. Attention Module توجه Control

Attention هي ما يحول modules إلى cognitive architecture بدل fixed pipeline.

بدل تنفيذ:

```text
الإدراك -> التخطيط -> التنفيذ -> التقييم -> التكرار
```

في كل مرة، تستطيع attention إعادة توجيه control.

أمثلة:

```text
CONTRADICTION  -> PLAN باستخدام HYPOTHESIS_TEST
STAGNATION     -> META_PLAN / اختر strategy مختلفة
LOW_CONFIDENCE -> اجمع المزيد أو ESCALATE
KNOWLEDGE_GAP  -> MEMORY
TASK_COMPLETE  -> RESPOND
```

ينفذ الفصل هذا router في deterministic code بدل استدعاء LLM أخرى.

ويجعل ذلك routing behavior أسهل في الفحص والضبط.

## 20. Memory Module تنشئ Experience مستمرة

يستخدم الفصل MCP reference memory server مدعومة بـ local knowledge graph.

وتتمثل primitives الأساسية في:

- **entities** — nodes أساسية،
- **relations** — روابط directed بين entities،
- **observations** — facts مرتبطة بـ entities.

تضيف cognitive memory module ثلاثة behaviors:

### الاسترجاع الاستباقي (Proactive retrieval)

قبل planning، استرجع prior experience ذات الصلة.

### تسجيل الخبرة (Experience recording)

بعد evaluation، سجّل strategy التي تمت تجربتها وما إذا كانت نجحت.

### بناء العلاقات (Relation building)

اربط problem types التي تشترك في strategies أوfailure modes أوresolutions.

ومع الوقت، تصبح memory خبرة مؤسسية منظمة بدل flat log.

## 21. لماذا يستخدم الفصل Graph Memory؟

يقوم المصدر بمفاضلة محددة.

تتميز vector stores في semantic similarity.

وتتميز knowledge graphs في explicit structural relationships.

بالنسبة إلى cognitive architecture، قد تكون relationships مثل:

```text
timeout_under_load
    --often_co_occurs_with-->
connection_pool_exhaustion
```

أكثر فائدة من مجرد معرفة أن نصين لديهما embeddings متشابهة.

ولا ترتبط architecture نفسها بصورة دائمة بـ memory backend واحدة لأن MCP توفر interchangeable interface.

```text
  الدورة 1
      |
      +--> الدورة المعرفية الداخلية
              إدراك
              memory
              تخطيط
              تنفيذ
              تقييم
              إعادة تخطيط عند الحاجة
              إعادة تنفيذ عند الحاجة
      |
      v
  فحص التقارب
```

وتتحكم inner cognitive cycle في جودة processing المحلية.

## 24. شرح عملي: سيناريو Troubleshooting متناقض

يوضح الفصل architecture باستخدام deployment pipeline تفشل تحت high traffic رغم أن standard timeout fix تمت تجربتها بالفعل.

قد تبحث flat agent عن timeout failures وتكرر standard fix.

أما cognitive architecture فتتصرف بصورة مختلفة.

### Perception

تصنف task باعتبارها contradictory وذات complexity مرتفعة نسبيًا.

### Memory

تسترجع prior experience ذات صلة مثل connection-pool exhaustion تحت load.

### Planning

تختار `HYPOTHESIS_TEST` وتقترح عدة candidate explanations.

### Execution

تختبر hypothesis واحدة في كل مرة باستخدام tools ذات الصلة.

### Evaluation

تحدّث confidence وفق جودة evidence واتساقها.

### Final Response

تعرض أقوى hypothesis مدعومة وdiagnostics مناسبة بدل تكرار standard fix التي فشلت بالفعل.

## 28. الوعي بحدود المعرفة (Knowledge-boundary awareness)

ليست أكثر production agent أمانًا هي التي تجيب دائمًا. بل هي التي تغير behavior عندما تكون evidence غير كافية.

يجمع الفصل signals مثل:

- retrieval relevance،
- memory coverage،
- current confidence.

ثم يصنف task الحالية باعتبارها:

```text
WITHIN المعرفة
EDGE من المعرفة
OUTSIDE المعرفة
```

عندما تقع task خارج knowledge المدعومة، ترفع architecture low-confidence signal وتتجه نحو graceful degradation بدل الاختراع الواثق.

وهذا هو المعنى العملي لعبارة "معرفة ما لا تعرفه" في الفصل.

## 29. Emergent Behaviors من Modules بسيطة

يصف الفصل أربعة behaviors لم تتم برمجتها باعتبارها module مخصصة واحدة.

بل تظهر من interactions بين modules.

### الفضول (Curiosity)

تؤدي low confidence مع knowledge gap إلى جعل architecture تبحث عن information إضافية تتجاوز narrow query الأصلية.

### الاستمرار التكيفي (Adaptive persistence)

تُسجل strategy فاشلة، ثم تعيد attention توجيه control، ويختار planning approach أخرى.

### العمق الانتقائي (Selective depth)

تستخدم المشكلات البسيطة والمألوفة fast path، بينما تستخدم المشكلات الصعبة architecture كاملة.

### التدهور الآمن (Graceful degradation)

عندما تظل evidence ضعيفة، تعرض agent uncertainty أوpartial information بدل اختلاق certainty.

الفكرة الأساسية هي architectural composition: تتفاعل عدة mechanisms بسيطة لإنتاج system behavior أغنى.

## 30. شخّص هل تحتاج Agent إلى Architecture كاملة

يقترح الفصل خمسة tests عملية تقابل failure modes الخمسة.

| الاختبار | السلوك عند النجاح | السلوك عند الفشل |
|---|---|---|
| Evidence evaluation | ترفض metadata/TOC باعتبارها evidence جوهرية | تعرض metadata باعتبارها answer |
| Stagnation awareness | تغير strategy بسرعة | تكرر search نفسها عدة مرات |
| Model updating | تعدل plan عندما تتغير premise | تواصل اتباع plan قديمة |
| Knowledge boundaries | تشير إلى uncertainty عند غياب coverage | تهلوس answer تبدو معقولة |
| Compositional reasoning | تقسم multi-tool task بصورة صحيحة | تعاملها كـ flat lookup واحدة |

إذا كانت agent موجودة تنجح باستمرار في هذه tests، فقد تكون cognitive architecture الكاملة overhead غير ضرورية.

وهذا engineering principle مهم: ينبغي أن تحل complexity failures تمت ملاحظتها فعليًا.

## 31. أربعة Metrics للكفاءة الإدراكية

يوصي الفصل بقياس architecture بدل الحكم عليها بالحدس.

### الكفاءة الإدراكية (Cognitive efficiency)

كم عدد cognitive steps المستخدمة مقارنة بالعدد الذي ينبغي أن تتطلبه task من هذا النوع؟

### معايرة Metacognition

إلى أي مدى ترتبط final confidence بالصحة الفعلية؟

### معدل التكيف (Adaptation rate)

كم iteration تحدث بين اكتشاف strategy سيئة والتحول بنجاح إلى أخرى؟

### دقة حدود المعرفة (Knowledge-boundary accuracy)

كم مرة تحدد agent بصورة صحيحة أن coverage غير كافية؟

لهذه metric نوعان مهمان من الأخطاء:

- **false positive:** تشير إلى uncertainty في سؤال سهل ومدعوم،
- **false negative:** تجيب بثقة عندما تكون evidence غير كافية.

## 33. Generalization معمارية وليست Parametric فقط

الحجة الأخيرة في المصدر هي أن agents الأكثر قدرة لا تأتي فقط من Models أكبر.

تفصل cognitive architecture قابلة لإعادة الاستخدام بين concerns:

- reasoning،
- monitoring،
- memory،
- adaptation،
- tool use،
- confidence control.

يمكن تحسين هذه components بصورة مستقلة وإعادة دمجها عبر domains مختلفة.

وبالنسبة إلى domain جديدة، يمكنك تغيير:

- perception task types،
- execution tools المتاحة،
- descriptions الخاصة بـ planning strategies،
- memory entities وrelations،

مع الاحتفاظ بـ cognitive infrastructure الأساسية نفسها.

## 34. Playbook عملي لتصميم Cognitive Agent

استخدم هذه العملية عند تحديد ما إذا كنت ستبني cognitive architecture وكيف ستبنيها.

### الخطوة 1 — راقب Failure Modes الفعلية

لا تضف modules لمجرد أن architecture تبدو متقدمة.

### الخطوة 2 — ابنِ Workspace منظمة

ينبغي أن تمثل state الـ task وstrategy وfindings وconfidence وhistory وsignals.

### الخطوة 3 — افصل Perception عن الإجابة

حدد أولًا نوع المشكلة التي استقبلتها.

### الخطوة 4 — اختر Strategy من Task Type

Direct أوdecompose أوexplore أوhypothesis-test.

### الخطوة 5 — أضف Metadata إلى Execution Results

أرفق source وrelevance وquality information.

### الخطوة 6 — نفّذ Evaluation أثناء التنفيذ

راقب progress وcontradictions وconfidence قبل final response.

### الخطوة 7 — نفّذ Routing حتميًا من Signals

اجعل attention behavior قابلة للفحص.

### الخطوة 8 — استرجع Memory قبل Planning

استخدم experience باعتبارها evidence، لا حقيقة لا تقبل السؤال.

### الخطوة 9 — تحكم في Final Presentation باستخدام Confidence

اجمع المزيد أوأشر إلى uncertainty عند الحاجة.

### الخطوة 10 — اكتشف Stagnation بصورة صريحة

كون agent تعمل لا يعني بالضرورة أنها تتقدم.

### الخطوة 11 — ضع حدودًا لكل من Outer وInner Loops

امنع runaway macro iteration وrunaway cognitive rerouting.

### الخطوة 12 — قِس هل Architecture تستحق Cost الخاصة بها

قارنها بـ baseline أبسط على tasks حقيقية.

## مفاهيم خاطئة مهمة (Important misconceptions)

### المفهوم الخاطئ 1: المزيد من Reasoning Patterns تجعل Agent أذكى تلقائيًا

> قد تجعل complexity غير المنتقاة النظام أبطأ وأصعب في control.

القدرة الجديدة هي اختيار reasoning strategy الصحيحة ومراقبتها.

### المفهوم الخاطئ 2: Cognition تعني Machine Consciousness

> في هذا الفصل، cognition مصطلح هندسي يشير إلى capabilities قابلة للملاحظة في problem modeling.

### المفهوم الخاطئ 3: Metacognition هي مجرد سؤال Model عن مدى ثقتها

> تأتي metacognition المفيدة من evidence على مستوى architecture، والاتجاهات، وretrieval quality، وconsistency، وconfidence state.

### المفهوم الخاطئ 4: Cognitive Workspace مجرد Conversation History

> هي typed state تمثل task model وstrategy وfindings وconfidence وhistory وrouting signals.

### المفهوم الخاطئ 5: ينبغي لكل Query أن تمر عبر Full Cognitive Cycle

> ينبغي للـ tasks البسيطة والمألوفة استخدام fast path عندما يكون ذلك ممكنًا.

### المفهوم الخاطئ 6: ينبغي لـ Memory أن تملي Current Answer

> ينبغي للخبرة السابقة أن تدعم planning، مع استمرار فحصها مقابل current evidence.

### المفهوم الخاطئ 7: Evaluation وReflexion متطابقتان

> تراقب Evaluation أثناء التنفيذ؛ بينما تنتقد Reflexion غالبًا بعد attempt.

### المفهوم الخاطئ 8: إذا كانت Agent ما تزال تنتج Output فهي ما تزال تحقق Progress

> قد تبدو stagnation منتجة بينما تضيف قدرًا ضئيلًا من information الجديدة.

### المفهوم الخاطئ 9: ينبغي لـ Architecture أن تجيب دائمًا في النهاية

> يُعد knowledge-boundary awareness وgraceful degradation من production features الأساسية.

## المصطلحات الرئيسية (Key terminology)

| المصطلح | المعنى |
|---|---|
| Primitive إدراكية (Cognitive primitive) | Reasoning strategy منفردة مثل ReAct أوToT أوReflexion |
| Architecture إدراكية (Cognitive architecture) | نظام يختار cognitive primitives ويركبها ويراقبها |
| الإدراك (Cognition) | جودة internal representation الخاصة بالـ agent وطريقة تعاملها مع task |
| ما وراء الإدراك (Metacognition) | مراقبة وتنظيم agent لعملية problem-solving الخاصة بها |
| تقسيم Task (Task decomposition) | تقسيم task جديدة إلى subtasks مفيدة |
| Dependency reasoning | فهم ترتيب subtasks والاعتماد بينها |
| استخدام الأدوات التركيبي | دمج tools في configurations جديدة متعددة الخطوات |
| Model updating | تعديل task model أوplan عندما تتغير evidence |
| Confidence calibration | توافق confidence مع الصحة الفعلية |
| Stagnation | استمرار activity من دون progress ذات معنى |
| Knowledge boundary | الحد بين knowledge/evidence المدعومة وغير المدعومة |
| Cognitive workspace | Shared structured state تستخدمها كل modules |
| Perception module | تصنف المشكلة وتمثلها |
| Planning module | تختار strategy وsubgoals |
| Execution module | تنفذ plan steps باستخدام tools |
| Evaluation module | تراقب progress وجودة evidence وconsistency وconfidence |
| Attention module | توجه control وفق workspace signals |
| Memory module | تسترجع وتسجل experience مستمرة |
| Fast path | Shortcut للـ tasks البسيطة والمألوفة |
| Hypothesis testing | Strategy للـ tasks المتناقضة باستخدام competing explanations |
| Confidence gate | قرار هيكلي بين present أوgather more أوsignal uncertainty |
| Graceful degradation | Response جزئية/غير مؤكدة وآمنة عندما تكون evidence غير كافية |

## احتفظ بهذه الفكرة (Retain this idea)

**Cognitive agent ليست مجرد agent تحتوي reasoning steps أكثر. بل هي architecture تبني model للمهمة، وتختار strategy مناسبة، وتراقب evidence وprogress، وتغير المسار عند الحاجة، وتتذكر prior experience، وترفض عرض conclusions ضعيفة باعتبارها certainty. القدرة المهمة ليست التفكير بلا نهاية — بل التفكير الانتقائي والمراقَب والمتكيف.**
